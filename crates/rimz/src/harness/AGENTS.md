# Agent harness

Local contract for `crates/rimz/src/harness/` — the spawn, drive, and reclaim machinery for agent sessions. Extends [crates/rimz/AGENTS.md](../../AGENTS.md).

Topic detail lives in [fleet.md](../../../../docs/internals/harness/fleet.md) (spawn, address, resume, reclaim), [scripting.md](../../../../docs/internals/harness/scripting.md) (supervised runs), [loops.md](../../../../docs/internals/harness/loops.md) (loop scheduling, signals and waits, and the assist log), and [budget.md](../../../../docs/internals/harness/budget.md) (dollar caps and the park), with the shared delivery substrate in [messaging.md](../../../../docs/internals/harness/messaging.md).

## Boundaries

- Resident loop launches stamp only the prompt leader's durable `loop_task`. `team_stage` uses it at root registration to load subscriptions; `schedule/team.rs` shares the standing-binding builder between team and loop registrations. Arming is a lifecycle write, never part of the read-only condition planner or ledger reader.
- The harness owns the checkout and channel team-hold rules (`resume::inspect_team_hold` and `resume::inspect_channel_hold`) a fresh team launch refuses on. `schedule/takeover.rs` owns the resident takeover rule as a pure function over agent rows: who occupies a launch checkout, and which open turn keeps every occupant from being stopped.
- `run/peer.rs::record_run_delivery` records confirmed delivery under the acknowledgment's existing workspace lock: a hook run id naming a subagent run selects answer stamping; otherwise, including a foreground `-p` peer's own run id, it enrolls launcher-opened peer turns.
- `team_prompt.rs` owns the embedded consensus, its read-only inspection copy under the definitions root (published, never read back), and the team prompt layer's derivation; `spec` decides the layer once per role cell at team compile, and `prompt_compose` composes it after the role's own prompt.
- `launch_plan.rs` is the exec wrapper's shared plan/apply boundary: `prepare_exec` is the wrapper's one entry for what to launch (definition refusal through compile), returning account-link and model warnings and the alias move as values on success and failure alike, and running the wrapper's account-home reconcile as a passed-in step between login resolution and compile; `compile` reads and decides without writing, while `apply` materializes prompt artifacts, the launch's temp unit and the room's `shared/`, skill copies, and provider-root skill links in host mode, and refreshes the consensus copy best-effort without ever failing a launch. The exec wrapper executes the plan; `agents explain` renders it without applying. Reminder text is retained from the process compiler's single render, never assembled a second time for inspection.
- The harness owns layout specs, effective launch resolution, profile prompt-file validation, launch finalization, the supervised run's one-cell launch plan (`plan::plan_supervised_launch`, which returns finalize warnings as values and writes nothing to stdout or stderr), provider-process compilation and argv, launch reminder assembly (`launch_reminders.rs` owns the one `<system_reminder>` tag, its paragraph order, and the solo model line; `launch_context.rs` renders a team member's identity, the grouped pipeline with owned stages and the live stage bracketed, the memory-file listing for Environment where the launch does not get it at prompt submit, and its seat's channel rule; the team and catalog producers return bodies and never wrap, and no prompt file adds a tag of its own), supervised run transitions over `store::run` records, the durable blocking-wait policy and run-wake socket (`run_wake.rs`), rebirth inspection and materialization, cohort and lane qualification/resume planning, relaunch posture resolution (`resume::resolve_posture`, shared by restart, fork, and every resume path), lane restore materialization, loop scheduling, hidden runner domain, auto-continue policy, and idle-compaction policy.
- `resume::resolve_posture` returns the planner's `ResumeLaunchPosture` beside its degradation reason. `plan` owns both resume-argv DTOs and never imports `resume`; the recovery plan and its entries are `harness`-private, reached from outside `resume` only by `rebirth`.
- Harness delivery rides `message`; it never reimplements queues, gates, retries, or transcript audit.
- `harness` never reaches `sidebar`: a harness helper that refreshes provider usage returns it, and its CLI entry publishes through `sidebar::refresh`, which alone owns account-cache fusion and publication.
- `scratch.rs` owns the shared team memory-file scan and advisory `blackboard.md` stage parser; launch reminders and cohort reports use the same rooted matching, deduplication, and probe-failure semantics.
- `board.rs` owns all board bytes read for writing, canonical worktree resolution, the board lock (including resume and registration re-wake), stamping, section creation and appends, Stage rewrites, and atomic publication. `rimz teams record` uses it to append stamped Goal, Decisions, and Result entries without a stage signal or delivery.
- The process compiler resolves the launch shell once (the machine's `[agents] shell`, else `proc::user_shell`) and carries it on `CompiledAgentProcess`: the wrapper, the sandbox re-wrap, the Qwen re-entry, the PATH probe, and the reminder's shell bullet all read that one value, and no other harness site reads `proc::user_shell`. The reminder carries no sampled git state, since a launch-time snapshot goes stale before the agent reads it, but names a linked worktree's primary checkout and recorded base from its `.git` metadata and RimZ marker, records written at creation. `runtime_env.rs` owns the prompt-submit sample instead: the fire rule and its claim marker under the runtime `live/` class, the team memory-file listing through the same `launch_context` renderer, and git state through `proc::run_bounded_git_output` under one two-second deadline, capped below 4,000 characters and wrapped by `launch_reminders`. `launch_plan::compile` decides once per launch whether the listing rides the reminder or the prompt (`[agents] runtime-env`, the adapter's `prompt_context`, and `agents::preflight_hooks` passing for the launch's login environment), and the process compiler stamps or clears `RIMZ_RUNTIME_ENV` to match. `launch_reminders.rs` renders the Loop section after identity, then the Environment section before Subagents, names the shell by kind (its file name), and escapes the cwd, worktree values, and shell.
- `team_stage.rs` owns the committed lifecycle reaction (subscription retirement, team binding arming, lifecycle signals, and stage owner re-wake) and stage flips: the clean-worktree precondition on a member hand-off (checked before the board write), the Stage rewrite and required Progress note through `board.rs`, durable `team.stage` signal (the typed `StageSignal` payload, read back by `stage_flips` for `rimz transcript`), direct prose `STAGE` delivery at the done boundary (never steer), best-effort shared-language-server stop for the board's checkout at Done, threshold-driven flip compaction as best-effort enrichment, and resume-time owner re-wake, from the exec wrapper (`rewake_resumed`) or the registration backstop, deduplicated against a stage notice already queued or delivered (since the wrapper's pre-spawn cutoff, or within a delivery window of a registration), read from the queue and history together under the workspace lock. The hand-off precondition covers a member leaving its own stage for one it does not own, including `Done`; compaction takes the same predicate but excludes `Done`, since no member works after it. Compaction and Done-stop errors never fail the flip; Done-stop runs under the board lock. It reuses the scratch parser and message delivery substrate; registration never rewrites the board.
- `schedule/signal.rs` owns the runtime signal vocabulary: `Signal`, `SignalSelector`, `WatchVerdict` and the `WatchOutcome` carrying it, the agent and team lifecycle mappings, and `fire_signal`. `WatchVerdict::label` is the one place a watch's outcome is put into words, and every renderer of one (`compose_wait`, `rimz loop logs`, `rimz loop show`) calls it rather than composing its own; `wait_output_path` is likewise the one derivation of a wait's `out/<reader>/` output file, from the wait row's stored reader, for the arming, the watcher and the elder alike. `WatchOutcome::measured` keeps the durable tail, measures `WatchOutcome.summary`, and records the host path; wait messages show that path with `FileSummary::label` (estimated tokens and lines) without the tail, and `no output` when a watched command's file is empty (a polled watch, whose file is not the thing waited on, stays silent instead). The persisted half sits below it in `store::event` (the `SignalName` grammar, the `agent`, `wait`, `team`, `ci`, `pr`, `trunk`, and `worktree` families reserved from user emitters, including `team.stage` produced with `SignalSource::Team`, `SignalSource`, and `SignalEventPayload`), and `From<&Signal> for SignalEventPayload` is the one conversion into it: `Store::append_signal` takes that payload, so no store module reaches up for a harness signal type. A subscription resolves against the signal's whole family: an exact name delivers, another member of the family skips (recorded, no delivery), and a different family or a failed `--match` is ignored. A signal subscription stays armed across siblings; only a delivering fire consumes a one-shot. Firing is in-process, with no queue and no replay: whichever process observes the event fires the tasks armed for it right there, and a signal nobody subscribes to is gone. A detached watcher is single-flight through its `RuntimePaths` lock, and losing that lock is an outcome the elder resolves, never something the watcher retries. `run_watcher` is that whole watcher lifetime (catalog gate, lock, the command run or the polled probe loop over the row's `WatchSpec`, signal append, fire), and it holds the lock through the fire so the elder cannot call the row lost mid-flight; `schedule/arm.rs` spawns the detached child and the CLI hands over the store and workspace. Watched commands persist an explicit check-in timeout, omit the default when cache keepalive is enabled with a known provider TTL, and otherwise default to 30m; they are never killed for a check-in and always report their exit; watcher fires serialize under the lock and cancellation stops the whole process group.
- `run.rs` is policy over the `store::run` record, which owns the schema, the codec, and the terminal wake sender. Every status transition is a locked read-modify-write here; verify settlement is one call, `settle_verify`, that picks cancel, pass, cap or re-prompt over private transitions. `create`, `load`, and `list` stay as wrappers over the store codec so callers work from `StatePaths` and leave the runs directory to them. Newly terminal subagent and peer runs publish their response files under that lock before the terminal record is written, since waiters read the record unlocked; publish failures warn without failing settlement, and the fleet reporter retries through the same idempotent publisher; a run that reports to nobody is outside the fleet, so its terminal write (which publishes it even as a plain background run) is its one attempt, and an explicit wait still reads the answer from the record. `response_path` and `earlier_response_path` are the one derivation of a response file, `out/<reader>/` from the record's stored launcher handle. Peer response names include the run id so successive turns retain separate answers. A subagent's first response keeps `<name>.output`; follow-up reopens increment its durable `follow_ups` counter and publish `<name>.<follow_ups + 1>.output`, leaving earlier files untouched. Reopens carry unjoined answer metadata and digest links into `earlier_answers`; claims are per answer, joins claim only the printed ordinal, and parent stops dismiss every answer. The hook settles a newly terminal non-peer run's spend through `settle_lifecycle`. The lifecycle fold evaluates its owed-wake input before locking and parks only clean completion; the wrapper-driven stranded-park settle requires two nothing-owed checks and a matching park timestamp under the lock. `run_wake.rs` is the receiving half of that wake: it binds the per-run socket, validates each frame by `(workspace_id, run_id)`, and treats the durable record as truth when a datagram is lost.
- `owed.rs` owns the session's owed-wake predicate, composing ordered pending-wait and message reads with launched-fleet settlement. A run that reports to nobody (`--detach`) is never debt: the fleet term reads `FleetRuns` and the team term reads `fleet::owed_team_runs`.
- `fleet.rs` owns the shared newest-run matching and launched-fleet settlement rule used by digests, their backstop, the owed-wake predicate, and pending-wait enrichment. It also selects open team runs for the launcher's pending waits and the owed-wake team term, and owns the dead-cohort rule the digest backstop settles by; teams stay out of the fleet digest. The detached rule lives here once: `FleetRuns::of` drops a member whose selected run reports to nobody, and `owed_team_runs` skips such team runs for debt while `ended_team_runs` keeps them for settlement, so no consumer filters on `report_to` itself.
- `schedule/arm.rs` owns the shared delivery builder, caller-scoped signal guards, live-subscription dedupe, and session retirement; its armed receipt retains the compiled `LoadedTask`. `schedule/arming.rs` owns effective arming and source defaults through `ArmState::resolve`; catalog-row `LoadedTask::enable` owns enabling and strike clearing. The catalog-private `clear_overlays` coordinates replacement/removal cleanup; instance insertion keeps separate arming and strike cleanup calls with distinct error paths. `schedule/team.rs` materializes declared role bindings at root-member registration with the adopted session identity. Instance rows live per workspace, and a session-pinned row never outlives its target's durable end. `retire_session` is the one removal primitive, called on lifecycle end or loss, explicit stop, the exec wrapper's exit stamp, and `agents restart`; its `RetireScope` takes every row of an identity that is over, or only the rows no later registration re-arms when the same session continues, so nothing depends on an order between a removal and a re-arm. `retire_ended_sessions` is the reconcile that covers every other producer of an end and the one place the "durably ended" predicate is spelled, pulled from each hook observation whose commit appended an event, and from `fire_signal_with_wait` before it selects a task. Both report how many removed rows nothing arms again, a count overlay-cleanup failures do not lose, and gc stays the backstop for a target with no agent row at all. Retirement never signals its own process, so a watcher may retire its own row mid-fire. Self timer/command waits steer with `Type: WAIT`; signal deliveries park at `done` with `Type: SIGNAL`.
- `schedule/runner.rs` owns the stop ladder as `stop_task`, keyed by task name and root so it reaches a consumed one-shot's run: run-lock probe, durable cancellation, grace wait, SIGTERM, grace wait, the `canceled` history row, and the manual-retry error. The CLI supplies the root and the cancellation as a closure and prints the outcome. `in_flight_run` is the one lookup of a run in flight: the lock decides, and the run record is read only while it is held. A task's lock is its bare-name file or any per-checkout file an `each_worktree` fire takes; `RunLocks` lists a root's `locks/` once and probes each run lock once; it reports a task's earliest-started holder and the held locks no row claims, and serves the display state, `in_flight_run`, and `stop_task`, and one private function spells the file name.
- `schedule/throttle.rs` owns the loop start throttle: the home-wide ticket queue and its lock, the `Turn` handle a launch reports through, cap counts, and the pressure, memory, and disk readings. `TaskFire::prepare_throttle` is its one entry from a fire, placed last in both ladders so only a fire that will start an agent takes a turn; a fire about to run a check takes its Ctrl-C listener from the same `Host` beforehand and `prepare_throttle` hands it to the hold. Every reading sits behind the `Host` trait, which tests replace. It is outside the sidebar import graph and samples only inside a waiting run's own pass.
- Terminal loop history rows are appended in the harness only, through the one `run_log` transition (and `run_log::record_stopped` for a stop's strike-neutral `canceled` row, whose task row may be gone); the CLI renders the transition it gets back and never writes a row. `run_log::LoopRunResult::spawn_exit_code` maps terminal spawn results to `store::run::RunStatus` and delegates exit codes to it; renderers keep no separate numeric table.
- The agent-address grammar, its renderer, pane binding, and the launch-instance grouping with its lineage projections live in the top-level `address` module at the message layer; `message`, `harness`, the CLI, and one verdicted `agents` renderer site reach it, and `address` reaches only `agents`, `store`, and `ids`. Handle rendering and address resolution read the addressable peer set; raw root rows are for accounting scans. Minting a handle and deciding whether a name is legal belong to `agents::petname`, which the harness calls.
- CLI handlers keep argument parsing, presentation, and cross-command orchestration. Harness modules own pure domain rules, durable records, helper argv shape, and side-effect boundaries.
- Elder-fired helpers in `schedule/fire.rs`, `auto_continue.rs`, `auto_gc.rs`, `auto_redeem.rs`, `cache_keepalive.rs`, `idle_compact.rs`, `idle_stop.rs`, `park_notice.rs`, and `stall_notice.rs` spawn hidden CLI subprocesses with fresh null stdio.
- `auto_continue.rs`, `auto_gc.rs`, `auto_redeem.rs`, `budget.rs`, `cache_keepalive.rs`, `deadline.rs`, `fleet.rs`, `idle_compact.rs`, `idle_stop.rs`, `orphan_sweep.rs`, `park_notice.rs`, `stall_notice.rs`, `run_timeout.rs`, `schedule/fire.rs`, `schedule/when.rs`, `schedule/launch_ledger.rs`, and `schedule/pending.rs` are in the sidebar import graph. Keep their evaluation side read-only and delegate durable mutations or provider transport to detached helpers; runtime-cache writes through `disk::atomic::write_temp_then_rename_cache` are the allowed durability path. Pending waits read the lenient catalog and launched runs without locks, migration, or writes. Resident launch ledger reads are strict and read-only; its separate mutation module belongs to the helper and catalog removal paths. `auto_gc.rs` also owns its sweep-stamp codec: the producer reads the stamp, and only the detached `rimz gc --unattended` helper calls its durable write. `schedule/fire.rs` writes the fire-state and condition-hold runtime caches before spawning, and the strike-neutral `start failed` history row a failed launch appends in-process, since no helper that never started can report its own failure. `idle_stop.rs` reads the pending requests in `store::idle_stop` and writes only its spawn-pacing cache; its full decision takes a `Store` for the detached helper, which alone stops the agent. `park_notice.rs` and `stall_notice.rs` read the run list and the producer's agents; locked claims on run records and queued notices belong to their detached helpers. No durable store write sits behind these paths.
- Assist records append from CLI handlers, detached helpers, the stage-flip domain, and the loop runner; sidebar-graph modules only pass the evidence those writers need.
