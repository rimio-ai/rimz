# Agent mount views

Local contract for `crates/rimz/src/sandbox/` — opt-in agent filesystem views. Extends [crates/rimz/AGENTS.md](../../AGENTS.md); behaviour lives in [sandbox.md](../../../../docs/internals/sandbox.md).

## Boundaries

- Sandbox owns isolation admission, bubblewrap admission, ordered mount plans, profile skill views, and the environment pins those plans require. The scoped view is not containment.
- The `sandbox` isolation level is provider flag mapping, owned by the adapters. Admission at that level probes nothing: no PATH check, no namespace probe, and no refusal for a provider without a switch, which warns and launches. Do not add a check here that the provider itself makes or skips.
- `TmpView` owns the one mapping between an agent's temp unit and what the agent sees: under scoped isolation the unit is `/tmp` (and `/var/tmp` maps back to it); paths stay host paths otherwise. It is built at the launch compile site and for a caller's own paths (`cli::caller_host_path`), never to print a result path. The host state path remains accessible; a temp unit is separate from host `/tmp`, not hidden from the host.
- Provider home resolution and native override keys belong to the agent capability seam; multiplexer endpoint resolution belongs to the mux domain. Do not duplicate either resolver here.
- Skill roots and the user-only marker come from the adapter (`skills_home`, `manual_skill`); rewritten copies live under the handle's owned unit, or under the room cache for handleless launches (`StatePaths::agent_skills_dir`). Preserve provider-root symlinks and non-skill entries; shadow rewritten skills at canonical paths reached through preserved symlinks, including outside the root, and refuse conflicting alias policies.
- An unlisted skill the view cannot prepare is omitted, never bound unrewritten. Each omission is a returned warning (`SkippedSkill` on `SandboxPlan`) that the exec handler prints; failures listing the skill root or writing under `skills_dir` remain errors.
- `plan` reads skill and system SSH-config sources and captures copy bytes, mount targets, and environment pins without creating files or directories. `apply` writes the captured copies and ensures the temp unit; a caller that needs both runs them in that order.
- The SSH-config mirror walks every Include reachable from `SandboxInputs.ssh_config_file` (the compiler passes `/etc/ssh/ssh_config`), regardless of Host/Match blocks. It accepts case-insensitive first tokens, whitespace or `=`, quoted arguments and globs; relative paths use the root config's directory. Each canonical regular file is visited once and captured with mode `& !0o022`, root included. Every Include line is rewritten to quoted cache paths for mirrored matches and host paths for unmirrored matches, in glob order per argument; no-match arguments are dropped, `~` is kept verbatim, and a line left with no path becomes a comment holding the original. Other lines keep their bytes. Missing/unreadable inputs give no copy or mount; dangling links, non-regular matches and unreadable files get no copy. No mirrored include means no copy or mount. One shared-publisher copy lives under `StatePaths.ssh_config_copies_dir` (`cache/ssh-config/<sha256>/`), with the digest covering placeholder-rewritten bytes, masked modes and names. Only the rewritten root is bound at its canonical path, after every other mount. User-config Includes are outside this walk.
- A bind of a single file detaches in every running view when the host renames a new file over its destination, which is how package managers and most config tools write. Bind a directory, or a file that is rarely replaced, and say which in the docs. The SSH mirror binds the system config root; replacing that file requires restarting the agent, while replacing included files does not.
- Launch compilation applies environment pins after shell startup; CLI execution retains the probed wrapper path and routes preparation errors through launch/run failure cleanup.
- `sandbox::plan` binds the launch's temp unit (`StatePaths::temp_unit_dir`, owner resolved by `launch_plan::compile`) at `/tmp` and `/var/tmp`, refuses a required path equal to either mount (`TmpCollision`), and rebinds required paths beneath them. `StatePaths::ensure_temp_unit` creates the unit and the room's `shared/`, both `0700`, whose host path `RIMZ_SHARED` names in all isolation levels; teardown leaves both for GC, a hard reset ends the processes that still have a unit as their `/tmp` before it deletes `tmp/`, and RimZ's result files live in the state `out/` class instead.
- Unit tests cover pure parsing and argv lowering. Filesystem and real bubblewrap tests live in `tests/integration/sandbox.rs`; room messaging and supervised handoff belong to the journey tier.
- Real-bubblewrap tests self-skip in CI, where the container denies the namespace (`bubblewrap unusable:` in `.config/allowed-test-skips.txt`), so a property of the view itself is proven only on a local non-root run; give it a bubblewrap-free test of `plan` and `apply` as well.
- A change to which paths a mount plan binds tests each entry kind in `tests/integration/sandbox.rs`: a plain file, a directory, a symlink, a missing path, a `.git` file pointing elsewhere, and a linked worktree. SSH-config mirrors cover a regular file, symlink, dangling symlink, directory, FIFO, and missing or unreadable source.
