# CLI layer

Local contract for `crates/rimz/src/cli/`: argv to typed requests, the process edge (tty, signals, exit codes, stdout/stderr discipline), and presentation (view models and renderers). Extends [crates/rimz/AGENTS.md](../../AGENTS.md).

## What lives here

- A free-text positional (a note, text, prompt, instruction, or message body) sets `allow_hyphen_values = true`; its reference page names `--` as the escape for a value that is exactly one of the command's flags, `-h`/`--help` included. Exception: agent and subagent launches reserve `--` for provider passthrough; an interactive agent launch cannot take such a prompt, a print run can read it from `agents -p --stdin`, and subagents can use `--prompt-file`. Launch prompts guard prefixes matching value-taking short flags so attached values cannot silently become prompts; document the spaced option spelling and the guard's application after `--`.
- clap argument types, stdin/file parsing, workspace lookup at the entry point, interactive prompts, stdout/stderr presentation, exit codes. A new, removed, or renamed flag updates the `cli_surface_is_stable` snapshot in the same commit: `cargo xtask test --name cli::surface_tests::cli_surface_is_stable`. Accept the change with `cargo insta accept`; never copy the `.snap.new` over the snapshot, since its header differs. The snapshot records command and argument shapes only; a help-text change moves no snapshot. A doc comment on an `Args` struct flattened into several subcommands prints in each one's `--help`; when the verbs take different input, set each one's help per verb and assert it per verb.
- Existing cross-command orchestration combining room, mux, store, agent, and message operations (`rimz start`, gc sweeps) is debt for rehome passes, not the target. Multi-step workflows with decisions, retries, settlement, or recovery belong to the library module owning the concept; straight-line sequences of library calls stay here.
- `wait/` resolves the calling live agent to arm self waits and presents self views, room wake-up cards, and receipts through `wake_view`. Named cancellation takes any delivery targeting the caller; `--all` takes only self waits. It and `loop_cmd/` call `harness::schedule::arm` for delivery construction, signal defaults and guards, dedupe, and detached watcher spawning; neither command imports the other. The shared resolver supports `@me`, including bare `loop add --wait` ([loops.md](../../../../docs/internals/harness/loops.md#waits)).
- Human and JSON rendering. Large render surfaces stay here: doctor, stats panels, transcript, pane, loop, and gc reports. A doctor row's cells name the problem, at most with its consequence, in a short phrase; the remedy goes only in the `fix` its tally records, so the table stays narrow and the closing block states each fix once. A finding or notice built from a template is rendered once per cause, and with one and with several members, before hand-off; read each result as a sentence.
- `workflow` parses and renders workflow commands without creating rooms and implements the harness's attempt-host seam over the library launcher and resolved stop entries; layouts carry one turn or session leader, and every agent cell carries the workflow attempt pin. The harness owns run admission, transitions, condition evaluation, script/shell/judge and command-step hosting, and detached advances over store-owned workflow records.
- Shared CLI-layer modules serve every command: `ctx` (the participant entry: workspace, store, channel, and the snapshot flavours), `render/` (output streams, a process-lazy machine theme, and typed state presentation), `wake_view` (wait lines, room cards, subscription summaries, and counts), `spinner`, `usage` (the usage error `main` exits 2 for, and the no-verb scene refusal), `send` (shared send flags and outcome presentation), `ask_commands` (the next-step, refusal, and receipt text `asks` and `answer` share), `address`, `profile_report` (profile/command catalog presentation), `loop_timer` (external loop tick and OS timer lifecycle shared with uninstall), `worktree_protection` (runtime pane, agent, loop-task, and team-board fact gathering for removal callers), and the target-resolution helpers in `mod.rs`.
- The shared `launch_interaction` module presents launcher decisions, notices and receipts. `worktree_entry` presents existing-checkout facts and launch-entry offers; the library launcher owns relaunch commands and protected recreation.
- Participants open through `open_existing_store`, directly or through `Ctx`, and refuse when the room has no readable workspace record. Identity-only and read-only maintenance commands may tolerate an absent room; none creates its state tree or re-records its identity. Identity resolution through `WorkspaceResolver::resolve_participant` remains independent of whether the room exists.
- **Invariant.** Only room-choosing commands create stores: `start`, `attach`, `reset`, and `workspace migrate`; the sessions picker and `web` reuse room preparation, and library birth, rebirth, and the launcher's supervised preparation (including a spawning `loop fire`) and checkout creation own their creation. `open_store` creates the state tree and records the workspace only for those commands. `ensure_room_creators` grep-enforces the closed creator file list; extending it is a deliberate decision.

## What lives in the domain modules

A handler parses, calls the domain, and presents; the knowledge lives in its owning module:

- `launcher` — layout and supervised preparation and shared execution, placement and child zones, trust verdicts, LSP admission, checkout settlement and cohort reconciliation.
- `harness` — launch compilation and validation vocabulary, resume/rebirth planning, schedule policy, run waits.
- `message` — dispatch conditions, delivery causality, reply-wait state.
- `room` — room identity (session→mux resolution, lock-based room admission, session→workspace-record lookup), private room context, the one birth path.
- `config` — format-preserving config editing and bootstrap.
- `store` — event construction, rotation policy, pane/session binding eligibility.
- `sidebar` — presence ingestion, topology fencing, cache publication.
- `worktree` — clean linear landing, sweep assessment, protection policy, and lifecycle cleanup.
- `agents` — provider argv vocabulary and per-kind context policy (field ownership, merge rules).

## Boundaries

- Resident loop and workflow helpers reuse `agents_cmd::stop_resolved` before launching. The harness reads owned worktrees to select the launch checkout's occupants and what blocks a takeover (`schedule::takeover`); each helper supplies runtime-scoped agent rows, stops over those unmodified rows, and presents.
- Human colors come from `render::palette` accessors, state tones come from typed `render::status` helpers, and provider names and handles come from `palette::identity`. Agent prose reaches a human through `render::prose::Prose`: markdown on a styled stdout and raw text when piped; one-line previews stay snippets. JSON, hook stdout, pane capture, scripting values, and streaming protocols stay raw.
- Human rendering is checked at its edges as well as at the snapshot sizes. At the narrowest width its docs support, strides, labels, and truncation run out of room. With colour off (`NO_COLOR`, `CLICOLOR=0`, `--color never`), `anstream` strips every SGR, so a mark told apart by tone alone (an overlay, a forecast, a muted span) reads as the data beneath it. Such a mark states what it draws then.
- A change that alters rendered text runs the merge base's binary and the head's on the same input in each mode it changes and reads the diff, not just the figures. Before building a base binary, read `rimz --version` on the installed one: a `+g<hash>` suffix without `.dirty` names the commit it was built from, and when that commit is the merge base it is the base binary. A bare release version gives no such shortcut. A change that lengthens a label inside a fixed-width layout (a heading padded to a name column, a one-line tab rail, a padded section title) renders each layout with every value the label takes and asserts that header columns still line up with row values and that no value is clipped; a line-width bound alone passes a clipped line.
- A human history list folds adjacent records that differ only in time into one row: what happened, `×N`, the span, and the worst member (the duration range, summed spend, and newest reason). A record that only explains another, such as a fire refused because a run held the lock, folds into that record's row as a count, matching the typed lock identity both records carry. Older histories fall back to log order. A lock-holding `overlapped` or `deferred` record with matched fires keeps its own row and counts once, never also as a folded fire. When a later tenure proves an unmatched holder gone, a `○ no record` row stands in for its missing record and keeps its fire counts; trailing refusals (after the last run, or in a checkout no later run used) still take no row, so the header's stale clause leaves out a refused fire it would otherwise count only when a row shows that fire. Compare typed fields, never stored text, and stored text never carries an age: an age frozen at write time is false when read and splits rows that agree. State a fact once (a pid the header states stays out of rows; a count a row states stays on that row, and the header names the fact without the number), and use one word for one thing throughout the screen. A rule that omits a section because it repeats another is rechecked whenever the change adds a fact to that section. `--json` keeps one entry per record. The reference application is `rimz loop show`'s RECENT RUNS, `crates/rimz/src/cli/loop_cmd/render.rs::collapsed_run_rows`.
- The CLI is compiled into the binary crate (`main.rs` owns its module) and reaches library items only through `rimz::`, so any item a handler calls must be `pub` in the library; `pub(crate)` is invisible here. A new `pub` item needs its `refactor-target.toml` admission (root [Testing](../../../../AGENTS.md#testing)).
- A command module's internals are private: one command never imports another command's functions or types. Shared logic moves to the domain module that owns the knowledge, or to a shared CLI-layer module when it is pure presentation.
- Code that moves from a handler into the library takes the CLI helpers it calls along with it: the helper moves to its library owner (`theme::fmt` for value formats) and the CLI's copy becomes a one-line delegate, as `render::compact_count` is, never a second body.
- Existing published orchestration entries are migration debt: `room` attach execution (used by `remote`), `hooks` install UX (used by `room` start and `setup`), `supervised` run driver (used by `agents_cmd`, `subagents`, and `loop_cmd`), `agents_cmd` resolved lifecycle operations and resume preconditions (used by `teams`, `subagents`, and `workflow`), and `subagents` parent-only child resume doorway (used by `message`). Layout commands and supervised callers use the library launcher for preparation, room entry and pane opening; the supervised driver retains waits, streaming, verify, retry decisions, joins and cleanup. Resident loops use the same launcher; resident loops prepare once, take over the target checkout, then execute that preparation, while ordinary agent commands execute immediately and render their receipt. Add no other published orchestration entries. Rehome passes move workflows to their library owners; rendering stays here, and `supervised` keeps publishing run rendering (used by `subagents`) as a sanctioned cross-command entry.
- Concrete typed structs and functions are the default shape here. A generic service trait earns its place once a second real caller needs the seam, never in anticipation of one.
- Domain code reports warnings as returned values and the handler prints them; the CLI owns every write to stdout and stderr.
