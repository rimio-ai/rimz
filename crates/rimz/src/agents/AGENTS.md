# Agent adapters

Local contract for `crates/rimz/src/agents/`, the integration layer. Extends [crates/rimz/AGENTS.md](../../AGENTS.md).

Behaviour lives in [adapter.md](../../../../docs/internals/agents/adapter.md) (this layer) and [model.md](../../../../docs/internals/agents/model.md) (the agent model the adapters feed), with one `adapter_<kind>.md` per kind beside them and [providers.md](../../../../docs/internals/agents/providers.md), [logins.md](../../../../docs/internals/agents/logins.md), and [spending.md](../../../../docs/internals/agents/spending.md) for accounts, logins, and spend. Upstream protocol references are `docs/externals/agent-adapter/<kind>-reference.md`. [agent-adapters.md](../../../../docs/contributing/agent-adapters.md) is the playbook for a new built-in.

## The boundary

- **Invariant.** An adapter is the single place an agent protocol is normalized. Provider modules stay private below [`adapters/`](./adapters/mod.rs): code outside `agents` resolves an `AgentDefinition` and calls neutral services, and `cargo xtask invariants` rejects a provider module path or a concrete adapter type named there.
- An adapter implements every capability trait, with an empty `impl` where the agent has no behaviour. The trait default is the single home for "this agent does not do that": no dispatch layer restates it.
- Shared decisions keep one home, and an adapter supplies their inputs without restating them: `SessionSource::session_start_signal` owns what a `SessionStart` source means, `LocalContextRefreshCtx::changed_transcript` owns the unchanged-source gate, and `AgentDefinition::attach_hook_context` writes hook-context replies in the shape `Capabilities::hook_context` declares.
- Adapters return provider-neutral intent and make no durable write. [`cli/hooks.rs`](../cli/hooks.rs) binds runtime identity, emits only `HookReply` on stdout, and submits lifecycle write intent to Store. A local refresh emits `FieldPatch` and `LocalTokenPatch` operations, which Store applies under the record lock without branching on kind. A context refresh works the same way: the adapter reads only its own provider source and returns write intent, and the CLI owns every durable write and the sidebar wakeup.
- Emit only the normalized outputs generic flows consume. A provider-only capability stays in its provider module until a second generic consumer proves an adapter seam.
- Nothing under `agents` imports `store`, and (**invariant**) no production code here imports the sidebar: workspace inputs flow in through `agents::spending`. The agent record types Store persists (`AgentContextRecord`, the budget vocabulary in [`state.rs`](./state.rs)) are owned here; the budget engine is `harness::budget`.
- **Invariant.** A provider home is an account. Every host-side read of one resolves from the login env map its caller passes, through the adapter's `config_home`. The gate rejects a process-env read of a provider home key outside tests, and a whole-process-env snapshot anywhere in this tree but [`login.rs`](./login.rs).
- **Invariant.** Every provider-file write goes through [`provider_file.rs`](./provider_file.rs), which follows a shared-settings symlink before it publishes atomically; the gate rejects the direct atomic write elsewhere in this tree. [`account_links.rs`](./account_links.rs) is the one writer of links between an account home and the provider's own home.
- **Invariant.** Every `spend.rs` is a read-only, sidebar-safe parser: the gate rejects store-write, run-wake, and broker imports there.
- Publication has one writer per file. `sidebar::refresh` alone writes the account caches and the model refusal record ([`model_refusal.rs`](./model_refusal.rs)). The `agents::spending` engine is the only runtime writer of `provider-spending.json` and `workspace-spending.<hash>.json`, through one version-stamping writer per file.
- One account record per login. Every source of a login's plan, metering, account id, or version (a probe, a live session's context, a usage read) writes the `accounts.json` record through [`account.rs`](./account.rs)'s `merge_account_reading`, and every surface reads only that record, never a live context. [The account record](../../../../docs/internals/agents/providers.md#the-account-record) gives the merge rules.
- Spend on a flat plan is a list-price estimate: the dollars `rimz stats` and the cards show are what the same tokens would cost at the provider's pay-per-token API price ([spending.md](../../../../docs/internals/agents/spending.md)).
- A read-only probe of a user-editable upstream JSON file parses through [`jsonc.rs`](./jsonc.rs). An install flow that rewrites the file keeps strict parsing, so comments are never silently discarded.
- A plugin manifest derives its claims: the declared canonical event list, capabilities, and probes generate both descriptor matrices. Its hook installation stays self-managed and its neutral output empty; its probes stay bounded, read-only, and off the store import graph.
- `skill_links` owns a host-mode provider-root symlink structurally: the link is RimZ's when its target, resolved relative to the root and lexically normalized without canonicalizing, lies under the RimZ skill library or packs directory, even when dangling. Plan and apply preserve foreign entries, and discovery skips owned links so they cannot change `skills::SkillChain` precedence.
- A new file in an adapter directory gets a row in its adapter page's `## Files` table when the page has one.
- Fail-fast, settled: A profile's `empty-dir` is enrichment too. A fresh eligible launch grants an undecided account's folder trust only when its grantable key is the resolved empty root, with a stderr line and an assist record. Saved-untrusted, non-grantable, and wider-key accounts start in the caller's directory with a notice and a `rimz doctor` row. A failed automatic write falls back with its file and error, while a dirty empty root refuses the launch. An explicit subagent `--empty-dir` and the undecided explicit-cwd fallback instead require that placement and refuse when it is unusable; neither trusts the target or any added directory.
- Fail-fast, settled: Tuning settings a provider cannot express (sandbox, effort, auto-compact, fast, code mode, and a model left behind by a kind switch), and tool lists it cannot apply, warn and launch without that setting. OMP ignores tool lists silently. Preset refusals remain for an adapter's own limits (an effort outside Hermes's level list or model on Droid) and for settings that define or limit the agent (a system prompt or `--max-turns`). Invalid auto-compact counts and relative effort in definitions still refuse.

## Hook discipline

- **Blocking ask hooks are sync.** Installing one as async is a hard install error. The source of truth for "must block" is the adapter's hook catalog or equivalent typed installer declaration, never the on-disk config.
- **Neutral follows the agent's decision contract**: empty stdout, or JSON on every wired event where the agent's hook contract requires it (Cursor, Antigravity).
- **Set installed hook timeouts from upstream deadlines**, leaving margin for RimZ to finish store writes before the agent kills the hook.
- **Install is idempotent.** Reclaim owned entries or whole files before rewriting the canonical set, and leave user-authored entries untouched. A shared JSON merge reclaims by the stable command substring.
- Golden every stdout shape, the neutral no-op and malformed-payload handling included, as an inline `insta` snapshot in the adapter's `tests` module.

## Before a change

Before a change of one of these kinds, read the section named beside it and do what it asks. No gate catches a skipped one.

- A provider's launch argv or `--settings` JSON, an adapter's permission arguments, `process_names` or `bin_names`, `ROUTINE_RIMZ_PREFIXES`, or a new `rimz` verb an agent runs from its own pane in a flow RimZ drives: [Launch surface and routine verbs](../../../../docs/contributing/agent-adapters.md#launch-surface-and-routine-verbs).
- A refresh that writes the context sidecar on another hook or passes an unchanged-stat gate, an input or a store or sidecar read added on the hook path, what `local_conversation_present` answers, an `Ignored` edge in `lifecycle::step`, or an adapter's `ContextCapability::context_cost`: [Context refresh and the hook path](../../../../docs/contributing/agent-adapters.md#context-refresh-and-the-hook-path).
- A declared coverage or lifecycle-hook verdict, a preset, an install version gate or hook set, or a conformance failure: [Coverage and conformance](../../../../docs/contributing/agent-adapters.md#coverage-and-conformance).
- A spending session key split, a rule that identifies a transcript by file name, a spend parser that counts a new source, or the order of price lookup candidates: [Spend and pricing](../../../../docs/contributing/agent-adapters.md#spend-and-pricing).
- The room spend slice (`aggregate_scoped_rollups` in [`spending/aggregate.rs`](./spending/aggregate.rs) and what it calls) or the spending walker's memo build (`SpendingWalker::ensure_memo`): [Timing comparisons](../../../../docs/contributing/running-gates.md#timing-comparisons).
