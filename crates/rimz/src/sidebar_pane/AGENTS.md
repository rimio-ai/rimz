# Sidebar renderer

Local contract for `crates/rimz/src/sidebar_pane/` — the sidebar renderer: the pane-resident supervisor and the room host that paints for it. Extends [crates/rimz/AGENTS.md](../../AGENTS.md). The renderer split lives in [docs/internals/sidebar/sidebar.md](../../../../docs/internals/sidebar/sidebar.md), the on-screen spec in [docs/interface/sidebar.md](../../../../docs/interface/sidebar.md), the color pipeline in [theme.md](../../../../docs/internals/theme.md), and the pet in [pets.md](../../../../docs/internals/sidebar/pets.md).

## The process

- `web` never imports `sidebar_pane`: the kitty placeholder encoding both speak is the leaf `pixel_wire` module, and the renderer's one read of `web` is `web::pixel_ttyd_pids`, the ttyd daemons serving the current pixel page.
- One [`host.rs`](./host.rs) process per mux session is the only painter; each pane's [`supervise.rs`](./supervise.rs) holds the pane's tty and hands the host its output fd over the wire in [`attach.rs`](./attach.rs). The supervisor's `SupervisorConfig` carries only argv/pane identity and cadence, without machine settings. [`app/attachment.rs`](./app/attachment.rs) is one pane's loop, [`app/plane.rs`](./app/plane.rs) the data plane the host runs once for all its panes, and [`app.rs`](./app.rs) keeps host-built `RoomConfig`, `ServeConfig`, `SidebarAppErr`, `install_panic_diagnostic_hook`, and runtime-file cleanup.
- The CLI refuses outside a mux pane first. The supervisor refuses non-terminal stdout or unavailable runtime paths before socket or terminal-mode work, initializes the runtime directories, and takes a shared room hold before attaching. On tmux it pins its own pane to `remain-on-exit off` at startup; a failed pin only warns. The room hold and tty guard last for its whole lifetime, including host retries; re-exec takes the hold again. Failure to acquire the hold refuses startup. When a host cannot attach or goes away, it clears and homes the screen with plain stdio control bytes, writes an uncolored cause and retry delay with raw-mode line ends, and retries on one backoff curve ([host recovery](../../../../docs/internals/sidebar/state.md#host-unavailable)). It never writes a notice while attached.
- The host keeps the session environment minus pane-scoped names; its spawner sets the room pin from a verified workspace record, or records why no host starts in the host log ([host environment](../../../../docs/internals/sidebar/state.md#the-room-host-and-its-attachments)).
- Nothing a pane's loop reaches reads the process's own terminal: geometry, cell aspect, and the cursor come from the pane's [`app/backend.rs`](./app/backend.rs), and pane identity from `ServeConfig::own_pane`. The host has no terminal, and an ambient read there would describe some other pane or block. Terminal modes and the event reader belong only to the supervisor.
- [`app/loop_state.rs`](./app/loop_state.rs) owns the renderer's state transitions and the loop-lifetime context. [`render/`](./render/mod.rs) turns a `SidebarSnapshot` into cells, and [`supervise.rs`](./supervise.rs) owns convergence.
- The supervisor forwards raw key presses, mouse input, and resize words as lines on the attach stream; the host resolves keys against the view's presentation (`ViewState`) before applying configured bindings, so help and search consume keys before normal commands.
- The supervisor carries the last painted view's selection baseline across attachments, host restarts, and supervisor re-exec. It seeds only a view without a baseline, at its first sized composition. Full views live only in host memory. A jump's placement carries the source frame's open set as one-paint geometry evidence, not toggle state; a same-host landing keeps the live view's order and hold deadline.
- `LoopState::watched` counts resolved membership and focus/input optimism for paint, frame timing, and hidden skipping. Input and observed visibility route to a shared view; hidden resize alone changes no view. Evidence routing never takes a view another painting pane holds. A change keyed on watched-ness tests both the optimism window and observed state, on tmux and Zellij.
- The fetch thread (`FetchWorker`) in [`app/fetch.rs`](./app/fetch.rs) owns the pane producer and folds retained inputs through the shared enrichment core rather than reading its publications. It publishes one unprojected room fold into the host's views; every attachment projects it for its own pane when it reduces, through the same routine as its seed. The refresher consumes that sampled fold, requesting and waiting at most its own data tick when no young fold exists, rather than folding independently. `rimz sidebar snapshot` computes privately over the same library, never this process's data path.
- Rendering reads the snapshot clock. `cargo xtask invariants` rejects `Timestamp::now()` in non-test render code, which is what keeps a frame reproducible from its snapshot alone.
- The attachment's `LoopClock` owns transition time and effect policy; the testkit scenario player feeds its views and native input path on virtual time, with external effects disabled.
- Content equal to the reducing view's accepted baseline applies clock-only, decided after projection with live reconciliation permission, and skips fusion, the regression gate and ordering. Notification and unread side effects still run on every final fold. The delivery rules live in [state.md](../../../../docs/internals/sidebar/state.md#one-fetch-cycle).
- Settled hidden panes leave the latest publication unread in the views without projecting until reveal, an own-view change, or a bounded reconciliation obligation: exit, gate, health failure, tab-read dwell, empty confirmation, focus repair or pending input focus. Freeze and overlay state do not block skipping; freeze deadlines sleep while hidden. Failures always apply and skipped finals complete requests and refresh the self-close watchdog. Events drain only their owners: revealing focus, owned notification targets, own stranded focus and owned focus intents. Width and filter events retain their local effects. Input still flushes; hidden resize changes geometry only. Jump leases order clicks without holding room work; priority pushes run before ordinary inbox work and maintenance.
- A change that skips folds lists every per-fold state it stops advancing (spend rolls, width-control stamps, read receipts) and every per-backend emitter it changes.
- The host's fetch worker refolds shared truth on every cycle, resting at least 250 ms after each cycle returns regardless of request mode; pane projections share agent-scaled collections, the group vector, and rows, and own their local metadata. Take mutable access to a shared collection only after a read proves a change is needed; group edits detach the vector and only changed row collections. An armed layout freeze detaches only the collections whose order the hold changes. Only completed production recovers refresh health; fast cached folds and new-attachment seeds never mask a failed pane read.
- Selection, layout freeze, spend animation, receipts/dwell and presentation toggles belong to the host's client views under one mutex. Co-viewers share one view; a split copies it, and arrival beside a continuing viewer joins the destination's view. Unpainted views do no work. Geometry, hit maps, render caches, width control, self-close and scheduling remain pane-local. Composition holds the view lock; terminal output, mux calls, asset loads and read-mark I/O do not. Routing and the latest fold are re-read after unlocked preparation. The membership, retention and evidence rules live in [state.md](../../../../docs/internals/sidebar/state.md#client-views).
- Room-owned state — the shared overlay, locked read marks, internal notification delivery, the room-wide unread reminder timer and reload decisions — stays with the host. One room socket receives external events and filters their workspace/session scope. The plane records those events and the host's own events once, requests at most one fold per event, and fans them out to its subscribers' bounded wake channels. Reload triggers post to the host inbox; one decision drains every pane or refreshes the shared plane in place.

## Read-only on the store

- The renderer draws; [`store/`](../store/AGENTS.md) writes. The invariant rejects a store-atomic or store-writer import anywhere under this tree, and it greps text, so state the rule in prose rather than pasting the banned paths.
- The rule covers test files too; a fixture writes its runtime files with serde and `std::fs::write`.
- Event-log history enters through a `RollupCursor` fold, the same rule that binds [`sidebar/`](../sidebar/AGENTS.md).

## The theme edge

- Resolve every color through a component token, `theme.component(Component::…)` in [`render/theme.rs`](./render/theme.rs), or a semantic accessor. The invariant rejects every named ratatui `Color` variant in render code — including the indexed and true-color constructors — leaving `Color::Reset` as the single literal a render file may name, so only the theme pipeline mints a color.
- Resolve every glyph through `theme.glyph(GlyphRole::…)`, which the shared core in [`theme/`](../theme/mod.rs) owns. The invariant carries the banned-literal list, which is what keeps the legend and the frame in step.
- The carrier layer is exempt: [`render/theme.rs`](./render/theme.rs) and its component tokens turn a tone into a ratatui color, and [`render/ansi.rs`](./render/ansi.rs) quantizes that carrier down for a limited terminal. Add a color or glyph there and name it by role everywhere else.
- A new mark, line, or chip gets its own `Component` variant even when an existing one already resolves to the tone it wants: a variant names one UI role, and borrowing another role's token lets that role's retune recolor the new element.
- A new `Component` variant names the element it paints in the [theme guide](../../../../docs/guide/theme.md)'s palette table, on the row of the palette slot `Component::resolve` maps it to.
- Measure the painted width of text the renderer did not format itself (a product name, a theme override, an account label) with `text_width` in [`render/layout.rs`](./render/layout.rs), never `chars().count()`: such text may hold wide or zero-width characters, and a budget counted in chars misplaces every cell and click target after them.
- On a card's identity line, a token (a badge, a mark) yields width before the handle does: the handle draws exactly as on a plain card, and the token drops when it does not fit beside it.

## Pets

[`pets/`](./pets/mod.rs) owns asset loading, sprite slicing, cell-art conversion, track selection, and captions. The renderer receives a `PetView` and nothing more, so decode, cache, and I/O stay inside the module.

## Tests

LoopState test rigs share views by default, as every attachment does in production; a test runs without views only when that path is its subject.

Supervisor integration tests use a PTY and a scripted host to prove refusal, notice/retry, promotion, preflight, self-close, watchdog, stray reaping, and SIGTERM cleanup at the pane. The testkit stray hook is `RIMZ_TEST_SIDEBAR_SUPERVISOR_STRAY_PID_FILE`, fired after a successful attach; `RIMZ_TEST_SIDEBAR_PANE_PROBE_STRIKE_LOG` appends the watchdog's strike count on every change, so a test synchronizes on counted strikes rather than on time. `RIMZ_TEST_MACHINE_CONFIG_LOAD_LOG` names a testkit log that appends one `strict` or `lenient` line for each machine-config build from disk, including memo reloads but not memo hits or the sentry-only core read.

Render tests golden a full screen through the `assert_snapshot` helper in [`render/tests/`](./render/tests/mod.rs), which pins `insta` settings and scrubs live durations and ages before comparing — reach for it rather than calling `insta` directly, so a frame never fails on elapsed time. `insta` stops at the first failing frame in each test, so when a change is expected to move several frames, run the affected test once with `INSTA_FORCE_PASS=1 INSTA_UPDATE=new` so every moved frame writes a `.snap.new`, review each one, then `cargo insta accept`. The frames in [docs/interface/sidebar.md](../../../../docs/interface/sidebar.md) are drawn from these snapshots: a render change updates the `.snap` and that page together. Before a render change, run `rg -l '<glyph or text you change>' --glob '*.snap'` from `crates/rimz/` and name every frame it returns in the plan or hand-off, with the value each should show afterwards. The pattern names both glyph sets, since Nerd Font frames draw a different glyph for the same role (`'▤|󰿦'`, not `'▤'`). Width tiers are measured on `content_width` (pane width minus 2): a line reads `RowCtx::tier` and never recomputes `Tier::for_width` from the pane width, so every line in a frame degrades at the same column (L2 from 46 pane columns). A line that admits elements by width is tested at the exact width each element drops and at one column either side of it: a spread of sampled widths steps over the band where two admission rules disagree. Assert an admitted hyperlink through the block's own interaction regions, which is where the renderer decides the link's columns; the painted OSC 8 bytes are asserted at a realistic pane width, because `paint_hyperlinks` indexes the buffer by logical line and a wrapped line above the target offsets its rows at narrow ones. Reducer, selection, and ordering tests stay pure and in-module.

A render fixture that draws a parent's subagent or wait entries gives the parent a prompt: `CardStage::of` in [`render/sections/agent_card/template.rs`](./render/sections/agent_card/template.rs) draws an idle, never-prompted card with no session history or context as Fresh, and a Fresh card has no subagents line.

For a renderer change, follow the [sidebar live check](../../../../docs/contributing/sidebar-live-check.md) before hand-off to verify the frame and click routing in a disposable room.
