# Configuration

Local contract for `crates/rimz/src/config/`: machine settings, profile and team definitions, and `rimz config` editing. Extends [crates/rimz/AGENTS.md](../../AGENTS.md). The `//!` header of [`config.rs`](../config.rs) describes the config tiers and load modes.

- A new config key stored as a string that a user can type as a bare number (a byte size, a duration, a budget) joins the always-string list in `crates/rimz/src/config/edit.rs::parse_set_value` and gets its own branch in `validate_set_value`, pinned beside the `gc.tmp_floor_min` cases in `crates/rimz/src/config/edit/tests.rs`. Otherwise `rimz config set <key> 1024` stores a TOML integer that the key's loader refuses.
- A config command that accepts a table key where `rimz config set` takes only leaves (`rimz config unset`) applies every rule keyed on a leaf or an entry path to each such path under the table as well: a whole-entry table that `crates/rimz/src/config/edit.rs::is_whole_struct_table` names goes whole, and `remote_control.claude` and `remote_control.codex` reach the running machine. Each rule gets a test that names a parent key, since a test of the named key alone passes while the parent path skips the rule.
- A change to a file under `crates/rimz/src/config/templates/` runs `cargo xtask test 'config::template_tests'`: `template_defaults_deserialize_to_machine_defaults` uncomments the template's default lines and parses the result, so a rewrapped prose comment line whose text begins with `[` reads as a table header and fails with `unclosed table`, and only the full gate otherwise runs it.
