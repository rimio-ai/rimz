Launch a persistent agent: a peer in its own context and background tab that the user can watch and type into. It keeps its context, reports when its turn settles, and takes follow-ups until you stop it. Use it for work that wants its own worktree, a specialist profile's craft, or a mind that outlives one brief.

`profile` is the one the user named. Otherwise `rimz agents profiles` lists every launchable profile with its model and purpose: pick the one whose description matches, or a bare model for a seat with no craft. It names one seat; a team goes through `team`. `prompt` is the agent's first turn: the goal, the files, the constraints, and how done is judged, including whether it commits or opens a pull request. `description` labels it in 3 to 5 words.

A change to the repo takes `worktree`, a kebab-case name of at most two words. A new worktree branches from `agents.worktree.base` when set, else from the `HEAD` of your repository's main checkout, so what the agent must see has to be on that base; a `team.role` branches as its team does. A review, plan, or question runs in this checkout. `from_pr` (a number or URL) or `cwd` places it elsewhere; give at most one of the three. A closed worktree is refused unless `fresh` starts a new session there. `name` gives a distinct handle when the channel already holds this profile's; `agent` inherits another profile or provider kind below the launched profile when the user asks for one.

The answer is the id `agent:<handle>`, and `report` says how the result comes: an `AGENT_REPORT` message once none of your agents is mid-turn, or that none comes and `join` is the way to the answer. `tasks` lists it, `join` blocks on it, and `stop` closes its pane and keeps its session; `rimz agents show @<handle>` shows it and `rimz agents resume @<handle>` brings a closed one back. A follow-up is a message to `@<handle>`, or `@<handle>#<worktree>` in a worktree. Before a first launch, call `guide` with `rimz-agents/launching`.
