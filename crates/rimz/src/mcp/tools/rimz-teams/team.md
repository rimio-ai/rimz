Launch a team: several agents on one pipeline in their own worktree (or pull request worktree), which plan, build, and review a change and report back as one when the board reaches Done. Use it for a change a seat that did not write it should review before it lands, a behavior-preserving cleanup pass, or a test-suite cut. Whatever the team must see has to be on its base branch before launch.

When `report` says a `TEAM_REPORT` comes, a report lands each time the board reaches Done; otherwise `join` is the way to the answer. A run usually takes hours, so end your turn after launching. Send follow-ups to `@<role>#<worktree>`, targeting the leader unless you mean one seat. Before a first launch, call `guide` with `rimz-teams/launching`.
