# Integration suite

Local contract for `crates/rimz/tests/integration/` — the crate's single integration-test binary. Extends [crates/rimz/AGENTS.md](../../AGENTS.md). Test tiers and runner rules live in [rust-conventions.md](../../../../docs/contributing/rust-conventions.md#tests).

## Harness

- One binary: every suite is a module of [`main.rs`](./main.rs), and [`common/`](./common/mod.rs) is declared once — no per-file harness duplication. Shared remote-connect PTY and terminal-query behavior lives in `common::ssh_trace`.
- Pick the tier by what the test drives: `common::Env` runs the `rimz` binary out of process with HOME, XDG, `TMUX_TMPDIR`, and `ZELLIJ_CONFIG_DIR` scoped to tempdirs; `common::Harness` opens a real in-process `rimz::Store` for direct API tests; `common::payloads` holds the golden agent hook payloads and `common::shim` the environment probes and fake executables, both shared across tiers.
- Every `Env` and `ZellijNamespace` arms an independent stdin-keepalive reaper before spawning children. The fixture HOME/runtime values are the process-ownership marker: on orderly drop or abrupt owner death the reaper stops both private mux endpoints, terminates every marker-carrying descendant, and removes the roots. A command that calls `env_clear()` must re-pin `HOME` or `XDG_RUNTIME_DIR` before it can become long-lived.
- Real tempdir, real store files — no in-memory stubs.
- A signal- or tick-fired task with only `--check` runs in a detached `rimz loop run` child that opens the root's room before the check unless a sidebar heartbeat under 5 s old exists ([external-fire behaviour](../../../../docs/internals/harness/loops.md#the-external-tick)). Signal tests seed the heartbeat just before firing; tick-fired tests cannot, because the same heartbeat makes `rimz loop tick` skip the root, so they wait out the room birth.
- A shell runs a trap only after its foreground command returns, so a signal that lands before that command is running as a program the signal kills is held behind it. A check script that must react to a signal backgrounds its long wait before publishing readiness, blocks in the `wait` builtin, and stops the background child in its trap (a background command ignores SIGINT). A test of delivery to a process group keeps that trap in a member other than the group leader, since the leader is the PID a single-process signal would also reach.
- To emulate signal delivery outside the suite, start the subject from a non-shell launcher in its own session (Python `subprocess.Popen(..., start_new_session=True)`). A shell that backgrounds it with `&` starts it with SIGINT ignored, and every result reads as a lost signal.
- `common::Env::rimz_at` defaults stdin to null so directly spawned commands cannot inherit buffered input from a test-running shell loop. Tests that exercise stdin set it explicitly afterwards; PTY commands keep their terminal input.
- `RIMZ_BIN` redirects every detached `rimz` helper spawn; point it at a missing path to exercise a spawn failure, which unit tests cannot reach, or at an executable that exits at once (`/bin/true`) to exercise a helper that spawns but never serves.
- A row created by `rimz agents exec` keeps its card only while its runtime owner lives; to produce or enforce on it, spawn the exec with a long-lived provider shim.
- A hook that ends, interrupts, or compacts a turn spawns a detached `message deliver` for the agent's queued head, with the hook's own environment. The test cannot await that child, so queue a message the test sweeps after such a hook, or give the hook the pane fixture and the `zellij-trace` shim.
- Every builder that runs `rimz` or creates a mux server scrubs the ambient session env at construction (`common::ScrubSessionEnvExt` — the `RIMZ_*` identity pin, the `ZELLIJ*`/`TMUX*` detection vars, and systemd's `INVOCATION_ID`, which would otherwise route loop ticks through `systemd-run --user` at a fixture runtime dir with no bus, and the provider home and config keys such as `CODEX_HOME` and `CLAUDE_CONFIG_DIR`, which adapters resolve ahead of the fixture `HOME` and which an agent on a named account passes to every child), so a suite run from inside a live RimZ room behaves like a clean shell; a test that needs one of these sets it explicitly afterwards.
- Every real `rimz` child pins `RIMZ_HOME` through `Env::rimz`/`rimz_at`/`pin_pty_command`, an explicit command environment, a shell or argv prefix, or inheritance from a Zellij server started through `ZellijNamespace`/`ZellijBackend::with_runtime_dir`. A tmux pane running `rimz` must re-pin the fixture home, by its command or the session environment. `cargo_bin` returns an executable path, not a spawn; follow that path to the command or server that supplies its environment.
- To prove a run leaves provider accounts alone, run the whole gate, lib unit tests included, with `CODEX_HOME`/`CLAUDE_CONFIG_DIR` pointed at sentinel copies and logging `claude`/`codex` shims first on `PATH` (each appends `$NEXTEST_TEST_NAME $*` to a log and exits 1); compare the sentinel tree and checksums before and after, and read the log for tests that start a real CLI. Checking only the sentinels, or only this binary, finds one leak per round.
- Stress a load-only flake in the binary itself, not through nextest: build once with `cargo xtask test --name <module>::<test>`, then loop the freshest `target/debug/deps/integration-<hash>` executable as `<bin> --exact <module>::<test> --test-threads=1` a few hundred times with output redirected to a file, while `nproc` busy loops (`sh -c 'while :; do :; done' &`) hold every CPU. Run the loop with `RUST_BACKTRACE=1`: a helper's panic line names the helper, and only the backtrace names the call in the test. Record each hog's `$!` and stop them with `kill` on those PIDs (in zsh collect them in an array, `hogs+=($!)` then `kill $hogs`, since a space-joined scalar does not word-split); a `pkill -f` pattern also matches the command line of the shell running it and kills that shell. Read the 1-minute load average before each batch and record it beside the count; a batch that another worktree's stress run overlapped is not a baseline. Count non-zero exits before and after the fix; a race that shows 1–3 in 400 loaded runs is typically 0 unloaded. A fix is shown only by a batch large enough to have caught the rate you saw: when the last residual was 1 in N, run at least 4N loaded runs on the final tree, in two batches, before calling it 0. A race against a spawned child's startup can stay at 0 in the serial loop, because a warm binary starts fast; run the loop's copies in parallel instead (`seq 400 | xargs -P $(( $(nproc) * 2 ))`, CPU hogs still on) to reproduce the full suite's contention.
- A flake on a file's `(mtime, len)` identity, such as a stat-keyed parse cache serving the prior parse after a same-length republish, runs the other way: load spreads the writes across mtime ticks and hides it. Loop it unloaded a few thousand times instead.
- **Invariant.** In-process workspace identity resolves through `common::Env::resolve_workspace`, under the same home as the fixture's child; an explicit root override uses `WorkspaceResolver::resolve_under` with the fixture's home. The invariant gate rejects ambient-home resolver entries and state or runtime path constructors under the test tree. Id-only constructors have one allowance: fixture binaries, which inherit their caller's pinned home. Explicit paths use `StatePaths::for_project_root_under` with the fixture's home, and runtime paths come from `RuntimePaths::for_state_under` over those state paths, as `common::Env::runtime_paths` does.
- `Env::new` creates no state root, so an id with no state is the fixture's default. Before making an id-only command refuse an unknown id, search this suite for tests that run it on a fresh `Env`; `gc::sidebar_snapshot_does_not_create_an_abandoned_state_scaffold` pins that read-only commands tolerate an absent workspace.
- A flake that shows only in some full-suite runs may depend on the runner's own state rather than on load. When the error names a derived identifier (a session or directory name), rerun the stress loop with `RIMZ_HOME` pointing at a directory pre-filled with non-owned `ws/collide-<hex4>` directories covering all 65,536 four-hex prefixes, using a slug different from the fixture's: an unrecorded directory with the fixture's own slug is adopted, not a collision. Id-only lookups adopt only a recorded directory, so the unrecorded collision fill cannot absorb them. Any new entry under the fill after a run marks a runner-home write; inspect both machine-wide additions and children of the collision directories with `find "$F" -mindepth 1 -not -path "$F/ws/collide-*" -not -path "$F/ws"; find "$F/ws" -mindepth 2`, where `F` is the fill root used as `RIMZ_HOME`.
- Find where a slow command idles before reading code: run the freshest `target/debug/deps/integration-<hash>` under `strace -f -tt -e trace=execve -o <file> <bin> --exact <module>::<test> --test-threads=1`, keep the `execve` and `exited with` lines, and read the gaps between them; a gap that matches a production constant (a 25ms poll for 1.5s or 3s) is a designed wait the fixture never satisfies, not load. Add `openat` to the trace set and keep its `ENOENT` lines to see what the idle process polls for. Satisfy it the way the real writer would rather than raising a timeout: seed the sidebar heartbeat a live room carries, or bind the child pane the way its hook does (`common::room` holds both, for Zellij and tmux). Under strace, stop the traced child by its own PID (`pgrep -P <strace pid>`), not strace's: killing strace leaves the child running, and `wait` never returns. A one-shot `sidebar snapshot`/`frame` walks provider transcripts only when no live sidebar serves spending for the same `RIMZ_HOME` (any room on the machine counts) and no current-version `provider-spending.json` exists. It is slow only when `cache/providers/spending.json` is cold. `Env` isolates `HOME` and hides that cost, so reproduce with a scratch `RIMZ_HOME` and the real `HOME` before assuming a designed poll. A dead room needs its `workspace.json` for `--no-produce` to take the consumer read.
- Rank tests by time before tracing: `cargo xtask test` prints only the summary, so run `cargo nextest run -p rimz --test integration --status-level pass -E '<filter>' > /tmp/<file>.log 2>&1`, then sort its `PASS [ Ns ]` and `LEAK [ Ns ]` lines (nextest marks a passing test that leaves a child holding its stdio as `LEAK`, most of this suite) with `grep -E '(PASS|LEAK) \[' <log> | sort -t'[' -k2 -rn`. For a serial shell loop, time with zsh `$EPOCHREALTIME` after `zmodload zsh/datetime` (unloaded, it expands empty and every duration reads zero), not `bc`, which the dev hosts lack.

## Placement

- Subdirectory matches tier: `store/` durability and CAS, `backend/` live-mux parity plus the real-browser web suite (`backend/web/`: real ttyd + headless Chromium, self-skipping without them), `examples/` the RimZ-authored in-process scripts running under their real interpreter (the Pi extension, the OpenCode plugin), `journey/` rendered user flows, `performance/` bounded resource use. A new suite lands where its tier says, not beside a similar-looking file.
- Host dependencies self-skip: a test that needs `zellij`, `tmux`, or `node` probes for the capability and skips when absent — a local run needs no installed mux, and the OpenCode suite additionally skips a `node` that cannot strip TypeScript syntax. Every self-skip goes through `common::skip` with a reason naming the missing capability, not the test (`tmux not on PATH`, `common::AF_UNIX_SANDBOXED`); the shared probes (`skip_if_sandboxed`, `require_tmux!`, `require_zellij!`, `require_web_stack!`, `common::git::git_missing`, the journey's `rimz_bin`) already call it. It prints the reason and records the skip, and `cargo xtask test` and `gate` list the self-skipped tests by reason after nextest's result, since nextest counts them as passed. GitHub CI runs every tier with `cargo xtask test --deny-skips`, which fails the run on any recorded skip reason that starts with no entry of `.config/allowed-test-skips.txt`, so there a missing `tmux` or `zellij` is a failure and the image must carry both: a new skip reason either gets its capability installed in `ci/Dockerfile` or an allow-list entry saying why CI cannot provide it.
- External seams are faked with the [`tests/fixtures/`](../fixtures/) shims (`zellij-trace`, `git-trace`, `ssh-trace`, `codex-appserver-stub`); mux-driving tests route `rimz` invocations at an isolated tmux server env and a private Zellij runtime so a developer's live sessions stay untouched.
- The journey's hook-firing stub agent fires no lifecycle hook for pasted text, so a message it receives stays `Sent`, never `Delivered`. To prove receipt, fire the receiving turn with `env.run_installed_hook_in_pane` (`UserPromptSubmit` carrying the rendered message text, then `Stop`). Split panes shrink the target pane, so capture with scrollback when asserting on text that may have scrolled.
- Time is deterministic: fixed-epoch fixtures, boundary-exact.
