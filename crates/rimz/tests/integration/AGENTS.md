# Integration suite

Local contract for `crates/rimz/tests/integration/`, the crate's single integration-test binary. Extends [crates/rimz/AGENTS.md](../../AGENTS.md). Test tiers and runner rules live in [rust-conventions.md](../../../../docs/contributing/rust-conventions.md#tests).

## Harness

- Every suite is a module of [`main.rs`](./main.rs), and [`common/`](./common/mod.rs) is declared once: shared harness code goes there, never into a second copy in a suite file.
- Pick the fixture by what the test drives: `common::Env` runs the `rimz` binary out of process under tempdir homes, `common::Harness` opens a real in-process `rimz::Store` for direct API tests, and `common::payloads` (golden agent hook payloads) and `common::shim` (environment probes and fake executables) serve both.
- **Invariant.** In-process workspace identity resolves through `common::Env::resolve_workspace`, under the same home as the fixture's child; an explicit root override uses `WorkspaceResolver::resolve_under` with the fixture's home. The invariant gate rejects ambient-home resolver entries and state or runtime path constructors under the test tree. Id-only constructors have one allowance: fixture binaries, which inherit their caller's pinned home. Explicit paths use `StatePaths::for_project_root_under` with the fixture's home, and runtime paths come from `RuntimePaths::for_state_under` over those state paths, as `common::Env::runtime_paths` does. A test reads the diagnostics log through `rimz::diag::DiagSink::under(state.root, state.workspace_id, ..).log_path()` on the fixture's `StatePaths`, since the gate rejects the log's file name under the test tree.
- Every real `rimz` child pins `RIMZ_HOME` through `Env::rimz`/`rimz_at`/`pin_pty_command`, an explicit command environment, a shell or argv prefix, or inheritance from a Zellij server started through `ZellijNamespace`/`ZellijBackend::with_runtime_dir`. A tmux pane running `rimz` must re-pin the fixture home, by its command or the session environment. `cargo_bin` returns an executable path, not a spawn; follow that path to the command or server that supplies its environment.
- Every builder that runs `rimz` or creates a mux server scrubs the ambient session environment and pins the fixture defaults (`common::ScrubSessionEnvExt`), so a variable a test needs is set on its command after the builder, never on the test process. A session born in the test process builds no command and is not scrubbed. [What the scrub removes and sets](../../../../docs/contributing/integration-tests.md#the-session-env-scrub).
- A command that calls `env_clear()` re-pins `HOME` or `XDG_RUNTIME_DIR` before it can become long-lived: the fixture reaper finds a test's descendants by those values.
- Any test that launches a provider through `rimz agents`, `rimz agents -p`, or `rimz subagents`, a resume included, sets `SHELL` to `common::write_fake_login_shell`; a real `/bin/sh` login shell reads the host profile, which on the CI image resets `PATH` and hides a fake provider. A launch a hook wakes (a workflow attempt after a lifecycle edge, a loop task fired by a lifecycle signal) runs under the `SHELL` its `hooks feed` command carried, so put the fake login shell on that feed too.
- Every command in a test that detects a provider (`trust grant --agents <provider>`, a launch, `--version` probes) gets the fake provider's directory on `PATH`, as `run.rs` does for its grant. A developer host with the real CLI installed hides the miss, and CI's image has none.
- A test that needs a host capability (`zellij`, `tmux`, `node`, a browser) probes for it and self-skips through `common::skip`, with a reason naming the missing capability, not the test; the shared probes (`skip_if_sandboxed`, `require_tmux!`, `require_zellij!`, `require_web_stack!`, `common::git::git_missing`, the journey's `rimz_bin`) already call it. CI fails a run on any skip reason that starts with no entry of `.config/allowed-test-skips.txt`, so a new reason gets its capability installed in `ci/Dockerfile` or an allow-list entry saying why CI cannot provide it. A test that needs real bubblewrap gates on `rimz::sandbox::preflight(Isolation::Scoped)` and skips with `bubblewrap unusable: {err}`, an allow-listed prefix: the GitHub job container denies the namespace, so such a test proves its property only on a local non-root run.
- External seams are faked with the [`tests/fixtures/`](../fixtures/) shims (`zellij-trace`, `git-trace`, `ssh-trace`, `codex-appserver-stub`), and mux-driving tests run against an isolated tmux server and a private Zellij runtime. No in-process `MuxBackend` fake exists: a failing multiplexer call is a fake executable.
- Time is deterministic: fixed-epoch fixtures, boundary-exact.
- An assertion on an event count prints the events on failure: a CI failure that names no writer cannot be traced afterwards.
- A test of a refusal or error message asserts the full reason text after the fixed prefix, plus the absence of any wrong-cause wording a shared error type could supply; a substring match passes a message that names the wrong cause.
- A negative substring assertion over command output uses a fixture name no output word can contain (`skip-bare`, not `one`).
- A change to `Env::rimz_at` (behind `Env::rimz`), `Env::pin_pty_command`, or a shared live fixture helper also runs `cargo xtask test -P journey` and `cargo xtask test -P live`: both builders make the `rimz` children of the `journey::` and `backend::` tiers, which `gate` does not run.

## Placement

- A new suite lands where its tier says, not beside a similar-looking file: `store/` durability and CAS, `backend/` live-mux parity and the real-browser web suite (`backend/web/`), `examples/` the RimZ-authored in-process scripts under their real interpreter (the Pi extension, the OpenCode plugin), `journey/` rendered user flows, `performance/` bounded resource use.

## Before a test

Before writing or debugging one of these, read the section of [integration-tests.md](../../../../docs/contributing/integration-tests.md) named beside it. Each holds fixture and stand-in behaviour the code does not show, and a test written without it passes for the wrong reason or flakes under load.

- A fixture struct taken apart, a port handed to a child, a child's stdin, the reaper's marker read straight after `spawn`, an id-only command on a fresh `Env`, files ordered by mtime, the browser suite, or an `examples/` fake host: [Fixtures and their processes](../../../../docs/contributing/integration-tests.md#fixtures-and-their-processes).
- A variable the scrub removes or sets, a new reader of host state, or proof that a run leaves provider accounts alone: [The session-env scrub](../../../../docs/contributing/integration-tests.md#the-session-env-scrub).
- A wait or deadline, a PTY or pipe read, a negative assertion on a client's stream, a kill after a readiness poll, an assertion added to an existing test, or a fix to one test race: [Waits and reads](../../../../docs/contributing/integration-tests.md#waits-and-reads).
- A launched provider or its stand-in, a rival agent in a lane, the wrapper pane's root process, or a pane closed in a managed worktree: [Launches and provider stand-ins](../../../../docs/contributing/integration-tests.md#launches-and-provider-stand-ins).
- A hook feed, a queued message's delivery, a send's compaction line, or a hook drainer's election or idle exit: [Hooks and message delivery](../../../../docs/contributing/integration-tests.md#hooks-and-message-delivery).
- A stop that must report stopped: [Stops](../../../../docs/contributing/integration-tests.md#stops).
- A loop task's fire, tick, or signal, or a `loop show`, `loop list`, or `loop logs` read: [Loop tests](../../../../docs/contributing/integration-tests.md#loop-tests).
- `zellij-trace` or another fake multiplexer, a sidebar heartbeat, a `ZellijNamespace` server, or a supervised attach: [Multiplexer doubles and heartbeats](../../../../docs/contributing/integration-tests.md#multiplexer-doubles-and-heartbeats).
- A signal sent to a shell script, or a SIGSTOPped process tree: [Signals and stopped processes](../../../../docs/contributing/integration-tests.md#signals-and-stopped-processes).
- A second build, `RIMZ_BIN`, or a wrapper around `rimz`: [Builds and wrapped binaries](../../../../docs/contributing/integration-tests.md#builds-and-wrapped-binaries).
- A `RIMZ_TEST_*` duration override: [Duration overrides](../../../../docs/contributing/integration-tests.md#duration-overrides).
- A `backend::` or `journey::` test, or a shared live fixture helper: [Live backend and journey tests](../../../../docs/contributing/integration-tests.md#live-backend-and-journey-tests).
- A `cargo xtask stress` batch the user allowed: [Stress batches](../../../../docs/contributing/integration-tests.md#stress-batches).
- A race to prove, or a hold or probe to place in its window: [Forcing a race](../../../../docs/contributing/integration-tests.md#forcing-a-race).
- A CI-only failure or a nextest `FLAKY` result: [Reading CI evidence](../../../../docs/contributing/integration-tests.md#reading-ci-evidence).
- A slow or idle command, or a rebirth that resumed no agent: [Tracing a slow or idle command](../../../../docs/contributing/integration-tests.md#tracing-a-slow-or-idle-command).
