# Integration suite

Local contract for `crates/rimz/tests/integration/` — the crate's single integration-test binary. Extends [crates/rimz/AGENTS.md](../../AGENTS.md). Test tiers and runner rules live in [rust-conventions.md](../../../../docs/contributing/rust-conventions.md#tests).

## Harness

- One binary: every suite is a module of [`main.rs`](./main.rs), and [`common/`](./common/mod.rs) is declared once — no per-file harness duplication. Shared remote-connect PTY and terminal-query behavior lives in `common::ssh_trace`.
- Pick the tier by what the test drives: `common::Env` runs the `rimz` binary out of process with HOME, XDG, `TMUX_TMPDIR`, and `ZELLIJ_CONFIG_DIR` scoped to tempdirs; `common::Harness` opens a real in-process `rimz::Store` for direct API tests; `common::payloads` holds the golden agent hook payloads and `common::shim` the environment probes and fake executables, both shared across tiers.
- Every `Env` and `ZellijNamespace` arms an independent stdin-keepalive reaper before spawning children. The fixture HOME/runtime values are the process-ownership marker: on orderly drop or abrupt owner death the reaper stops both private mux endpoints, terminates every marker-carrying descendant, and removes the roots, except an `Env` dropped while panicking with `RIMZ_TEST_KEEP_FAILED` on, whose reaped roots are kept (see the stress bullet). A child is identifiable only once its exec has published that environment in `/proc/<pid>/environ`, which can trail `spawn` under load, so a test that depends on the marker straight after `spawn` waits for it. A command that calls `env_clear()` must re-pin `HOME` or `XDG_RUNTIME_DIR` before it can become long-lived.
- Real tempdir, real store files — no in-memory stubs.
- A signal- or tick-fired task with only `--check` runs in a detached `rimz loop run` child that opens the root's room before the check unless a sidebar heartbeat under 5 s old exists ([external-fire behaviour](../../../../docs/internals/harness/loops.md#the-external-tick)). Signal tests seed one with `common::room::seed_sidebar_heartbeat`, which dates it ahead so it stays live for the whole test; tick-fired tests cannot, because the same heartbeat makes `rimz loop tick` skip the root, so they wait out the room birth.
- A shell runs a trap only after its foreground command returns, so a signal that lands before that command is running as a program the signal kills is held behind it. A check script that must react to a signal backgrounds its long wait before publishing readiness, blocks in the `wait` builtin, and stops the background child in its trap (a background command ignores SIGINT). A test of delivery to a process group keeps that trap in a member other than the group leader, since the leader is the PID a single-process signal would also reach.
- To emulate signal delivery outside the suite, start the subject from a non-shell launcher in its own session (Python `subprocess.Popen(..., start_new_session=True)`). A shell that backgrounds it with `&` starts it with SIGINT ignored, and every result reads as a lost signal.
- `common::Env::rimz_at` defaults stdin to null so directly spawned commands cannot inherit buffered input from a test-running shell loop. Tests that exercise stdin set it explicitly afterwards; PTY commands keep their terminal input.
- `RIMZ_BIN` redirects every detached `rimz` helper spawn; point it at a missing path to exercise a spawn failure, which unit tests cannot reach, or at an executable that exits at once (`/bin/true`) to exercise a helper that spawns but never serves.
- A row created by `rimz agents exec` keeps its card only while its runtime owner lives; to produce or enforce on it, spawn the exec with a long-lived provider shim.
- A hook that ends, interrupts, or compacts a turn spawns a detached `message deliver` for the agent's queued head, with the hook's own environment. The test cannot await that child, so queue a message the test sweeps after such a hook, or give the hook the pane fixture and the `zellij-trace` shim.
- Every builder that runs `rimz` or creates a mux server scrubs the ambient session env at construction (`common::ScrubSessionEnvExt` — the `RIMZ_*` identity pin, the `ZELLIJ*`/`TMUX*` detection vars, and systemd's `INVOCATION_ID`, which would otherwise route loop ticks through `systemd-run --user` at a fixture runtime dir with no bus, and the provider home and config keys such as `CODEX_HOME` and `CLAUDE_CONFIG_DIR`, which adapters resolve ahead of the fixture `HOME` and which an agent on a named account passes to every child), so a suite run from inside a live RimZ room behaves like a clean shell; a test that needs one of these sets it explicitly afterwards. The same scrub sets `RIMZ_CODEX_BIN` to a path that does not exist, so every fixture room reads codex as not installed, as CI does: no broker pane, and no host `codex app-server` or `codex login status`. A fake `codex` on `PATH` stands in for the agent a test launches, never for those; a test about the app-server, the broker, or the login probe sets `RIMZ_CODEX_BIN` to `codex_appserver_stub()` or its own fake on the command that births the room. A session born in the test process (`open_sidebar` with `sidebar_opts` or a `SidebarPaneOptions` literal) builds no command, so the scrub never reaches it: its mux server and panes inherit the test process's environment, where `cargo xtask test` exports the same missing-path default to every nextest run. Under a bare `cargo nextest run` those in-process births are not covered and can start the host `codex`. Other host provider CLIs remain reachable on a fixture's PATH, so a test counting PATH-level forks holds the accounts cache fresh, as the `Fixture` in `performance/sidebar_diff_stats.rs` does.
- Every real `rimz` child pins `RIMZ_HOME` through `Env::rimz`/`rimz_at`/`pin_pty_command`, an explicit command environment, a shell or argv prefix, or inheritance from a Zellij server started through `ZellijNamespace`/`ZellijBackend::with_runtime_dir`. A tmux pane running `rimz` must re-pin the fixture home, by its command or the session environment. `cargo_bin` returns an executable path, not a spawn; follow that path to the command or server that supplies its environment.
- To prove a run leaves provider accounts alone, run the whole gate, lib unit tests included, with `CODEX_HOME`/`CLAUDE_CONFIG_DIR` pointed at sentinel copies and logging `claude`/`codex` shims first on `PATH` (each appends `$NEXTEST_TEST_NAME $*` to a log and exits 1); compare the sentinel tree and checksums before and after, and read the log for tests that start a real CLI. Checking only the sentinels, or only this binary, finds one leak per round.
- Stress a load-only flake with `cargo xtask stress <module>::<test>`, not through nextest, whose retries and group caps hide the rate you are measuring. The command builds and locates the test's binary, runs 400 copies of it two per CPU in the test sandbox while one busy process per CPU holds the host, and prints the 1-minute load average before and after the batch beside `failed: K/N`; each failing copy's output, run with a backtrace so a helper's panic names the call in the test, stays under `--out` with `summary.txt`. Give each batch its own `--out`: the command refuses a directory that already holds kept copies. A batch the xtask budget stops still writes `summary.txt`, counting only the copies that completed; widen the budget with `RIMZ_XTASK_TIMEOUT` for a long batch. Record the load beside the count; a batch that another worktree's stress run overlapped is not a baseline. Before a loaded batch, stress a matched pre-existing test with the same flags first: when that control itself fails most copies (one run saw about 90% at load 160 to 675 on 30 cores), the batch measures the host, so lower `--jobs` until the control passes before reading anything into the new test. Count failures before and after the fix; a race that shows 1–3 in 400 loaded copies is typically 0 unloaded. Classify each failing copy by its panic before counting. A fix is shown by the bug's own signature going to zero across the after-batches; copies that fail in fixture setup (room birth, launch timeouts) are listed separately and do not count against the fix. That zero takes two batches on the final tree at the failing baseline's own flags, each with at least the baseline's copies, before calling it 0; when the last residual was rarer than one per baseline batch (1 in N), size both batches with `--copies` to hold at least 4N between them as well. Judge an after-batch by matching the baseline's shape (copies, `--jobs`, `--hogs`), not by the load it ends at: a fixed test finishes sooner and ends lower (one run's fixed batches ended at 69 to 98 against 128 for their baseline). 4N alone can come out too small to hold the jobs busy (16 to 206 copies against 60 jobs in one run). Copies run in parallel by default because a race against a spawned child's startup can stay at 0 in a serial loop, where a warm binary starts fast; `--jobs 1` is that serial loop, for a test whose copies would contend with each other rather than with the suite. To read a failing copy's store, event log, and diagnostics, add `--env RIMZ_TEST_KEEP_FAILED=1`: an `Env` dropped while panicking moves its home and runtime roots to `/tmp/rimz-test-kept-*/` and prints a `rimz-test-kept-roots:` line naming them into that copy's `run-N.out`. The copy's event log is `rimz-home/ws/<workspace>/log/events.log.jsonl` under the kept home root; each line carries a length and a CRC before the JSON, so read it with `cut -d' ' -f3- | jq`. Paths recorded inside the kept state still name the original roots, and the kept directories are yours to delete. `cargo xtask test` strips the variable; a bare `cargo nextest run` carries it. To prove a run keeps or moves an artifact, assert on the contents at the destination and make the probe test fail with an uncaught panic: a missing original path holds after removal and after a move alike, and stress keeps output only for failing copies.
- A probe that wraps `rimz` does nothing before the command under suspicion: capture state after that command returns or alongside it, since a few tens of milliseconds of probe work can close the race being hunted (about 380 wrapped runs of one rebirth flake showed no failure for this reason). Show the probe reproducing the failure before using it to refute a cause, and count a known-positive baseline of an event before reporting it absent.
- To wrap `rimz` without a source edit, use the path `common::shim::cargo_bin` checks first: a `rimz` in the grandparent directory of the running test executable. A directory holding a wrapper `rimz` and a copy of the binary at `deps/integration-<hash>` intercepts the test's own calls (`Env::rimz_bin`) and the hook feeds of `common::shim::write_hook_firing_agent`; room panes run the staged build the room records at birth (`RoomContext::claim_owner`) and bypass it.
- An assertion on an event count prints the events on failure: a CI failure that names no writer cannot be traced afterwards.
- A test that kills a pane or process after polling for a readiness event checks that the event is written after the killed process installed the handlers whose behaviour the test asserts. A supervising `rimz agents exec` wrapper installs its SIGHUP/SIGTERM handlers before its first pane binding, so its own first `agent.attached` (runtime owner is the wrapper) is a valid readiness point for its hangup behaviour. Prove a new such test through the stress loop above, not one nextest run.
- A flake on a file's `(mtime, len)` identity, such as a stat-keyed parse cache serving the prior parse after a same-length republish, runs the other way: load spreads the writes across mtime ticks and hides it. Loop it unloaded a few thousand times instead. `--hogs 0 --jobs 1 --copies 4000` is that loop.
- A failure that is fast in CI needs fast local runs: compare the failing CI attempt's duration with one unloaded local run and read `uptime` first. If the local run takes several times the CI duration, or the load average is far above `nproc` before you start, the loop measures the host, so instrument the test and reproduce in CI instead.
- `gh run download <run> -n nextest-junit` returns only the latest attempt, which is usually the passing one. List a run's attempts with `gh api repos/<owner>/<repo>/actions/runs/<run>/attempts/<n>` and fetch the failed attempt's report by artifact id.
- A rebirth that plans no resume for an agent prints nothing at the default log level: a skipped candidate gets a `not resumed:` line, an agent that never became a candidate gets none. Run that `rimz start` with `RUST_LOG=warn,rimz::harness::rebirth=debug,rimz::cli::room=debug` (`journey::deep`'s `REBIRTH_TRACE`) and read its stderr: it names the birth path (session already live, or inspected with the candidate count), the roster read (absent or unreadable, or its entry count and how many have an audit row), and, per agent, why it is not a candidate (`ended`, `owner live` with the pid, `no audit row`) or why a candidate got no tab. Read room state only after that start, never between a teardown and it: a probe there delays the rebirth by 20 to 150 ms, enough to hide a race a fast run loses. `records/last-death.json` lists an agent whenever the roster named it, whatever the later gates decided.
- **Invariant.** In-process workspace identity resolves through `common::Env::resolve_workspace`, under the same home as the fixture's child; an explicit root override uses `WorkspaceResolver::resolve_under` with the fixture's home. The invariant gate rejects ambient-home resolver entries and state or runtime path constructors under the test tree. Id-only constructors have one allowance: fixture binaries, which inherit their caller's pinned home. Explicit paths use `StatePaths::for_project_root_under` with the fixture's home, and runtime paths come from `RuntimePaths::for_state_under` over those state paths, as `common::Env::runtime_paths` does.
- `Env::new` creates no state root, so an id with no state is the fixture's default. Before making an id-only command refuse an unknown id, search this suite for tests that run it on a fresh `Env`; `gc::sidebar_snapshot_does_not_create_an_abandoned_state_scaffold` pins that read-only commands tolerate an absent workspace.
- A flake that shows only in some full-suite runs may depend on the runner's own state rather than on load. When the error names a derived identifier (a session or directory name), rerun `cargo xtask stress` with `--env RIMZ_HOME=<fill>`, a directory pre-filled with non-owned `ws/collide-<hex4>` directories covering all 65,536 four-hex prefixes, using a slug different from the fixture's: an unrecorded directory with the fixture's own slug is adopted, not a collision. Id-only lookups adopt only a recorded directory, so the unrecorded collision fill cannot absorb them. Any new entry under the fill after a run marks a runner-home write; inspect both machine-wide additions and children of the collision directories with `find "$F" -mindepth 1 -not -path "$F/ws/collide-*" -not -path "$F/ws"; find "$F/ws" -mindepth 2`, where `F` is the fill root used as `RIMZ_HOME`.
- Find where a slow command idles before reading code: run the test binary (the `binary:` line `cargo xtask stress` prints) under `strace -f -tt -e trace=execve -o <file> <bin> --exact <module>::<test> --test-threads=1`, keep the `execve` and `exited with` lines, and read the gaps between them; a gap that matches a production constant (a 25ms poll for 1.5s or 3s) is a designed wait the fixture never satisfies, not load. Add `openat` to the trace set and keep its `ENOENT` lines to see what the idle process polls for. Satisfy it the way the real writer would rather than raising a timeout: seed the sidebar heartbeat a live room carries, or bind the child pane the way its hook does (`common::room` holds both, for Zellij and tmux). Under strace, stop the traced child by its own PID (`pgrep -P <strace pid>`), not strace's: killing strace leaves the child running, and `wait` never returns. A one-shot `sidebar snapshot`/`frame` walks provider transcripts only when no live sidebar serves spending for the same `RIMZ_HOME` (any room on the machine counts) and no current-version `provider-spending.json` exists. It is slow only when `cache/providers/spending.json` is cold. `Env` isolates `HOME` and hides that cost, so reproduce with a scratch `RIMZ_HOME` and the real `HOME` before assuming a designed poll. A dead room needs its `workspace.json` for `--no-produce` to take the consumer read.
- Rank tests by time before tracing: `cargo xtask test` prints only the summary, so run `cargo nextest run -p rimz --test integration --status-level pass -E '<filter>' > /tmp/<file>.log 2>&1`, then sort its `PASS [ Ns ]` and `LEAK [ Ns ]` lines (nextest marks a passing test that leaves a child holding its stdio as `LEAK`, most of this suite) with `grep -E '(PASS|LEAK) \[' <log> | sort -t'[' -k2 -rn`. For a serial shell loop, time with zsh `$EPOCHREALTIME` after `zmodload zsh/datetime` (unloaded, it expands empty and every duration reads zero), not `bc`, which the dev hosts lack.
- A Zellij focus probe sets up the client before it measures. A client that has sent no input since attaching is not moved by `action focus-pane-id` and is not the client a focus-taking `new-pane` follows, so type into it first. An empty `ZELLIJ_CONFIG_DIR` opens a floating first-run wizard that takes focus, so a hand-built probe writes a `config.kdl` with `show_startup_tips false` before attaching. A focus proof for a user-run command issues the action from inside the client's pane, inheriting `ZELLIJ` and `ZELLIJ_PANE_ID`: an action from outside any pane is a different condition.
- Exact geometry assertions over repeated Zellij splits size the anchor's extent to a multiple of the resulting parts. Halving an odd extent takes a cell from a neighbour (a 39-row anchor became 20+20 while its neighbour went from 39 to 38), which reads as a placement fault.

## Placement

- Subdirectory matches tier: `store/` durability and CAS, `backend/` live-mux parity plus the real-browser web suite (`backend/web/`: real ttyd + headless Chromium, self-skipping without them), `examples/` the RimZ-authored in-process scripts running under their real interpreter (the Pi extension, the OpenCode plugin), `journey/` rendered user flows, `performance/` bounded resource use. A new suite lands where its tier says, not beside a similar-looking file.
- Host dependencies self-skip: a test that needs `zellij`, `tmux`, or `node` probes for the capability and skips when absent — a local run needs no installed mux, and the OpenCode suite additionally skips a `node` that cannot strip TypeScript syntax. Every self-skip goes through `common::skip` with a reason naming the missing capability, not the test (`tmux not on PATH`, `common::AF_UNIX_SANDBOXED`); the shared probes (`skip_if_sandboxed`, `require_tmux!`, `require_zellij!`, `require_web_stack!`, `common::git::git_missing`, the journey's `rimz_bin`) already call it. It prints the reason and records the skip, and `cargo xtask test` and `gate` list the self-skipped tests by reason after nextest's result, since nextest counts them as passed. GitHub CI runs every tier with `cargo xtask test --deny-skips`, which fails the run on any recorded skip reason that starts with no entry of `.config/allowed-test-skips.txt`, so there a missing `tmux` or `zellij` is a failure and the image must carry both: a new skip reason either gets its capability installed in `ci/Dockerfile` or an allow-list entry saying why CI cannot provide it.
- External seams are faked with the [`tests/fixtures/`](../fixtures/) shims (`zellij-trace`, `git-trace`, `ssh-trace`, `codex-appserver-stub`); mux-driving tests route `rimz` invocations at an isolated tmux server env and a private Zellij runtime so a developer's live sessions stay untouched.
- The journey's hook-firing stub agent fires no lifecycle hook for pasted text, so a message it receives stays `Sent`, never `Delivered`. To prove receipt, fire the receiving turn with `env.run_installed_hook_in_pane` (`UserPromptSubmit` carrying the rendered message text, then `Stop`). Split panes shrink the target pane, so capture with scrollback when asserting on text that may have scrolled.
- Time is deterministic: fixed-epoch fixtures, boundary-exact.

## Multiplexer test doubles

No in-process `MuxBackend` fake exists; a failing multiplexer call is a fake executable.

| Double | Reach | Can make fail |
| --- | --- | --- |
| `zellij-trace` fixture binary, behind `RIMZ_ZELLIJ_BIN` (`common::shim::zellij_trace_shim`) | every suite; logs each argv, plus each `--layout` file's contents under `RIMZ_TEST_ZELLIJ_LOG_LAYOUTS` (RimZ deletes the file afterwards) | writes and Enter (`RIMZ_TEST_ZELLIJ_MODE=fail-write`, `fail-enter`), session birth (`birth-fails`, `socket-overflow-on-birth`), `new-tab` (`RIMZ_TEST_ZELLIJ_FAIL_NEW_TAB`), `close-pane` (`RIMZ_TEST_ZELLIJ_FAIL_CLOSE_PANE`). A cached pane listing comes from the topology cache `common::room::seed_live_zellij_room` writes; an authoritative one runs `list-panes`, scripted by `RIMZ_TEST_ZELLIJ_LIST_PANES` |
| `fake_zellij_script` in `zellij_health.rs` | that file | `list-panes`: sleep past a timeout, or exit non-zero |
| `fake_tmux` in `asks.rs`, `tmux_shim` in `web.rs`, `common::shim::write_path_shim` for a custom body | PATH shims | nothing as written; a custom body decides |
| `counting_action_shim` in `src/mux/zellij/tests.rs` | library unit tests only | any `action`, by run count |
