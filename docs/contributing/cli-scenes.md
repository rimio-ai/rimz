# CLI scenes

> See [rust-conventions.md](./rust-conventions.md#cli-shape) for how the CLI is parsed and [the CLI layer contract](../../crates/rimz/src/cli/AGENTS.md) for what a handler may own. Two sections below bind every command: [Human history lists](#human-history-lists) covers folded repeats and one fact stated once, and [Changing rendered output](#changing-rendered-output) covers what a change to human rendering checks.

A scene is a top-level command that owns one kind of thing and the verbs over it: `rimz agents`, `rimz teams`, and `rimz subagents`. `rimz agents` is the reference design; `rimz teams` follows it. A change to a scene keeps the six rules below true, and a new scene starts from them. The command forms each scene prints live in its reference page ([agents.md](../reference/cli/agents.md), [teams.md](../reference/cli/teams.md)); the shared exit codes live in [cli.md](../reference/cli.md#exit-codes).

## The list opens with attention

A scene's `list` leads with what needs a person, before the inventory. The rows come from one library projection, `crates/rimz/src/store/snapshot/view/model.rs::needs_you`: the sidebar's attention status (waiting, failed, or paused, lifted when a current child of either origin waits or a provider-native child fails), else the rowless status under the room's park demotion. Its age is the open ask's `since`, else the row's last activity. `rimz agents list` and `rimz teams list` render those rows with `crates/rimz/src/cli/render/mod.rs::needs_you`. `rimz teams show` takes each member's row from the same catalog as `teams list`, and `rimz teams wait` reads the projection on every poll. All four therefore agree with each other and with the sidebar by construction.

A scene never filters on `AgentStatus::is_attention()` itself, and never classifies by counting status strings. A team whose board owner holds no live seat adds a `not live` row; owner liveness is `crates/rimz/src/address.rs::role_holders` over the cohort's live members, the rule flip delivery already applies.

`rimz agents list --filter` selects rows through one library vocabulary, `crates/rimz/src/address/selector.rs`: the field table (`Field`), the flat row (`AgentRow`), the query and its default set (`Query`). The scope (`#lane`, `-w`, `--all`) applies first, and a filter only narrows it; a term naming `lane`, `live`, or `parent` replaces that field's default and no other, and one naming `launcher` replaces the `lane` and `parent` defaults. An `@me` value in `parent` or `launcher` matches only once the handler binds the calling agent (`Query::with_caller`). The row's serialized keys, `--filter help`, and shell completion all read `Field`, so a field added there reaches every surface, and each enum field's values come from an exhaustive match on its type. A malformed query is a `UsageError` that names the term.

The action commands that take a target set (`agents stop`, `restart`, `mark`, `refresh`, `wait`, and `message`) select through the same rows: `crates/rimz/src/cli/select.rs::select_targets` reads positional references, `--filter`, or a lone `-` (one address per line on stdin), applies the consent rule (more than one target needs `--all`, refused with exit 2 and the command with `--all` added; `refresh` never asks), and hands the command its targets with the identity each was selected as. Each command reads every target again just before it acts (`select::reread`), prints one receipt line per agent, and exits 1 through `select::batch_result` when any failed. `message` passes its selection to `rimz::message::dispatch` as resolved recipients (`DispatchRequest::selected`), which skip the fan-out consent and the group prefix.

## One described address shape

Each scene names its target one way and says so in help. Agents take `@handle[#channel]`, and their root lane spells `#main`. A team cohort is `team#lane` (`forge#feat-x`); a root-checkout cohort launched without `--channel` has the team's own name as its lane (`forge#forge`), not `#main`. Every verb that acts on one cohort takes that positional, and a flag that selects the same thing (`-w NAME`) is described as the same selection rather than as a second address. Help prints the positional's meaning, not a bare metavariable.

## Wrong input exits 1, a bad command line exits 2

- **Exit 2** (`crates/rimz/src/cli/usage.rs::UsageError`, mapped in `crates/rimz/src/main.rs::error_exit_code`): the command line itself cannot mean anything. A bare scene, a positional that is neither a verb nor a configured target, a launch prompt that is exactly a verb (`rimz teams forge stop`), conditional argument shapes clap cannot express.
- **Exit 1**: the command line parsed, and the thing it names is not there. An unknown lane, a cohort with no live members in that lane, a leader that is not live. The error lists the valid values (`live cohorts are in #a, #b`), or the command that would make one exist (`rimz teams resume forge`).
- **Exit 0** only when the requested effect happened. A launch that started no agent and delivered no prompt exits 1, whether the reconciler refused unattended, the user canceled, or the target was already gone; the one exception is focusing a live cohort when no prompt was given.
- A command that answers a question (`rimz loop explain`, a future `--check`) exits 0 when the answer is yes, 1 when it is no, and 2 when the question itself does not parse, so a script can tell "false" from "typo" by status alone.

A bare scene's refusal puts the list command on line 1, since a truncated read keeps the first line, followed by the scene's grouped orientation (`crates/rimz/src/cli/usage.rs::UsageError::missing_scene_verb`, `crates/rimz/src/cli/help.rs::scene_orientation`). Scene help and that refusal share the one orientation, grouped See, Drive, Start, Define; launch flags live under `<scene> launch --help` (`crates/rimz/src/cli/help.rs::customize_scene`).

## Actions report what they hit and the next command

A verb that changes something prints the target it acted on, by address, and the command a person would run next. A prompt delivered to a live cohort prints the shared dispatch receipt (`crates/rimz/src/cli/send.rs::report_dispatch`) plus the line saying the cohort was already running; stop and restart head with `stopped forge#lane (N members)`; a stop that leaves a pending board names its stage and the addressed resume and `flip ... Done` commands. A refusal that preserves the user's input carries it into the suggested command, quoted with `crates/rimz/src/cli/usage.rs::shell_command`.

Progress for a long wait goes to stderr in both human and `--json` modes, so stdout stays the result.

## A bare word launches only a launch spec

A scene's positional launch (`rimz agents <SPEC>`, `rimz teams <TEAM>`) is a shortcut for `launch`, and a word that could mean something else refuses with exit 2 and both readings. A word that resolves to a launch spec launches, whoever is live: `@word` is the only way to name an agent that exists, and an `@word` or `#scope` in the spec slot refuses with exit 2 and the command for that reading. An unresolved agents-scene word refuses with exit 2 and nearby verbs or launch names, or the compact launch catalog when none is close (`crates/rimz/src/cli/agents_cmd/mod.rs::run`). A team-scene word that is neither a command nor a configured team suggests nearby verbs or teams, otherwise lists both sets (`crates/rimz/src/cli/teams/mod.rs::guard_launch`). Explicit `launch` excludes verbs from suggestions, keeps exit 1 for an unknown target, and is the escape that sends any prompt literally.

## One vocabulary

User-facing text in a scene uses the scene's nouns and nothing older. For teams: a *cohort* is one team's run on a lane, addressed `team#lane`; a *lane* is `#lane`. "Instance" stays in JSON keys and serde names, which scripts read, and leaves every human string. A hint addresses a cohort as `team#lane`, never as `-w <worktree>`. When a change renames a noun, grep the old one by stem across `crates/rimz/src/cli`, `docs/`, `crates/**/AGENTS.md`, and rustdoc in the same change.

## Human history lists

This is not one of the six scene rules: it binds every command that prints such a list. A human history list is a screen that prints stored records as rows or blocks for a person to read. Every such screen keeps these rules; its reference section states its own key.

- **Scope.** The screen folds a run of repeats into one row. `--json` keeps one entry per record, unfolded. A screen without `--json` has its reference page name where each folded member's own record can be read.
- **What folds.** Only records RimZ made. Text a person or an agent wrote never folds, since in a conversation the text is the record.
- **The key.** Records fold when the typed fields behind every cell agree, apart from the time cells and the cells the fold sums or ranges. The key fixes what the record is about (which command, condition, child, or signal subject) and how it ended (outcome, exit, status). A member's text may differ only as the reason for an outcome the key fixes, the readings that explain that reason, or a handle that opens the member's own record (an id, a log path), and the row shows the newest member's. A field that names another subject or outcome is never one of these. When the text is itself what happened (a wake notice naming a command and its exit, a reason naming the condition that was met), members fold only when a typed field shows they agree; until a typed field written at record time exists, they keep their own rows. A field that no row prints and that does not name what the record is about never splits a row: [`events list`](../reference/cli/events.md#list-recent-signals) folds signals whose payloads differ outside the subject. A field that does name it stays in the key even when no row prints it, as loop's run id does.
- **Typed fields.** A typed field is a stored typed field, a RimZ-written header line parsed into a typed kind, or a subject the screen builds at read time from named payload fields. Stored text compared as a string is never one.
- **Adjacency.** Adjacent means within one stream, the subject the screen groups by: an agent, a channel, an assist kind and subject, a section's own list. Records of other streams, and records the screen does not show, do not break a run; a shown record of the same stream with a different key does.
- **Records that explain or sum others.** A record that only explains another folds into that record's row as a count, matched by a typed identity both records carry: [`loop show`'s RECENT RUNS](../reference/cli/loop.md#loop-show) folds a fire refused at the run lock into the run that held it. A summary written after the records it sums takes no row when their rows already state it. A record the header states takes no row only on a screen whose header states it; elsewhere it keeps its row.
- **Records that carry their own evidence.** Where each record's output is the point, as in [`loop logs`](../reference/cli/loop.md#loop-logs), each record that produced output (a run, a guard decline) keeps its own block, and only records that explain it fold into that block. Repeats that produced nothing (gate refusals) still fold by the key.
- **The folded row.** It shows what happened, `×N`, and the span (`render::folded_span`, omitted under one second, where it would read as a broken clock), and takes every other field from the member the rule names: the duration range (`render::range_label`), summed spend and counts, and the newest member's reason, readings, and handles. A field read from the newest member alone is a bug for every other field: check each one when a change adds a field to a folded row or folds a render that printed one row per record.
- **Limits.** On screen, a list's limit (`-n`, `--limit`, `--runs`) counts what the screen prints (rows, blocks, or lines); with `--json` it counts records. The limit never splits a folded row. A line that reports what the limit hid names its unit.
- **Ages and quotes.** Stored text never carries an age: an age frozen at write time is false when read and splits rows that agree. Text delivered to an agent (a notice or keepalive body) quotes what the agent was told; it may keep its age, and the fold never compares it.
- **One fact once.** State a fact once: a pid the header states stays out of rows, and a count a row states stays on that row while the header names the fact without the number. Use one word for one thing throughout the screen. A rule that omits a section because it repeats another is rechecked whenever the change adds a fact to that section.
- **Applications.** [`loop show`](../reference/cli/loop.md#loop-show) RECENT RUNS and [`loop logs`](../reference/cli/loop.md#loop-logs) (`crates/rimz/src/cli/loop_cmd/render.rs::collapsed_run_rows`), [`workflow show --history`](../reference/cli/workflow.md#inspect-runs), [`stats --assists`](../reference/cli/stats.md#the-assist-timeline), [`agents history`](../reference/cli/agents.md#history), [`events list`](../reference/cli/events.md#list-recent-signals), and [`message list`](../reference/cli/message.md#list-messages) with [`message show`](../reference/cli/message.md#show-one-message)'s TIMELINE. A new screen starts from the nearest of these.

## Changing rendered output

This is not one of the six scene rules either: it binds a change to human rendering on any command. Human rendering is a table, a list, a `doctor` row, a finding or notice built from a template, or a command a view prints for the user to copy.

- Check the change at the snapshot sizes, at the narrowest width its docs support, and with colour off (`NO_COLOR`, `CLICOLOR=0`, or `--color never`). With colour off, `crates/rimz/src/cli/render/mod.rs::out` strips every SGR sequence, so a mark told apart by tone alone (an overlay, a forecast, a muted span) states what it draws. A change that lengthens a label inside a fixed-width layout (a heading padded to a name column, a one-line tab rail, a padded section title) renders the layout with every value the label takes. Its test asserts that header columns line up with row values and that no value is clipped, since a bound on line width alone passes a clipped line.
- Run the merge base's binary and the head's on the same input, in each mode the change alters, and read the diff of their output. An installed binary whose `rimz --version` ends in `+g<hash>` with no `.dirty` was built from that commit, so it is the base binary when that commit is the merge base. A clean build of a release tag prints the bare version and gives no such shortcut.
- Render a finding or notice built from a template once per cause, and once with one member and once with several, and read each result as a sentence.
- A command a view prints for the user to copy names its target through the resolver that command runs, and uses the stable id when the readable name would select something else. It carries `--root` when the target is in another room, decided by `crates/rimz/src/workspace.rs::WorkspaceResolver::resolve_participant` (`WorkspaceResolver::resolve` ignores the pane's room pin), or it carries `--root` always. It puts every flag before `--`.
- A view offers a printed command only while that command's own gate would pass. A `rimz agents` launch needs a live room session, which `crates/rimz/src/room/mod.rs::require_live_mux` checks (the palette's launch mode judges it so) and a readable workspace record does not prove, since the record outlives the room. A view that prints a new `rimz` command has a test that feeds the printed target back through the resolver the command runs, and again after each change the product allows between the print and the user's run.
