# Stats CLI

`rimz stats` prints your token and dollar history across every project on the machine: spend and token totals, model and role breakdowns, and a heatmap of daily use. Its held view adds a stacked spend chart and assist counts; `--assists` shows the timeline. It touches no agent and no session, and it runs anywhere, in or out of a room or a project. What each figure means and how dollars are priced is the [Token Insight guide](../../guide/insight.md); how the panel is computed and fitted to the terminal is [stats internals](../../internals/stats.md).

```sh
rimz stats                              # print the panel once
rimz stats --dollars                    # shade the heatmap by dollars instead of tokens
rimz stats --refresh                    # hold the panel open and repaint every minute
rimz stats --json | jq '.windows.week'  # tokens and dollars over the last 7 local days
rimz stats --assists                    # latest 50 effective assist lines, repeats folded
rimz stats --assists -n 0 --all          # all retained attempts, including held ones
rimz stats --agents                     # every agent profile, unfolded
rimz stats --teams                      # every team, without per-role rows
rimz stats --subagents                  # every subagent profile, unfolded
rimz stats --rebuild                    # rebuild saved days from present transcripts
```

| Flag | Effect |
| --- | --- |
| `--dollars` | Shade the heatmap by dollars spent and title it `Spend activity`. Under `--json` it only sets `unit` to `usd`; `--assists` ignores it. |
| `--json` | Print the [stats document](#json-output) instead of the panel. Conflicts with `--refresh`. |
| `--window <WINDOW>` | Select `today` (default), `week`, `month`, or `year` for breakdowns, sessions and assists, and the held dashboard's initial tab. The Spend table always shows all four; the heatmap summary follows the drawn grid. Conflicts with `--assists`. |
| `--refresh` | Open the [held dashboard](#the-held-dashboard): a full-screen panel that refreshes every 60 seconds and re-centres on resize. Conflicts with `--json`. |
| `--assists` | Print the [assist timeline](#the-assist-timeline). Conflicts with `--agents`, `--teams`, `--subagents`, and `--refresh`; supports `--json`. |
| `--agents` | Show every solo agent profile with spend or recorded effort in the selected window, including provider-named rows, with spend, fleet dollar share, input, output, cached tokens, hit rate, distinct sessions, and agent-time. With `--json`, also include profiles with work tokens and no spend. Conflicts with `--teams`, `--subagents`, `--refresh`, and `--assists`. |
| `--teams` | Show every team with spend or recorded effort in the selected window, with the agent columns plus messages. Team roles appear only in JSON. With `--json`, also include teams with work tokens and no spend. Conflicts with `--agents`, `--subagents`, `--refresh`, and `--assists`. |
| `--subagents` | Show every subagent profile with spend or recorded effort in the selected window, with the agent columns. These dollars are already counted in their owners or the remainder. With `--json`, also include profiles with work tokens and no spend. Conflicts with `--agents`, `--teams`, `--refresh`, and `--assists`. |
| `-n N` | With `--assists`, show at most N timeline lines, or N events with `--json` (default 50); 0 means all retained. |
| `--all` | With `--assists`, include held and undelivered attempts. |
| `--rebuild` | Rebuild every saved UTC day in retention for discovered accounts from present transcripts, using current prices. Prints rebuilt days and before/after dollars with unchanged account-days, `No saved day changed; N account-days unchanged.`, or `Nothing to rebuild.` Warns once per account on stderr when transcripts are gone and saved figures were kept, with the kept UTC-day count and dates (consecutive days as `start..end` ranges). Conflicts with `--json`, `--refresh`, `--assists`, `--agents`, `--teams`, `--subagents`, `--dollars`, `--window`, `-n`, and `--all`. |

A conflicting pair exits `2`. Of the [global flags](../cli.md#global-flags), `--color` applies; `--root` and the backend flags are accepted and change nothing, because the figures are machine-wide.

`--rebuild` exits `0` when every requested account-day was compared, including unchanged or empty history and days kept because no transcripts remain. Incomplete transcript discovery exits `1` before parsing or publishing, without retry advice. An account with an unread transcript is deferred: stdout keeps its summary, stderr names that account and its UTC dates (consecutive days as `start..end` ranges), says they stay pending, and the command exits `1`. An unavailable spending producer lock or shared history maintenance lock exits `1` with a retry message. A newer, malformed or unreadable history format mark also exits `1`, naming the mark file without retry advice; a missing mark is usable. A requested rebuild writes no assist; automatic replacements write a `spend_rebuild` assist. A partially deleted day follows its remaining transcripts and may fall; a day with no transcripts keeps its saved figure. Transcript-logged costs stay as logged rather than taking a new list price.

## What the panel shows

History days use the configured `timezone`, or the system's named timezone. An unnamed system zone falls back to UTC; set `timezone` to an IANA name to select another zone.

The one-shot panel opens with Today, 7 days, 30 days, and 52 weeks. Today starts at local midnight; the other windows cover the last 7, 30, and 364 local calendar days, including today. The rows are `dollars (vs prior)`, `tokens + cache reads`, and `per active day`. The 7-day and 30-day dollars include a trend against the preceding equal window when it had spend, capped above 999% as `↑999%+`; a change rounding to zero reads `±0%`. Dollar figures keep their alignment whether a trend is present or not. Spend per active day divides each window's dollars by its days with tokens, including Today.

Models, Providers, Agents, Teams, then Subagents follow, each labelled `(today)`, `(7 days)`, `(30 days)`, or `(52 weeks)` for the selected window. Every share is the row's dollars divided by fleet dollars in that window. Each section ranks by dollars, shows the top three rows with spend or recorded effort, and folds the rest into a counted tail such as `N other teams`. Empty sections are omitted. Token units are uppercase, and session counts use grouped thousands. Models use provider identity colours; profile and team names stay muted. Providers shows `SESSIONS TOKENS HIT TOK/S`; compact Agents and Subagents add `AGENT-TIME` after `SESSIONS`, and Teams adds `AGENT-TIME MSGS (YOU)`. Explicit views keep the input/output/cache columns and append effort after the session count.

Providers includes all spend by provider kind, including historical and unobserved sessions. Agents groups solo seats by profile; Teams sums each team's seats into one row. Both include the dollars, tokens, and active time of subagents those seats launched, when their owner was recorded. Their sessions and messages count only the seats' own work. Subagents groups sessions launched by `rimz subagents` by profile as an already-counted cross-cut, not another owner. Native provider children inherit their pane's role. A bare-kind launch uses its provider kind as its profile key, merging with a profile of that name. Agents, Teams, and Subagents hide only when empty, including when Agents has only provider-named rows.

Claude sessions in one project count separately; a native subagent's work counts toward its parent session.

`AGENT-TIME` is estimated time working, summed across sessions and parallel seats: `45s`, `41m`, `6h12m`, or `1d03h`. `MSGS (YOU)` counts incoming human prompts and agent messages once on the receiving side, for example `10 (1)`, or `10` without human prompts. Zero effort cells read `-`. A row with only agent-time or messages still appears. A team's sent-message split stays in `roles[]` in JSON, not in panel rows.

For example, a compact Teams row:

```text
  Teams (today)             SPEND   SHARE  SESSIONS  AGENT-TIME   MSGS (YOU)   TOKENS  HIT TOK/S
  recon                      $576   55.6%        91         45m        2 (1)     1.1B  97%    91
```

Muted coverage text sits above the first visible profile or team section. When the window begins before role recording, it says `roles recorded since DATE, earlier spend counts as No owner recorded`. When only effort history starts later, it says `agent-time and messages recorded since DATE`. When both apply, they join with a middle dot, shortening the effort clause to `agent-time and messages since DATE` and wrapping to the Spend table's width. Each date is compared with the window's local-midnight start, and the text disappears when all three sections hide. Explicit `--agents`, `--teams`, and `--subagents` text views list every qualifying row, or say no spend was recorded in the named window; they keep the applicable coverage text even when empty.

Between Teams and Subagents, the full report adds `No owner recorded`: fleet dollars minus Agents and Teams, clamped at zero, with its share of fleet spend. It hides below one cent. A note beneath it gives the subagent spend without a recorded owner, when that amount reaches one cent. Models, Providers, and Agents + Teams + No owner recorded each add up to fleet dollars. Subagents follows with an already-counted note, which explicit `--subagents` keeps. Explicit role views omit the remainder.

The local-day heatmap follows the breakdowns. Its legend reads `N active days since Mon D · streak N days · busiest Mon D`, counting and ranking only the drawn grid while keeping the full-history current streak, regardless of the selected window. A date in an earlier calendar year adds the year as `Mon D YYYY`. The summary sits below the key, wrapping to the Spend table's width. The final `as of` time is the publication time in its published timezone, with a date when the publication is not from today. The full report appends the selected window's session count and average cost, such as `390 sessions today at $2.63 each`; the other window labels are `in the last 7 days`, `in the last 30 days`, and `in the last 52 weeks`. This clause is omitted for zero sessions and explicit role views. A cold one-shot run does not print the wordmark; the held dashboard keeps it when space permits.

With no daily history or role usage, the full report replaces the tables and heatmap with `No agent sessions recorded on this machine yet.` and `Spend appears here after your first agent session; rimz stats reads it from each agent's own session files.`, followed by the publication time.

## How fresh the figures are

`rimz stats` reads the spending cache at `~/.rimz/cache/providers/provider-spending.json` (under `$RIMZ_HOME` when it is set). A running sidebar keeps that cache current, and each mode treats it differently:

| Run | Cache | What happens |
| --- | --- | --- |
| `rimz stats`, `--json`, `--agents`, `--teams`, `--subagents` | present and its figures cover today in its timezone | Prints the cache as it is. Nothing is walked or fetched. |
| `rimz stats`, `--json`, `--agents`, `--teams`, `--subagents` | missing, its figures cover another local day, or written by an incompatible RimZ version | Reads every agent transcript on the machine, writes the cache, then prints. When the panel goes to a terminal, a `Reading session files [bar] n/total` spinner reports progress. |
| `--refresh` | any | Requests fresh figures every 60 seconds through the same spending service the sidebar uses, which rereads transcripts that changed. |
| `--assists` | not read | Reads only the assist log. |

A one-shot run can print figures from earlier today. A walk that begins before midnight still covers the earlier day even if it finishes after midnight, so a one-shot run refreshes it again. Run `rimz stats --refresh`, or open a room, for updates within the day.

Recorded UTC days, closed fourteen days after their end, replace live account-days in these figures. They survive transcript deletion and cache rebuilds under `accounts/.history/`, shared with other homes using the same accounts folder and kept by uninstall and reset. The newest decodable line for an account-day is effective; `--rebuild` appends replacements without removing the preceding figures ([history rules](../../internals/agents/spending.md#closed-day-spend-lines)).

If a refresh cannot read session files and only an older publication remains, a one-shot run exits with an error rather than showing yesterday's breakdowns as today. The older publication stays intact, and a held dashboard can continue showing it.

Every run except `--assists` creates RimZ's shared state directories when they are missing. Beyond that, only the transcript walk writes files or uses the network. The walk writes the spending cache, its walk cursor, and the price-table cache beside it, unless another process is already writing them. It also migrates and maintains shared history, records newly closed days, and may start a background rebuild when restored or synced usage grows on a saved day. Automatic rebuilds leave a `Spend rebuild` assist with the changed days and before/after dollars. It fetches the price tables from LiteLLM and models.dev when the cached table is more than a week old, or sooner when your history holds models it has no price for. Set `RIMZ_PRICING_OFFLINE=1` to skip every fetch (`0`, `false`, and an empty value leave fetching on); prices then come from the cached table and the table built into the binary. The walk and pricing are described in [spending internals](../../internals/agents/spending.md).

## The held dashboard

`rimz stats --refresh` takes over the pane on the terminal's alternate screen and repaints in place, leaving no scrollback. It is the default pane of the `rimzd` daemon view ([rimzd internals](../../internals/rimzd.md)).

| Key | Action |
| --- | --- |
| `←`, `→`, `h`, `l` | Move one range, stopping at Today and 52 weeks. |
| `t`, `w`, `m`, `y` (either case) | Jump to Today, 7 days, 30 days or 52 weeks. |
| `Tab`, `Shift-Tab` | Cycle the ranges with wrap. Spend breakdowns and assists follow the selected range. |
| `r`, `R` | Restart the dashboard on the current binary, keeping its flags. `rimz reload` does the same to every running dashboard. |
| `q`, `Ctrl-C` | Quit. |

Other keys do nothing. The final line reads `←/→ range · t/w/m/y jump · r reload · q quit`. In the daemon view both `q` and `Ctrl-C` are ignored and the hint omits `q quit`; closing the pane ends the dashboard.

The dashboard starts on Today, or the tab selected by `--window`, with dollar totals in its tab rail. When the full rail does not fit, inactive tabs show only their labels and the active tab keeps its total. Below the wordmark are the token heatmap, tab rail, stacked spend chart, Models, Providers beside Where it went, Teams, Agents beside Subagents, Assists, and key hint. Section titles use normal foreground in bold. Today draws 24 local-hour bars; 7 days draws seven daily bars; 30 days draws thirty; 52 weeks draws the newest seven-day blocks that fit, up to 52, naming the count in its title. Each total covers its bars' days, except that below 62 columns the 52-week view keeps its total while drawing fewer weeks. The chart uses the Models table's named set, order and swatches, with the remainder in Other and no separate legend. Readable scheme hues nearest the provider brand stay consistent across tabs, but can move with the 30-day spending rank on refresh. Tops use eighth blocks, and even tiny positive spend stays visible. The 7-day, 30-day and 52-week views' dashed average line is the mean of the drawn bars, including today's partial bar (the newest week in the 52-week view) and missing bars as zero, without the forecast extension. The 7-day and 30-day views label it `avg $X`, or just `$X` when narrow; their titles show only the trend against the prior equal window when it had spend. The 52-week view puts `┄ avg $X a week` in its title without crowding the weekly bars. No spend means no line or average label. Every tab has the same grid-scoped heatmap footer as the one-shot report, with unpadded dates and the year added for earlier calendar years.

At full width, Today's header shows `today $X so far · ~$Y by midnight · ░ yesterday $Z`. When the title line overflows, it first drops `today $X so far · `, already shown in the active tab. On every tab, the left chart title then shortens to preserve comparison figures whenever they fit alone. Yesterday's same-hour dollars appear as whole muted `░` cells above the cell holding today's bar top, including future hours, never tinting or covering spend. The ghost height rounds to whole cells. The forecast is spend so far plus the previous seven local days' mean spend in hours after the spend snapshot's recorded local hour, counting missing days as zero and never falling below spend so far. It excludes the rest of that hour rather than extrapolating today's pace. The bar holding today in the 7-day, 30-day and 52-week views gets an extension in its model colour faded toward the background; Today shows the forecast only in its header. Where spend shares a cell with an extension above it, the spend glyph keeps its model tone and the forecast uses the background, reaching the cell top. With colour off (`NO_COLOR`, `CLICOLOR=0`, or `--color never`), the extension neither draws nor contributes to the ceiling, but yesterday's ghost and the header figures stay. Axis dates stay separated; Today's final `23` is muted, while `today` and `now` on the other tabs stay accented. The final label starts under the newest bar when it fits there, otherwise ending at the plot edge. These forecast and comparison marks are held-view features, not one-shot or JSON output.

Held breakdowns rank by dollars and keep up to seven named Models, four Agents, Subagents and Teams, and three Providers, each plus Other. Rows below 1% of their own section's dollars fold. A tail containing just one entry keeps its name even below that threshold or past the named-row limit. Models show HIT, TOK/S and TOKENS, hiding TOK/S when every named model row is untimed; Other's always-`–` rate does not keep it open. Providers show dollars, fleet share, hit rate and grouped session counts; a provider under 1% shows `<1%` and sessions without hit rate. Where it went prints Teams, Agents and No owner on one line each, with fleet-dollar percentages and the ownerless remainder clamped at zero. Teams and Agents use accent and meta; No owner is faint. Profile and team markers and filled bars use their group's tone (cool for Subagents), with normal foreground names, and Other rows stay muted throughout. Agents, Subagents and Teams show shares of their own section, not of the fleet. A muted note marks Subagents as already counted, after its total or below its title when space is tight. Teams adds AGENT-TIME, MSGS (YOU) and TOKENS, summing effort in Other. Message cells keep two-cell gutters even with wide counts. The role-recording date appears in Where it went when needed; the dashboard has no effort-recording note.

The frame is centred horizontally at up to 113 columns and vertically using the tallest tab at its chosen fit step, so switching tabs does not shift it. With no terminal row count there is no vertical padding. Sections have one blank separator and no bottom padding. Below 112 columns, side-by-side sections stack and bars shrink; a heatmap footer too wide beside its key moves below it and wraps within the frame. Every tab uses the same fit step, chosen by measuring all four rendered frames: drop the wordmark; collapse Assists to one line; drop the heatmap; drop Agents and Subagents; keep two named Models and Teams; drop Teams; reduce the seven-row plot to four rows, then two. Remaining overflow clips the body, preserving the final key hint. A refresh that fails leaves the last frame on screen with no marker. When the first refresh fails, the dashboard shows `Spending refresh unavailable - retrying.` with the cause and tries again after 5 seconds. Reload returns to the initial tab specified by the flags.

The Assists block omits held-attempt detail and zero-count categories. `Auto-compact` counts requests, including undelivered ones; other categories count effects. The header adds `(records since …)` when retained history starts after the selected window. Its collapsed form names the active tab's category count and points to `rimz stats --assists`. Both the dashboard and the [assist timeline header](#the-assist-timeline) group counts by thousands, including reset and agent details, and label Auto-continue's duration as `(after 5.1h parked)`: time before resuming, not time saved.

## JSON output

`rimz stats --json` prints one pretty-printed object describing the selected window (today by default). Breakdowns carry every model, provider, profile, and team with dollars or work tokens in that window, plus profile and team rows with recorded effort alone, with no `Other` folding and no row cap. To inspect a timed model over the year:

```sh
rimz stats --window year --json | jq 'first(.models[] | select(has("tokens_per_sec"))) | del(.tools)'
```

| Field | Contents |
| --- | --- |
| `as_of`, `timezone` | Publication time (RFC 3339 with offset) and the timezone used by the daily buckets. |
| `unit` | `tokens`, or `usd` under `--dollars`. The token and dollar fields below are present either way. |
| `window` | Selected window: `today`, `week`, `month`, or `year`. |
| `roles_since` | First retained role-record date, `YYYY-MM-DD` in the published timezone, covering solo, team, and subagent sessions. Omitted when no records exist. |
| `effort_since` | First retained active-time or message record date, independently of role history; omitted when none exists. |
| `sessions` | Sessions in the selected window. |
| `active_days_28` | Days with usage among the last 28. |
| `longest_streak`, `current_streak` | Consecutive days with usage. |
| `most_active_day` | `YYYY-MM-DD` of the heaviest day. Omitted when there is no usage. |
| `windows` | `today`, `week`, `month`, and `year`, each with `tokens` and `usd`, plus `tool_calls` and a `tools` map of calls by tool name, each omitted when empty. `today` is the local calendar day in the published timezone. |
| `models` | One object per model, sorted by `usd`: `model` id, display `name`, `tokens`, `input`, `output`, `cache_read`, `tool_calls`, `tools`, `cache_hit_pct`, `tokens_per_sec`, `usd`, and `share` of the total dollars as a fraction. |
| `providers` | One object per provider kind with selected-window dollars or work tokens, sorted by dollars: `kind`, display `name`, `tokens`, `usd`, `sessions`, `tool_calls`, `tools`, `cache_hit_pct`, optional `tokens_per_sec`, and `share` of selected-window fleet dollars as a fraction. |
| `agents` | Every solo profile with selected-window dollars, work tokens, or effort, sorted by dollars then profile: `profile`, `sessions`, `active_secs`, `input`, `output`, `cached`, `cache_hit_pct`, `tokens`, `usd`, and selected-window fleet dollar `share`. Provider-named rows are included. Spend, tokens, and active time include owned subagents; sessions do not. |
| `teams` | Every team with selected-window dollars, work tokens, or effort, sorted by dollars then team: `team`, `sessions`, `active_secs`, `messages: {total, from_user}`, `input`, `output`, `cached`, `cache_hit_pct`, `tokens`, `usd`, `share`, and `roles`. Each role has `role` (a roleless layout cell, as in the built-in `peer` team, uses its profile, else its provider kind), `sessions`, `active_secs`, `from_user`, `from_teammates`, `to_teammates`, and the same spend fields and fleet-dollar `share`. Team totals sum their roles; incoming messages count once, not again when sent. |
| `days` | One object per local calendar day in the published timezone with usage, oldest first: `date`, `tokens`, `usd`. |
| `subagents` | Every profile with selected-window dollars, work tokens, or effort: `profile`, `sessions`, `active_secs`, `input`, `output`, `cached`, `cache_hit_pct`, `tokens`, `usd`, and selected-window fleet dollar `share`. An already-counted cross-cut. |
| `no_owner` | Selected-window `usd` outside Agents and Teams, its fleet-dollar `share`, and `subagent_usd` with no recorded owner. Absent from explicit role-view envelopes. |
| `assists` | The selected-window effective-assist rollup only, without events. |

`tokens` is always input plus output plus cache-read tokens, and `input` includes cache writes. `tool_calls` and `tools` are omitted when zero or empty.

`tier_fallbacks` counts one per fresh tier move, whether it passed an unbuildable family, a spent account, or both. Replayed stamps, including a molt without `--agent`, are not counted again. Its benefit line names the first pass (`not buildable` or the usage reason); the event retains all usage `skipped` entries and optional `unbuildable` entries with their full build errors.

`providers`, `agents`, `teams`, and `subagents` are always arrays, including when empty. `cache_hit_pct` in profile and team rows is `null` when there is no input to measure; in model and provider rows it is omitted. `tokens_per_sec` is a rounded integer from the selected-window tally, omitted when the model or provider has no timed responses. Activity days, streaks, and the most-active day retain their full-history meaning regardless of `--window`.

An `auto_gc` event carries `scope` (`room` or `machine`); records written before scopes existed read as `machine`. Totals cover the whole sweep's scope. The durable assist record additionally holds own-room `class_bytes` and `worktree_paths` (the first 50 removed paths in sweep order, `[]` for legacy records), which this JSON projection does not expose. `worktrees_removed` remains the full count, so a count above the path-list length indicates truncation on new records ([GC report](./maintenance.md#the-report)).

A `tmp_evict` event counts one successful temp-unit eviction toward `tmp_evictions`, not `sweeps`, and its allocated bytes toward `reclaimed_bytes`; an error counts under `held.tmp_evictions`. In the timeline header, the `Temp evictions: N` category shows its own count and held attempts, separately from `Auto-gc:` sweeps; Auto-gc's byte detail totals both kinds. Its GC timeline row names the handle, reclaimed bytes, and workspace. JSON also carries optional `ended_at`, `free_bytes_after` (the measured filesystem-available space, which may lag removal), `floor_bytes`, and `error` on failure. Allocated bytes count hardlinked files once per tree; snapshots can retain those blocks after removal.

The `assists` object holds `port_forwards` (automatic forwards opened), `empty_dir_grants` (automatic empty-root folder-trust writes), `judge_declines` (fresh judge polarity declines), `model_aliases` (catalog-derived model moves), `redeems` and `resets` (successful window-reset redemptions, and those whose outcome is `reset`), `manual_redeems` and `manual_resets` (the user-initiated subset, excluded from the `Auto-redeem:` text row), `resumes` and `recovered_secs` (delivered auto-continues, and the time spent parked before those resumes), `compacts`, `keepalives` (delivered prompt-cache pings), `idle_stops` (`stop --when-idle` requests that stopped their agent), `idle_stop_withdrawals` (requests withdrawn by a prompt from the user), `molts` (fresh successor tabs opened), `launch_retries` (relaunches of agents that died at startup), `restores` and `restored_sessions` (room restores, and the agents they brought back in a tab confirmed open), `sweeps` (completed automatic gc sweeps), `spend_rebuilds` (automatic saved-day rebuilds that appended replacements), `tmp_evictions` (successful temp-unit pressure evictions), `reclaimed_bytes` (their combined bytes: apparent for sweeps, allocated for temp units), and `workflow_starts`, `workflow_steps`, `workflow_routes`, `workflow_parks`, and `workflow_ends` (workflow runs a loop task started, step attempts launched, routes including closed merged waits, parks, and runs that reached `done`, `failed`, or `canceled`). `held`, present when any attempt did not take effect, maps each of those count names to its held attempts. Timeline events carry an `assist` type (`port_forward`, `empty_dir_grant`, `stall_notice`, `resident_launch`, `tier_fallback`, `hibernate`, `judge_decline`, `model_alias`, `workflow_start`, `workflow_step`, `workflow_route`, `workflow_park`, `workflow_end`, `auto_continue`, `auto_compact`, `idle_compact`, `cache_keepalive`, `idle_stop`, `idle_stop_withdrawn`, `molt`, `launch_retry`, `flip_compact`, `auto_redeem`, `auto_resume`, `auto_gc`, `spend_rebuild`, or `tmp_evict`), its `at` time in UTC, and the fields of that type. Model moves carry `kind`, `login`, `alias`, `from`, and `to`. A redemption carries the account name as `login` when its record has one, and its text row names the account when it is not `default`, as in `↻ codex@spare credit`. Manual redemptions keep the `auto_redeem` record type with `reason: "manual"`; their event text says `manual`, and they are not automation assists. What each assist is lives in [the assist log](../../internals/harness/loops.md#the-assist-log).

`Spend rebuild: N` counts automatic rebuilds, not account-days. Its timeline row shows the distinct rebuilt UTC-day count and total dollars before and after. Each `spend_rebuild` event carries the pending `days` it started from (`YYYY-MM-DD`), parsed transcript `files`, `rebuilt` account-days (`login`, `day`, optional `before_usd`, `after_usd`), and `kept` account-days (`login`, `day`). An empty or unchanged rebuild writes no record. These records count as effective even when some other account-days were kept or deferred.

The `Port forwards: N` category counts successful report-driven opens by `rimz remote connect`. A server returning after stopping counts again; reopening an existing forward after link recovery does not. Each `port_forward` event has `host`, `remote`, `local` only on success, and `error` only on failure. Failed attempts count under `held.port_forwards` and appear with `--all`; persistent local-port exhaustion contributes one held attempt. These records live on the laptop, so read its stats, not the host's.

The `Empty-dir trust: N` category counts automatic folder-trust grants on the empty root. Each `empty_dir_grant` event carries `kind`, account `login` (`kind@name`), trusted `key`, changed provider-file `path`, and `profile` when named. Its benefit line names the provider, account, folder, and profile; its forensic line adds the provider file. A successful write counts even if a later launch preflight refuses; failures and grants completed by another writer produce no record.

The `Judge declines: N` category counts fresh judge declines, not later fires held by the same decision. Each `judge_decline` event carries `task`, `checkout`, judge `profile` and `kind`, `reason`, and optional `cost_usd`. Its timeline line names the task, profile, reason, checkout, and recorded cost. Manual fire, a new true condition edge, or an elapsed recheck can produce a fresh decline ([resident judge memory](./loop.md#waits-and-checks)).

The `Keepalive: N` category counts delivered pings. Each `cache_keepalive` event carries `kind`, `agent_id`, optional `label`, `idle_secs`, `waits`, optional `horizon_secs`, `message_id`, `delivered`, optional `error`, and `capped` (true on the ping that told the agent the keepalive maximum was reached; its `◷` line ends with `, limit reached`). `horizon_secs` is the [keep-warm](../../guide/configuration.md#keep-warm) finite maximum that was holding the agent (`max`, or the keepalive cap for a `while`-only hold); its timeline line reads `holding warm (2h)`. `waits` counts all pending waits, including subagent and team waits. Failed attempts appear with `--all` without increasing the count.

The `Idle stop: N` category counts [`stop --when-idle`](./agents.md#stop) requests that stopped their agent. Each `idle_stop` event carries `kind`, `agent_id`, `label`, `idle_secs` (how long the agent had rested), `idle_after_secs` (the requested threshold), optional `requested_by` (the asking agent's handle), `stopped` (the agent's own pane closed), and optional `error`. A stop that left the pane open appears with `--all` with `stopped: false` and leaves its request armed. `error` can accompany `stopped: true`: the agent closed and something else failed, such as a child's pane staying open.

The `Idle stop withdrawn: N` category counts requests withdrawn by a prompt from the user. Its JSON rollup key is `idle_stop_withdrawals`. Each `idle_stop_withdrawn` event carries `kind`, `agent_id`, optional `label`, `idle_after_secs` (the withdrawn threshold), optional `requested_by`, and `requested_at`. These events count as recorded, never held; their `↶` line names the agent, threshold, and requester when an agent asked.

The `Launch retry: N` category counts relaunches of agents whose CLI died before opening a session, one per [relaunch](./agents.md#launch-a-layout). Each `launch_retry` event carries `kind`, `label` (the agent's handle), `run_id` (omitted for a launch without a supervised run), `attempt` (which relaunch of that launch, from 1), `exit_code` (omitted when a signal killed the process), `startup_ms` (how long the process that died lived), `relaunched`, and optional `error`. A relaunch that could not spawn appears with `--all` and `relaunched: false`.

The `Workflow: N` category sums the five [workflow](./workflow.md) assist kinds. Every workflow event carries `run` (the `wf_` id) and `workflow`. `workflow_start`, emitted only for loop-created runs, adds `task` (the loop task), `checkout`, and `prompt` (whether the run has one); its line reads `workflow babysit-pr started by loop babysit-pr`. `workflow_step` adds `step`, `visit`, `seq`, and the attempt's `handle` and `run_id` (both null for a command step); `workflow babysit-pr sweep launched (visit 2)`. `workflow_route` adds `node`, `outcome`, and `to` (the next node, or `@wait`, `@done`, `@failed`, `@user`); `workflow babysit-pr pr said needs-sweep → sweep`. A merged wait writes one route when it closes, with `count` set to its final poll count; its line reads `workflow babysit-pr pr waited ci-pending ×12`. An open wait contributes no route yet; other routes omit `count`, and older events without it still render as `said`. `workflow_park` adds `node`, `reason`, and optional `text`; `workflow babysit-pr triage parked: asked: Which fix ships first?`. `workflow_end` adds `state` (`done`, `failed`, or `canceled`); `workflow babysit-pr done`.

## The assist timeline

The `Molts: N` category counts agents moved into fresh sessions by `rimz agents molt`. The JSON rollup exposes `molts`; each `molt` event names the predecessor (`kind`, `agent_id`, `label`), the successor (`successor_kind`, `successor_id`, `successor_label`), and optional inherited `generation`. The successor id is its launch id. A molt counts once its new tab opens, even if the successor later fails or arming the predecessor's idle stop fails. Timeline lines show both handles; forensic lines retain both providers and ids.

By default, `rimz stats --assists` prints the latest 50 lines of assists that took effect, newest first, with the non-zero category counts over all retained records. Times use the configured timezone. Repeated outcomes for the same subject and assist kind fold within that subject's history of that kind, even when other subjects or kinds interleave. A changed outcome or policy key breaks the repeats; different agents and targets stay apart. A repeated line reads `YYYY-MM-DD HH:MM outcome · ×N over span · identifiers` (`over span` omitted under one second), using its newest member's time, reason, readings, and identifiers. Reclaimed bytes, GC removal and problem counts, judge cost, and recovered parked time are summed; idle, silence, and startup durations become ranges. These measured readings round down to whole minutes from one minute up and to whole hours from one day up (`59m`, `1h06m`, `1d02h`), while thresholds, the keep-warm horizon, and the GC cutoff print as configured. Repeated resumes omit the individual clock-time span. A workflow route with its own poll count never folds again, and neither does a spend rebuild, since each names its own days and dollars.

`-n` counts lines after folding, so each line's `×N` includes every matching record, even beyond the limit. `--all` includes held and undelivered attempts. When more remain, the trailer says `… N older; rimz stats --assists -n 0 for all`, where `older` counts records outside the printed lines. The printed repeat counts plus `older` equal the filtered record count. Zero shows all retained records across both log generations, not unlimited history. JSON keeps one event per record, with `-n` and `older` counting records rather than lines.

The header counts each kind's attempts that did not take effect beside it, for example `Auto-compact: 2 (239 held)`. Delivery-based events count only when delivered, except a stall notice, which counts once queued for its parent and is held only on an error. A stall notice still counts if later withdrawn because its child run ended before delivery. Stops and relaunches use their recorded success flags. Hibernation counts freezes; a deepening step adds its reclaimed bytes, takes effect, and is never held. Redemption counts require a window reset; GC, temp evictions, and port forwards require no error. Molts, model aliases, tier fallbacks, empty-dir grants, resident launches, judge declines, compact commands and room resumes count as recorded.

`rimz stats --assists --json` emits `{as_of, rollup, events, older}`, respecting `-n` and `--all`; its `as_of` is the read time, with the offset of the configured timezone. `--agents --json`, `--teams --json`, and `--subagents --json` emit `{as_of, window, agents|teams|subagents, roles_since?, effort_since?}` with only the selected array. The default stats JSON carries the assist rollup without events; every breakdown's `share` is a dollar share.

| `↘` | Tier fallback: the profile used the next available model. |
