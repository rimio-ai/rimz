# Performance

> This is the performance model over the mechanisms, not the mechanisms themselves. Sidebar data flow, cadences, and the published-file inventory live in [state.md](./sidebar/state.md); presence, ranking, and recovery in [sidebar.md](./sidebar/sidebar.md); the durability contract and write classes in [store.md](./store.md#durable-state); the backend pane roster and the Zellij presence channel in [multiplexers.md](./multiplexers.md); the live-profiling field guide and capture log in [profiling.md](./profiling.md). This doc says where the milliseconds go, what the whole fleet costs RimZ, which optimizations bound them, and the rules the next change follows.

## The performance model

Read this first; everything else is detail under it.

RimZ watches a fleet for one human. The workload has a characteristic shape: tens of agents append to one flat-file store concurrently, a sidebar renders the room and must stay interactive while they do, and **the room is idle most of the time** — a fleet emits in bursts and then waits on a model or a human. Good performance here is three goals at once, in three different places:

- **The read/render path — perceived latency.** The sidebar's render/input loop is the one thread a human feels. Its goal is that the UI never blocks, drops a keystroke, or freezes the spinner. It may show data that is stale by a tick; it may never stall. This is where "responsiveness" lives.
- **The write path — contention.** Tens of agent hooks commit to one workspace at once. Its goal is that a concurrent append costs no felt latency — the critical section is a queue of microsecond holds, and durability rides off the lock.
- **Idle steady state — near-zero work.** When nothing changes, the room should cost almost nothing: no polling spin, no per-frame fork, no directory rescan. An optimization that speeds the busy path by adding idle work is usually a net loss, because idle is the common case.

Underneath all three sits one guardrail: **correctness lives in the store, never on the render thread.** A performance change may leave the UI stale by a tick; it may never make it wrong, and it never trades a durability or CAS invariant for latency.

The whole design keeps these from fighting each other by **decoupling them onto independent clocks and threads**. The core abstractions, each named once with its code home:

- **The serve loop, fetch worker, and cache refresher.** `rimz sidebar serve` runs one event loop that blocks only in `recv` on its wakeup socket ([`sidebar_pane::app::serve`](../../crates/rimz/src/sidebar_pane/app.rs)). Expensive work is offloaded to a background **`FetchWorker`** thread, which owns cadence, election, consumer memoization, notifications, and result publication ([`app::fetch`](../../crates/rimz/src/sidebar_pane/app/fetch.rs)), plus an elder-gated **cache refresher** for heavy refresh lanes ([`app::cache_refresh`](../../crates/rimz/src/sidebar_pane/app/cache_refresh.rs)). The loop never forks or fsyncs.
- **One producer, many consumers.** The eldest live renderer per workspace is elected **producer** and pays the room-scoped external reads once: the fetch worker owns pane resolution, provider-local session discovery, and roots, while the cache refresher owns git diff-stats and accounts and requests account-global spend from one separately elected warm service. Every younger renderer is a **consumer** that keeps one [`PublishedSnapshotReader`](../../crates/rimz/src/sidebar/consumer.rs) and folds the producer's published caches in process; low-level producer and test code may supply a cursor to `read_published_snapshot` directly. Workspace election is by UUIDv7 birth order through one shared renderer-local tracker ([`sidebar::ProducerElectionTracker`](../../crates/rimz/src/sidebar/mod.rs)); the spending service uses a schema- and persistent/discovery-namespace-versioned lifetime lock and Unix socket.
- **Event-fresh truth over a coalesced frame.** Durable truth (the store rollup) is read event-fresh on every fold; the backend pane roster is coalesced behind a TTL cache and folded under it. They have separate clocks, so a status flip repaints now while pane discovery stays cheap.
- **Push over poll.** A change a writer knows about posts a typed wakeup; the loop folds it within one wakeup. The poll is the missed-wakeup backstop, never the primary channel.
- **A zero-fsync critical section.** The workspace flock covers truth mutation only; durability is a group fdatasync on an off-lock write tail. The contract lives in [store.md → Durable state](./store.md#durable-state); this doc bounds its hot-path cost.

## Where the milliseconds go

Four threads carry all the cost, and only one of them faces the human.

- **The render/input loop** does sub-millisecond, in-process work: advance the spinner from the cached snapshot, apply an input in place, append an overlay event and re-fuse, or fold a finished fetch. The fuse is pure — no IO, no subprocess, no clock read — and perf-guarded at fleet scale. A keystroke or a fused pane event paints off-grid on the spot; everything else coalesces to one paint per `[theme.display] refresh_ms` boundary.
- **The fetch worker** runs two speeds per cycle through one owned `FetchWorker`. The producer folds the event-fresh store rollup, pane frame, and workspace sidecars once and publishes the renderer-independent enrichment; consumers validate and adopt it, then apply only pane exclusion, own-view, and presence locally. A missing or mismatched publication falls back to the same full in-process fold — no mux roster read, no git — so truth keeps painting through producer failover. Only on the producer, and only when pane truth and its process-local monotonic attempt cadence are both due, does it pay the reconciling **produce** as the cycle's second post; that produce resolves panes, refreshes group roots, and projects the heavy caches rather than producing them inline.
- **The producer's cache refresher** ([`sidebar_pane::app::cache_refresh`](../../crates/rimz/src/sidebar_pane/app/cache_refresh.rs)) ticks on the data cadence and publishes the heavy refresh caches from the latest pane frame: fleet spending, provider accounts, usage/credits, auto-continue, Codex daemon ghost-reap inputs, and git diff-stats. The elder tab's fast lane no longer serializes behind those lanes; a cold heavy cache projects empty for a tick, then the refresher fills it.
- **The store critical section** is the write path's hot spot: one event-log `write()`, zero fsyncs, microseconds under the flock. Everything heavier — the group fdatasync, the snapshot publish, the wakeup fanout — runs after the lock releases.

The three end-to-end budgets the cost map rolls up into, each with its dominant term named so a regression is visible at review:

- **Keypress → pixel: one in-process paint.** Input applies synchronously and marks the frame dirty. Nothing on this path takes a lock, forks, or reads the store.
- **Pane event → pixel: one fuse plus one off-grid paint.** A typed overlay event (`PaneClosed`, `FocusChanged`, …) appends to the in-memory store, re-fuses the held frame, and paints immediately; the producer's verifying pull squares truth behind it ([state.md → Fusion Rules](./sidebar/state.md#fusion-rules)).
- **Write → pixel: bounded by the base frame bucket** (`[theme.display] refresh_ms`, 100ms default). Commit under the flock (µs) → wakeup datagram (µs) → consumer folds the published frame in process (O(1) cached, O(delta) on a race) → next dirty frame paints. The frame bucket dominates; everything upstream of it is orders of magnitude smaller.

`WORKTREE_ROW_CAP` is a renderer cap on the idle/process tail, not a hard snapshot row-count cap. Active, paused, blocked, finished, focused, and unread rows stay renderable past the cap so direct jump targets and unread convergence remain visible, and `+K more` can expand the calm tail. The O(rows) observer pass scales with the full snapshot roster, while the resting render and selection walks scale with the visible set; both remain bounded by the live pane count in the 20-100 agent target, and the fleet-scale compose/observer guards are the proof. If that bound becomes too loose, the cap-preserving upgrade is row virtualization in the renderer rather than hiding active/result rows from snapshots.

One steady-state cost is deliberately not broken out in the table yet: each sidebar supervisor polls the durable workspace record once per second to converge on a new build, so a room pays one record `stat()` per sidebar per second at rest. Executable hashing runs only after that record's metadata changes, and the embedded presence-wasm digest resolves lazily once, so the resting cost is the bare stat. The measured cost-table row is deferred to a later pass — the mechanism is in [Build promotion](./sidebar/sidebar.md#build-promotion).

## The tick budget

The sidebar meters producer ticks against the budgets declared in [`sidebar/meter.rs`](../../crates/rimz/src/sidebar/meter.rs). The wall bound covers in-process work (`wall_ms - mux_wait_ms`) for one configured data tick, while mux subprocess wait has its own 5s bound; byte and spawn bounds stay absolute because they track storm shape rather than cadence. The budgets mirror the cost map and move with it: a cost-map change revisits the tick budgets in the same PR. Sustained breaches write `tick_budget_breach` diagnostics ([diagnostics.md](./diagnostics.md)) with `last_mux_wait_ms`, `mux_wait_ms`, and `budget_mux_wait_ms`, and the first active record in an episode emits one `warn!` through the observability bridge. The meter observes only; producer work proceeds unchanged.

The harness launches no agents and spends no model tokens: it appends lifecycle events, publishes pane topology, folds snapshots, enriches cached sidecars, fuses overlay events, and renders fixed frames through the same public entry points the sidebar uses.

## The overhead, at fleet scale

RimZ is the layer that watches a fleet for one human, so its own footprint is sized against a single agent rather than the fleet: the cost of observing twenty or a hundred agents stays a small, near-flat fraction of running one of them, and that ratio is the performance target as much as the measurement. The deterministic rows below come from the counter gates and synthetic fleet benches; RAM and CPU use the manual recipe in [profiling.md](./profiling.md) because resident set and scheduler share depend on the host. The fleet shape is 20, 50, and 100 concurrent agents spread across a handful of rooms — two to five workspaces, each a repo or a directory of worktrees, which is how a developer's agents actually divide.

The cost attaches to three units, and only the cheapest grows with the agent count:

- **Per workspace, once; spending per namespace, once.** Each room elects its eldest renderer as the sole producer, which pays pane roster and process metrics on the fetch worker plus git/accounts on the cache refresher, then publishes caches the other tabs fold in process. Every workspace with the same persistent cache and provider-discovery environment requests spend from the same warm walker, so producer promotion and demotion add no parsed cursor copy or allocator high-water. Cell pets retain prepared terminal grids; only pixel pets retain decoded RGBA frames, and disabled pets retain neither.
- **Per worktree, activity-tiered or long-cadence.** The git diff-stats input set scales with distinct group roots, not agents; a root drops to the 60s idle TTL the moment its agents go quiet, and the whole sweep is capped at `MAX_PARALLEL_GIT` (8) fork chains. PR-state probes scale with origin repos, not worktrees: each due repo enumerates open PRs once, local branches match that open set, and only open-to-terminal transitions pay a targeted per-branch read. A hundred agents sharing a few checkouts pay a few hot roots; a hundred-worktree room pays the cap and the idle tier.
- **Per agent, cheap and event-driven.** An agent reports through a short-lived `rimz hooks feed` child that appends to the store only when something happens — a turn boundary, a blocking question, a tool — and exits. Nothing resident wraps a running agent: a blocking prompt records one waiting event and hands the ask back to the agent's own UI, so even a waiting agent holds no RimZ process.

Two costs stay flat in the agent count by design: durability is one group `fdatasync` per second per workspace however many agents append into it, and the snapshot publish is one debounced cache rename per second per workspace — both scale with rooms, not agents. The hot runtime caches — the published snapshot, heartbeats, diff-stats, process samples — land in `$XDG_RUNTIME_DIR` (tmpfs), so their churn is memory traffic, never disk IO.

Remote render-stream bytes sit outside the core network budget: SSH carries whatever visible full-screen TUIs repaint. Idle RimZ surfaces are near zero; busy agent TUIs and system monitors are commonly tens of KB/s, scaled by terminal size and visible high-churn panes. `rimz remote bandwidth` samples the room on the serving host and attributes that process write-rate per pane.

Set against the agents it tracks, the overhead reads as a rounding error, and the gap widens as the fleet grows. One developer's week of Claude and Codex sessions came to 1.23 GiB of transcript JSONL — ~177 MiB a day — with runtime processes resident at 250–340 MiB (Claude) and 50–65 MiB (Codex) each; RimZ watched the same fleet for tens of MiB of durable state total, a resident set on the order of a single one of those agent processes, a fsync a second per room, and one pricing refresh a week over the network. A release-day model missing from the price table can add a 30m, 1h, 2h, 4h, 8h, then 16h chase, then a 24h-capped chase until pricing lands; once the unknown set clears, pricing returns to the weekly baseline. The agents' transcript and process cost climbs with the agent count; RimZ's climbs only with the room and worktree count, so a denser fleet widens the ratio rather than narrowing it. The scaling terms the model flags first — git enrichment across many worktrees and transcript-discovery stat volume as fleet history grows — are producer-side and activity-gated, so they surface in fetch-worker latency long before they reach the human's frame.

## Principles

The rules every performance change here follows, ordered — an earlier rule outranks a later one when they conflict.

1. **The render thread never blocks.** No subprocess fork, no fsync, no synchronous pane roster read on the loop. Offload to the worker and wake the loop when it finishes; a single in-flight fetch is the unit of work, and the loop stays interactive while it runs.
2. **Decouple the frame from the fetch.** Responsiveness — the spinner advancing, the cursor holding, a click highlighting — is a redraw from the *cached* snapshot, not a data refresh. The render layer is a fixed-timestep loop on its own clock; the data layer arrives on a slower, event-driven cadence and folds in when ready. The two never share a clock: a smoothness change tightens the frame interval and costs only in-process paints, while a freshness change rides the data layer (principle 3). Never invert it — letting a frame drag a pane-roster+git fetch behind it spends a fork to move a spinner.
3. **Push over poll.** A change a writer knows about posts a wakeup; the loop folds it within one wakeup. Polling is the missed-wakeup backstop, never the primary channel. A datasource that feeds the UI but is not the store (a statusline or local transcript sidecar) gets a wakeup of its own rather than waiting for the next tick.
4. **Cache the disposable; fsync the durable.** Crash-durability is for truth alone — the event log and the cold-path records (the write-class contract in [store.md](./store.md#durable-state)). Everything derived — the rollup caches, the snapshot cache, diff-stats, the context sidecars — renames atomically *without* fsync (`write_temp_then_rename_cache`), because it rebuilds from truth on the next read. A torn read is impossible either way; only "survives a power cut" is traded, and for a rebuildable file that buys nothing while costing two fsyncs on a path the UI waits on.
5. **Single-flight, then coalesce.** One outstanding fetch at a time; a burst of deltas collapses to one fetch, and a delta racing an in-flight fetch defers exactly one follow-up, never a queue. The same lock+poll election ([`store::single_flight`](../../crates/rimz/src/store/single_flight.rs)) sits on every shared external read, so concurrent sidebars and rooms share one producer instead of stampeding.
6. **Pay the roster read once per window.** Pane discovery and the git probes are the snapshot's cost; bound them with a short TTL cache and reuse the last good result. A degraded read backfills missing fields per pane from the last good read rather than flashing a corrupt frame, and the renderer holds the last good frame rather than commit a regression ([sidebar.md → Presence model](./sidebar/sidebar.md#presence-model)).
7. **Cheapest correct read.** The snapshot catch-up is O(delta bytes) from the persisted fold base on the common path, O(active-events + items) at worst, never O(history); archives are touched only at rotation. Skip work that cannot matter — an idle room with no agents skips the sidecar directory scans entirely.
8. **One producer per workspace, one renderer per tab.** The external-read cost is per *production*, so production stays at one while every tab keeps its own renderer. The eldest live instance is elected producer and publishes the shared caches; every younger renderer reads them in process and never exits, so a per-tab pane never goes dark. This caps the mux server to one round-trip per workspace per tick — production, not renderer count, is what is bounded — and staleness recovery belongs to the election, never to the consumers (see [The election, assessed](#the-election-assessed)).

## What's optimized

The mechanisms in place, by the structure each creates — each described once, with its code home. The chronology lives in git; the lessons that prevent re-introduction are below in [Anti-patterns we removed](#anti-patterns-we-removed).

Build identity stamps read the linker-provided `.note.gnu.build-id` or Mach-O `LC_UUID` from the image prefix ([`build_id::of_file`](../../crates/rimz/src/build_id.rs)); the whole-binary SHA-256 remains only the fallback for images without a supported note.

### Decouple the frame from the fetch

The snapshot fetch runs on the background worker; the loop blocks only in `recv` and folds results via a `snapshot` wakeup ([`app::serve`](../../crates/rimz/src/sidebar_pane/app.rs), `spawn_fetch_worker`, `request_fetch`, `apply_fetch_outcome`). The animation tick redraws the spinner from the *cached* snapshot and never fetches, so a missed push degrades only to the backstop tick, not a per-frame poll storm. Animation cadence is classified ([`render::animation_cadence`](../../crates/rimz/src/sidebar_pane/render/mod.rs), `app::frame_interval`): fast work stays on the base grid, row animations redraw at `BREATH_ANIMATION_FRAME`, and a dirty data fold clamps back to the base budget so freshness never waits on cosmetic motion. Smaller cuts on the same hot path: the `NO_COLOR` lookup caches in a `OnceLock`, and pane `command`/`cwd` move out of the owned `PaneTopologyPane` instead of cloning per pane per tick.

### Animate only what a human watches

Each renderer carries its own pane id and the latest folded same-tab focus view, so the serve loop can tell whether an attached client is viewing the sidebar's tab. A watched tab keeps the normal animation grid; an unwatched or detached tab treats cosmetic motion as idle and wakes on the data/watchdog backstop. Off-screen non-producer consumers clamp identity-free store and topology work to `UNWATCHED_FOLD_CLAMP` (one second) and metrics-only pane publications to `UNWATCHED_METRICS_FOLD_CLAMP` (the three-second background sample cadence), while presence publications, the producer, and watched renderers stay immediate. Deferred requests merge the strongest freshness requirement and earliest deadline, so later topology or store work shortens a pending metrics window instead of waiting behind it; every immediate fold absorbs pending work. Focus onto the sidebar's own pane optimistically resumes the watched grid for a short window and flushes a deferred fold, so a tab switch onto a sidebar-focused tab animates without waiting for the produce round-trip. Dirty data folds still paint once, which keeps the off-screen buffer current for the next tab switch while spinner, pet, money-roll, scrollbar, and effect frames stop spending render CPU in panes no client sees. Unknown ownership or missing own-view state reads as watched, so demos, tests, and cold starts keep the responsive path.

Cell-pet loading prepares all 72 terminal grids off-thread and drops the decoded RGBA sheet before the renderer adopts them. A pet, tier, or size change and a cell-tier aspect change follow the same asynchronous reload path; pixel assets ignore cell aspect, and disabled pets release loaded and pending assets immediately.

### One producer per workspace

The eldest renderer is elected producer through one `ProducerElectionTracker` shared by every renderer thread and publishes the shared caches; younger renderers read them in process — never their own mux/git reads, never exiting. A cached consumer performs no filesystem work before its elder heartbeat expires, then validates that one heartbeat; a cached producer rescans on the heartbeat-write cadence so a resumed older instance demotes it. The producer itself runs the produce **in process** on its fetch worker ([`sidebar::produce::produce_snapshot`](../../crates/rimz/src/sidebar/produce/mod.rs)) rather than forking `rimz sidebar snapshot` per tick; it resolves panes and roots while projecting the cache refresher's heavy lanes. A monotonic attempt stamp owned by that long-lived worker makes normal production require both a cold/stale durable topology frame and no attempt within the data tick; the worker records before entering production, so failures and forced refreshes also bound the following ordinary attempt, while a newly promoted worker with no prior attempt can repair a due frame immediately. Durable pane timestamps keep their topology and observation meanings and remain the cross-process truth. The elder-gated cache refresher runs `refresh_producer_caches` on the same data cadence and owns the heavy cache writes through [`sidebar::refresh::refresh_heavy_lanes`](../../crates/rimz/src/sidebar/refresh/mod.rs). The CLI `snapshot` arm delegates to `produce_snapshot_with_refresh`: produce a pane frame once, fold the base, refresh heavy lanes, then fold the same frame with those lane values. The ordered enrichment spine splits into renderer-independent [`enrich_workspace`](../../crates/rimz/src/sidebar/enrich.rs) and renderer-local `project_local`; the producer publishes the workspace result as `workspace-projection.json`, while each renderer applies its own pane exclusion, own-view, and presence. Pane topology/metrics section stamps plus the exact rollup extent and config generation make adoption a live-truth verdict; legacy, corrupt, or stale files use the full fold. A `cargo xtask invariants` grep bans store-writer, run-wake, and broker imports under `crates/rimz/src/sidebar/`, so the in-process producer can never grow write-side machinery unnoticed.

Consumers shed idle folds with a source-sensitive input stamp ([`consumer::{consumer_projection_inputs_stamp, consumer_fold_inputs_stamp}`](../../crates/rimz/src/sidebar/consumer.rs)). A successful adoption records the slim five-input set; a fallback restores the conservative full set of rollup, published caches, runtime sidecars, message queue, filtered spending/budget/auto-continue inputs, and config generation. When the active stamp matches, the worker posts an unchanged outcome that clears single-flight state without replacing the snapshot or dirtying the frame. An ordinary non-producer request constructs the stamp and may skip. A dispatched non-producer pane-publication request must fold, but it also captures the pre-fold stamp and records it after success; hidden topology and metrics events reach that dispatch through their one- and three-second coalescing bounds, while presence remains immediate and cheap because it preserves the workspace-affecting section stamps. A racing input changes the next stamp and forces another fold, while the common unchanged request skips instead of reseeding. Producer cycles, force folds, producer-fresh requests, hard refreshes, and failed folds still invalidate the memo, and eager stamps stay off those mandatory paths. The producer groups admitted pane workspaces by agent kind, discovers normalized local sessions, probes adapter admission and launch defaults, and publishes both through one same-session `agent-projection.json`; consumers perform one parse and zero provider-config or provider-store I/O, unchanged producers pay exact metadata stamps only, and one semantic comparison permits at most one atomic write and wake. A 30s backstop forces a real fold even when the stamp is unchanged. The same path shares `Arc<MachineConfig>` values from a short-TTL config memo, so a stable room avoids both config-directory restats and deep config clones on every consumer tick.

### Event-fresh truth over a coalesced frame

The published `snapshot.json` carries typed pane topology, metrics, and presence values; every atomic write broadcasts `PaneFramePublished` with the input kind that changed. Legacy unit publications decode as topology, so a mixed-build room keeps the conservative bound. The rollup is read event-fresh from `latest.json` on every dispatched fold and folded over the coalesced panes ([`consumer::{read_published_snapshot, rollup_snapshot}`](../../crates/rimz/src/sidebar/consumer.rs)). A status change or a new agent in an existing pane repaints within one wakeup, while pane discovery stays coalesced for genuine open/close. Every change a writer knows about pushes a wakeup so it skips the poll window: store and sidecar writers post a `StoreDelta`; accepted Zellij topology snapshots are host-diffed into typed pane overlays (`PaneOpened`, `CommandChanged`, `PaneClosed`, `FocusChanged`), while the tmux control-mode subscriber emits the same taxonomy directly; the elder's transcript watcher covers Codex's mid-turn gap ([state.md → Push Channels](./sidebar/state.md#push-channels)). Both backends write the presence stamp while their push channel is live, so the producer stretches its pane TTL; Zellij uses plugin topology for roster and client view plus a pipe nudge for structural repair reads, while tmux keeps its cheap poll as roster truth ([Zellij presence channel](./multiplexers.md#zellij-presence-channel), [tmux presence fast path](./multiplexers.md#tmux-presence-fast-path)). A published frame with no viewed panes uses the same stretched TTL while the session is detached or fully backgrounded; attach/focus returns the next produced frame to the responsive cadence. Agent birth/death that must beat the cache carries a producer-only pane-freshness floor (`min_pane_cache_ms`) so the producer pulls fresh, publishes, and broadcasts a topology publication for consumers to refold; topology freshness floors stay reserved for explicit structural repair after a local mux mutation.

### Incremental everything

No reader pays O(history) for store truth. The rollup persists a raw fold base plus its `(generation, offset)` stamp; catch-up seeks to the offset and folds only new frames ([`snapshot::{RollupCache, catch_up_rollup}`](../../crates/rimz/src/store/snapshot/fold.rs)). Runtime projection, terminal resume-message outcomes, and smart-compact dedupe ride the same fold, so doctor/resume and auto-continue read rollup state instead of rescanning `events.log.jsonl`. `message --wait` captures a frame-aligned offset under the workspace lock before enqueue/send, polls only appended frames through delivery, then reads the cached snapshot and newly appended transcript bytes on a 500 ms reply tick. A long-lived `RollupCursor` per fetch worker holds the parsed base in memory, so a warm fold is one stat plus the appended frames; a `(path, mtime, len)` parse cache on `snapshot.json`, `latest.json`, and `rollup.json` returns `Arc<T>` handles so unchanged files skip both JSON re-parse and cache-hit deep clone ([`store::parse_cache`](../../crates/rimz/src/store/parse_cache.rs)). The fleet spend walk is incremental in three layers: the walker-owned directory index stats only active frontiers on ordinary due passes and performs a complete authoritative reconciliation every 15 minutes; the disk cache stores `(mtime, len, cursor)` per returned file so a grown file parses only its appended suffix and only a truncated or rewritten file re-parses cold; and the elected user-global `SpendingWalker` holds the sole parsed cache plus a generation/file-signature-keyed boxed slice of dedup winner locations. Serialized workspace requests borrow entries, origins, and native session identities from that cache, so the memo does not clone history. Cold changed files parse through a bounded worker pool, the service thread publishes partial aggregates on `WALK_CHECKPOINT_INTERVAL` and checkpoints the cursor cache only when the persist gate opens, and new files older than the widest spend window plus skew margin are skipped without writing cache records. Dead file records past that boundary retire from discovery and aggregation; their durable cursor entries can rebuild the same frontier after a complete scan without becoming a second truth source. Unchanged walks still run one in-memory arithmetic pass over the retained deduped set so rolling spend windows and session headlines stay exact for the current time. Compaction folds finalized rows older than 8 days into per-day rollups inside the same entry stream; dirty-gated writes skip the shared `spending.json` rewrite when a pass observes no file change or sits inside the warm min interval. The producer's Git state applies the same process-local rule to stable untracked contents: porcelain still enumerates every path and memo hits consume the same logical 8 MiB prefix, but only stamp misses read bytes. Allocation cuts ride along: `reap_stale_sessions` marks superseded sessions with a parallel `Vec<bool>` instead of a `BTreeSet` of cloned tuples, and `reduce_agent_states` deserializes lifecycle fields straight from the borrowed `&Value`.

### Per-enrichment cadences

Every display figure is display-only by invariant ([DESIGN.md → Triage at a glance](../../DESIGN.md#triage-at-a-glance)), so each enrichment gets its own natural cadence behind process-safe stamps in the cache file it already writes; account probes carry one stamp per provider so a failure retries alone, and due providers occupy four bounded workers rather than one additive subprocess chain. The fleet spend walk gates the whole walk on `SPENDING_TTL` ([`agents::spending::engine`](../../crates/rimz/src/agents/spending/engine.rs)); one versioned service per persistent/discovery namespace keeps the walker warm, while sidebar code supplies workspace inputs, consumes durable publications on service failure, and held stats shares the same owner. An invariant keeps the agents domain independent from sidebar code. Process sampling rides per-pane hot/idle stamps decoupled from the pane-read clock ([`produce::metrics`](../../crates/rimz/src/sidebar/produce/metrics.rs)); the git probes use activity-tiered TTLs whose hotness comes from store agent activity, not filesystem watching, in-process `.git` ref reads skip ancestry forks and carry ahead/behind, did_work, and landed facts forward when the cached HEAD/trunk pair and clean verdict are unchanged, and the due worktree sweep runs through a saturating pool bounded by `MAX_PARALLEL_GIT` ([`refresh::git_stats`](../../crates/rimz/src/sidebar/refresh/git_stats.rs)); PR-state probes enumerate open PRs once per due repo, use `PR_STATE_HOT_TTL` for hot/focused repos and `PR_STATE_TTL` for idle repos, bypass the TTL when cached HEAD changes, cap failure backoff at that repo tier, pin cached `merged` states, and pay targeted per-branch reads only for open-to-terminal transitions; and `git worktree list` rides its own `WORKTREE_ROOTS_TTL`. The live producer's cache refresher drives service spend requests plus accounts/git/PR state on the data tick and lets each lane self-gate on its own TTL. Stamps live in cache files, so every process agrees on freshness across failover. The focused spending, service, and ownership-invariant tests pin the idle, warm, fallback, and projection cases.

### The zero-fsync write path

The critical section covers durable truth only — one event-log `write()` — and the flock hold drops to microseconds; the off-lock write tail issues a group fdatasync debounced to ≤1/s, so one writer per interval makes the whole fleet's appends durable. Length-plus-CRC32 framing makes a lost suffix deterministic corruption that the next write tail self-heals. The snapshot publish runs after the lock releases, single-flighted and debounced to ≤1/s or 64 KiB of unpublished tail, and rollup reads are lock-free. The full contract — write classes, recovery, the CI grep that funnels every fsync through `store/atomic.rs`, and the perf tier that pins exact syscall counts — lives in [store.md → Durable state](./store.md#durable-state). The mux seam took the same fork-shedding treatment: an event-driven wait replaces the per-command poll tax ([`mux::command::CommandSpec::run_bounded`](../../crates/rimz/src/mux/command.rs)), tmux room birth batches its option sets into one client invocation, and version probes memoize.

### Keep helper processes cheap

Short-lived `rimz` helper processes reuse a cached build id instead of hashing the running executable on every spawn ([`build_id`](../../crates/rimz/src/build_id.rs)); the cache is keyed by executable path, mtime, and length, and a miss still computes the same SHA-256 prefix written into runtime artifacts. Self-spawns resolve through one helper that honors `RIMZ_BIN`, repairs Linux `current_exe()` paths ending in ` (deleted)` after an atomic reinstall, and falls back to PATH, so long-lived sidebars keep launching helpers across dogfooding rebuilds. The Zellij presence plugin hashes raw stable manifest fields before it allocates projected pane fields, so title-only `PaneUpdate` storms skip projection, canonical reduction, focus classification, topology serialization, and pokes ([`policy::raw_stable_hash`](../../crates/rimz-presence-zellij/src/policy.rs)). Foreground-command events patch the canonical room and publish through the normal 100ms-floored changed-snapshot path.

Zellij rooms start and attach with `disable_session_metadata true`, so the server's session-info sidecar stops rewriting `session-metadata.kdl` and running command-discovery `ps` on the room's behalf. That is a room option rather than a renderer optimization, but it removes server work that otherwise scales with pane count and host process-table size.

### Warm context, no cold spawns

Codex enrichment skips the cold-spawn handshake: a per-session broker holds one warm, already-handshaked `codex app-server` and serves it over a unix socket ([codex.md → Context and transcript](./agents/codex.md#context-and-transcript)). It runs as a pane in the `rimzd` daemon tab, respawns a dead child once, and always leaves a cold-spawn fallback, so enrichment never depends on it. The `rimzd` tab — sidebar plus a configurable content column that defaults to supervised `rimz stats --refresh --hold`, with daemon hosts when present — is born in every room; each room pays one lightweight poll-supervisor process for that content column, not one per agent. The elder's transcript watcher closes Codex's mid-turn freshness gap — it holds a filesystem watch on each live root Codex rollout JSONL and runs the existing stat-gated refresh on the write, debounced to one flush per 300ms per session, posting the same `StoreDelta` the hook path does ([state.md → Push Channels](./sidebar/state.md#push-channels)). Both are latency hints over the unconditional producer tick: a watcher that never starts costs nothing.

### Anti-patterns we removed

The mistakes worth not re-introducing, because each looked reasonable:

- **`ACTIVE_REFRESH`** refetched every 500ms purely to keep a spinning agent's `$`/tokens current — a subprocess fork per frame to move a spinner, and on Zellij its periodic pane roster read even reset unrelated panes' cursor blink. The cost it bought is now covered by context-sidecar pushes (principle 3).
- **The consumer self-heal** let every consumer produce on producer staleness; the single-flight loser wait (~200ms) sat under the old Zellij pane-roster floor, so every loser timed out into its own uncached produce — an N-way fork storm on exactly the tick the room was already degraded. Recovery now belongs to the election alone.
- **Per-tab pane-roster reads** pinned the mux server with N× round-trips; the first fix over-corrected to a per-workspace renderer-exit election, which blacked out every tab but one. The standing answer is one producer, N renderers — production capped, renderers not.
- **A consumerless `zellij pipe`** was spawned per store write per Zellij session with no consumer; it is dropped.
- **Per-producer spending walkers** duplicated the account-global parsed cursor and allocator high-water in every promoted workspace and retained it after demotion; the elected persistent/discovery-namespace service holds one warm walker, while durable publications and the direct one-shot fallback preserve recovery.
- **Serde fragments streamed directly into spending-service sockets** turned each JSON token into a Unix-socket syscall; framed IPC writes now pass through one fixed-capacity buffer.
- **Per-spawn build-id hashing** streamed the full `rimz` binary through SHA-256 in every short-lived wake and hook helper, even though the build identity was identical across those processes.
- **Unconditional Zellij manifest projection** cloned and merged the full room on every `PaneUpdate`, including title-only updates agents emit per output line; the plugin now hashes stable raw fields first and only pays the full pipeline on real roster changes.
- **Per-second consumer refolds** reloaded config, cloned published JSON, enriched, and rendered once per renderer even while every input file was unchanged; consumers now stamp the exact read set and skip to a lightweight unchanged outcome until an input or the 30s backstop requires a real fold.
- **Runtime-root catch-all invalidation and eager mandatory stamps** let unrelated temp/rename cache traffic invalidate every consumer and walked the full metadata set even for requests whose explicit freshness demand could not skip. The stamp now scans only filtered dynamic spending, budget, and auto-continue inputs and stays off producer, force-fold, producer-fresh, and hard-refresh paths; pane publication is the narrow exception because its mandatory successful fold seeds the next ordinary skip.
- **Per-worktree scans of a provider-global session store** made every Codex workspace in the pane set enumerate and sort the same `~/.codex/sessions` and archive trees during one fold; local-session discovery now batches exact workspace paths per agent kind, so Codex pays that shared traversal once and workspace-partitioned adapters keep their natural bucket reads.
- **Per-thread full heartbeat scans** made fetch, cache refresh, tmux watch, transcript watch, and diagnostics each open and decode every renderer heartbeat; every renderer now shares one tracker that returns a warm elder without IO, validates one heartbeat at expiry, and bounds producer rescans to the heartbeat-write cadence.
- **Repeated unchanged tmux presence probes** let event-driven fetches issue several `list-clients` calls inside one second because an unchanged sample never advanced the published frame timestamp; the separate probe-attempt stamp throttles both success and failure without republishing `snapshot.json` or waking every consumer.
- **Zellij session-metadata churn** kept a disabled-resurrection room writing metadata and running command discovery anyway; RimZ now passes the separate `disable_session_metadata` room option so serialization and metadata both follow the clean-rebirth contract.
- **Unwatched delta refold storms** let identity-free store wakeups refold every renderer in every tab at the writer's event rate; unwatched non-producer renderers now coalesce those nudges behind `UNWATCHED_FOLD_CLAMP`, while watched panes and the producer remain immediate. Any fold that fires immediately — including presence publication, watchdog, and backstop folds — absorbs the deferred nudge, so a hidden tab folds once instead of leaving a deferred echo.
- **Unit pane-frame publications** made topology, metrics, and presence writes indistinguishable, so each background metrics sample forced every hidden renderer through the full fold. Publications now carry their typed intent: hidden topology folds within one second, hidden metrics within the three-second sample window, and presence remains immediate; earliest-deadline merging keeps store/topology work from waiting behind metrics.
- **Consumer checkout rediscovery** statted every group path and reopened `.git` plus `rimz-worktree.json` independently for diff and PR projection. The producer now publishes exact root→marker-name classifications with its worktree-root cache, both projections share the already-read diff cache, and a name mismatch stays a plain channel without checkout IO.
- **Accepted-fetch snapshot churn and repeated wiring reads** cloned full snapshots while every producer and consumer fold reopened provider hook/model files. The commit path transfers the accepted snapshot into `current`; the elected producer now probes wiring once behind exact input stamps and publishes the normalized projection for zero-config-I/O consumer folds.
- **Unconditional pulled-baseline cloning** retained a full raw snapshot and deep-cloned it into every accepted presentation frame even with no active overlay or focus fence. Overlay-free pulls now move directly into presentation, focus resolution and observer comparisons retain compact facts, and a full baseline exists only while realtime fusion or a rare gate hold can outlive its source; `fuse_owned_no_overlay` pins the allocation boundary.
- **Warm spending path rematerialization** recursively collected, sorted, and deduplicated the same active provider paths for every service request after directory discovery was already warm. The discovery index now caches the ordered vector behind separate frontier and cache-reconciliation generations, so changed directories and retired files invalidate it while unchanged workspace requests reuse it.
- **Per-fold read-mark reopening** opened every renderer receipt file on each enrichment and notification fold even when the receipt directory was unchanged. The merged receipt parse now keys off the atomically published generation inode plus the directory stamp and returns a shared value until a renderer or manual writer publishes a new receipt.
- **Redundant provider transcript reads** sent Kiro history through a spend walker that could produce no rows, reparsed changed Kimi/Grok/Droid sessions for live cost, and extracted terminal assistant text once per sink. Kiro now stays out of spend discovery, each changed live session reuses one provider-owned typed parse for context and cost, lifecycle orchestration shares one terminal extraction, and bounded tail-first readers retain full correctness fallbacks.
- **Binding-log write amplification** appended the same lazy-pairing ambiguity on every producer fold for resumed panes with unknown process-start timestamps; the producer now keeps a process-local signature per workspace and agent, so `binding.log.jsonl` records the first distinct ambiguity and every genuine change, not each fold.
- **Cold-produce git fork storm.** A cold producer snapshot forked `git` per group root end to end (≈2400 `execve` attempts / 240 execs on a 20-worktree fixture) because every root re-derived its merge-base; in-process `.git` ref reads now reuse the cached HEAD/trunk merge-base and skip the ancestry forks when the pair is unchanged, and the `sidebar_diff_stats` perf guard plus the git-trace shim pin the fork count.
- **Forge PR-probe retry loop that wiped last-known-good.** A deterministic `gh`/`tea` list failure retried on the hot TTL with no command deadline and erased the cached open-PR map on each failure, so a forge outage became a permanent per-worktree fork/network loop; the probe now backs off on consecutive failures while retaining the last-known-good map, bounds each call, and pins terminal `merged` states — `merged_worktrees_are_pinned_not_reprobed` guards the terminal case.
- **Delegated account-usage identity retry loop.** A Pi no-credentials probe could complete under the kind-wide default after account preflight requested an exact sub-provider scope, so the next producer fold read the scope mismatch as a new login and spawned another helper despite the settled-auth TTL. Settled no-credentials completions now inherit unresolved scope, owner, and credential-stamp fields from the claimed preflight identity, and `no_credentials_completion_adopts_preflight_scope_and_settles_cadence` pins the next fold to the long retry cadence.
- **Deleted-inode processes after reinstall.** An atomic reinstall left long-lived renderers resolving `current_exe()` to `rimz (deleted)` — self-spawn helpers failed `execve`, and sidebar supervisor parents held the deleted binary inode until session end while orphaning stray children as long-lived zombies; the shared `rimz_exe` resolver repairs the ` (deleted)` suffix for helper self-spawns, and supervisor-owned reload convergence with stable sidebar instance ids re-execs the parents off the deleted inode onto the new binary — now driven by each supervisor's once-per-second workspace-record poll and sequenced worker-first — while supervisor-side stray-child reaping clears the orphans.
- **Per-fold lifecycle warnings on the Sentry path.** A deterministic projection outcome warned once per fold per renderer, and `attach_stacktrace` made every consumer pay backtrace capture and symbolization before the `before_send` limiter could drop the event — ~200 MiB and 0.78 s per fold versus ~18 MiB clean. Projection diagnostics stay at debug level, and an xtask invariant keeps `warn!` and `error!` out of production `store/snapshot` code.
- **Consumer workspace-spending derivation from the global cursor.** A missing workspace sidecar made every renderer parse and aggregate the account-global `spending.json`, while the producer retained a second deep-cloned winner set. Consumers now read published provider/workspace aggregates only, and the producer memo keeps compact cache locations.
- **Per-tick provider-local discovery.** Every producer tick still enumerated provider stores and reparsed bounded candidates after publication ownership removed the per-renderer duplication. Provider-owned typed snapshots now stat known topology and candidate dependencies, reparse only changed candidates, and force one bounded reconciliation every 30 seconds; Antigravity also folds its global store once for the whole workspace batch.
- **Authoritative daemon repair on every maintenance cadence.** A healthy room rebuilt the desired view, ran Claude preflight, and listed backend panes every 30 seconds. Stable input stamps plus a fresh reconciled frame now spawn zero children; only changed inputs or unhealthy/stale frame evidence enter preflight or authoritative repair.

## Bottlenecks and deferred work

Real wins identified but not taken, because each changes a contract or crosses a backend-parity boundary and deserves its own change with tests. Ranked by expected payoff.

1. **Zellij topology freshness depends on the presence plugin.** RimZ removed the slow JSON pane-list path from product runtime; if the plugin is missing, denied, or wedged, Zellij rooms hold the last good frame and `rimz doctor` names the failing precondition. The cheap recovery path is a plugin pipe nudge plus bounded cache wait; deeper watchdog behavior belongs in the presence channel rather than a CLI fallback.
2. **Zellij compact-bar and scrollback footprint.** A 100-pane room carries one compact-bar wasm instance per tab and large server-side scrollback RSS. RimZ can recommend configuration and avoid adding pressure, but those resident costs belong to Zellij's plugin and scrollback model.
3. **tmux `list-panes` over the held control client.** The elder's `tmux -C` control client already writes its stdin (the `refresh-client -B` subscription) and parses reply blocks, so issuing `list-panes` over the same client and reading its wrapped reply is a small extension that would eliminate the producer's per-window fork+connect. The saving is ~10–30ms on tmux — already the cheap backend — and the poll must still back a dead watcher. Revisit if tmux pane reads surface in producer-tick latency.
4. **Delta-bearing wakeup datagrams.** The `StoreDelta` event could carry the appended frames themselves, so a warm consumer folds straight from the datagram with zero file IO. With the warm cursor fold already one stat plus a page-cache-hot read, the residual win is microseconds; the cost is a second delivery path for state that must never *become* truth (datagrams are lossy and unordered). Build only when sustained fleet rates reach hundreds of events per second.
5. **Pricing-cache pruning.** Pruning `pricing-cache.json` to models the fleet has actually used would shrink the stale-arm parse, but with the spend walk now shared and gated it is below the noise floor.
6. **A faster workspace-projection codec.** The current JSON projection stays inspectable and mixed-build tolerant, while the changed-file and parse-cached adoption benches pin its materialization cost. If a live consumer profile makes projection parsing dominant, replace only this disposable file's serde codec with postcard behind the same source identity, atomic publication, and fallback mechanics.

Evaluated and **rejected** — recorded so the next pass does not re-litigate them:

- **Lock-free `O_APPEND` event appends.** The recovery model assumes the flock makes the log single-writer-at-a-time, so only the trailing frame can tear; concurrent appenders' independent dirty pages can write back out of order, leaving a zeroed *middle* frame, which rebuild correctly treats as a hard error. Making it safe needs per-frame magic for resync — the CRC validates a frame but cannot relocate the next boundary past a torn middle — all to shave a lock tail that is now a queue of microsecond holds. See [store.md](./store.md#durable-state).
- **Binary snapshot format.** The parse cache already removes the re-parse on delta storms, the `RollupCursor` holds the parsed base in memory, and JSON keeps `rimz sidebar snapshot --json` inspectable. A binary checkpoint would accelerate a parse that no longer happens.
- **Caching the wakeup heartbeat scan.** N is live sidebars, the reads are page-cache-hot, and the fanout already runs after the lock releases, below the write's fsync floor. A cache would have to live cross-process and re-validate exactly what the TTL + re-stat already validate.
- **A resident writer daemon behind the per-event `rimz hooks feed` spawn.** The agent's own hook contract spawns a process per event regardless, so a daemon removes only the rimz-binary startup: a page-cache-hot exec plus workspace resolve, store open, and a µs-scale append — single-digit milliseconds of CPU each, ~0.1–0.3 core at 30 chatty agents (~20–30 spawns/s) and under a core at 100, off every human-facing budget. The spawned child carries two contracts a daemon would have to re-earn: its synchronous direct append is what lands truth under the agent's hook-execution guarantee, and its stdout is the decision channel, so a daemon path needs an ack protocol, a request/response surface, and a direct-append fallback for a dead daemon — a fallback that is the current design. The transport seam already exists as the one command string in the agent's hook config; no code-level abstraction is needed to keep it swappable. Revisit only on measured hook-spawn CPU in [profiling.md](./profiling.md) captures at fleet scale, or sustained per-workspace event rates in the hundreds per second — the same threshold as delta-bearing wakeup datagrams above; the first response then is shaving the feed child's startup, ahead of any resident process.

## Maintaining performance

### Adding a performance change

1. Name the thread the cost lands on. If it is the render/input loop, the change is wrong until the work moves off it.
2. Prefer a push (a wakeup the writer already posts) over shortening a poll interval. A tighter poll burns cycles in the idle case; a wakeup costs nothing until something changes.
3. Decide durability explicitly: durable state fsyncs, a next-tick-rebuilt cache does not. Do not reach for `write_temp_then_rename` on a disposable file.
4. Keep single-flight: a new fetch trigger routes through `request_fetch`, never a bare spawn, so it coalesces with the rest.
5. Measure the idle case too — an optimization that speeds the busy path by adding idle work is usually a loss; the fleet is idle most of the time.
6. The gate is the proof. `cargo xtask ci` stays green, including the invariant that the sidebar render path imports no durable store-writer module and forks no `pane capture`/`send`; `cargo xtask perf` refreshes wall-clock and allocation figures when the change moves a measured path.

### Optimizing perceived response time

Responsiveness is what the user feels, not what the profiler measures: a frame that paints now with slightly-stale data beats a fresh frame that arrives late. The UI/UX levers, in the order to reach for them.

1. **Acknowledge before you finish — except where one source of truth is worth the wait.** Where the local intent *is* the truth, redraw it the instant the input lands: a browse pick and the help overlay paint synchronously in `app::apply_input`. The jump is the deliberate counter-example — it fires the focus command on a detached thread (`app::spawn_pane_focus`), changes no local state, and lets the **derived** selection catch up on the next fold, so a stale frame can never roll the highlight back. Reach for the optimistic redraw before making an action faster; reach for the derived-only model when the echo would need its own protocol to stay honest.
2. **Animate on wall-clock, never on I/O.** The spinner and cursor advance from `wall_clock_phase` on a fixed interval, independent of whether a fetch is in flight. Motion that stalls when data is slow reads as hung even when nothing is wrong; a steady tick from cache reads as alive. Drive any future animation off the same monotonic base so a refetch or delta can never reset its phase.
3. **Tune smoothness and freshness on separate dials.** A smoother UI shortens the frame interval — cheap, in-process paints (principle 2). Fresher data adds a push, not a tighter poll (principle 3). Conflating the two is how a cosmetic tweak becomes a CPU regression — the `ACTIVE_REFRESH` mistake. If a "make it feel snappier" request lands, ask first whether it is a frame-rate problem or a data-latency problem; they are fixed in different layers.
4. **Keep session-wide effects off the frame path.** A redraw writes only to the sidebar's own pane and is safe at any rate. A mux *action* — a roster read, a `pipe` broadcast — touches the whole session and can reset an unrelated pane's cursor blink, so it belongs on the slow, event-driven data layer, never on the animation tick.

### The election, assessed

Is the eldest-UUIDv7 + flock + staleness design robust enough? **Yes — the flock is the real election; the eldest rule is a "don't even try" optimization; the TTL carries liveness.**

- **The flock is the actual election.** Correctness never depends on who believes it is the elder: every shared external read single-flights through [`store::single_flight::coalesce`](../../crates/rimz/src/store/single_flight.rs), so two renderers that both produce still collapse to one pane-roster read per TTL window. The system is safe with zero, one, or many self-declared producers.
- **The eldest rule is the efficiency layer.** UUIDv7 ids sort by birth, so the shared `ProducerElectionTracker` lets every younger renderer skip production before ever contending the lock — N tabs become one producer plus N−1 in-process cache reads. Cached consumers validate one elder at heartbeat expiry, and cached producers rescan on the heartbeat-write cadence; the tracker remains only an optimization because a wrong pick is bounded by the flock and healed by the TTL.
- **Takeover latency, as the user perceives it.** On a producer death the next-eldest's scan flips within one heartbeat TTL and it produces on its next cycle — fresh panes in well under ten seconds, while **status flows the entire time** through the rollup fast lane, which needs no producer. A window open/close lagging a few seconds during a rare producer crash sits comfortably inside principle 1's staleness tolerance.
