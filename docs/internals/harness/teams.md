# Team memory and stages

> How a team's shared files work: the archived board and stage notes, the `.rimz/team/blackboard.md` stage board, and `rimz teams flip`. The code is [`harness/scratch.rs`](../../../crates/rimz/src/harness/scratch.rs) (the scan and the board parser) and [`harness/team_stage.rs`](../../../crates/rimz/src/harness/team_stage.rs) (flips and re-wakes). Launching a team is [fleet.md](./fleet.md); the `team.stage` signal and the stage-owner message are [loops.md § Team signals](./loops.md#team-signals). Users read the [teams guide](../../guide/teams.md) and [cli/teams.md](../../reference/cli/teams.md).

A team cooperates through files in its checkout. The members write the content; RimZ finds the files, reads the board's current stage, and performs the one board edit it owns, the stage flip. Neither the board nor member status is lifecycle authority: stages are advisory progress for the agents and the reports.

## Scratch files

A staged team (nonempty `stages` or any role's `owns`) keeps its board and notes through the checkout's `.rimz/team` symlink into `team-notes/<run>/` in room state. Registration at fresh launch, cohort resume, and place-first restore takes the canonical checkout's board lock before resolving or replacing the link. Resume reuses a working link only when `run.json` names the same team; otherwise it restores the newest run by `created_at` whose manifest names this team and canonical checkout. Fresh never searches unlinked archives: it reuses only a same-team linked run whose board is not at `Done`. A missing, unreadable, or invalid manifest is not a match. Otherwise registration creates a dated run with a once-written `run.json`, then atomically publishes its canonical absolute target. Team and checkout name components are sanitized and bounded to 80 characters each, leaving room for collision suffixes. Replacing a link never changes the old run. A real file or directory at the team link, or a checkout whose `.rimz` is itself a symlink or the RimZ home, refuses with the path and fix. A home nested below `.rimz` is allowed. Seed a symlinked `.rimz` through `.worktreeinclude` instead of `.worktreelink`, or replace it with a directory. Failures creating the directory, manifest, or link refuse that launch or restore tab. No existing root board is migrated.

`Team::scratch_patterns()` returns declared extra Git excludes only, empty when unset. Registration adds `/.rimz/team` for staged teams, plus the subdirectory link's root-relative pattern when needed, and passes the extras to the best-effort exclude publisher ([worktrees.md § Team scratch patterns](./worktrees.md#team-scratch-patterns)). `scratch::memory_patterns` independently supplies `.rimz/team/blackboard.md` and `.rimz/team/*-notes.md` for staged teams only. Extra excludes and `run.json` are never listed as memory. Archive retention and reset are owned by the [store catalog](../store.md#what-is-on-disk).

`scratch::scan(root, patterns)` resolves the patterns against the checkout root for three consumers, the member launch reminder, the [prompt-submit Environment block](./fleet.md#environment-at-prompt-submit), and `rimz teams show`, so all see the same files. It strips a leading `/` before rooting each glob, matches files only, and returns absolute paths sorted and deduplicated across patterns. Each file carries its line count (zero when unreadable) and its modification time when metadata allows. An invalid glob or a failed traversal sets `probe_failed` instead of failing the scan.

The reminder, or the prompt-submit block on a launch that gets its listing there, ends its Environment section with a code block showing `$ ls .rimz/team/blackboard.md .rimz/team/*-notes.md`, then the matching paths relative to the checkout, or `(no such files)`. It omits line counts and omits the block for unstaged teams. A failed probe adds the factual line that RimZ could not inspect every pattern. `teams show` scans again on every call and reports line counts and modification ages; its human output shows paths relative to the worktree, and its JSON keeps them absolute.

## The board and its stage

`scratch::board_stage` reads the first line starting `Stage:` in `<worktree>/.rimz/team/blackboard.md`, independently of declared extra excludes. Only a terminal ` (@owner)` suffix splits off as the owner, stored without `@`; other parenthesized text stays in the stage name, so `Stage: Implement (delta) (@coder)` is stage `Implement (delta)` owned by `coder`. A missing or unreadable board has no stage. `scratch::board_section` reads the trimmed text under a `## <heading>` line up to the next ATX heading outside a fenced code block, `None` when absent or blank.

`teams show` combines the team's declared `stages` (its `pipeline` line, with the implicit `Done` last) with the board's current stage. The stage's age is the `at` of the newest `team.stage` event from `stage_flips` whose instance is the cohort and whose destination is the board's stage; a hand-edited board or a flip rotated out of the active event log leaves the age unknown, and the stage shows without one. Each armed signal subscription's fire state is the newest loop run-log record for its task name. Its PR and CI line comes from the published sidebar projection (the snapshot's `worktree_groups`), with no forge call of its own, so an absent PR line is not proof that no PR exists.

`crates/rimz/src/cli/teams/list.rs::CohortState::for_cohort` maps the published group's shared unit headline, matched by cohort member row identity, to `blocked`, `paused`, `working`, `sleeping`, `idle`, or `done`; rowless cohorts use `UnitStatus::from_members` without a pipeline. Only a Success headline backed by a board at `Done` maps to `done`; other Success headlines map to `idle`, even though the cockpit and tab suffixes can show the turn verdict's ✓. Member `needs_you` details remain diagnostic, not a second state override. Team reports and wait progress share this board-completion rule, matching the board read that settles `teams wait`.

`rimz teams wait` is the third reader. It resolves each cohort once through the drive verbs' selector, then polls `board_stage` at the members' shared worktree every 500 ms: an exact `Done` settles completed and reads the `Result` section; any other stage, or no board, reads the published snapshot for progress and liveness, and when the cohort is gone from `address::team_cohorts` reads the board once more, settling completed on `Done` and failed otherwise, so a flip that races the members' exit is never reported as a failure. It never scans the event log or subscribes to `team.stage`, since signals do not replay and a blocking CLI cannot receive one.

## Team reports

An agent-launched team reports its leader to the launcher once per `Done`, with one `TEAM_REPORT` from `@rimz` (`HarnessNotice::TeamReport`). The report rides a team run: a `RunRecord` carrying `RunRecord.team` (the leader's `launch_id` and the `<team>#<channel>` instance), owned by [`harness/run/team.rs`](../../../crates/rimz/src/harness/run/team.rs). Interactive launch opens it for the prompted leader when the caller is an agent, the prompt is nonempty, and the leader's adapter has native root turn hooks; a user launch, a promptless launch, and a resume open none. The lifecycle hook routes the leader's observations to it by launch id, and `fold_team_lifecycle` keeps the leader's newest final message at each turn end, follows the leader onto a new conversation row, and never settles the run.

The flip settles it. After `team_stage::flip` returns, `rimz teams flip` calls `crates/rimz/src/cli/agents_cmd/team_report.rs::on_flip`. A flip into `Done` from any other stage publishes the leader's message to `<leader>.<run_id>.output`, queues the report to the launcher's current row with gate `Done`, then marks the run completed with the report's message id; queueing first means a crash between the two re-reports at the next `Done` rather than losing this one. The board lock serializes flips, so only one flip sees the transition into `Done`. A flip out of `Done` opens a fresh team run carrying the previous run's task and leader, so the next `Done` reports again. Stop, restart, and rebirth settle the run without a report. When a cohort otherwise ends (no live members remain, or every member's recorded process is dead), the sidebar's digest backstop or the launcher's parked wrapper settles it: completed if the board reads `Done`, otherwise failed with `cohort ended before Done` and reported once as a failure `TEAM_REPORT`. Both reporters queue before the terminal CAS; a loser cancels its own message. A hand-edited `Done` with a live cohort still reports nothing. A resume opens no run, so after death settlement its next `Done` reports nothing. An ended launcher settles at a Done flip with no report. Team seats open no per-turn peer runs, so launcher messages to them report nothing.

A team launched with `--detach` carries `report_to: nobody` on its team run, and the run splits by purpose. Settlement still selects it: `on_flip` and the dead-cohort backstop publish the leader's response and mark it completed or failed exactly as an attached run, but queue no message and store no `report_message_id`, and return `TeamReportOutcome::Detached` so the flip receipt says the team was launched detached. `reopen_team_run` copies the policy from the cohort's newest run, so the stretch after a flip out of `Done` stays detached. Debt does not select it: `fleet::owed_team_runs` feeds the owed-wake team term and the pending-wait projection and skips `nobody` runs, while `ended_team_runs` keeps reading every open run so a dead detached cohort is still settled. That settlement needs a live launcher, as it does for an attached team.

An open team run that reports to its launcher also projects a `Team` pending wait on that launcher: a resting launcher displays working until `Done` or cohort-death settlement ends the wait. Its operational status remains sleeping for delivery and [prompt-cache keepalive](./loops.md#prompt-cache-keepalive).

Each report ends with `Memory: <absolute board path>`, naming the canonical run-directory file when the run can be resolved, so the path survives checkout removal. The flip receipt supplies the canonical board path; the report maps it through the launcher's `TmpView::agent_path`, just like the response path. If the death backstop cannot resolve the checkout link, its failure report retains the checkout-path hint instead.

## Recording an entry

`rimz teams record` calls `board::record` for Goal, Decisions, or Result. It normalizes text, rejects blank input, stamps the entry in the machine time zone, and indents nonblank continuation lines two spaces so they cannot become headings or Stage lines. Under the same board lock as a flip it reads, appends after the last nonblank section line, and publishes atomically. Section bounds are the board reader's: a `## <name>` heading matched after trimming, ended by the next ATX heading outside a code fence. Missing sections follow Goal, Decisions, Progress, Result order; a missing or empty board gets all four under `# Blackboard`, without Stage. Its atomic temp sibling and publication stay inside the resolved run directory. It returns nothing to the CLI beyond success and emits no store record, signal, delivery, or compaction. The CLI shares worktree and caller resolution with flip but does not load or trust-check a team definition, and needs no live cohort. It refuses a missing, dangling, or foreign run link with the link path and a relaunch or resume instruction; neither board command creates a run.

## Flipping a stage

`board.rs` owns the board's write-side mechanics: canonical worktree resolution, the per-worktree lock, reads for writes, stamping, section insertion, Stage rewriting, and atomic publication. `team_stage::flip` composes these through `board::LockedBoard`; the re-wake reads through the same locked handle. Both require the manifest to name the writing team, and re-wake skips a foreign or unowned run. `rimz teams flip [TEAM#LANE] <stage> "<note>"` calls the stage domain from a member (`Flipper::Member`) or the user (`Flipper::User`). Both board commands resolve an explicit address to its live cohort, falling back to its audit-store hold. Flip also uses that fallback in the current checkout; record without an address needs no cohort but still requires a linked run with a named owner. An unscoped human record uses that owner; a member uses its own team. A stopped cohort flips as the user with no members; `Done` ends its hold without removing the checkout. The ordinary flip report pipeline still runs, but stop and restart have already settled their team run without a report.

1. **Resolve the owner.** The team must have at least one role that owns a stage (`NoOwners`), the destination must be a declared stage or `Done` (`UnknownStage`), and a stage other than `Done` must have an owning role (`UnownedStage`).
2. **Lock and read.** The flip takes the per-worktree board lock (`RuntimePaths::board_lock`) and resolves the link to this room's run directory before reading the board. A missing or invalid link refuses, as does a manifest naming another team or none; the error names the link and owner and tells the caller to stop and resume the writing team. A missing board within a matching run reads as empty, and the current stage is the `from` of the flip.
3. **Check a hand-off.** A hand-off is a member leaving a stage its role owns for one it does not own, `Done` included. Before any write, a hand-off requires `git status --porcelain=v1 --untracked-files=all` over the checkout with `:(exclude).rimz/team` to be empty, and refuses with the dirty paths otherwise. The archive link is exempt even if exclude registration failed; other modified or untracked files still count, and ignored extras never appear. A worktree outside Git has nothing to commit and passes.
4. **Rewrite the board.** The first `Stage:` line becomes `Stage: <to> (@<owner>)` (no owner for `Done`); without one, the line goes after a leading `# ` heading or at the top. The note is appended as a ledger line, `- YYYY-MM-DDTHH:MM:SS±HH:MM @<by>: <from> -> <to> — <note>` or `opened <to>` for a board with no stage, at the end of the `## Progress` section (an existing `## Progress log` section is accepted), which is created when absent. Stamps are RFC 3339 with the UTC offset, written in the configured time zone; `scratch::board_run` reads legacy offset-less stamps (seconds or minute form) in the configured zone. Its sidebar run span starts at the first parseable entry, moves to each later flip out of `Done`, and stops at the last transition to `Done` only while the board stage is `Done`; malformed entries are skipped and note text never supplies a transition. The board is published atomically.
5. **Open the stage.** The flip appends the `team.stage` signal, fires its subscriptions, and delivers a `STAGE` message to the owner at the `done` boundary unless the stage is `Done` or the flipper owns it ([loops.md § Team signals](./loops.md#team-signals)). `Done` stops language servers for the locked checkout, not the archive directory. A failure after the board write returns `PartialFlip`, naming what completed and telling the user to re-run the flip.
6. **Compact the flipper.** On a hand-off to a stage another role owns, when the role's `flip_compact` threshold (falling back to `[harness] flip_compact`, then the role's built-in default) is reached, the flipper's pane gets its compaction command. This is best-effort enrichment recorded in the assist log; it never fails the flip. A flip to `Done` never compacts, because no member works after it. Independently, the producer's [idle compaction](./messaging.md#idle-compaction) checks resting members using role `idle-compact` over the machine default, and also stops at `Done`.

## Resume re-wake

`team_stage::rewake` re-opens a stage for a root member whose role owns the board's current stage, when that stage is not `Done`. It opens the same stage again with `by = "rimz"` and `from == to`, so the owner is told to continue from the board's last Progress line. A re-wake reads the board under the lock but never edits it, never checks the worktree, and never compacts. A missing or invalid link makes the re-wake a no-op. `stage_flips`, the history `rimz transcript` renders, skips re-wakes.

Two producers call it:

- **The exec wrapper's resume.** Every `Resume` action (cohort resume, lane restore, the partial-live lane split, `agents restart`, `teams restart`, and rebirth) passes through `rimz agents exec`. After it binds the pane and stamps `rimz.agent-resumed`, which revives the ended card ([model.md](../agents/model.md)), the wrapper calls `team_stage::rewake_resumed`. This is the trigger for providers that register lazily (Codex, OpenCode, Kiro, Antigravity, and plugins declaring `registers-lazily`), which emit no registration until their first turn, or never. A lazy provider's notice is typed as soon as the pane is bound. A non-lazy provider's notice is held as provider start pending until it registers or one delivery window passes.
- **Registration.** The lifecycle reactor still calls it when a root member registers. This is the backstop for a registration that is not a resume, such as a fresh launch into an open stage or `/clear`, since a registration does not say which it is. A fresh lazy launch into an open stage is re-woken only at its first registration.

Each producer skips a member a Stage notice already covers, checked under the board lock so a wrapper and a registration racing for one member cannot both enqueue. Both skip when an open Stage notice for the card is still in the queue, so a restart after a resume whose notice never landed does not add a second. The wrapper also skips one delivered at or after a cutoff it takes before the provider could start (before the resume stamp, which precedes the provider), since a non-lazy provider can register and take the reactor's notice before the wrapper's own check runs. A notice from an earlier attempt is older than the cutoff, so a member that dies again right after its notice is still re-woken. The reactor instead skips one delivered within one delivery window of the registration, which covers Codex registering in the same turn the typed notice started. The check reads the queue and the message history together under the workspace lock (`Store::list_messages_and_history`): an acknowledgement moves a record from one to the other under that lock, so an ack landing mid-check cannot hide it. The history append is best-effort; when it fails, a delivered notice is in neither list and the next producer re-wakes once more.
