# Workflow engine

A workflow is a durable run through a flat graph of checks and steps, defined in `workflow.toml` and sealed into the run when it starts. The run record is the only truth. Every decision reads it under the room workspace lock, a wake only asks the engine to read it again, and the journal beside it is evidence for people, never an input. A check decides where the run goes next: a `run` command, a shell command, a condition over loop facts, a sleep, or a headless judge. A step launches a layout with one supervised leader or runs a command, then hands the run to a check. A loop task can start runs, and the scheduler tick re-drives every active run so its clock bounds fire on time.

The [workflows guide](../../guide/workflows.md) teaches the format, and the [workflow CLI reference](../../reference/cli/workflow.md) owns every command, printed line, park reason, and JSON shape. This page owns how the engine decides.

## Terms

| Term | Meaning |
| --- | --- |
| node | A check or a step. The run sits at one node at a time (`RunRecord.node`), entered at `entered_at`. |
| attempt | One evaluation of a check or one launch of a step, published on the record as a `LiveAttempt` of kind `script`, `judge`, or `agent`. Run and shell checks, conditions, sleeps, command steps, and message steps use `script`; a message step's attempt also carries the `message` id it queues. |
| seq | The attempt's number, allocated from `RunRecord.next_seq`. A settlement whose seq is no longer the live attempt's writes nothing. |
| host | The process that owns a live attempt (`LiveAttempt.host`: PID and process-start token). For a hosted check or command step it is the `advance` running it; for an agent step it launches or stops the layout. |
| child | A hosted check or command step's process group (`LiveAttempt.child`: leader PID and start token). |
| wait | The run stays at its node: a check routed to `@wait`, or a step whose admission is blocked. Repeats merge into `RunRecord.wait`. |
| hold | A wait a condition case with `for` creates, with outcome `hold`. |
| park | State `parked`, reached by routing to `@user`. `resume` leaves it; `restart` also re-enters a parked agent step. |
| bound | The run deadline, a node's timeout, or a step's visit cap. The engine routes a bound itself; a step timeout forwards the existing input, and other bounds supply an engine object. |
| terminal | `done`, `failed`, or `canceled`. A terminal record never changes again. |

## Definitions

Definitions live at `~/.rimz/workflows/<name>/workflow.toml`. Unknown fields and invalid optional values warn with their dotted path and are ignored; required fields and invalid live route targets still refuse. `rimz workflow schema` derives its JSON Schema from the loader's types, with `#[schemars(deny_unknown_fields)]` keeping `additionalProperties: false` for editor feedback rather than runtime refusal. `rimz workflow validate [dir] [--json]` loads agent profiles through the machine definition catalog and reports dotted paths, resolved edges, warnings, and errors. It never creates a room, and it checks a directory anywhere, so a definition's source can be checked before it is copied into the definitions directory; `rimz workflow run` (`crates/rimz/src/cli/workflow.rs::start`) and a loop-started run (`crates/rimz/src/harness/schedule/runner.rs::TaskFire::prepare_workflow`) each refuse a directory outside it. The committed fixture `crates/rimz/tests/fixtures/workflows/babysit-pr/` shows script checks with declared wakes, supervised steps, a judge, and signs. Nothing installs it.

`crates/rimz/src/harness/workflow/spec.rs::load` reads text and delegates to `crates/rimz/src/harness/workflow/spec.rs::parse`, the same entry `engine::create` uses for the bytes it seals. `crates/rimz/src/harness/workflow/spec/tolerant.rs::parse` deserializes a `toml::Value` through `serde_path_to_error` and `serde_ignored`, retrying after removing the innermost failing optional field. Route type errors are retained while typed placeholders let semantic cleanup identify dead routes; a surviving type error refuses. An agent step's optional `on.invalid` is removed with a warning instead, including when loading legacy sealed text. Required failures keep their exact structured path, and syntax errors retain their line, column, and excerpt. Only the successful pass contributes unknown-key paths, avoiding duplicate warnings. Wake-entry removal retains original array indices in later paths. `crates/rimz/src/harness/workflow/spec.rs::Wake` and `crates/rimz/src/harness/workflow/spec.rs::Route` have hand-written deserializers because serde's untagged buffering hides unknown table keys from `serde_ignored`.

`crates/rimz/src/harness/workflow/spec/tolerant/clean.rs::apply` clears semantically invalid optional values, misplaced fields, and dead check routes, recording each in `WorkflowSpec.ignored: Vec<Issue>`. This pass is pure and stays in the sidebar import graph; it does not read machine configuration or write records. `validate_spec` prepends those issues to its environment warnings and applies required-field and graph rules to the cleaned spec. Thus a discarded timeout still refuses where that node requires one, and a discarded total visit bound cannot bound a step cycle. Bad targets on remaining routes and wrong-typed `on` tables still refuse, because dropping a live route would silently select its default. The [reference](../../reference/cli/workflow.md#validate-and-schema) owns the field-by-field tolerance rules.

Workflow `timeout`, `sleep`, `for`, route `delay`, and workflow/step `stagger` use `spec::duration`: `s`/`m`/`h`/`d`, at most `365d` inclusive. Overlong optional values warn and are dropped; `sleep` refuses validation, and a command step whose timeout was dropped refuses as missing. The same bound applies when rereading a sealed live graph, without grandfathering: `spec::load_run` validates nothing, so a sealed overlong `sleep` never refuses; at evaluation `script::condition_now` returns `DurationTooLong` and the check routes `invalid`. `capacity-wait` keeps its separate shared parser and is unbounded.

### The header

| Field | Rule |
| --- | --- |
| `scope` | Required. `worktree` runs every node in the selected checkout, and `project` runs every node at the room's project root. |
| `start` | Required. Names a check or a step, never a special target. |
| `summary` | Optional. One nonempty line describing the workflow. Omission never warns. |
| `deadline` | Optional. An RFC 3339 instant, or a local civil date or datetime. A bare date is local midnight. The record stores the resolved instant. |
| `on.deadline` | The one header edge. Uses on-break or the `@failed` floor (legacy `@user`). |
| `limit` | Optional `max-parallel` and/or `stagger`, shared by open agents stamped with this workflow name across the home. |

### Checks

`[checks.<name>]` selects exactly one runner (`Check::kind`):

| Kind | Selected by | Also takes | Routes |
| --- | --- | --- | --- |
| run | `run` | `wake`, `timeout`, `on` | Its own outcomes, plus `timeout` and `invalid`. |
| shell | nonempty `shell` | `wake`, `timeout`, `on` | Requires `on.pass` and `on.fail`. Accepts only those plus `on.timeout` and `on.invalid`. |
| judge | `agent`, with required `prompt-file` and `summary` | `window`, `wake`, `timeout`, `on` | Its own outcomes and `timeout`. A failed evaluation retries once, then follows `on.invalid`; legacy records park at `@user`, ignoring that edge. The profile's adapter must have a headless launch. |
| condition | nonempty `cases` | required `else`, `provider`, `account`, `timeout`, `on` | Every case outcome and `else` must be routed. Other routes warn and are ignored, except `unknown`, `timeout`, and `invalid`. |
| sleep | nonzero `sleep` duration | required `then`, optional `when`, `for`, `provider`, `account` | `then` on expiry or a matching condition; `sleeping` and unread `unknown` wait. No timeout edge. |

Every kind accepts a `summary`: one nonempty line describing what the node does. It is required for judges and optional elsewhere. Admission validation runs after tolerance, so a judge's dropped blank or multiline summary refuses at `checks.<name>.summary` with `add summary = "..."`. Sealed-run loading does not revalidate admission: an older judge without one keeps running with the fallback description. Misplaced optional settings warn and are ignored; conflicting runners still refuse. A `window` holds provider-window terms only. A condition or conditional sleep requires `provider` when its terms read `window.*`; an unknown provider or one without such a term is ignored, as is an `account` without a remaining provider.

A condition's cases are an ordered array of tables. Write it inline in `[checks.<name>]`, one case per line (`cases = [ { when = [...], outcome = "..." }, ... ]`); the loader reads `[[checks.<name>.cases]]` blocks as the same array. Each case:

| Field | Rule |
| --- | --- |
| `when` | Required loop-grammar term array. A term may not match the value `unknown`: route `on.unknown` instead. Stage names are checked against the effective teams plus `Done` when validation runs from a workspace, and a warning says so otherwise. |
| `outcome` | Required. Not a reserved outcome. |
| `for` | Optional nonzero hold in `s`, `m`, `h`, or `d`. A held case must route its outcome away from `@wait`. |

`wake` is a list of selector strings or `{ signal, match }` tables (`signal` required, `match` optional), parsed by the loop's selector and match validator. Unknown table keys warn and are ignored. Invalid entries, agent-family selectors, and team selectors other than exact `team.stage` warn and are dropped individually (`SpecErr::LifecycleWake` supplies the lifecycle reason); a table's missing or wrong-typed `signal` still refuses.

### Steps

`[steps.<name>]` selects exactly one of `agent`, `run`, `shell`, or `message` (`crates/rimz/src/harness/workflow/spec.rs::Step::kind`), and requires `then` naming a check or a nonempty list of checks, never steps or special targets; a message step's `then` instead names exactly one node, `@done`, or `@failed` (`crates/rimz/src/harness/workflow/validate.rs::message_then`). Common optional fields are `summary` (one nonempty line), `timeout`, `max-visits`, `max-visits-per-outcome`, and `on.cap`. A run or shell step requires `timeout` and ignores the agent-only `prompt-file`, `lifecycle`, `keep`, `window`, `takeover`, `share`, `throttle`, `limit`, `capacity-wait`, `on.capacity`, `on.asked`, and `on.invalid` with warnings, including explicit default values. Run argv resolution is the same as for run checks; shell text is nonempty and unconfined.

A message step's `message` must be an `@` address without a pane id that `address::parse_selector` accepts and that is neither `@user` nor `@me` (`crates/rimz/src/harness/workflow/validate.rs::message_target`). `prompt-file` is optional and confined; `agent::compose` skips it when absent and prefixes the header line `engine::Notice::text` writes. The tolerant cleaner shares the command-step ignore block with message steps and adds `on.asked` and `timeout`; every other step ignores `on.undelivered` (`crates/rimz/src/harness/workflow/spec/tolerant/clean.rs`). `graph.rs` gives a message step an `undelivered` edge in place of an agent step's `invalid`, filled from `on-break` under `RouteDefaults::OnBreak` and from `@user` under legacy `Park` defaults, and `WorkflowSpec::target` maps its `died` to `undelivered`, never `then`. `reject_reserved_targets` refuses `@user` and `@break` there.

An agent step requires `prompt-file`. `agent` takes the fresh-launch layout grammar: kinds, profiles, virtual cells, and mixed agent/command layouts. A team runs only in a `stay` step (`crates/rimz/src/harness/workflow/validate.rs::step_layout` refuses it elsewhere, naming `lifecycle = "stay"`), and the host launches it through the launcher's team layout path with the step's leader run. Command-only layouts and ambiguous prompt leaders refuse; judges still take one profile. Agent-only optional fields are `lifecycle` (`until` by default, `turn`, or `stay`), `keep` (default false, ignored on `stay`), `window`, `takeover`, `share`, `throttle`, `limit`, `capacity-wait`, `on.capacity`, `on.asked`, and `on.invalid`. `Step::lifecycle` resolves the definition default for every reader; command steps remain turn-shaped. `limit` has the same table as `workflow.limit`: a positive integer `max-parallel`, a positive `s`/`m`/`h`/`d` `stagger`, or both. An invalid `max-parallel` or `stagger` is ignored with a warning, and a limit left with neither is ignored whole with `set max-parallel or stagger` (`crates/rimz/src/harness/workflow/spec/tolerant/clean.rs::limit`). Staying steps (`stay` and `until`, including an omitted lifecycle) warn and ignore `on.asked`, and `stay` steps `timeout`, naming `lifecycle = "turn"` as the fix; an `until` step's timeout runs from its launch (`crates/rimz/src/harness/workflow/inspect.rs::timeout_at`). Runs sealed before `spec_version` 1 keep the old rules and ignore every later field (`crates/rimz/src/harness/workflow/spec/tolerant/clean.rs::launch_fields`). Until steps cannot use a sleep as their turn-end check, and the refusal names the same fix. Turn and until steps warn when their leader adapter cannot report background work. Every agent step warns when auto-continue is off that a provider-limit pause waits for the user. Judge warnings distinguish Claude's limited attempt from a failed Codex judge, which retries once, then follows `on.invalid` (legacy records park).

`throttle = "off"` skips the machine turn, stagger, pressure, memory, disk, and capacity check, not the two machine caps or applicable workflow and step limits. `capacity-wait` reuses `config::CapacityWait`: a positive `s`/`m`/`h`/`d` duration or `forever`, the default. `on.capacity` defaults to `@failed` and may name `@done` or a node, but never `@user` or `@wait`: giving up does not park a run or introduce a new durable park reason.

Both visit limits must be at least 1. `max-visits-per-outcome` accepts an integer or `{ limit = N, reset-on = "outcome" }`, with a nonempty string list also accepted for `reset-on`. Its limit must be below `max-visits` when both are set, since the total cap trips first. An invalid inner value drops the whole cap; unknown inner fields warn at their dotted paths and are ignored individually. Counts use the routed outcome and `record.key` through `crates/rimz/src/store/workflow.rs::RunRecord::visit_bucket`, with null for missing input. The outcome is `record.input.outcome`, except a cap object for the current node uses `record.input.routed_by` to preserve the refused bucket across park and resume. Sending-check identity does not split a bucket. Forwarded input and `resume --at` retain the outcome; engine routes into a different step count under their own outcome. `on.cap` uses on-break or the `@failed` floor (legacy `@user`); an agent step's `on.asked` has no default and keeps the question live when absent. Neither edge may target `@wait`, and `on.cap` may not target its own step. Validation prints an `asked` edge only when explicitly set.

`crates/rimz/src/harness/workflow/state.rs::Transition::finish_check` resets each step whose surviving cap lists the valid check answer's final outcome in `reset-on`, after rewriting an unexpired condition hold to `hold`. It clears only that step's outcome rows, never `total` or the run-wide grant, and journals `VisitsReset { step, outcome }` on the answering check entry only when rows were nonempty. The route target does not matter, including `@wait` and `@done`. Engine routes, invalid answers, and answers still held do not reset. A number cap, or a table without `reset-on`, accumulates until manual restart or cap resume; switching failure outcomes does not reset counts.

### Edges and the graph

An edge names another node, `@wait`, `@done`, or `@failed`; legacy runs also support `@user`. Checks and steps share one name namespace, and an author-written node or workflow name is nonempty ASCII letters, digits, `-`, and `_` (`crates/rimz/src/harness/schedule.rs::validate_name`). The resolver in `crates/rimz/src/harness/workflow/graph.rs::WorkflowSpec::edges` supplies check and step edges and the header deadline. Check `timeout`/`invalid`, agent-step `invalid`, message-step `undelivered`, step `cap`, and header `deadline` use their explicit route, else `on-break`, else the runtime floor `@failed`. Agent capacity defaults to `@failed`, and a condition or conditional sleep's `unknown` to `@wait`. Engine routing, validation rows, timeout admission, cycle detection, and inspection read that resolver. A step's turn-ending outcomes, including its timeout, resolve through `then`, except that a set `on.failed` takes a `died`, `timeout` or `limited` ending (`WorkflowSpec::routes_on_failed`); an absent `on.asked` keeps the question live and is not a displayed edge.

Each edge also carries fireability and, when it can never fire, a typed reason. `Edge::mark` owns the human wording used by validation and inspection. `Transition::finish_judge` retries once, then follows `invalid`; legacy judges still park independently of that edge, which remains marked never-firing for them. Capacity needs a finite wait and enabled throttle and can only give up in an automatic loop-started run. An unset header deadline is conditional on a run grant, not a never-firing edge. Edges filled by on-break carry `EdgeSource::OnBreak`, wire `"on-break"`.

`RunRecord.route_defaults` freezes this policy: missing fields decode to `park`; creation writes `on_break`. `spec::parse_run` passes it through the same parse funnel as `default_lifecycle`, including cached sidebar projection. A `park` record retains all old defaults and ignores on-break in its sealed text. Only `on_break` specs synthesize the agent handler as `@break`, a stay step ending at `@failed`. Its input adds `edge` and `from` when the route is applied, including after a held verdict or a sleep. A pending held verdict keeps the journal's unannotated object so inspection can recognize it as pending. Break launches disable leader-wrapper cleanup, and every ending detaches rather than stops them, including a late launch returned after cancel. `bound`, agent ending preparation and inspection omit its deadline. Its default prompt carries a bounded debug trace; an author's prompt uses the ordinary confined-file path.

An active run at `@break` accepts resume, except while a live owner is launching or settling its attempt. The existing ending protocol saves a route to `--at` or `input.from`; the next advance detaches the session, journals Resume under the destination, and re-enters that node. The reserved `@break` node is not a resume destination. Input survives; a cap break resets the source step's total and every outcome/key count, even with `--at`. Resume before a break launch clears its occupancy/capacity wait and re-enters directly. Other active runs still accept only extensions.

`RunRecord.break_agents` retains the detached break leader's and live children's handles before the next admission. It defaults to empty and is omitted when empty, without a record-version bump. The CLI host filters those handles from the snapshot before both occupancy and eviction, so this run never waits for or stops its own detached debuggers. Other occupants keep the shared takeover rules.

A check's `on` value is a target string or `{ to = "<target>", delay = "30m" }`, with a required string `to` and optional nonzero `s`/`m`/`h`/`d` delay. A delay is meaningful only on a check named by an until step's `then`, on a route outside the listed checks, other than `@wait` or a return to an until step using that check. Invalid or misplaced delays warn at `checks.<check>.on.<outcome>.delay` and are dropped without dropping the route; unknown route-table keys warn individually. A missing or wrong-typed `to` follows the same live-route refusal and dead-route cleanup as a wrong-typed string route. `Edge.delay` is serialized only when present, and never makes a check-only cycle count as waiting.

`crates/rimz/src/harness/workflow/graph.rs::WorkflowSpec::walk` takes reverse postorder from `start`, traversing fireable edges last-to-first in display order. It walks a header deadline destination after the start component, and lists unreachable nodes alphabetically. A step hangs under its `then` check only when that check occurs earlier in the walk and has a fireable edge to the step. This keeps a forward return, such as land's `triage` to `ruled`, standalone. Hanging children follow their parent's edge order.

`crates/rimz/src/harness/workflow/script/condition.rs::case_marks` projects the latest answer's readings through `WhenExpr::truth`, stopping at the winner or first unread case; later cases are not reached. A holding wait's `case` selects the held winner. The adjacent `unread_reasons` parser recovers per-term unread reasons from `answer`'s stored prose, using its null-reading keys as delimiters so commas and parentheses inside a reason survive. It adds no stored field.

| Rule | Why |
| --- | --- |
| `timeout`, `invalid`, `cap`, `capacity`, `deadline`, `unknown`, and `hold` are reserved (`crates/rimz/src/harness/workflow/spec.rs::RESERVED_OUTCOMES`). No case or `else` uses one, and no check answers one, except a condition or conditional sleep's `unknown`. | The engine produces them for its own routes. |
| `on.timeout` cannot be `@wait`. | The timeout clock has already expired. |
| A check with any resolved `@wait` edge needs a `timeout`, except a sleep. | A sleep has its own finite duration; other waits need a bound. |
| A cycle through steps needs a `max-visits` on one of them. | A per-outcome cap alone cannot bound a check that names a new outcome or key every time. |
| A surviving cap's `reset-on` needs `max-visits` and outcomes found on checks' non-reserved edges. | Resets must be answerable and cannot remove the run's only bound. Errors use `steps.<step>.max-visits-per-outcome.reset-on`; dropped caps get no reset errors. |
| A check-only cycle needs a wait edge. A hold is not an edge and does not count. | Otherwise one advance would loop without pause. |

Validation warns, without refusing, about turn or `until` steps whose leader adapters do not report background work (`do_background`, which every row carries), and turn steps or judges while machine auto-continue is off. A per-outcome cap without `reset-on` also warns when the step is not the start, no `then` reaches it, and all incoming edges share one outcome name: it repeats `max-visits` unless a check answers keys. Script, shell, and agent checks do not suppress that warning.

For each command or message step with `max-visits = N` (`validate.rs::never_waits`), `validate_spec` warns at `steps.<name>` when a cycle through such steps and checks has no non-deadline `@wait` route: it can spend all N visits in one advance. Agent steps and checks with explicit or implicit waits break that cycle; a case hold does not. The warning asks for a check that can wait if this is unintended. It appears at `workflow validate` and `workflow run`, not loop-started admission, which drops warnings.

### `run` and `shell`

`run` is an argv parsed with `shlex`, never shell text: pipes, variable expansion, and redirection belong inside a script. Every word containing `/` names a file relative to the workflow directory (`crates/rimz/src/harness/workflow/spec.rs::resolve_argv`). Only normal path components are accepted, and canonical resolution must stay inside the directory. Other words, such as `sh` or `uv`, resolve through `PATH`. Files are resolved and hashed again at every evaluation.

`shell` is unrestricted `sh -c` text. Its sealed spec digest covers the command, and the paths it references are neither confined nor hashed one by one.

Checks must be idempotent. A host killed after a script's effects but before settlement causes a fresh evaluation, never recovery from the previous stdout.

## Run control

Human run inspection calls `crates/rimz/src/harness/workflow/script.rs::condition_now` for one condition check or conditional sleep: the first listed check on an agent step, or the current check on a live or parked run. It shares the engine evaluator, including sleep expiry and the CI Git fence; a sleep previewed from an agent step starts at the preview, since the step has not entered it yet, so it never reads as slept. It returns the forge timestamp from that same cache snapshot. There is no check child, write, or probe refresh. Preview freshness starts at step or parked-node entry (held sessions keep their session-entry floor); `hold_until` reads only a wait belonging to the selected check and case. Child checks and plain sleeps have no now line. JSON and history do not call this entry.

`engine::create` admits a run in this order:

1. Compare every nonterminal run of the same workflow against the candidate, each by the path `ScopeRoots::path` gives for that run's own scope kind. A match is the typed `WorkflowErr::Exists`.
2. Read the prompt and the definition bytes, load those bytes through `spec::parse`, then validate the cleaned spec with `validate_spec` against the run's project.
3. Require the room's workspace record (`rimz start` creates the room).
4. Under the workspace lock, repeat step 1, then write the run home (`store::workflow::initialize`).
5. Spawn a detached `advance`.

Step 1 runs before the prompt or definition bytes are read, so a held run wins over a broken definition, a prompt-file error, or a scope-kind edit. Comparing each existing run by its own kind keeps a worktree run at the project root from blocking a different worktree. `rimz workflow run` validates the definition directory before it calls `create`, so a manual start of a broken definition refuses on the definition even while a run holds the slot. The CLI prints `Exists` as a refusal, and a loop fire reaching `create` follows its task's `overlap` policy: `overlapped` naming the run by default, or a retained trigger that drains once the run's report lands. A scheduled condition task with a launch entry never reaches `create`: it exits silently.

`rimz workflow run` resolves `-w` to an existing RimZ-owned worktree before it calls `create`, never creating one, so an unknown worktree refuses even a project-scoped run. Without `-w` the checkout is the current one. Worktree scope runs in that checkout. Project scope always runs at the root, and the CLI prints a stderr notice when `-w` named a worktree. Run ids are `wf_` identities. `list` enumerates active and parked runs across rooms, attention first, then workflow groups with self-clearing capacity holds last. Human rows read each run's journal for a horizontal rail (an unreadable journal leaves that row's reached history empty without failing the list), cache PR readings once per room, and lazily read the room roster once when naming a with-you agent. `crates/rimz/src/cli/workflow.rs::RoomView::agent` reads the cached-alive roster `agents list` reads and projects the published pane frame over it, so the peers match the card's, without the dashboard enrichment. The views join the session attempt's run/sequence/Step pin, prefer the leader's recorded pet identity among layout cells, and use its card handle, falling back to its recorded pet name; JSON and loop detail gain no enrichment reads. `show`, `cancel`, `resume`, and `restart` accept addresses and workflow names through `crates/rimz/src/cli/workflow/resolve.rs::select`; caller-room matches win, otherwise several rooms require `--root`. `show <workflow>` draws the definition rail and then the runs table; `show <workflow> <node>` prints one definition node in full. Run ids, including the hidden `advance` positional, still resolve from any directory through `crates/rimz/src/disk/paths.rs::workflow_runs_under`, which skips a room whose run homes cannot be read. An active session attempt (held first, else the slot's agent attempt) with `asking` has DETAIL `asking you: <handle> (<kind>): <text>` in list text and JSON `detail`, with text collapsed to one line; a single-run show says `<step> is asking you` and prints the full ask below. Both state labels use the Waiting role. Without an ask, a live staying attempt has DETAIL `with you`, then ` · checking <check>` while held, then `: <wait phrase>` at that check, or ` · <check>: <wait phrase>` after it if waiting; show says `<step> is with you`, uses the full card handle in its headline and the shared check/wait suffix, with no duplicate status below. Other live runs print the park or wait phrase, otherwise running with its configured visit bound or checking. `crates/rimz/src/cli/workflow_view.rs::detail` supplies workflow and loop detail without the node or `since`; their JSON keeps node-entry `since` separately. Human list ages use the park time, ask time, first capacity-hold time, or node-entry time. The list supplies the optional channel-less agent name to `detail` and appends a cached PR number itself; JSON and loop callers supply no agent.

Single-run show renders an address/PR header, a state headline, the current check's saved readings and journal time on active runs, an additional live condition now line and its forge probe time on active or parked runs, origin and completed cost, ask text or park explanation, a painted active or horizontal parked/terminal rail, capped visit counts, a bounded trail, and a work-directory/history footer. The saved readings come from the latest evaluation since node entry, including script readings; they do not re-evaluate the check. The headline separates state, agent context and bound-forecast tones; with-you details stay in that headline. Warnings follow the rail before visits, except in history where they follow the headline. `crates/rimz/src/cli/workflow/show/rail.rs::View::rail` paints the shared definition rows from the sealed specification, journal and record. The trail reads `crates/rimz/src/harness/workflow/inspect.rs::hops`, including held-session turn ends, and node entry counts come from `crates/rimz/src/harness/workflow/inspect.rs::reached`, shared with the sidebar strip; an evaluated check is marked reached even when its turn-end verdict was discarded and routed nowhere. Both take the record's held session: while a saved closing verdict waits (a route delay or an ineligible leader), its evaluation projects no route, so the trail, history and reached marks name neither its target nor a visit to it until the session closes. These are projections, never transition authority. `crates/rimz/src/cli/workflow_view.rs::glyph_role` selects the headline and current-node glyph together. Condition case marks and unread reasons come from the harness; saved values appear in the readings line and current values in the now line, while the unread case retains its reason. `--history` renders the journal as typed facts, folding repeated answers and wakes and omitting duplicate route evidence and represented closing waits, with targets from the sealed specification except where a turn-end verdict records its own target; a `turn_end` row prints its target only when kept, pushed or closed, and a pending saved verdict prints none. `--json` keeps the durable record and journal and adds the derived address. See [Inspect runs](../../reference/cli/workflow.md#inspect-runs) for the output contract.

`cancel` takes the workspace lock and returns false on a terminal record, so the first terminal write wins. It kills the child of a hosted check or command step and ends the run `canceled`. For an agent step it stages a `canceled` end with cause `Cancel` and stops the attempt ([Stopping an attempt](#stopping-an-attempt)). While a live host is mid-launch or already ending the attempt, cancel leaves the stop to that host.

An optional cancel reason travels through `Ending` to settlement and the `Cancel` journal row, including deferred agent stops. Both fields default to absent for older records and are omitted when no reason was supplied. The hidden `workflow cancel --reason TEXT` flag carries internal cancellation causes; `crates/rimz/src/harness/workflow/mod.rs::cancel_args` builds its argv using the machine-wide run id.

`resume` refuses a terminal run, and on an active run outside `@break` it accepts only `--extend`. A parked run re-enters its current node, or `--at <node>`, with a fresh `entered_at` (so a fresh timeout clock) and a cleared judge retry, retaining input and key. A cap resume resets the capped step's total and every bucket, journaling `VisitsReset { all: true }`; other parks retain counts. `--extend visits=+N` adds a run-wide `visit_grant` to every step's `max-visits` and `max-visits-per-outcome`, for every bucket. Resets leave the grant unchanged; outcome bounds compare against counts since the last reset. `--extend deadline=<when>` replaces the deadline and re-arms it. The return value is the persisted record from before the detached advance was spawned, so a receipt need not reload a record that advance may already have changed.

## Storage and isolation boundary

`restart` stages `EndCause::Restart { continued }` on the current or restored held agent and reuses the off-lock stop and sequence/host-checked settle protocol. At a parked agent step with no session attempt, a matching-node `prev_attempt.run_id` identifies the previous session. With `--continue`, restart restores that attempt for stopping, including a still-live detached card, before the replacement launches; `record.restart.settled` marks its already-journaled sequence so settlement does not repeat its end or cost. Settlement preserves input/key, re-enters the owning step, clears its total and buckets, and journals `VisitsReset { all: true }` and `Restart { step, continued }`. A durable `record.restart` carries the optional leader session through stop recovery and occupancy waits until launch publication consumes it; parking or terminal settlement clears it too. That one launch uses throttle's manual-start path and skips `window`; later visits regain normal admission. The CLI resolves `--continue` from the selected attempt's supervised run `agent_id` and durable audit rows, checks provider support, conversation presence and the room account's history pool before staging, and passes the checked sequence to reject a moved attempt. Launcher preparation rechecks conversation presence and the selected room-default account's pool after stop work; an intervening account change cannot resume into a foreign pool. An after-stop resume failure follows step `on.invalid` in new runs; legacy records park at the step with reason `invalid`, and their park text names the fresh `rimz workflow restart <run>` command. The restart receipt shows that park only when the launch settled before it printed; otherwise it reports `awaiting launch`. A concurrent cancel can replace the ending and wins settlement.

Before stopping an attempt, the host retires its pending push-back by message id, including an unconfirmed `Sent` prompt, through `Store::retire_message`. The queue writer cancels it with terminal history and audit evidence; unrelated messages and delivered prompts are untouched. A producer that queues after the stop's retirement re-reads the attempt's ownership and ending before delivery and retires its obsolete push too. Thus a continued restart's first clean turn is not gated by the abandoned attempt's push, while the current attempt's own unconsumed push still defers judgment.

The launcher keeps fresh identities and fresh companions, but compiles the leader's exec action as `Resume` when `LeaderRun.resume` is present. The shared fresh-cell compiler still installs the run id, workflow pin, reminder, managed account and cleanup policy; account resolution uses the room default. `agents restart` routes only current Step pins through this control path, leaving team restarts alone; former step restarts clear their pin and run outside the workflow.

Each room holds one home per run, `owned/workflows/<run-id>/`. All its paths come from the disk path module (`crates/rimz/src/disk/paths.rs::WorkflowPaths`):

```text
record.json        current run, version 3 (reads 1, 2, and 3)
journal.jsonl      append-only evidence: transitions, and a row per check evaluation, so a polling check grows it on every recheck
workflow.toml      sealed specification bytes
definition/        an inline run's definition root: its source text and the assets it names
work/              RIMZ_WORKFLOW_DIR, writable by nodes
  context.json     replaced before every evaluation or attempt
  notes/           link to kept automation notes (legacy runs and runs without notes: scratch directory)
  signs/           live step guidance, created with the run
  <seq>.check.log  run-check stderr or shell-check combined output
  <seq>.check.json judge's whole saved answer
  <seq>.step.log   command-step stdout and stderr
```

The record, the sealed spec, and the journal sit outside the node-writable `work/`. Notes are reached through the link in `work/`; signs and step claims live under `work/`, and the engine reads only `signs/<step>.md`, never notes or claims. Every evaluation and attempt takes a fresh `seq`, a judge retry and a re-run after a dead host included, except a message step's re-send after a dead host, which keeps its attempt's `seq` and message id so the queue takes the notice once. A node therefore keys a `notes/` write by the item it records, since keying it by `seq` would not make a repeat a no-op.

`crates/rimz/src/harness/workflow/engine.rs::create` takes a `DefinitionSource`: a deployed directory, whose basename names the run, or an inline definition a loop task compiles, its text plus named asset files. An inline run's `workflow` is its task name, and `crates/rimz/src/store/workflow.rs::seal_definition` writes the text and assets into the run's own `definition/` before validation, which becomes its `spec_dir`, so prompts and scripts are re-read from that root rather than from the task's config. A refused inline start removes that root before any record exists. `RunRecord.origin` records which source started the run (`deployed` or `inline`; absent decodes as `deployed`). A live run blocks a new start on the same scope path when it shares the start's origin and name, or its task, so a task whose row changes what it runs still overlaps its own live run.

A run a person starts whose graph has no agent step, agent check or message step needs no room's workspace record. A run a loop task starts always needs one, since its detached advance finds the run through the room's record (`engine::create` refuses with `no room`). A run of checks allocates no notes folder, and its `work/notes/` is a scratch directory, when it is inline (a loop task's check-only run fires too often to keep a folder each time) or when no room exists. Any other creation refuses without a room and allocates `automation-notes/<yyyymmdd>/<HHMMSS>Z-workflow-<workflow>-<lane>/` from the record's `created_at` sample and stores its root-relative path in optional `RunRecord.notes`. Its v2 `run.json` names the workflow, run ID, and scope checkout. Every step cell carries that relative path in `LaunchRecord.notes`, and launched descendants inherit it from their parent's row. Relaunches preserve it; forks clear it. Claude's additional-directory grants include that run folder, rejecting paths outside the room's automation archive, and the checkout's valid team run when present. Team reminders and memory listings keep resolving through the checkout's `.rimz/team` link. Agent-step briefs name `<step>-notes.md` unless `notes = false`; command steps warn and ignore the field. Absent record fields preserve legacy runs' behavior. GC reads current workflow and agent ownership under the workspace lock and holds it through removal; non-terminal workflows and live agent rows protect their folders, and an unreadable rollup protects all automation notes.

Soft reset keeps run homes, and hard reset removes them, unlike supervised-run records. Garbage collection removes a terminal run's whole home once `record.json` is older than the seven-day owned grace and the run owes its loop task no report. A home without `record.json` is a crash during creation (or during an inline run's sealing), which every reader skips, and it goes once the home directory itself passes the same grace.

After CLI advance, cancel, or restart returns from the engine, `crates/rimz/src/cli/workflow.rs::write_history_copy` writes terminal history into the run's notes folder and warns without failing the committed transition when copying fails. The shared writer, `crates/rimz/src/cli/workflow_view/history.rs::write_copy`, uses the `show --history` journal renderer, raw prose and a color-stripping stream. Terminal history names the absolute local end in the headline and uses date-qualified local clocks (`YYYY-MM-DD HH:MM`) on every row for reproducible bytes. Writing replaces an existing copy. Legacy records without notes write none, and an archive already deleted by its retention or the user is not recreated.

Before GC removes an eligible terminal home, it calls the CLI's history writer off-lock when the copy is missing. A failed copy keeps the home. The sweep then reacquires the workspace lock and rechecks terminal state, record age, notes path, and sequence before removal; rendering never holds that lock. A dry run predicts removal without writing a copy. Bare `show`, including `--history` and `--json`, resolves the caller and walks launched parents with a cycle guard to the first workflow pin.

The record stores the scope, project root, sealed-spec digest and original definition directory, prompt, current node and entry time, state and park, routed input and key, open wait and recheck time, per-step totals and outcome/key visits since reset, the visit grant, deadline state, the sequence allocator, the live attempt, an optional held session, the previous step attempt, and the terminal time. Each step's visits serialize as `{total, outcomes: [{outcome, key, visits}]}`, with nullable outcome and key; legacy `{total, keys: [{key, visits}]}` records load as null-outcome rows. Its optional `task` names the starting loop task. `manual` is true only for a run created by `rimz loop fire`, whose steps skip capacity waits but still claim applicable workflow limits; false defaults on old records and is omitted on write. Older binaries ignore `manual`. Keys keep integer versus string identity. New runs use version 3, including check-only and explicit-turn definitions. The loader accepts versions 1, 2, and 3. Older binaries refuse version 3 and skip it in lists rather than rewrite an unsupported run. Such binaries also miss that run's scope claim, the same mixed-version exposure as pre-stay binaries with stay runs. Unknown `Wait.hold` strings load as absent; the shared [hold-kind contract](./loops.md#the-start-throttle) covers both workflow and condition waits.

The record's `default_lifecycle` freezes the omitted agent-step lifecycle for the run: new runs write `until`, and an absent field decodes as legacy `turn`. Raising an old record to version 3 does not change that default. Sealed-spec readers pass it into `spec::load_run` (or the sidebar's byte-cached `spec::parse_run`) before cleanup, so legacy timeouts, `on.asked` edges and sleep-check eligibility survive every re-entry.

Engine rereads use the same tolerant loader as admission, without repeating `validate_spec`: a live run keeps advancing on the cleaned definition the acting binary understands, rather than being stranded by a renamed optional field. Required parse failures still refuse. Ignored-field issues are skipped by serde and schema generation, not stored in `RunRecord`. `crates/rimz/src/cli/workflow/show.rs::render` and `crates/rimz/src/cli/workflow/list.rs::render` recompute them from the sealed bytes with that frozen default, so a newer binary can mark a field the creation binary understood. This does not make binaries that predate the tolerant loader accept newer fields, or relax run-record version checks.

A journal entry carries its time, node, optional attempt sequence, and one event: evaluation, attempt, visit reset, turn-end decision, closed wait, engine route, park, terminal, cancel, resume, signal wake, or forwarded signal. An evaluation keeps the routed object and its `origin` (`check` or `engine`, defaulting to `check` when absent). An invalid answer also keeps a stderr tail. Script and judge evaluations keep the digests published with the attempt's child, whichever process ends the attempt, and an evaluation whose child never spawned has none. Attempt rows and `PreviousAttempt` carry the admitted outcome in `routed_by` beside the key, defaulting to null for older entries. Visit resets identify the step and answered outcome; inspection takes reset boundaries from these events, not by re-evaluating the spec's reset rule.

`engine::persist` is the one publication path. Under the workspace lock it appends each journal entry and data-syncs the journal, then replaces the record, then writes accounting. A crash between append and replacement can leave a duplicate entry with the same sequence, and history never authorizes a transition. Creation syncs every new directory up to the room root. Readers skip torn or unknown journal rows.

`LiveAttempt` and `JournalEvent::Attempt` carry optional string `started_past_limit`: the skipped hold text, without an age. It defaults to absent and is omitted when absent; the record version stays 3. `prepare` stores it on admission and `Transition::settle_step` copies it into the journal. `show` prints `<text>; started anyway: manual starts do not wait` while that session is current (including `held.attempt`), and history prints it inside the settled attempt's block. JSON exposes the field itself. No text goes to `workflow run` or `loop fire` stdout or stderr.

## The advance loop

`engine::advance` is one loop of three phases, and each phase boundary is a lock boundary:

1. Prepare, locked (`crates/rimz/src/harness/workflow/engine.rs::prepare`). Load the record and decide: return, hold or restore an until session, stage an ending, route a due bound, reclaim a dead host's hosted attempt, count an early advance against a wait, merge a step admission wait, ask for capacity admission, or publish a new attempt with its `seq` and `context.json`.
2. Run, off-lock: evaluate the check, run a command step, ask the capacity door, launch an agent step (stopping a takeover's occupants once the launch is prepared), enqueue its saved push-back id, or stop an ending agent step.
3. Settle, locked: reload the record, confirm the attempt's `seq` is still live, route, and persist.

A stale settlement writes nothing. One advance keeps going until the run waits, parks, ends, meets a live host, or would evaluate the same check twice with no step attempt or newer eligible until turn end between. A held verdict resolves before a wait can stop the advance. Repeated cap routes also yield rather than spin without launching. Each guard leaves the run active, and the next wake or tick drives it on.

### Hosted children

Run checks, shell checks, judges, and command steps run inside the short-lived `advance` process, never as supervised runs. Preparation publishes the live attempt (kind, sequence, node, start time, host PID and start token) and its context under the workspace lock, so a stale host cannot overwrite a newer attempt's context. `crates/rimz/src/harness/workflow/script.rs::with_child` then re-takes the lock, re-reads the bounds, spawns the child, and publishes the child's group-leader PID, start token, and file digests in one write, before it releases the lock and waits for output. Spawn and publication thus share the lock with cancel and bounds. Run steps pass argv directly through the hosted runner; shell steps use `sh -c`. Both tee stdout and stderr to `crates/rimz/src/disk/paths.rs::WorkflowPaths::step_log`, `work/<seq>.step.log`.

While it waits, the host re-reads the record at the bounded subprocess runner's interrupt cadence and interrupts its child when the attempt is no longer live or a bound is due. Another advance leaves a live host alone while no bound is due. A check host that is dead, or whose PID was reused, turns its attempt into an engine-origin `canceled` evaluation, which re-runs free. A command step instead journals a `canceled` attempt with a lost-host reason and follows `then`, without repeating its side effect or counting another visit.

Any advance or cancel kills the recorded group under the lock before withdrawing the attempt, including when the host is stalled or dead (`Transition::kill_child`). It signals only when the leader's start token still matches or, once the leader's token is unreadable, when a live member of that group carries this run's `RIMZ_WORKFLOW_RUN` marker. Membership is checked again after reading the marker and liveness. A missing or changed token alone never authorizes a signal. A hosted leader stays unreaped until its pipes close, so the published PID and token stay a valid kill handle. A surviving host reaps its child when it resumes, and its stale sequence cannot settle again.

A run or shell check or command step runs in the scope checkout with null stdin, the room workspace pin, `RIMZ_WORKFLOW_RUN`, `RIMZ_WORKFLOW_DIR`, and `RIMZ_WORKFLOW_DEFINITION`. `context.json` holds `run`, `prompt`, `node`, `seq`, `key`, `input`, `output_path` (`work/<seq>.check.json` for a judge, null otherwise), `retry`, `signs_path`, and `prev_attempt`. An until session also publishes `live_attempt` ([checking an open session](#until-checking-an-open-session)). A step's context adds `visit` (its outcome/key bucket count at admission, including this launch or push-back) and `visits` (total since the last full reset). The live attempt stamps `visit` at launch and at each admitted push-back; the context, `live_attempt.visit`, `prev_attempt.visit`, and the attempt journal row keep that latest number through resets alone. Older attempts without a stamp use the current bucket count. `prev_attempt` exposes the step, attempt outcome, admitted outcome (`routed_by`), sequence, visit, key, start and end, claim path, handle, supervised run id, HEAD pair, stopped and surviving children, ask or limit evidence, cost, exit `code`, and `log`, with null for whatever was not observed. Signs and the run prompt compose only agent prompts and message-step messages.

### Command-step settlement

`crates/rimz/src/harness/workflow/state.rs::Transition::finish_script` is the end-recording entry for non-agent attempts across the hosting advance, bound, cancel, and dead-host reclaim. The node table decides the journal shape: a step records `Attempt` and `prev_attempt`, a check keeps the engine `Evaluation`. Agent and command steps share the attempt journal and routing tail. Exit 0 is `ended`; nonzero, an external signal, spawn failure, and log-open failure are `died`. These and a step timeout (`timeout`) follow `then` with the original input. The run deadline is `canceled` and follows `on.deadline`; cancel is `canceled` and terminal. An interrupted child whose bound was extended before settlement is `canceled` and follows `then`.

Only an interrupted child is classified by the bounds at settlement. A child that exited on its own keeps its exit outcome; the next prepare applies any still-due run deadline. Another advance meets the same rule: `Transition::bound` leaves a step whose published child has exited to its live host, and that advance stops. The hosting process samples HEAD after reaping, off-lock. Other settlers leave `head_end` null. `code` is null for a signal or an unobserved exit, and `log` is set only when the step log exists. Agent-only evidence is null, while `claim_path` still names the sequence's claim file. Both new evidence fields default when absent in older records and journal rows.

Command steps bypass `AttemptHost`, prompt composition, provider windows, and occupancy completely. A message step bypasses windows, occupancy, capacity, and the throttle too, and never reaches `script::execute_step`: `prepare` composes its text before it publishes the `LiveAttempt`, so the digests are recorded, mints `LiveAttempt.message`, and returns `Decision::Message`. `engine::message_step` then calls `AttemptHost::message` off-lock (the CLI host resolves the address from the scope's directory channel among living addressable agents, queues `HarnessNotice::Wait` automated at gate `Done` with `queue_message_once` under that id, and attempts delivery at once), holds at `RIMZ_TEST_WORKFLOW_RESULT_GATE`, relocks, and settles through `Transition::finish_message`: `ended` with the target handle follows `then`, `died` with the reason routes `undelivered` with `ParkReason::Invalid`. A compose error takes the `died` path without a host call. A dead host's attempt with a `message` id is re-sent under the same id by the next advance's `prepare`, not canceled, and the queue keeps one copy; the attempt journal row carries the id. The common cap check still precedes visit and sequence allocation. A fast cycle has no new throttle: it can consume its cap within one advance, so workflow authors route through a waiting check.

Three windows stay open. Only the hosting process writes the step log, so when another advance enforces a bound on a stalled host, the next check can read the log before the host drains what the killed child wrote. A host killed after the spawn and before it publishes the child leaves `child` unset, so the dead-host reclaim kills nothing and the command can outlive its settled attempt. Checks share that second window. A live host that stalls (SIGSTOP, a frozen cgroup) after its command's group leader exits holds the step: `Transition::bound` leaves it to that host, so no other advance enforces the step timeout or the run deadline, and a group member still running keeps running. The host's own bound kills the group once it resumes, and the dead-host reclaim kills it once the host dies. Waiting for the group to empty would close this window only by reopening another: `kill(-pgid, 0)` succeeds while the exited leader is still unreaped, so another advance would again overwrite the exit the host is about to record.

### Check answers

Run checks save complete stderr to `work/<seq>.check.log` after the bounded runner returns, creating the file even for an empty stream. Stdout remains the answer, and invalid evaluations retain the journal's 4096-byte stderr tail. The push-back brief looks backward for the `TurnEnd {pushed}` matching `attempt.push.message`, then that check's preceding evaluation sequence. It names that check and measures `.check.log` for run/shell or `.check.json` for a judge with `FileSummary`; reason precedes the output path/label, and empty or missing files say `no output`. No file content is copied. Without a matching row it falls back to the step's first check and omits the output line. The durable push-back and journal formats do not change.

A run check or a judge answers exactly one JSON object: a required string `outcome`, an optional string `reason`, an RFC 3339 `recheck_at`, and a string or integer `key`. Other fields stay in the object as payload. The full normalized object (`crates/rimz/src/harness/workflow/state.rs::normalize_object`) becomes the next node's input, and a missing key inherits the run's current key. A sleep journals its own answers but forwards its incoming input and key on routes other than `@break`, including legacy invalid and deadline parks; the next step's visit bucket therefore still uses the incoming outcome. A route to `@break` instead supplies the failure object plus `edge` and `from`, preserving the inherited key.

For a run check, these route `invalid` with an engine object: a nonzero exit, stdout that is not one object, a wrong field type, an unrouted or reserved outcome, a bad `recheck_at`, and a `run` file that no longer resolves. A judge's failures settle differently ([Headless judges](#headless-judges)).

`recheck_at` only delays a `@wait`. `Transition::bounded_recheck` clamps it to the earlier of the check's timeout and the run's unfired deadline, so the tick cannot sleep past either bound. A judge's provider-limit reset is clamped the same way.

### Shell checks

A shell check runs through the loop's `crates/rimz/src/harness/schedule/runner.rs::run_command` in its hosted mode, with no SIGINT listener. A shell check or step goes through the same `rimz loop check-exec --command` trampoline as a loop check, and a run step through `rimz loop check-exec -- <argv>`, which execs the argv without a shell. The host first resolves `sh` or the run step's program on the child's `PATH`, so a missing program stays a spawn error rather than the trampoline's exit. The trampoline calls `setsid`, so the command leads a new session and process group with no controlling terminal, and a command that opens `/dev/tty` cannot stop on the caller's job control. Before polling, the spawn callback publishes the leader under the workflow lock, and a callback error kills the group and returns the error. A child killed before its trampoline reaches `setsid` leads no group yet, so `Transition::kill_child` falls back to killing the leader's PID when `killpg` finds none. The interrupt predicate runs every 20 ms, kills the group at once, and bounds pipe draining to 200 ms. Output is teed to `work/<seq>.check.log`.

The engine builds the answer from the exit: `pass` for exit 0, otherwise `fail` with a reason (the [reference](../../reference/cli/workflow.md#json-shapes) owns the shape). Digests are empty and no tail is journaled. A spawn or log-open failure routes `invalid`. The workflow's own timeout and deadline interrupt through the same predicate and settle through the engine's bound routes, never as `fail`, and no loop default timeout applies.

### Conditions and holds

A condition runs the same prepare, evaluate, and settle protocol with kind `script` and no hosted runner child (`crates/rimz/src/harness/workflow/script/condition.rs::evaluate`). The loop evaluator and leaf matcher stay two-valued. A projection used only by workflows computes Kleene truth from the readings: the first true case wins, an unknown case before it answers `unknown`, and all false selects `else`.

Every forge reading is cleared unless the latest probe succeeded at or after the forge floor. A held evaluation uses `held.entered_at`, the session's step entry; every other evaluation uses `record.entered_at`, the check's entry. The same floor gates the CI commit fence. The check timeout still uses `record.entered_at`, the hold time while held. Stage and projected usage-window readings have no such floor. For ordinary checks the floor has two latency costs: a check can wait about five minutes at idle probe cadence, and consecutive forge checks each wait for a new probe. A closed room leaves the last facts that pass the relevant floor in force. The answer carries the winning case index (omitted for `else` and `unknown`), the inherited key, the readings after the floor and commit fence, and, for `unknown` only, a reason naming each unread key. A held floor's reason names the session's start rather than the check's entry. Its origin is `check` and its digests are empty.

After the floor passes, bare `ci` on an Open link with a nonempty `open.head` is fenced by commit. First, a readable local HEAD differing from the PR head makes `ci` unread only when `git merge-base --is-ancestor <local> <pr_head>` exits exactly 1. Otherwise, a known, nonempty `ci_sha` differing from the PR head makes it unread. Rule 1 wins when both apply; the floor's reason precedes both. The [reference](../../reference/cli/workflow.md#json-shapes) owns the two reason forms. An unreadable local HEAD skips rule 1, not rule 2. An ancestry exit 0, 128 (including an unfetched PR head), other exit, timeout, or spawn error also leaves rule 2 to decide. An unknown `ci_sha` skips only rule 2. Without a PR head, including legacy empty heads, merged or closed links, Gitea, and GitHub facts misses, the floor alone applies. Branch selectors, `pr`, `pr.queue`, `pr.mergeable`, `pr.review`, and PR-less `branch_ci` have no commit fence and remain subject to propagation lag. Loop conditions share the floor and the fence through `crates/rimz/src/harness/schedule/when.rs::forge_unread` and `crates/rimz/src/harness/schedule/when.rs::CiSource::ci_fence` ([loops](./loops.md#condition-planning)).

The evaluator reads the cache once, then reads fresh local HEAD in the scope path, comparing the PR head with local HEAD and `ci_sha` with the PR head. Both git reads live in `crates/rimz/src/harness/schedule/when.rs::CiSource::ci_fence` and are bounded at two seconds through `crates/rimz/src/proc/mod.rs::run_bounded_git_output`; the sidebar graph reaches them through loop conditions, and they only read. Git runs only for a case naming bare `ci` after the floor passes and an open PR head is known; ancestry runs only when local HEAD differs. Settlement under the workspace lock does not re-read either input: the answer describes the cached PR head at `checked_at`. A later commit or push is a new fact for the next evaluation in this check, or on returning from a step.

No probe cadence or signal changes accompany the fence. A local HEAD change nudges one probe; if it beats the forge, the next probe uses the repository TTL (20 seconds hot, 300 seconds idle). CI signals fire only on verdict changes, so `failed` at an old commit becoming `failed` at the new one is sampled by the minute workflow tick rather than a CI signal. The wait therefore adds up to a tick after the cache catches up.

Settlement under the lock decides holds, never the off-lock evaluator. A winning case with `for` merges a wait keyed by `(outcome, case)`, with outcome `hold`, the case's outcome as detail, and the case index in `Wait.case`. A hold keeps the run's routed input and key. Once `now - first >= for`, the case routes its own outcome and any matching visit reset fires. Any other answer closes the hold, and a later true case starts it again. Ordinary check evaluations recompute the bounded `first + for` recheck, so a wake keeps `first`. The tick re-samples an ordinary hold before its recheck time, and a transition that falls entirely between two samples goes unseen. A held until wait also rechecks on those signals and the minute tick, while its leader rests on the judged turn.

### Sleeps

A sleep evaluates in-process with no child, digest, or stderr. Its nonzero `sleep` duration runs from `record.entered_at`; entry through a route or a parked resume restarts it. Its required `then` names a node or terminal target, never `@wait`. An until step cannot name a sleep as its `then` check, because that check samples leader turn ends rather than running an independent timer. Sleep accepts `on.invalid` under on-break defaults; legacy sleeps retain the hardcoded `@user` route. It ignores `wake`, other `on` routes, `timeout`, `else`, `window`, and `prompt-file` with dotted warnings.

Expiry is checked first and answers `{outcome: then, reason: "slept <sleep>"}`. Before expiry, a plain sleep answers `{outcome: sleeping, recheck_at: <entered_at + sleep>}`. That stored edge is clamped to an earlier deadline, and the tick does not spawn before it. A plain sleep journals just its entry and expiry evaluations.

With `when`, `Check::condition_cases` supplies one derived case with outcome `then` and the optional `for`; the same condition evaluator supplies freshness, unread handling, subscriptions and hold settlement, with fallback `sleeping`. `sleeping` and `unknown` store no recheck, so the minute tick keeps sampling, and matching signals wake it earlier. Expiry may be about a minute late and wins over an unfinished hold. `for` warns and is ignored when invalid, zero, absent `when`, or at least `sleep`. Sleeps have real `sleeping → @wait` and, with `when`, `unknown → @wait` edges, so they bound check-only cycles without a timeout. Definition views hide those default edges and the derived case, printing `sleep`, `when`, `for`, and `then` instead. List detail and the show headline read `sleeping 12m/30m when ci=passed → fix`, omitting `when` for a plain sleep and never appending a recheck clock.

### Waits and parks

A wait keeps its node and the node's original timeout clock. Repeated identical waits merge in the record (`first`, `last`, `count`, `recheck_at`), and leaving the wait appends one summary to the journal. A check wait's span runs from the answer that opened it to the newest answer merged into it. An advance that arrives before an ordinary wait's `recheck_at` increments its count and moves `last` to that advance without evaluating. A hold is re-sampled instead.

For legacy runs, `@user` parks with the typed bound reason or the check object's `reason` text. A check-timeout park carries no text of its own; the flushed wait and last shell-check log explain the timeout in `show`, and `show --history` keeps the check answers. `@done` and `@failed` end the run.

### Bounds

Every advance checks bounds before routing; an agent observation first updates its live ask hold. The engine routes a bound with an engine object that inherits the current key:

| Bound | Fires when | Input object | Route |
| --- | --- | --- | --- |
| Deadline | Once, when the unfired deadline passes. It stops gating until `--extend deadline` re-arms it. | `{outcome: deadline, deadline: T}` | `on.deadline` |
| Check timeout | The check's `timeout` after `entered_at`. It spans every evaluation and wait at the node. | `{outcome: timeout, node: C, timeout: S}` | `on.timeout` |
| Step timeout | The turn step's `timeout` after the attempt started, excluding closed ask pauses (`asked_ms`); never due while `asking` is set. | The run's routed input | Ends the attempt as `timeout`, then `then`. |
| Visit caps | Before launch, the total visits reach `max-visits + visit_grant`, or the current outcome/key bucket's visits since reset reach the `max-visits-per-outcome` limit plus `visit_grant`. Total is checked first. Nothing launches, and no visit or sequence is consumed. | `{outcome: cap, step: S, bound: "max-visits" or "max-visits-per-outcome", visits: N, max: M, routed_by: "name" or null}`. `routed_by` preserves the capped bucket's outcome for re-entry at S. `visits` and `max` belong to the tripped bound, with the grant included in `max`. | `on.cap` |

## Agent attempts

Agent steps launch through `launcher::prepare_layout` and `launcher::execute`, with room Birth and a detached leader run (`turn` for turn steps, `session` for staying steps). They open an unfocused new tab titled `run <leader kind>`, never as the advancing agent's children. The leader retains supervised preflight and defaults an unset permission mode to Auto; companions use layout preflight with loop-equivalent trust verdicts and workflow-named refusals. Every agent cell carries `WorkflowAttemptRef {run, seq, role}` and pins `RIMZ_WORKFLOW_RUN`, `RIMZ_WORKFLOW_DIR`, and `RIMZ_WORKFLOW_DEFINITION` under every isolation level. Only the leader has a run; command cells follow its durable record and close themselves after it settles. RimZ-launched children do not inherit this attempt identity, but do inherit the separate [automation stamp](../agents/model.md#the-rollup) naming the workflow and launching step. `LiveAttempt.lifecycle` explicitly decodes a missing value as turn and omits turn on write, preserving legacy in-flight attempts independently of the definition's until default.

### Admission

Admission checks, in order, bounds, the visit caps (total first, then the current outcome/key bucket, whose count is zero before its first visit or after reset), each agent cell's provider window, checkout occupancy, workflow/step limits, the machine FIFO when machine-gated, and both machine caps for an automatic loop-started agent step. Unless `throttle = "off"`, the start also checks machine stagger, resources, and the capacity script. The caps and workflow/step limits apply even to an `off` step; manual or detached starts claim without capacity waiting. Each blocked window, occupancy, or capacity check merges a wait that keeps the routed input and key and spends no visit or sequence:

| Blocker | Wait |
| --- | --- |
| The step's `window` is closed for any agent cell's provider. | `window`, with the blocking term and its reading in `Wait.detail` (`5h.left=12<42`), which the waiting line prints. |
| An occupant is mid-turn. | `takeover` |
| An idle occupant, and the step has neither `takeover = true` nor `share = true`. | `occupied` |
| The shared start throttle or a workflow/step limit holds the step. | `capacity`, with `Wait.kinds`, `Wait.detail`, optional typed `Wait.hold`, and optional `Wait.gives_up_at`. The kind survives retries and closing the wait into history; legacy waits omit it. |

Who occupies the checkout follows the [shared takeover occupancy rule](./loops.md#condition-planning). A step with `share = true` skips the occupancy read and eviction entirely and never records a `takeover` or `occupied` wait, while window, capacity, and visit bounds still apply; its agent still counts as an occupant for later steps without `share`. `takeover` and `share` together refuse at `steps.<n>.share`. At the project root, owned nested worktrees are excluded. A step with a `worktree` destination reads occupancy, and evicts, at that destination rather than at the run's scope (`crates/rimz/src/harness/workflow/engine.rs::prepare`), and a takeover there relaunches the destination's stopped team cohort fresh rather than resuming it. With `takeover = true`, capacity is decided before eviction, so a capacity-held step never stops the occupant. Admission runs off-lock in its own round trip, and each return re-reads bounds, visit caps, window, and occupancy. Eviction is part of the launch (`StepLaunch.evict`): the CLI host prepares the launch first, so a launch its preparation refuses (a saved-untrusted folder, untrusted hooks) stops no one, then stops the occupants and executes the prepared launch. The host reads the checkout again there even when the first read found it free: a takeover stops an occupant that arrived while the launch was prepared, and the host returns any other occupancy it finds (`crates/rimz/src/cli/workflow/host.rs::Host::evict`). The engine then takes back the attempt and the visit it counted (`Transition::withdraw_attempt`) and waits `takeover` or `occupied` as the first read would, with no failure or strike. An eviction error, launch-group resolution error, or admission error becomes a counted `died` attempt following `then`, except that an oversized agent group forces `@failed`, never `then` or `on.capacity`.

`advance` asks `schedule::throttle::try_admit` at most once per next-sequence/node pair and carries its answer into the next locked `prepare`. A route can change the node without allocating a sequence, so either part changing discards the answer and its turn. The kind/account grouping uses the same launch-cell resolution as the window. A held answer leaves no ticket and persists `step_wait("capacity", reason)`; the minute tick retries it. `Wait.first` survives consecutive capacity holds, but another wait outcome restarts it. At its give-up time, the engine journals a `capacity` route with input `{outcome: "capacity", step, reason, kinds, waited_ms}` plus the inherited key, then follows `on.capacity`; the run deadline remains an independent bound. Admission carries its optional turn through `StepLaunch`, `LeaderRun`, and `prepare_run_layout` to `SupervisedRunRequest.throttle_turn`, reported by `open_fresh`. Any other ending drops the turn. Runs with no `task` or with `manual = true` take no turn unless a limit applies, in which case they evaluate the holds a scheduled start would meet, only to record the first, never to wait, and claim an `Admitted` ticket. Command steps, checks, and existing staying sessions never take a turn.

The manual pass shares the scheduled `launching` / `limits::evaluate` expression under the queue lock, before writing the admitted ticket and before any launch stamp moves. Only workflow/step holds become notes, never machine holds. A census or stamp read failure admits without a note; with no configured limit it skips the census entirely. Restarts use this manual pass too. The admitted `Turn` carries the skipped hold into `prepare`; held, open, or errored answers carry none. No assist is written: the start is the user's action.

`crates/rimz/src/harness/schedule/throttle/limits.rs` owns the locked limit pass. The request carries workflow name, step, asking run id, capacity arrival (`Wait.first`, or the current request instant), sealed limits, and whether it may wait. Admission first refuses an automated group larger than any applicable cap, naming the cap and its fix. Otherwise, under `loops/throttle.lock`, an in-flight turn of the same limited workflow comes first, then FIFO, workflow count, step count, workflow stagger, step stagger, the machine queue when machine-gated, both machine caps, and finally machine stagger and resource checks when machine-gated. Every limit hold, the in-flight one included, is reported under its limit kind before any machine hold, so a waiter keeps its FIFO standing on a pass where the machine also holds it. Every cap requires the whole incoming agent group to fit. Other admitted-but-unlaunched starts reserve their agent counts under the same lock; a same-workflow in-flight turn keeps limited starts serialized until the rows are visible. No workflow or step limit bypasses a machine cap.

The census counts rows only, using `crates/rimz/src/harness/schedule/throttle.rs::open` across every known room. Workflow scope selects rows whose `automation` stamp names that workflow; step scope also matches its step name. Companions and RimZ-launched children and peers count separately, provider-built-in subagents do not, and an open row of a terminal run still counts. No supervised-run read or leader deduplication participates. Workflow records are read only for FIFO waiters. An unreadable required room or stagger record holds a scheduled start as `store`, never as a short count or absent stamp.

FIFO reads Active same-workflow capacity waiters ordered by `(Wait.first, run id)`: `workflow_limit` holds every step, `step_limit` only its matching step. A free slot can remain idle until the earliest waiter's next minute tick. Hold text prefixes `workflow <name>: ` or `step <name>: ` to `N of M agents open (@a, @b, +K)`, `next start in <duration>`, `N earlier start(s) waiting`, or `N start(s) launching` while a same-workflow launch is not yet counted (named for the workflow limit when one is set, else the step). Cap reasons name multi-agent demand separately (`this start opens 2`). Names use the shared `name_counted` rule, at most two handles then `+K`. The existing capacity give-up path for temporary holds is unchanged.

`Turn::report_launch` alone stamps `loops/start-stamps.json`, resolved by `crates/rimz/src/disk/paths.rs::loop_throttle_start_stamps`, under the same queue lock as the launched ticket. The record has `machine` (an optional launch timestamp in milliseconds) and `workflows` (workflow name to `last_launch_ms` and a `steps` map of step names to timestamps). Only machine-gated launches set `machine`; limited launches set their workflow and step stamps. It uses the queue's rename-atomic cache writer, not per-launch fsync; process crashes retain completed replacements, while power loss can lose the newest queue or stagger write. Missing means no prior launch; when scheduled admission needs a configured stagger, malformed or unreadable holds as `store`. An unreported dropped turn stamps nothing. Manual limited launches reserve in-flight scope and restart workflow and step stamps without waiting, but neither manual nor `off` launches restart machine stagger.

Prompt composition and `git rev-parse HEAD` run under the lock after the first bound read, and they take time. So `prepare` takes a fresh clock after them and reads the bounds again, and a bound that came due meanwhile routes without publishing an attempt, spending no visit and no sequence. Only after that second read does an admitted launch count the visit, record HEAD, and publish its context and live attempt, stamped with the fresh clock. The bounds are re-read rather than the work moved off-lock, because admission and publication share the lock on purpose. After prompt composition the window reading is not re-read: it was sampled in the same pass, and provider windows move in minutes.

### Prompt composition

`crates/rimz/src/harness/workflow/engine/agent.rs::compose` joins three texts with blank lines at every launch: the prompt file, `signs/<step>.md` when present, and the run prompt. A sign's canonical path must stay inside `work/`. The digests are keyed by the spec's prompt-file spelling, `signs/<step>.md`, and `prompt`, and absent optional text has no digest. A relaunch can find a dirty checkout left by a stopped attempt, and the step's prompt must handle it.

`crates/rimz/src/harness/workflow/engine/agent.rs::break_prompt` classifies the current input edge and node, not past failures. Its trace includes the last six source entries, the latest evaluation, history/evaluation counts and the last eight journal entries. Judge evaluations name `.check.json`, run/shell evaluations `.check.log`, and conditions/sleeps no file. The serialized excerpt is capped at half the text-prompt guard, leaving room for the surrounding instructions; full journal and context paths remain outside the excerpt.

`crates/rimz/src/harness/workflow/brief.rs::step` composes a separate `### Workflow` launch-reminder body off-lock in `engine::agent::launch`, from the sealed spec and published, bumped run record. It reads the journal through the same `routing_hop` rule as `show`, and the lenient task catalog from the project root, including disabled visible tasks, for the current trigger. A resume counts as the sender after a park or when returning from `@break`, even before its agent launches; an active run's `--extend` does not replace that sender. Unreadable enrichment drops only the arrival sentence or trigger clause. The rail follows `WorkflowSpec::walk`, groups returning steps beside their check, and draws arrows only for live non-deadline routes; unreachable nodes stay out even after an explicit resume there. Visit bounds include resume grants. `StepLaunch.workflow_note` travels through the leader's supervised request as `ReminderSection::Workflow`, never as a `Loop` section; companions get no section, and a step's subscriptions are its own `subscribe` wakes. `crates/rimz/src/harness/workflow/script/judge.rs::run` sets the shorter `brief::judge` section on its headless request without changing the prompt's JSON contract. The notes point models at workflow views, not raw context files. Ordinary agent resume refuses current workflow pins, and rebirth skips them. Workflow restart, including `agents restart` of a current step, recomposes the note for its fresh or resumed leader.

The leader's check descriptions follow `then` list order: conditions retain their cases, scripts and shells show command plus optional summary and their distinct execution/path rules, and judges show only a summary. A sealed judge without a summary gets a fixed agent-judge sentence, not its prompt filename. Script and shell descriptions explicitly allow the agent to run the command itself.

### How an attempt ends

`crates/rimz/src/harness/workflow/engine/agent.rs::prepare_end` observes once, stamps the clock after observation, and updates the hold before deciding an end, in this precedence order:

| Condition | Outcome / effect | Route |
| --- | --- | --- |
| Unfired run deadline at or before now | `canceled` | `on.deadline`, once |
| Turn step, no open hold, `started_at + timeout + asked_ms` at or before now | `timeout` | `on.failed` when set, else `then` |
| Supervised run `completed` | `ended` | `then` |
| `failed`, `verify_failed`, or `timed_out` | `died` | `on.failed` when set, else `then` |
| `canceled` | `canceled` | `then` |
| `budget_exceeded` | `limited`, with no known reset | `on.failed` when set, else `then` |
| Live run, observed provider limit, error, interrupt, or budget park | Keep the attempt live | None |
| Turn run `pending` or `running`, blocking ask, explicit `on.asked` | `asked` | `on.asked` |
| No supervised run and dead launch host | `canceled` | `then` |
| Until attempt, new eligible leader turn end | Hold the session aside and evaluate `then` | Saved verdict decides keep or close |
| Otherwise | Keep the attempt live; persist only a changed hold | None |

The `on.failed` column is one rule, `WorkflowSpec::routes_on_failed`: settlement (`Transition::settle_step`) and the routing lookup `WorkflowSpec::target` that `workflow show` draws from both read it, and `inspect::attempt_superseded` folds a `died`, `timeout` or `limited` attempt into the `failed` route that follows it, so the trail prints one hop.

The terminal-status and explicit-ask mapping is one pure function, `crates/rimz/src/harness/workflow/engine/agent.rs::observed_outcome`; timeout and deadline stay outside it. Live provider limits never end an attempt. A pending ask therefore beats the step timeout even with `on.asked`, but not the deadline or cancel. A completed run still ends `ended` even if an ask remains visible.

For turn, stay, and until attempts, `LiveAttempt.asking` stores `{since, text, kind, handle}` while a blocking ask is observed. `held_since` opens one shared hold at the earliest ask, limit, error, or budget-park evidence, clamped to `[started_at, now]`; `asked_ms` stores closed held time as u64 milliseconds. Overlapping evidence keeps the hold open and is credited only once, when all pausing evidence clears. Silence and interrupts do not hold the timeout. A legacy open ask without `held_since` supplies `asking.since`. Optional fields default when absent and are omitted when empty or zero; the engine raises old records to version 3 before publication. An ask's visibility normally begins at its open time; a Codex Auto permission is hidden during automatic review and becomes visible 60 seconds after arrival unless the rollout proves the asking Code Mode cell finished and closes the ask, so review time does not pause the attempt timeout ([waiting and asks](../agents/model.md#waiting-and-asks)). Further asks keep their interval's start and replace its text, kind, and handle. A stable hold writes nothing, and a hold-only write journals and accounts nothing. Already-ending attempts do not update the hold; staging any end clears it.

Leader lifecycle hooks wake the run; subagents have no workflow pin and are sampled by the roughly one-minute tick. Two holds without an intervening observation merge into one pause, and a subagent's answer may remain credited and displayed until the next tick. A step already overdue when the hold opened times out after it clears. Old `asked` parks and already-staged `asked` ends still settle and resume as before, including the `@user` fallback when the sealed step has no `on.asked`. Records without pause fields start with no pause.

A route through `then` forwards the run's routed input unchanged, with the current key: the attempt's outcome and evidence go to `prev_attempt`, never into the input. A queued asynchronous question does not end an attempt. The host reads asks by ask id and limits from typed turn-error classes, taking the reset from the affected agent's account and model, never from provider text. A launch refusal is `died`, or `limited` for a budget refusal, with the refusal text as the attempt's reason.

Workflow-owned supervised runs record an errored `TurnEnded` or `TurnInterrupted` as optional `stopped_turn = {at, disposition: failed | canceled}` rather than a terminal status. They remain Running and clear any inherited owed-wake `parked_at`; the next `TurnStarted`, `ToolUsed`, `AwaitingInput`, or clean end clears the evidence. Non-workflow runs keep their terminal-disposition table. Session runs record the same evidence across turns. `Observed.stopped` combines this with displayed turn-error classes and the card's budget-park timestamp, as `limit`, `error`, `interrupt`, or `budget`. Failed and interrupted turns do not enter the until check. A turn run's provider exit still becomes Failed and follows `then` as `died`; no new park is introduced.

A staying attempt records live ask holds but does not end on them or live provider limits, and has no step timeout. Turn ends, interruptions, session-end hooks, and RimZ budget parks keep its session run open; `until` adds the check-driven close below. A park still interrupts the provider and stamps its ledger; a budget-gate refusal before launch still reads `limited`. Provider exit completes a registered session as `ended`, or an unregistered one as `died`; a crash after registration also reads `ended`. The run deadline, except at `@break`, beats a completed observation and routes `on.deadline` with outcome `canceled`. Cancel, restart, reset and rebirth also cancel staying attempts. Every `@break` ending detaches its agent, and its wrapper cleanup is disabled. A staying end records no ask in `prev_attempt`, and companion trees never control an attempt's end.

### Until: checking an open session

An until step's `then` accepts a check name or a nonempty list. Graph entry follows the first name; membership keeps a held session open across a route. Each adjacent pair requires a direct live check edge, and until lists exclude sleeps. Other lifecycles and command steps warn from `validate_spec` on a list of two or more checks, not in the loader's ignored fields, then enter the first check normally. A listed move requires the same eligible judged turn as a push or close, closes the source wait, clears the saved verdict and check retry, updates node/entry, and evaluates the destination in the same advance without changing input/key. It writes `TurnEnd {action: kept, check: source, target: destination}`; existing history, hop and assist readers project the route. Every decision names its actual check, including a discard or interruption before a verdict exists. Delays between listed checks are ignored by the tolerant cleaner and excluded by `close_after`; closing delays read the answering check's route. A check reached without a held session keeps ordinary routing behavior.

An eligible leader turn end moves the agent attempt into `RunRecord.held = {attempt, entered_at, verdict?}` and enters its `then` check, with no visit or input/key change. The held attempt is an until Agent attempt with a run, a `judged` turn identity, and no ending; the slot is empty or holds that check's Script/Judge attempt. Held sessions never survive restoration, staging an ending, parking, or terminal settlement. The ordinary check engine owns windows, sequences, publication, retries, limits, timeouts, dead-host reclaim, and CAS while the session is aside. Routing saves `{node, entered_at, at, target, object, reason}` in `held.verdict` instead of applying it; `at` is the evaluation's journal instant.

The identity is `{agent_id, started_at, ended_at}` from the leader's projected turn stamps, with `ended_at >= started_at`; successful compaction at rest can supply equal stamps. An interrupted turn can have a closed identity but is not eligible while stopped. The engine requests `Observation::LeaderTurn` only when preparing an until attempt without a staged ending or observing its held session; turn/stay attempts, cancel and post-stop cost observations use `Observation::Attempt` without leader-turn reads. The host computes rest fresh under the workspace lock: `idle_stop::resting`, no owed wake, no queued message, and no other open supervised run, excluding exactly this session's run id. Pending ingress blocks only when its `RIMZ_WORKFLOW_RUN` names this workflow run and its `RIMZ_RUN_ID` names this leader's supervised run, except exactly the frame named by this advance's `--woken-by` ingress id. Detached former leaders and companion frames therefore do not block the current leader's rest. The waking frame's apply has committed before spawning the advance, but the drainer publishes its applied cursor only after the apply exits; the advance is the frame's wake, not a reason to wait for another one. The exception lasts for this advance's lifetime, including the fresh observation after evaluation; every other pending frame naming this leader's run still blocks. The engine also requires no blocking ask or non-clean stop, descendants included. `LiveAttempt.judged` consumes the identity before evaluation, so restoring the session cannot begin another initial check for that end; a held wait instead re-samples at the check.

Before other preparation, a held preflight observes the session and folds its hold, then checks the deadline and provider exit or budget-exceeded status before considering a verdict. A same-step verdict closes any wait, restores the session, and applies its input/key. It checks both visit caps in that answer's bucket before bumping once and stamping `LiveAttempt.visit`. A capped answer journals the ordinary cap route and closes through that route. Otherwise it publishes `LiveAttempt.push = {message, queued: false}` and `TurnEnd {action: pushed, visit, message}` under the workspace lock, then calls `AttemptHost::push` off-lock. The host composes a System/Done synthetic message and atomically enqueues only if the id is absent from both live queue and all retained history; delivery uses the ordinary message pipeline. A failed or interrupted push retries the same id without recounting. The host's enqueue acknowledgment is persisted only if sequence and message id still match. Restoration keeps the session's sequence, run and step entry time, clears check retry state and `seen`, and rewrites context to the step view. A `@wait` answer instead leaves the session held at the check, clears its saved verdict, merges an ordinary rechecking wait and writes `TurnEnd {kept}` without a visit. A new wait's `first` and every merge's `last` use the answer's `at`; older verdicts without it use the merge instant. Subscribed signals and the minute tick re-sample the held wait. If the leader no longer rests on its judged turn, preflight closes the wait, abandons any check in flight and restores the session with `TurnEnd {discarded, reason: "leader turn moved on"}`; the next clean rest is judged.

A closing verdict needs a fresh locked observation after evaluation. A different or missing turn tuple discards it, keeping the consumed marker; the advance may then check a newer eligible end. An identical tuple that is no longer eligible, or whose route delay has not expired, defers the saved verdict until a later advance, without paying for the check again. The shared `close_after` inspection helper reads the delay from the sealed spec at the verdict's node and outcome, measuring from `verdict.at` (or `verdict.entered_at` for a legacy verdict without `at`); no new record field or version is needed. An identical eligible tuple at or after that instant restores the session and stages `Ended/Lifecycle` with `Ending.route = verdict`, then uses the ordinary off-lock stop or detach. Settlement journals the ended attempt and the closed turn end, restores the check's node and entry time, and applies its route exactly once instead of following `then`. A step destination launches normally, another check sees the ended session in `prev_attempt`, and legacy `@user` parks at the check. Without a held session, the route applies at once, including after `resume --at` the check.

Provider exit and deadline abandon any live check, restore the session, record an interrupted turn end, and stage the ordinary stay ending; cancellation does the same before its existing stop branch. Cancel replacing an already-staged verdict close records interruption and removes `Ending.route`, so late settlement cannot also record a close. Check timeouts still start from the hold's check entry; the deadline belongs to held preflight. Future judge backoff never suppresses paced session observations by the scheduler. A saved verdict resolves before the ordinary check timeout, even with an open wait; signal wakes and active-run extensions do not shorten its delay.

Each judged end or held-wait answer has a `turn_end` decision (`kept`, `pushed`, `closed`, `discarded`, or `interrupted`), carrying the session sequence, step, turn identity, check, and optional verdict outcome/target or explanatory reason. Pushed, closed and kept moves between listed checks book one route assist at the check; a kept wait books only when the wait closes. Discards and interruptions book none. Evaluation, Route and Attempt rows alongside a decision book no additional route or retry/rerun diagnostic. Held evaluations retain ordinary retry/rerun diagnostics without route assists unless a verdict is saved: engine-origin evaluations then book nothing and raise no `WorkflowRetry` or `WorkflowRerun`. Wait, Park and Terminal accounting is unchanged.

`context.json` has `live_attempt = {step, seq, visit, visits, key, started_at, handle, run_id, claim_path, head_start, turn_end}` while an until session has no staged ending, held or in the slot. Its turn end is `judged` or null; it has no outcome, ending timestamp, or ending commit. `prev_attempt` stays the last ended attempt. Check publications retain the check's top-level sequence, output and retry fields without step visit fields; a push-back or discard restores the step view, a held wait keeps the check view, and a close leaves the next publication to replace it.

Accepted boundaries: a turn starting after the final per-run ingress read but before off-lock stop can be cut off, since stopping has no provider/input coordination; fast turns can coalesce into the latest eligible rest rather than a lossless replay; a long check window or judge-limit wait can spend a check whose later verdict is discarded. Publication still appends journal, writes record, then appends assists, so crashes can duplicate a journal row or miss an assist, as for other transitions.

A held forge reading can be one probe old, back to the session's start, rather than from the judged turn. A same-SHA CI rerun or PR reopen inside that turn can therefore read as its earlier state. CI on a new head is still fenced by the PR head. A fact changing after the leader's last turn end is sampled at the next eligible end, using the latest probe, or while held at `@wait` when a subscribed signal or the minute tick re-samples the check.

### Stopping an attempt

Every end publishes `ending` and saves the observation into `prev_attempt` under the lock before anything stops, which keeps the asks and limits the stop would retire. By default, the host stops every pinned layout agent and its tree off-lock, observes cost immediately afterward, then samples HEAD. It then re-locks, checks the sequence and the stopper's identity, journals the attempt, and routes. No successor launches before the stop or detach returns.

For `keep = true`, `StepLaunch.keep` disables the leader wrapper's completion cleanup, and a Lifecycle ending calls `AttemptHost::detach` instead of stop. A legacy push-back cap parked at `@user` remains forced; a cap routed elsewhere detaches. Detach cancels a nonterminal supervised run and clears each matching leader/companion pin through `crates/rimz/src/store/writer.rs::Store::clear_workflow_pin`, stopping nothing. Its `agent.workflow_cleared` event compares the complete expected `{run, seq, role}` again in the reducer; mismatches keep their pin. Existing card fields suffice, so snapshot and rollup versions do not change; older binaries treat the new event as `Other`. Cleared cards are ordinary recovery candidates. `agents resume` refuses a current pin with the workflow-restart fix, clears a former pin only after preflight, and keeps it with a warning when the workflow record cannot be read.

Settlement rechecks a forced ending after off-lock detach. A cancel that replaced the Lifecycle ending still stops the layout before settling. Stop can recover already-detached, unpinned cells from the leader's original launch group; a card pinned to a different attempt is never selected by that fallback.

- A later advance leaves a live stopper alone and reclaims a dead one, merging the staged child evidence with the new stop inventory.
- A cancel during launch leaves the live launch owner to publish and stop the run it gets back.
- When the launcher is dead, the stopper finds the unpublished supervised run by its workflow id and attempt sequence and stops it before settlement.
- Live launched descendants are stopped first; they and companion cells are recorded under `children.stopped`. Independently launched peers and team cohorts survive under `children.live`, with their board stage when available.

Stops use the shared cascade and add no workflow-specific lifecycle events. The next visit's [occupancy read](./loops.md#condition-planning) skips a stopped attempt whose owner has exited, even while its cached row remains. The host stops every unended row with the attempt pin, even if the leader row is absent or ended, plus the detached cohort described above; it falls back to the supervised stop only when neither inventory remains. Attempt cost comes from the leader run after stop or detach; companion spend stays on cards and in stats, and unstamped spend stays null.

## Headless judges

The shared launch compiler reads the pinned run's `spec_dir` for `RIMZ_WORKFLOW_DEFINITION` and the Environment `- workflow:` line, independently of `env_reminder`. A failed record read returns a launch warning and omits both. Non-workflow launches unset that variable alongside `RIMZ_WORKFLOW_RUN` and `RIMZ_WORKFLOW_DIR`.

A judge (`script/judge.rs`) runs through the shared headless profile resolver and the judge core (`crates/rimz/src/harness/headless/judge.rs::prepare`) with automatic permission mode. The core classes a failed attempt, and `Transition::finish_judge` asks its one retry rule (`FailureKind::retry_owed`) whether the attempt is owed a second run. Its profile must resolve to exactly one agent cell, or the evaluation fails (`crates/rimz/src/harness/headless.rs::HeadlessProfile::resolve`). Its Judge section names `rimz workflow show $RIMZ_WORKFLOW_RUN --history`; the prompt names `RIMZ_WORKFLOW_DIR` and `output_path`, and demands exactly one JSON object with the check fields and no prose or Markdown fence. The schema stays open, so extra fields stay routed input. Claude receives it as its schema argument (`crates/rimz/src/agents/adapters/claude/headless.rs::ClaudeHeadless::render_argv`). Codex omits its strict structured-output switch for an open schema and reads the prompt-shaped last message from its output file. Closed schemas, loop verdicts among them, keep Codex schema enforcement. The provider's structured value is saved to `output_path`, the engine reads that file when there is none, and the value goes through the same normalizer as script stdout.

A judge is read-only on the scope checkout and its Git admin and common directories. Scoped isolation overlays them read-only after all reach rebinds, and host isolation enforces the rule only through the prompt. The root view and the required-path rebinds leave `work/` writable, a room home under host `/tmp` included. A judge evaluation never produces `asked`: nothing reads asks from a headless child, and what the provider does with a permission request in automatic mode is provider behaviour. Claude classifies provider limits in its adapter. Codex supplies no typed limit result, so a limited Codex judge fails as `died`. Before it prepares the child, `crates/rimz/src/harness/workflow/script/judge.rs::budget_refusal` reads the judge's resolved account through `harness::budget::scope_gate` (the fleet and account daily caps and the park), then `agents::provider_budget_gate` on the account binding `crates/rimz/src/harness/workflow/script/judge.rs::managed_launch` resolves for the run's checkout, then, when the run belongs to a loop task, that task's surplus gate in the catalog through `crates/rimz/src/harness/schedule/runner.rs::surplus_refusal`; a refusal is the `budget` failure, which `Transition::finish_judge` routes to `@failed` with a `budget` route row, and `run_log::report_run` reads that row as `budget skipped`.

Folder-trust and adapter minimum-version checks run before the judge takes the workspace lock to spawn. A failed judge evaluation settles by its failure (`Transition::finish_judge`):

| Failure | Result |
| --- | --- |
| Engine-decided `canceled` (dead host) | Re-runs free. |
| Typed provider limit | Spends no retry. Waits until the known reset, clamped like `recheck_at`, or until a subscribed wake or the tick when the reset is unknown. A matching wake clears a known reset's backoff. |
| `died`: a launch refusal, a nonzero exit, no object, or an output file that is not JSON. `invalid`: an object the normalizer rejects. | One immediate retry with `context.retry = {outcome, reason}`, then `on.invalid` (explicit, on-break, or the `@failed` floor) with `outcome: "invalid"` and the original kind in `failure`. Legacy `park` records park as `check`. A launch refusal carries its text as `reason`. |

The record stores `check_retry` and `check_retry_context`, so retry evidence survives a dead host without reading the journal. Both reset on node entry and on a parked resume.

## Wakes

A wake only spawns an `advance`, which reads the record again. `run`, `resume`, and `restart` spawn one, and `rimz workflow advance <id>` is the manual form. There is no signal replay: a lost wake delays progress until the next tick.

### The signal helper

Every signal routed through the scheduler's shared firing entry, except lifecycle signals, spawns one room helper when the room has an active run (`crates/rimz/src/harness/schedule/signal.rs::wake_workflows`). That path only reads records and spawns, carrying the whole signal as JSON in the helper's argv. The helper (`engine::wake`) takes the workspace lock per run, reloads each active run and its sealed spec, and matches the current check's subscriptions and the live staying session's step subscriptions, through the same delivery matcher as loop triggers. A sibling skip does not wake. A run where neither matches gets no write, journal entry, or spawn.

On a match the helper clears the record's and the wait's `recheck_at`, journals the signal name, and marks a live evaluation and held session `woken`. Publishing a new held check request clears the session flag before reading its inputs. If a wake arrives during that check or before its saved `@wait` merges, the merge clears the new backoff and re-evaluates immediately, once, bypassing the hot-loop guard for that wake. Ordinary evaluation settlement does the same for a woken `@wait`. Wakes during the retry can ask for another pass, and without one the ordinary guard applies. The helper spawns one `advance` per matched run, so one slow script cannot hold back another run. A run that fails to load warns without blocking the others.

A step subscription forwards to the leader of `RunRecord::session_attempt` (`engine::subscriber`) only while that attempt is not a turn, has no staged `ending`, and has a supervised run. The held until session counts, so a check and its held step can both take one signal. The helper mints the message id under the lock and records it in a `signal` journal row keyed to the session's step and seq, then queues the message off-lock through `AttemptHost::forward`. The CLI host queues it once under that id, as `Type: SIGNAL` from `@rimz` (`HarnessNotice::Signal`), automated, at the done gate, with `about_run` naming the attempt's run, then attempts delivery at once as `Host::push` does. A run that ends before delivery cancels the message there (`message/deliver.rs::cancel_moot_message`), so subscriptions retire with the attempt on every path that ends its run. The text opens with `signal_subject` and the details the loop's SIGNAL delivery prints, then the workflow, step and run id. A step-only match writes only that journal row: no record write, assist, or advance. A failed queue warns and keeps the row. A check match writes the row in the same transition as its `wake` row.

### Subscriptions

A step's subscriptions come from its `subscribe` list (`Step::subscriptions`); the tolerant loader drops them on turn, command, and message steps. A check's subscriptions come from its `wake` list, or, for a condition or conditional sleep, from its terms (`Check::subscriptions`). A plain sleep has none:

| Condition term | Derived selector |
| --- | --- |
| Checkout `ci` | `ci.*` |
| Checkout `pr`, `pr.queue`, `pr.mergeable`, or `pr.review` | `pr.*` |
| Stage | `team.stage` |
| Stage with a branch selector | `team.stage` with `board = "*"` |
| Forge branch-selector or `window.*` | nothing |

Negated terms derive the same selectors. At match time, never persisted, and for checks and steps alike (`engine::delivers`), `ci` and `pr` selectors add `path = scope.path` unless `path` or `branch` is explicit, and `team.stage` adds the board `crates/rimz/src/harness/scratch.rs::durable_board_path` resolves for the scope unless `team`, `instance`, or `board` is explicit; the branch form's explicit `board = "*"` keeps it room-wide, since its board lives in another checkout. Other families stay room-wide. A checkout relink therefore follows its new archive, and project scope matches the project root. A check with no subscriptions runs only on its recheck time and the tick. A matched wake still clears a hold's or a judge limit's backoff.

### Supervised-run edges

An agent step's supervised run wakes its own workflow directly, through `engine::wake_run`. Every newly terminal run write through the harness wakes the run named in its `workflow` field after releasing the workspace lock: provider exits without hooks, wrapper failures, timeouts, and rebirth cancellation included ([scripting.md](./scripting.md#the-record)). Workflow budget parks never settle a run. A hook-ended run that is not a peer turn settles its session spend before the wake, so the advance reads the stamped cost. Non-terminal lifecycle and turn-error frames carrying `RIMZ_WORKFLOW_RUN` wake only that run. An advance spawned inside a frame's apply names that frame's ingress id on argv (`--woken-by`), so its own still-pending frame cannot defer rest; advances outside an apply carry no waking id.

Room teardown cancels supervised runs without waking workflows, and the next advance settles those attempts. Rebirth excludes every workflow-pinned cell from recovery and cancels nonterminal workflow runs even outside the roster, unless a live provider or wrapper still serves them, then wakes each workflow to decide again. A stop never closes a supervised run's pre-rebirth pane id in the new session. A descendant's frames carry no workflow pin, so its asks and limits are sampled at the next step edge or tick, within about a minute.

## The tick

`crates/rimz/src/harness/schedule/fire.rs::fire_due_tasks` ends every scheduler tick, from the room host or the external timer, by calling `tick_workflows` for the root. It reads the room's run records and spawns `rimz --root <root> workflow advance <id>` for each due active run. A run is due when it has no `recheck_at`, when its `recheck_at` or its unfired deadline has passed, while it holds a condition case, or while an until session is held. Parked and terminal runs are never spawned. The engine decides everything else (bounds, window, occupancy, capacity, a live host). The tick reads `recheck_at` so that early advances do not inflate an ordinary wait's `×N` count, and it never clears backoff the way the signal helper does. Under the systemd timer the spawned advance leaves the oneshot service's cgroup, as a loop run does.

Spawns are paced by the runtime cache `lanes/workflow-tick.json`, a map of run id to last spawn: at most one spawn per run per 60 seconds (`WORKFLOW_TICK_SECS`), except that a `recheck_at` or deadline that passed since the last spawn fires at once. A plain sleep stores its end as `recheck_at`, so it gets no intermediate spawn; a conditional sleep stores no end backoff, so it keeps sampling each minute, including during a hold. The tick writes the cache before spawning and drops runs no longer active. A read failure counts as an empty cache, and a write failure warns and skips that tick's spawns. `fire.rs` is in the sidebar import graph, so it writes only that cache and spawns, and the invariant grep keeps it off the writer and the wake socket.

For workflow authors, an ordinary check's `@wait` without `recheck_at` is re-evaluated about every minute, so a check that wants a slower pace names `recheck_at`. An until session's held `@wait` follows the same cadence and subscribed signal wakes while the leader rests on its judged turn. A live step is observed every tick, so a descendant's ask or provider limit is noticed within a minute.

A held closing verdict's route delay expires on that existing minute tick, with no stored recheck edge. Closing can therefore lag the instant by about a minute plus driver spacing. Inspection shows `checking <check>: closing in 23m → <target>` while the instant is still ahead; once due, the normal checking phrase returns if the leader is not yet at rest.

The external timer's roots (`crates/rimz/src/cli/loop_timer.rs::task_roots`) include every room with a nonterminal run, found through `crates/rimz/src/disk/paths.rs::workflow_runs_under`, so a manual run in a room with no loop task and no sidebar still ticks.

## Loop tasks

Every loop fire but an unguarded delivery starts a workflow run: a `workflow = "<name>"` task (`TaskAction::Workflow`) its deployed definition, and every other task the inline graph `schedule/compile.rs` builds from its row ([loops.md § The compiled graph](./loops.md#the-compiled-graph)). The fire's ladder is [loops.md § One fire](./loops.md#one-fire): it checks launch memory, takes the admission lease, births the room when needed, checks memory again, admits the task's daily cap and surplus, then calls `engine::create` with the task's resolved prompt, `task = Some(<name>)`, and `manual` set only for `LoopRunMode::Manual`. The fire takes no start-throttle turn; the run's agent steps ask for their own turns before launching. A scheduled fire of a task that remembers its checkout (`stay`, or `workflow` with `when`) with a launch entry returns `AlreadyLaunched` without a history row, whether the run is active, parked, or terminal. The entry outlives run-record GC. Other tasks neither read nor write these entries and admit a fresh run after a previous run finishes.

After `create` succeeds, `WorkflowStart` stays immediately after creation, then the runner writes a remembering task's launch entry under the run lock before appending its `launched` history row with the `wf_` id. A write failure is logged and attached to that launched row, not reported as a failed creation. `Exists` carries the holder's task and scope kind with its unchanged display text. If that task matches, a remembering fire repairs its entry. The fire then follows the task's `overlap` policy against the run (`runner::TaskFire::prepare_overlap`): a strike-neutral `overlapped` row naming the run under `skip` or for a manual fire, `deferred` under a retaining policy. Later scheduled fires of a remembering task are silent. A foreign holder produces skips without an entry and retries at five minutes while the condition holds. A manual `loop fire` bypasses the entry check and replaces an entry only on a new run. A crash after creation but before recording can start a second run if the first also ends before repair; finished pre-upgrade runs are not adopted.

A task-started run reports its outcome to the task once it ends. `create` marks the record `loop_report = owed`. After the terminal write, `engine::persist` appends the report row through `run_log::report_run` (run id, `completed`, `failed`, or `canceled`, summed attempt and evaluation cost, and whether a step started) and then rewrites the mark as `sent`, all under the workspace lock. A crash between the two leaves the run owed: `fire.rs::tick_workflows` treats it as due, and `advance` on an owed terminal run only reports. The report can therefore land twice, and its readers fold it by run id ([strikes](./loops.md#history-strikes-and-arming)). A record without the field reads `none`, so runs that ended before the upgrade never report. `reassign_task` clears the mark when it detaches a run from a removed task. A fresh judge decline in a task-started inline run appends a `JudgeDecline` assist (`script/judge.rs::record_decline`): a verdict whose route leads to no step or agent check while the opposite verdict's route leads to one.

`each-worktree` takes `workflow` as well as `stay`: the fire runs per owned checkout under that checkout's run lock and stamps `checkout` on its row. A project-scoped condition workflow creates its run at the root and books every checkout, including later ones; other triggers skip only while a live run holds the scope. `stay`, `takeover`, `subscribe`, `check`, `judge`, `throttle`, and `capacity-wait` are refused on a workflow task, each naming the workflow node that owns the concept (`crates/rimz/src/harness/schedule.rs::TaskActionErr::WorkflowField`). `agent` and `wait` conflict with `workflow`, and `account`, `verify`, and `max-attempts` are refused because they need an agent action (`crates/rimz/src/harness/schedule.rs::TaskAction::from_entry`). `rimz loop add --workflow` writes such a row after the same definition validation `workflow run` performs (`crates/rimz/src/cli/workflow_view.rs::deployed_definition`), and refuses at add the flags a workflow fire ignores as well as those the stored row refuses. The trust hash covers `workflow` (`crates/rimz/src/trust.rs::ExecutableTask`).

`RunRecord.task` is the provenance `rimz loop list` and `rimz loop show` select live runs by, together with the record's project root. `loop show` and `loop logs` also take finished runs by `RunRecord::ran_for` (task and project root, any state), and `loop show` joins launch memory by run id, rendering expired records as `gone`. Their RUN targets and `workflow show` commands come from one `crates/rimz/src/cli/workflow_view/resolve.rs::RunTargets` load per command, the resolver `workflow show` runs. A `rimz workflow run` run has no task, so it appears in `rimz workflow list` and the sidebar under no task. A `rimz loop fire` run retains its task and records `manual = true`. `loop list` joins every Active capacity wait of the task's runs with condition waits and waiting tickets: self-clearing starts enter HELD and count in NEXT, while needs-a-fix starts put the task in NEEDS YOU. Its JSON retains the oldest durable `capacity_wait`. `loop rename` rewrites `task` on the task's nonterminal records under the workspace lock (`engine::reassign_task`) and leaves terminal records unchanged; their moved launch entries still name them in `loop show`. `loop remove` uses the same transition with no target task, so live runs continue independently and a re-added task does not adopt them. Finished records keep the name they ran under, so a task re-added under that name lists them in `loop show`.

## Attention

`crates/rimz/src/sidebar/enrich.rs::project_workflow_and_throttle_state` reads workflow records once per fold, producer and passive reader alike, for group projection and `SidebarSnapshot.throttle_notices`. Active `capacity` waits contribute alongside live condition-loop records and room-scoped waiting tickets. Each needs-a-fix cause carries its oldest reason and held-start count; self-clearing holds add no notice. Legacy workflow parks produce no attention notice. Workflow failures lead to their configured on-break agent or end the run; only an agent asks in its own pane.

The same record scan projects live runs into frame-backed worktree groups, including groups with no pane. Active and Parked runs participate; every terminal state drops out. Bounded, stat-gated caches supply the sealed main rail and the parsed journal; reached names are folded on each pass with the record's held session, sharing `inspect::hops` and `inspect::reached` with the CLI rails. Held until sessions project their held step rather than the evaluating check, and the library's `RunRecord::session_attempt` and `RunRecord::step_agent` keep CLI and sidebar agent identity aligned ([snapshot contract](../sidebar/state.md#the-fold-spine)). A legacy parked run keeps the strip's `parked` word. This path changes neither scheduler forge demand nor workflow transitions.

## Accounting

`crates/rimz/src/harness/workflow/engine/accounting.rs::transition` runs after `persist` publishes a transition and maps the journal entries it wrote. Accounting keys on evaluation origin, not on outcome words, because a check may legally route `canceled` or `limited`. An explicit `Route` suppresses evaluation and attempt accounting. A `turn_end` row suppresses evaluation, route and attempt accounting, including retry/rerun diagnostics. A saved verdict suppresses all engine-origin evaluation accounting and diagnostics.

| Journal entry | Accounting |
| --- | --- |
| Explicit `Route` | One `workflow_route`, unless the record now waits, holds a session, or the transition carries `turn_end`. |
| Check-origin evaluation | One `workflow_route`, unless the record now waits, holds a session, an explicit route accounts for it, or the transition carries `turn_end`. |
| Engine-origin `canceled`, run active | `workflow_rerun` diagnostic, no assist. |
| Engine-origin `limited`, or run canceled | No assist. |
| Other engine-origin evaluation, active with retry context | `workflow_retry` diagnostic, no assist. |
| Other engine-origin evaluation | One `workflow_route` (including a second judge failure following `invalid`, or parking at `@user` on a legacy record), unless the record holds a session, an explicit route accounts for it, or the transition carries `turn_end`. |
| Attempt end | One `workflow_route`, unless the run was canceled, an explicit route accounts for it, or the transition carries `turn_end`. |
| `turn_end` | One `workflow_route` at the check for a push-back, close or kept move between listed checks; none for a kept `@wait`, discard or interrupt. |
| Closed `Wait` | One `workflow_route` to `@wait` at the wait's own node and the summary's timestamp, with `count` set to the final merged count, even on cancel. |
| Park or terminal | `workflow_park` or `workflow_end`. |
| Signal `Wake` or forwarded `signal` | None. |

An open wait has no route assist yet: `list` and `show` carry its live state, while the sidebar raises notices only for holds needing a fix. Closing a window, takeover, occupied, or capacity wait follows the same summary rule. Route records outside waits omit `count`. Explicit-route suppression also keeps a bound's engine evaluation from counting twice. `crates/rimz/src/harness/workflow/engine/accounting.rs::step` appends `workflow_step` after an agent step's supervised run or a command step's child is published, and once per message attempt after the host call, with the target handle when one agent took it; a command step has null handle and supervised run id. The loop runner appends `workflow_start` on creation. All five assist kinds count under the workflow category in `rimz stats`. Diagnostics are rate-limited forensics that stats never reads.
