# Workflow engine

A workflow is a durable run through a flat graph of checks and steps, defined in `workflow.toml` and sealed into the run when it starts. The run record is the only truth. Every decision reads it under the room workspace lock, a wake only asks the engine to read it again, and the journal beside it is evidence for people, never an input. A check decides where the run goes next: a `run` command, a shell command, a condition over loop facts, a sleep, or a headless judge. A step launches a layout with one supervised leader or runs a command, then hands the run to a check. A loop task can start runs, and the scheduler tick re-drives every active run so its clock bounds fire on time.

The [workflows guide](../../guide/workflows.md) teaches the format, and the [workflow CLI reference](../../reference/cli/workflow.md) owns every command, printed line, park reason, and JSON shape. This page owns how the engine decides.

The target language the engine is being rebuilt toward, and the loop command beside it, are specified on [workflow-language.md](./workflow-language.md).

## Terms

| Term | Meaning |
| --- | --- |
| node | A check or a step. The run sits at one node at a time (`RunRecord.node`), entered at `entered_at`. |
| attempt | One evaluation of a check or one launch of a step, published on the record as a `LiveAttempt` of kind `script`, `judge`, or `agent`. Run and shell checks, conditions, sleeps, command steps, and message steps use `script`; a message step's attempt also carries the `message` id it queues. |
| seq | The attempt's number, allocated from `RunRecord.next_seq`. A settlement whose seq is no longer the live attempt's writes nothing. |
| host | The process that owns a live attempt (`LiveAttempt.host`: PID and process-start token). For a hosted check or command step it is the `advance` running it; for an agent step it launches or stops the layout. |
| child | A hosted check or command step's process group (`LiveAttempt.child`: leader PID and start token). |
| wait | The run stays at its node: a check routed to `@wait`, or a step whose admission is blocked. Repeats merge into `RunRecord.wait`. |
| hold | A wait a condition case with `for` creates, with outcome `hold`. |
| park | State `parked`, reached by routing to `@user`. `resume` leaves it; `restart` also re-enters a parked agent step. |
| bound | The run deadline, a node's timeout, or a step's visit cap. The engine routes a bound itself; a step timeout forwards the existing input, and other bounds supply an engine object. |
| terminal | `done`, `failed`, or `canceled`. A terminal record never changes again. |

## Definitions

Deployed definitions live at `~/.rimz/workflows/<name>/workflow.toml`. A loop task's row compiles to an inline definition instead ([Loop tasks](#loop-tasks)). A definition is strict: an unknown field, a field the node's kind does not take, a wrong-typed value, and an invalid optional value all refuse at their dotted path. `rimz workflow schema` derives its JSON Schema from the loader's types (`crates/rimz/src/harness/workflow/spec.rs::schema` over `WorkflowFile`), so `additionalProperties: false` in the schema and the loader's refusal are one rule. `rimz workflow validate [dir] [--json]` loads agent profiles through the machine definition catalog and reports dotted paths, resolved edges, warnings, and errors. It never creates a room. Its argument is a directory anywhere, a deployed workflow name, or a loop task whose row compiles to a workflow (`crates/rimz/src/cli/workflow/definition.rs::Definition::resolve`), so a definition's source can be checked before it is copied into the definitions directory. A name that is both a deployed workflow and a task refuses until it is written `workflow:<name>` or `task:<name>`. Without an argument it validates every directory in the definitions home except dot directories, where `loop eject` stages. `rimz workflow run` (`crates/rimz/src/cli/workflow.rs::start`, through `crates/rimz/src/cli/workflow_view.rs::deployed_definition`) refuses a directory outside the definitions home. The committed fixture `crates/rimz/tests/fixtures/workflows/babysit-pr/` shows script checks with declared wakes, supervised steps, a judge, and signs. Nothing installs it.

`crates/rimz/src/harness/workflow/spec.rs::load` reads text and delegates to `crates/rimz/src/harness/workflow/spec.rs::parse`, the same entry `engine::create` uses for the bytes it seals. `parse` first refuses a node named `@break` and any `@user` or `@break` target an author wrote (`reject_reserved_targets`), then `crates/rimz/src/harness/workflow/spec/kinds.rs::deserialize` reads the `toml::Value` into `WorkflowFile` through `serde_path_to_error`. Every table carries `deny_unknown_fields`, so the first error refuses alone, as `<dotted path>: <serde message>`: an unknown key is named at the key itself, and a missing required field at the field. Syntax errors keep their line, column, and excerpt. `WorkflowFile::lower` refuses a name used by two kinds (`SpecErr::DuplicateNode`), then lowers each kind table into a `Check` or `Step` that records its table word (`CheckTable`, `StepTable`), which validation paths and the `validate` KIND column print.

`validate_spec` applies required-field, value and graph rules to the lowered spec: an invalid optional value (a zero `max-visits`, an overlong duration, `mode = "plan"`, an unparsable `budget`), a route for an outcome the check cannot answer, and each cross-field rule refuse with the path and fix. It warns without refusing only on what the definition alone cannot settle: stage names checked outside a workspace, a leader adapter that cannot report background work, and auto-continue off. The [reference](../../reference/cli/workflow.md#definition-fields) owns the field-by-field rules.

After lowering and the `@break` synthesis, `parse` compiles the spec into the `crates/rimz/src/harness/workflow/definition.rs::Definition` every reader consumes: the engine, graph, inspection, scripts, the brief, throttle limits, the CLI views, the sidebar seeds and schedule probe demand. Compiling never fails. Each node's kind, route targets and edges, conditions, durations, windows, budgets, stagger, wake selectors and subscriptions, and the `shlex` split of `run` are parsed there once, each kept as its authored text beside the parse result, error included, so a view prints the authored text and a value that admission would refuse still fails where it is used, as each use site decided before. A node with no single runner has no `Kind`, and a route to a name that is no node is still a node target. Values that read the clock, the filesystem or live configuration stay at their use: the header deadline's timestamp, slash-word resolution of `run`, prompt and system-prompt files, judge profiles and launch groups.

Workflow `timeout`, `sleep`, `for`, and workflow/step `stagger` use `harness::duration::duration`: `s`/`m`/`h`/`d`, at most `365d` inclusive. An overlong value refuses validation. Engine rereads of a sealed definition never validate, so a sealed overlong `sleep` never refuses there; at evaluation `script::condition_now` returns `DurationTooLong` and the check routes `invalid`. `admission.give-up` keeps the separate `config::CapacityWait` parser and is unbounded.

### The header

| Field | Rule |
| --- | --- |
| `scope` | Required. `worktree` runs every node in the selected checkout, and `project` runs every node at the room's project root. |
| `start` | Required. Names a check or a step, never a special target. |
| `summary` | Optional. One nonempty line describing the workflow. Omission never warns. |
| `deadline` | Optional. An RFC 3339 instant, or a local civil date or datetime. A bare date is local midnight. The record stores the resolved instant. |
| `on-break` | Optional. Where unrouted failure edges go: `@done`, `@failed`, or `{ agent = "<profile>", prompt-file = "..." }`, which synthesizes the reserved `@break` session ([Edges and the graph](#edges-and-the-graph)). Any other string refuses. |
| `on.deadline` | The one header edge. Uses on-break or the `@failed` floor. |
| `limit` | Optional `max-parallel` and/or `stagger`, shared by the live agent step attempts of this workflow name's runs across the home. |

### Kinds

Each node is written as one of eight tables; the table word is its kind, so no field selects a runner. `WorkflowFile::lower` turns `test`, `script`, `judge`, `condition`, and `sleep` into a `Check`, and `agent`, `command`, and `message` into a `Step`; `Check::kind` and `Step::kind` read the lowered fields and compile into `Node::kind`. The [reference](../../reference/cli/workflow.md#definition-fields) lists every field each table takes; the rules the engine and validation add:

| Table | Lowers to | Rules |
| --- | --- | --- |
| `test` | `Check`, `CheckKind::Run` or `Shell` by `run`/`shell` | Answers `pass` or `fail` from its exit code. Accepts only `on.pass`, `on.fail`, `on.timeout`, and `on.invalid`, as typed fields. |
| `script` | `Check`, run or shell | Answers one JSON object on stdout. Any outcome it can answer may be routed, plus `timeout` and `invalid`; a route for another reserved outcome refuses as a dead route. |
| `judge` | `Check`, `CheckKind::Judge` | Requires `prompt-file` and `summary`; `admission` holds `window` only. A failed evaluation retries once, then follows `on.invalid`. The profile's adapter must have a headless launch. |
| `condition` | `Check`, `CheckKind::Condition` | Nonempty `cases`, required `else` and `on.unknown` (`crates/rimz/src/harness/workflow/validate.rs::Validation::condition_fields`). A route for any outcome other than a case, `else`, `unknown`, `timeout`, or `invalid` refuses as a dead route. No `wake`. |
| `sleep` | `Check`, `CheckKind::Sleep` | Nonzero `sleep`, required `then`, optional `when`, `for`, `provider`, `account`, and `on.invalid`. `sleeping` and unread `unknown` wait. No timeout edge. |
| `agent` | `Step`, `StepKind::Agent` | Required `prompt-file`; the agent-only fields and launch settings below. |
| `command` | `Step`, run or shell | Required `timeout`; `then` is one check; `on.cap` is its only route. |
| `message` | `Step`, `StepKind::Message` | `then` is one node, `@done`, or `@failed` (`crates/rimz/src/harness/workflow/validate.rs::message_then`); `on.cap` and `on.undelivered`. |

Every kind accepts a `summary`: one nonempty line describing what the node does. It is required for judges and optional elsewhere; a judge without one refuses at `judge.<name>.summary` with `add summary = "..."`. Sealed-run loading does not revalidate admission, so a run sealed before that rule keeps running with the fallback description. A `window` holds provider-window terms only. A condition or conditional sleep requires `provider` when its terms read `window.*`, and refuses a `provider` without such a term and an `account` without a `provider`.

A condition's cases are an ordered array of tables. Write it inline in `[condition.<name>]`, one case per line (`cases = [ { when = [...], outcome = "..." }, ... ]`); the loader reads `[[condition.<name>.cases]]` blocks as the same array. Each case:

| Field | Rule |
| --- | --- |
| `when` | Required loop-grammar term array. A term may not match the value `unknown`: the shared `WhenExpr` parser refuses it at every condition site, since a term over an unread key is unknown by itself. Stage names are checked against the effective teams plus `Done` when validation runs from a workspace, and a warning says so otherwise. |
| `outcome` | Required. Not a reserved outcome. |
| `for` | Optional nonzero hold in `s`, `m`, `h`, or `d`. A held case must route its outcome away from `@wait`. |

`wake` is a list of selector strings or `{ signal, match }` tables (`signal` required, `match` optional), parsed by the loop's selector and match validator. A session's `subscribe` list takes the same entries plus an optional `prompt`, which refuses on a check's `wake`. An invalid entry, an agent-family selector, and a team selector other than exact `team.stage` refuse at the entry's index (`SpecErr::LifecycleWake` supplies the lifecycle reason).

### Steps

An agent step's `then` names one check, `@done`, or `@failed`, never a step: where the run goes when the attempt ends on its own. `@done` or `@failed` ends the run there. A command step names only a check. Common optional fields are `summary`, `max-visits`, and `on.cap`; agent and command steps also take `timeout`. Run argv resolution is the same for a command step as for a test or script; shell text is nonempty and unconfined.

A message step's `message` must be an `@` address without a pane id that `address::parse_selector` accepts and that is neither `@user` nor `@me` (`crates/rimz/src/harness/workflow/validate.rs::message_target`). Its optional `session` pins the agent session the address must resolve to, so a handle reused by another session goes undelivered. `prompt-file` is optional and confined; `agent::compose` skips it when absent and prefixes the header line `engine::Notice::text` writes. `graph.rs` gives a message step an `undelivered` edge in place of an agent step's `invalid`, filled from `on-break`, else the `@failed` floor, and `Definition::target` maps its `died` to `undelivered`, never `then`. `reject_reserved_targets` refuses `@user` and `@break` there.

An agent step's `agent` takes the fresh-launch layout grammar: kinds, profiles, virtual cells, and mixed agent/command layouts. A team runs only in a session without a `rest-check` (`crates/rimz/src/harness/workflow/validate.rs::step_layout` refuses it on a turn or a rest-checked session, naming `lifecycle = "session"` and the removal of `rest-check`), and the host launches it through the launcher's team layout path with the step's leader run: a team has no one turn end or rest to judge. Command-only layouts and ambiguous prompt leaders refuse; judges still take one profile. Agent-only fields are `lifecycle` (required, `turn` or `session`; `crates/rimz/src/harness/workflow/spec/kinds.rs::AgentNode` has no default, so a missing or other value is a parse error), `rest-check` (sessions only), `keep`, `notes`, `subscribe` (sessions only), `admission`, `on.capacity`, `on.asked`, `on.invalid`, `on.failed`, and the launch settings below. `keep`, `timeout`, and `on.asked` hold on both lifecycles; a step's timeout runs from its launch (`crates/rimz/src/harness/workflow/inspect.rs::timeout_at`). `Step::lifecycle` reads the written value; command steps remain turn-shaped. `admission.max-parallel` and `admission.stagger` lower into the step's limit, the same shape as `workflow.limit`: a positive integer `max-parallel`, a positive `s`/`m`/`h`/`d` `stagger`, or both. `rest-check` refuses on a turn, when empty, and for any entry that is not a test, script, judge, or condition (a sleep included). Turn steps and sessions with a `rest-check` warn when their leader adapter cannot report background work. Every agent step warns when auto-continue is off that a provider-limit pause waits for the user. Judge warnings distinguish Claude's limited attempt from a failed Codex judge, which retries once, then follows `on.invalid`.

An agent step's launch settings are `account`, `mode`, `effort`, `fast`, `budget` (the `--budget` grammar), `system-prompt-file` (confined to the workflow directory), and `worktree` (a new worktree of the run's checkout under that name). `crates/rimz/src/harness/workflow/definition.rs::Node::launch_overrides` resolves them, `engine::agent::launch` passes them in `StepLaunch.overrides`, and the CLI host maps them onto the launcher's overrides and cohort request as a fresh launch applies them (`crates/rimz/src/cli/workflow/host.rs::Host::launch`). A `--continue` restart resumes the session on the account, system prompt, and checkout it was launched with, so the host drops `account`, `system-prompt-file`, and `worktree` there. `account` also pins every cell's start group for capacity admission, which then skips availability routing. The engine asks the host for those start groups (`AttemptHost::start_groups`), and both hosts resolve them through `harness::workflow::launch_groups`. `mode = "plan"`, an unparsable `budget`, and an invalid `worktree` name refuse at their paths.

`admission.throttle = "off"` skips the machine turn, stagger, pressure, memory, disk, and capacity check, not the two machine caps or applicable workflow and step limits. `admission.give-up` reuses `config::CapacityWait`: a positive `s`/`m`/`h`/`d` duration from the first capacity hold, or `forever`; it lowers into `Step::capacity_wait`. Unset gives up at the run's give-up instant, `RunRecord.give_up`, when its start set one (`rimz workflow run --give-up`, or a scheduled inline loop fire's default), and waits forever otherwise; `forever` on the node wins over the run's instant. `on.capacity` defaults to `@failed` and may name `@done` or a node, but never `@user` or `@wait`: giving up does not park a run or introduce a new durable park reason.

`max-visits` must be at least 1. It caps the step's entries counted in `RunRecord.visits`, a plain count per step (`crates/rimz/src/harness/workflow/spec.rs::Step::tripped_visit_bound`), raised by the run-wide `visit_grant`. `on.cap` uses on-break or the `@failed` floor; an agent step's `on.asked` has no default and keeps the question live when absent. Neither edge may target `@wait`, and `on.cap` may not target its own step. Validation prints an `asked` edge only when explicitly set. A count clears only on a manual restart or a cap resume.

### Edges and the graph

An edge names another node, `@wait`, `@done`, or `@failed`. Checks and steps share one name namespace, and an author-written node or workflow name is nonempty ASCII letters, digits, `-`, and `_` (`crates/rimz/src/harness/name.rs::validate_name`). The resolver in `crates/rimz/src/harness/workflow/graph.rs::Definition::edges` supplies check and step edges and the header deadline. Check `timeout`/`invalid`, agent-step `invalid`, message-step `undelivered`, step `cap`, and header `deadline` use their explicit route, else `on-break`, else the runtime floor `@failed`. Agent capacity defaults to `@failed`, and a conditional sleep's `unknown` to `@wait`; a condition's `unknown` has no default and comes only from its required `on.unknown`. Engine routing, validation rows, timeout admission, cycle detection, and inspection read that resolver. A step's turn-ending outcomes, including its timeout, resolve through `then`, except that a set `on.failed` takes a `died`, `timeout` or `limited` ending (`Definition::routes_on_failed`); an absent `on.asked` keeps the question live and is not a displayed edge.

Each edge also carries fireability and, when it can never fire, a typed reason. `Edge::mark` owns the human wording used by validation and inspection. `Transition::finish_judge` retries once, then follows `invalid`. Capacity fires with a finite node give-up, never with `forever`, and with an unset one only for a run that carries a give-up instant (`Fireability::WithGiveUp`, wire `"with-give-up"`). An unset header deadline is conditional on a run grant, not a never-firing edge. Edges filled by on-break carry `EdgeSource::OnBreak`, wire `"on-break"`.

A spec with `on-break` synthesizes its agent handler as `@break`, a session ending at `@failed`. Its input adds `edge` and `from` when the route is applied, including after a held verdict or a sleep. A pending held verdict keeps the journal's unannotated object so inspection can recognize it as pending. Break launches disable leader-wrapper cleanup, and every ending detaches rather than stops them, including a late launch returned after cancel. `bound`, agent ending preparation and inspection omit its deadline. Its default prompt carries a bounded debug trace; an author's prompt uses the ordinary confined-file path.

An active run at `@break` accepts resume, except while a live owner is launching or settling its attempt. The existing ending protocol saves a route to `--at` or `input.from`; the next advance detaches the session, journals Resume under the destination, and re-enters that node. The reserved `@break` node is not a resume destination. Input survives; a cap break resets the source step's visit count, even with `--at`. Resume before a break launch clears its occupancy/capacity wait and re-enters directly. Other active runs still accept only extensions.

`RunRecord.break_agents` retains the detached break leader's and live children's handles before the next admission. It defaults to empty and is omitted when empty, without a record-version bump. The CLI host filters those handles from the snapshot before both occupancy and eviction, so this run never waits for or stops its own detached debuggers. Other occupants keep the shared takeover rules.

Every `on` value and every `then` is a target string (`crates/rimz/src/harness/workflow/validate.rs::validate_spec`). A session's rest checks compile to edges with outcome `rest-check` (`graph::REST_CHECK`), appended after the step's other edges, so the walk, the cycle bound and the unreachable list see each listed check. A route the author wrote carries `EdgeSource::Explicit`; only an edge the engine filled carries `Default` or, from `on-break`, `OnBreak`.

`crates/rimz/src/harness/workflow/graph.rs::Definition::walk` takes reverse postorder from `start`, traversing fireable edges last-to-first in display order. It walks a header deadline destination after the start component, and lists unreachable nodes alphabetically. A step hangs under its `then` check only when that check occurs earlier in the walk and has a fireable edge to the step. This keeps a forward return, such as land's `triage` to `ruled`, standalone. Hanging children follow their parent's edge order.

`crates/rimz/src/harness/workflow/script/condition.rs::case_marks` projects the latest answer's readings through `WhenExpr::truth`, stopping at the winner or first unread case; later cases are not reached. A holding wait's `case` selects the held winner. The adjacent `unread_reasons` parser recovers per-term unread reasons from `answer`'s stored prose, using its null-reading keys as delimiters so commas and parentheses inside a reason survive. It adds no stored field.

| Rule | Why |
| --- | --- |
| `timeout`, `invalid`, `cap`, `capacity`, `deadline`, `unknown`, and `hold` are reserved (`crates/rimz/src/harness/workflow/spec.rs::RESERVED_OUTCOMES`). No case or `else` uses one, and no check answers one, except a condition or conditional sleep's `unknown`. | The engine produces them for its own routes. |
| `on.timeout` cannot be `@wait`. | The timeout clock has already expired. |
| A check with any resolved `@wait` edge needs a `timeout`, except a sleep. | A sleep has its own finite duration; other waits need a bound. |
| A cycle through steps needs a `max-visits` on one of them. Failure routes count as edges; the deadline's does not. | Otherwise the run can revisit its steps without end. |
| A check-only cycle needs a `@wait` edge. A hold is not an edge and does not count. | Otherwise one advance would loop without pause. |

Validation warns, without refusing, about turn steps and sessions with a `rest-check` whose leader adapters do not report background work (`do_background`, which every row carries), and turn steps or judges while machine auto-continue is off.

### `run` and `shell`

`run` is an argv parsed with `shlex`, never shell text: pipes, variable expansion, and redirection belong inside a script. Every word containing `/` names a file relative to the workflow directory (`crates/rimz/src/harness/workflow/spec.rs::resolve_argv`). Only normal path components are accepted, and canonical resolution must stay inside the directory. Other words, such as `sh` or `uv`, resolve through `PATH`. Files are resolved and hashed again at every evaluation.

`shell` is unrestricted `sh -c` text. Its sealed spec digest covers the command, and the paths it references are neither confined nor hashed one by one.

Checks must be idempotent. A host killed after a script's effects but before settlement causes a fresh evaluation, never recovery from the previous stdout.

## Run control

Human run inspection calls `crates/rimz/src/harness/workflow/script.rs::condition_now` for one condition check or conditional sleep: the first listed check on an agent step, or the current check on a live or parked run. It shares the engine evaluator, including sleep expiry and the CI Git fence; a sleep previewed from an agent step starts at the preview, since the step has not entered it yet, so it never reads as slept. It returns the forge timestamp from that same cache snapshot. There is no check child, write, or probe refresh. Preview freshness starts at step or parked-node entry (held sessions keep their session-entry floor); `hold_until` reads only a wait belonging to the selected check and case. Child checks and plain sleeps have no now line. JSON and history do not call this entry.

`engine::create` admits a run in this order:

1. Compare every nonterminal run against the candidate. A run blocks when its firing checkout (`RunRecord::firing_checkout`) is the path `ScopeRoots::path` gives for that run's own scope kind, and it shares the candidate's origin and name, or its task. A match is the typed `WorkflowErr::Exists`.
2. Read the prompt. An inline definition is sealed into the new run's `definition/` here.
3. Read the definition bytes, load them through `spec::parse`, then validate the lowered spec with `validate_spec` against the run's project.
4. Require the room's workspace record when the graph has an agent step, a message step, or an agent check, or when a loop task starts the run (`WorkflowErr::NoRoom`; `rimz start` creates the room).
5. Under the workspace lock, repeat step 1, allocate the run's notes folder when it keeps one (`store::notes::allocate`), then write the run home (`store::workflow::initialize`).
6. Spawn a detached `advance`.

Step 1 runs before the prompt or definition bytes are read, so a held run wins over a broken definition, a prompt-file error, or a scope-kind edit. Comparing each existing run by its own kind keeps a worktree run at the project root from blocking a different worktree. Matching by task means a task whose row changes what it runs still overlaps its own live run. A run whose loop fire cut its own fresh worktree (`RunRecord.fire_tree`) has the project root as its firing checkout, so each fire's fresh tree still overlaps the last. A failure after step 2 removes an inline run's sealed root, since no record exists to keep it. `rimz workflow run` validates the definition directory before it calls `create`, so a manual start of a broken definition refuses on the definition even while a run holds the slot. The CLI prints `Exists` as a refusal, and a loop fire reaching `create` follows its task's `overlap` policy: `overlapped` naming the run by default, or a retained trigger that drains once the run's report lands. A scheduled fire of a task that remembers its checkout and already has a launch entry there never reaches `create` ([Loop tasks](#loop-tasks)).

`rimz workflow run` resolves `-w` to an existing RimZ-owned worktree before it calls `create`, never creating one, Without `-w` the checkout is the current one. Worktree scope runs in that checkout. Project scope always runs at the root, so `-w` on a project-scope workflow refuses with `<name> has scope = project, so it runs at <project root>; start it without -w`; a loop fire never passes it. Run ids are `wf_` identities. `list` enumerates active and parked runs across rooms, attention first, then workflow groups with self-clearing capacity holds last. Human rows read each run's journal for a horizontal rail (an unreadable journal leaves that row's reached history empty without failing the list), cache PR readings once per room, and lazily read the room roster once when naming a with-you agent. `crates/rimz/src/cli/workflow.rs::RoomView::agent` reads the cached-alive roster `agents list` reads and projects the published pane frame over it, so the peers match the card's, without the dashboard enrichment. The views join the session attempt's run/sequence/Step pin, prefer the leader's recorded pet identity among layout cells, and use its card handle, falling back to its recorded pet name; JSON and loop detail gain no enrichment reads. `show`, `cancel`, `resume`, and `restart` accept addresses and workflow names through `crates/rimz/src/cli/workflow_view/resolve.rs::select`; caller-room matches win, otherwise several rooms require `--root`. `show <workflow>` draws the definition rail and then the runs table, and `show <task>` does the same for a loop task's compiled graph and its live runs, with the same `workflow:` and `task:` selectors as `validate`; `show <workflow> <node>` prints one definition node in full. Bare `show`, including `--history` and `--json`, resolves the calling agent and walks launched parents, with a cycle guard, to the first workflow pin (`crates/rimz/src/cli/workflow.rs::calling_run`). Run ids, including the hidden `advance` positional, still resolve from any directory through `crates/rimz/src/disk/paths.rs::workflow_runs_under`, which skips a room whose run homes cannot be read. An active session attempt (held first, else the slot's agent attempt) with `asking` has DETAIL `asking you: <handle> (<kind>): <text>` in list text and JSON `detail`, with text collapsed to one line; a single-run show says `<step> is asking you` and prints the full ask below. Both state labels use the Waiting role. Without an ask, a live session attempt has DETAIL `with you`, then ` · checking <check>` while held, then `: <wait phrase>` at that check, or ` · <check>: <wait phrase>` after it if waiting; show says `<step> is with you`, uses the full card handle in its headline and the shared check/wait suffix, with no duplicate status below. Other live runs print the park or wait phrase, otherwise running with its configured visit bound or checking. `crates/rimz/src/cli/workflow_view.rs::detail` supplies workflow and loop detail without the node or `since`; their JSON keeps node-entry `since` separately. Human list ages use the park time, ask time, first capacity-hold time, or node-entry time. The list supplies the optional channel-less agent name to `detail` and appends a cached PR number itself; JSON and loop callers supply no agent.

Single-run show renders an address/PR header, a state headline, the current check's saved readings and journal time on active runs, an additional live condition now line and its forge probe time on active or parked runs, origin and completed cost, ask text or park explanation, a painted active or horizontal parked/terminal rail, capped visit counts, a bounded trail, and a work-directory/history footer. The saved readings come from the latest evaluation since node entry, including script readings; they do not re-evaluate the check. The headline separates state, agent context and bound-forecast tones; with-you details stay in that headline. `crates/rimz/src/cli/workflow/show/rail.rs::View::rail` paints the shared definition rows from the sealed specification, journal and record. The trail reads `crates/rimz/src/harness/workflow/inspect.rs::hops`, including held-session turn ends, and node entry counts come from `crates/rimz/src/harness/workflow/inspect.rs::reached`, shared with the sidebar strip; an evaluated check is marked reached even when its turn-end verdict was discarded and routed nowhere. Both take the record's held session: while a saved closing verdict waits on an ineligible leader, its evaluation projects no route, so the trail, history and reached marks name neither its target nor a visit to it until the session closes. These are projections, never transition authority. `crates/rimz/src/cli/workflow_view.rs::glyph_role` selects the headline and current-node glyph together. Condition case marks and unread reasons come from the harness; saved values appear in the readings line and current values in the now line, while the unread case retains its reason. `--history` renders the journal as typed facts, folding repeated answers and wakes and omitting duplicate route evidence and represented closing waits, with targets from the sealed specification except where a turn-end verdict records its own target; a `turn_end` row prints its target only when kept, pushed or closed, and a pending saved verdict prints none. `--json` keeps the durable record and journal and adds the derived address. See [Inspect runs](../../reference/cli/workflow.md#inspect-runs) for the output contract.

`cancel` takes the workspace lock and returns false on a terminal record, so the first terminal write wins. It kills the child of a hosted check or command step and ends the run `canceled`. For an agent step it stages a `canceled` end with cause `Cancel` and stops the attempt ([Stopping an attempt](#stopping-an-attempt)). While a live host is mid-launch or already ending the attempt, cancel leaves the stop to that host.

An optional cancel reason travels through `Ending` to settlement and the `Cancel` journal row, including deferred agent stops. Both fields default to absent for older records and are omitted when no reason was supplied. The hidden `workflow cancel --reason TEXT` flag carries internal cancellation causes; `crates/rimz/src/harness/workflow/mod.rs::cancel_args` builds its argv using the machine-wide run id.

`resume` refuses a terminal run, and on an active run outside `@break` it accepts only `--extend`. A parked run re-enters its current node, or `--at <node>`, with a fresh `entered_at` (so a fresh timeout clock) and a cleared judge retry, retaining input and key. A cap resume clears the capped step's visit count, journaling `VisitsReset { step, outcome: "cap" }`; other parks retain counts. `--extend visits=+N` adds a run-wide `visit_grant` to every step's `max-visits`. Resets leave the grant unchanged. `--extend deadline=<when>` replaces the deadline and re-arms it. The return value is the persisted record from before the detached advance was spawned, so a receipt need not reload a record that advance may already have changed.

`restart` stages `EndCause::Restart { continued }` on the current or restored held agent and reuses the off-lock stop and sequence/host-checked settle protocol. At a parked agent step with no session attempt, a matching-node `prev_attempt.run_id` identifies the previous session. With `--continue`, restart restores that attempt for stopping, including a still-live detached card, before the replacement launches; `record.restart.settled` marks its already-journaled sequence so settlement does not repeat its end or cost. Settlement preserves input/key, re-enters the owning step, clears its visit count, and journals `VisitsReset { step, outcome: "restart" }` and `Restart { step, continued }`. A durable `record.restart` carries the optional leader session through stop recovery and occupancy waits until launch publication consumes it; parking or terminal settlement clears it too. That launch passes the step's window, occupancy, and capacity admission as any start does. The CLI resolves `--continue` from the selected attempt's supervised run `agent_id` and durable audit rows, checks provider support, conversation presence and the room account's history pool before staging, and passes the checked sequence to reject a moved attempt. Launcher preparation rechecks conversation presence and the selected room-default account's pool after stop work; an intervening account change cannot resume into a foreign pool. An after-stop resume failure follows step `on.invalid`. The restart receipt shows that route only when the launch settled before it printed; otherwise it reports `awaiting launch`. A concurrent cancel can replace the ending and wins settlement.

Before stopping an attempt, the host retires its pending push-back by message id, including an unconfirmed `Sent` prompt, through `Store::retire_message`. The queue writer cancels it with terminal history and audit evidence; unrelated messages and delivered prompts are untouched. A producer that queues after the stop's retirement re-reads the attempt's ownership and ending before delivery and retires its obsolete push too. Thus a continued restart's first clean turn is not gated by the abandoned attempt's push, while the current attempt's own unconsumed push still defers judgment.

The launcher keeps fresh identities and fresh companions, but compiles the leader's exec action as `Resume` when `LeaderRun.resume` is present. The shared fresh-cell compiler still installs the run id, workflow pin, reminder, managed account and cleanup policy; account resolution uses the room default. `agents restart` routes only current Step pins through this control path, leaving team restarts alone; former step restarts clear their pin and run outside the workflow.

## Storage and isolation boundary

Each room holds one home per run, `owned/workflows/<run-id>/`. All its paths come from the disk path module (`crates/rimz/src/disk/paths.rs::WorkflowPaths`):

```text
record.json        current run, version 8 (reads only 8)
journal.jsonl      append-only evidence: transitions, and a row per check evaluation, so a polling check grows it on every recheck
workflow.toml      sealed specification bytes
definition/        an inline run's definition root: its source text and the assets it names
work/              RIMZ_WORKFLOW_DIR, writable by nodes
  context.json     replaced before every evaluation or attempt
  notes/           link to kept automation notes (runs without notes: scratch directory)
  signs/           live step guidance, created with the run
  <seq>.check.log  run-check stderr or shell-check combined output
  <seq>.check.json judge's whole saved answer
  <seq>.step.log   command-step stdout and stderr
```

The record, the sealed spec, and the journal sit outside the node-writable `work/`. Notes are reached through the link in `work/`; signs and step claims live under `work/`, and the engine reads only `signs/<step>.md`, never notes or claims. Every evaluation and attempt takes a fresh `seq`, a judge retry and a re-run after a dead host included, except a message step's re-send after a dead host, which keeps its attempt's `seq` and message id so the queue takes the notice once. A node therefore keys a `notes/` write by the item it records, since keying it by `seq` would not make a repeat a no-op.

`crates/rimz/src/harness/workflow/engine.rs::create` takes a `DefinitionSource`: a deployed directory, whose basename names the run, or an inline definition a loop task compiles, its text plus named asset files. An inline run's `workflow` is its task name. Either way `crates/rimz/src/store/workflow.rs::seal_definition` writes the definition into the run's own `definition/` before validation, which becomes its `spec_dir`: for a deployed run, `read_definition_dir` reproduces the whole directory: every directory, empty ones included, every regular file with its permission bits, and every symlink that resolves inside the directory as a symlink, to a directory as well as a file and never walked through, its target rewritten relative to the link's own directory (`relative_target`), so an absolute link becomes a relative one that resolves to the same entry in the sealed copy. An entry it cannot seal (unreadable, resolving outside the directory, a dangling link, neither a file nor a directory, or a name that is not UTF-8) refuses the start with `<path>: cannot seal it into the run: <reason>`. Prompts, scripts, argv paths, and `RIMZ_WORKFLOW_DEFINITION` all read that copy, so an edit to the deployed directory or the task's config after start changes nothing in the run. `RunRecord.origin` records which source started the run (`deployed` or `inline`; absent decodes as `deployed`).

A run a person starts whose graph has no agent step, agent check or message step needs no room's workspace record. A run a loop task starts always needs one, since its detached advance finds the run through the room's record (`engine::create` refuses with `WorkflowErr::NoRoom`, which the loop records as `start failed`). A run of checks allocates no notes folder, and its `work/notes/` is a scratch directory, when it is inline (a loop task's check-only run fires too often to keep a folder each time) or when no room exists. Every other run allocates `automation-notes/<yyyymmdd>/<HHMMSS>Z-workflow-<workflow>-<lane>/` from the record's `created_at` sample and stores its root-relative path in optional `RunRecord.notes`. Its v2 `run.json` names the workflow, run ID, and scope checkout. Every step cell carries that relative path in `LaunchRecord.notes`, and launched descendants inherit it from their parent's row. Relaunches preserve it; forks clear it. Claude's additional-directory grants include that run folder, rejecting paths outside the room's automation archive, the checkout's valid team run when present, and the home-wide note store once it exists. Team reminders and memory listings keep resolving through the checkout's `.rimz/team` link. Agent-step briefs name `<step>-notes.md` unless `notes = false`; only the `agent` table takes the field. GC reads current workflow and agent ownership under the workspace lock and holds it through removal; non-terminal workflows and live agent rows protect their folders, and an unreadable rollup protects all automation notes.

Soft reset keeps run homes, and hard reset removes them, unlike supervised-run records. Garbage collection removes a terminal run's whole home once `record.json` is older than the seven-day owned grace and the run owes its loop task no report. A home without `record.json` is a crash during creation (or during an inline run's sealing), which every reader skips, and it goes once the home directory itself passes the same grace.

After CLI advance, cancel, or restart returns from the engine, `crates/rimz/src/cli/workflow.rs::write_history_copy` writes terminal history into the run's notes folder and warns without failing the committed transition when copying fails. The shared writer, `crates/rimz/src/cli/workflow_view/history.rs::write_copy`, uses the `show --history` journal renderer, raw prose and a color-stripping stream. Terminal history names the absolute local end in the headline and uses date-qualified local clocks (`YYYY-MM-DD HH:MM`) on every row for reproducible bytes. Writing replaces an existing copy. A run without notes writes none, and an archive already deleted by its retention or the user is not recreated.

Before GC removes an eligible terminal home, it calls the CLI's history writer off-lock when the copy is missing. A failed copy keeps the home. The sweep then reacquires the workspace lock and rechecks terminal state, record age, notes path, and sequence before removal; rendering never holds that lock. A dry run predicts removal without writing a copy.

The record stores the scope, project root, sealed-spec digest and original definition directory, prompt, current node and entry time, state and park, routed input and key, open wait and recheck time, per-step visit counts since the last reset, the visit grant, deadline state, the sequence allocator, the live attempt, an optional held session, the previous step attempt, and the terminal time. Optional fields carry the source (`origin`), the detached break agents (`break_agents`), a staged restart (`restart`), the judge retry (`check_retry`, `check_retry_context`), two start arguments, `give_up`, the run's give-up instant for an agent step that sets no `admission.give-up` (a loop fire's default comes from [loops.md](./loops.md#history-strikes-and-arming)), and `capacity`, `skip` for a `--skip-capacity` run and omitted for the default `wait`, and five loop facts: `loop_report`, `fire_tree`, and `surplus` and `surplus_after`, the task row's `surplus` and `surplus-after` values as written when its fire started the run, which the run's judges gate on, and `fire`, what the loop fire that started the run tells its briefs, frozen at creation: `manual` with the task's name for `rimz loop fire`, or `scheduled` with the task's name and the brief's trigger clause (none for a watch trigger); a hand-started run has none. The typed `outcome` is written with the terminal state ([Loop tasks](#loop-tasks)). Each step's visits serialize as one integer under the step's name. Its optional `task` names the starting loop task. `manual` is true only for a run created by `rimz loop fire`, which names its origin and nothing else, since capacity reads the start argument alone; it is omitted when false. Keys keep integer versus string identity. Runs use version 8, which is also the definition language's version: a run sealed under another language refuses rather than being read by new rules. `crates/rimz/src/store/workflow.rs::load` reads the version before it decodes the record and refuses any other version with one message naming the run and `rimz workflow cancel <run>`. `cancel` given that run's id removes its home without decoding it (`crates/rimz/src/store/workflow.rs::remove_refused`), leaving any agent it started running, and `list` prints each refusal on stderr. Every background reader treats a refused home as absent through `crates/rimz/src/store/workflow.rs::WorkflowStoreErr::is_refused`: the throttle's workflow census (`crates/rimz/src/harness/throttle.rs::SystemHost::workflows`) and `crates/rimz/src/store/workflow.rs::unfinished_under`, strict reads included, skip it with a warning, and GC removes the home once the record is past the owned grace, when its version is older than `VERSION`. A change to what a stored record or its sealed definition means raises `VERSION`, so a record an older RimZ wrote refuses rather than changes behaviour mid-run. Unknown `Wait.hold` strings load as absent; the shared [hold-kind contract](./loops.md#the-start-throttle) covers both workflow and condition waits.

Engine rereads load the sealed copy through the same strict `spec::load` and compile as admission, without repeating `validate_spec`. A sealed definition that no longer parses (a hand-edited copy) refuses every transition; `engine::cancel` loads it too, so such a run cannot be canceled. `crates/rimz/src/cli/workflow/show.rs::render` and `crates/rimz/src/cli/workflow/list.rs::render` print no definition warnings.

A journal entry carries its time, node, optional attempt sequence, and one event (`crates/rimz/src/store/workflow.rs::JournalEvent`): evaluation, attempt, visit reset, restart, turn-end decision, closed wait, explicit route, park, terminal, cancel, resume, signal wake, or forwarded signal. An evaluation keeps the routed object and its `origin` (`check` or `engine`, defaulting to `check` when absent). An invalid answer also keeps a stderr tail. Script and judge evaluations keep the digests published with the attempt's child, whichever process ends the attempt, and an evaluation whose child never spawned has none. Attempt rows and `PreviousAttempt` carry the admitted outcome in `routed_by` beside the key, defaulting to null for older entries. Visit resets identify the step and answered outcome; inspection takes reset boundaries from these events, not by re-evaluating the spec's reset rule.

`engine::persist` is the one publication path. Under the workspace lock it appends each journal entry and data-syncs the journal, then replaces the record, then writes accounting. The first replacement that makes the record terminal carries its typed outcome, and a live record carries none. A crash between append and replacement can leave a duplicate entry with the same sequence, and history never authorizes a transition. Creation syncs every new directory up to the room root. Readers skip torn or unknown journal rows.

`LiveAttempt` and `JournalEvent::Attempt` carry optional string `started_past_limit`: the skipped hold text, without an age. It defaults to absent and is omitted when absent. `prepare` stores it on admission and `Transition::settle_step` copies it into the journal. `show` prints `<text>; started anyway: the run skips capacity` while that session is current (including `held.attempt`), and history prints it inside the settled attempt's block. JSON exposes the field itself. No text goes to `workflow run` or `loop fire` stdout or stderr.

## The advance loop

`engine::advance` is one loop of three phases, and each phase boundary is a lock boundary:

1. Prepare, locked (`crates/rimz/src/harness/workflow/engine.rs::prepare`). Load the record and decide: return, hold or restore a rest-checked session, stage an ending, route a due bound, reclaim a dead host's hosted attempt, count an early advance against a wait, merge a step admission wait, ask for capacity admission, or publish a new attempt with its `seq` and `context.json`.
2. Run, off-lock: evaluate the check, run a command step, ask the capacity door, launch an agent step (stopping a takeover's occupants once the launch is prepared), enqueue its saved push-back id, or stop an ending agent step.
3. Settle, locked: reload the record, confirm the attempt's `seq` is still live, route, and persist.

A stale settlement writes nothing. One advance keeps going until the run waits, parks, ends, meets a live host, or would evaluate the same check twice with no step attempt or newer eligible rest between. A held verdict resolves before a wait can stop the advance. Repeated cap routes also yield rather than spin without launching. Each guard leaves the run active, and the next wake or tick drives it on.

### Hosted children

Run checks, shell checks, judges, and command steps run inside the short-lived `advance` process, never as supervised runs. Preparation publishes the live attempt (kind, sequence, node, start time, host PID and start token) and its context under the workspace lock, so a stale host cannot overwrite a newer attempt's context. `crates/rimz/src/harness/workflow/script.rs::with_child` then re-takes the lock, re-reads the bounds, spawns the child, and publishes the child's group-leader PID, start token, and file digests in one write, before it releases the lock and waits for output. Spawn and publication thus share the lock with cancel and bounds. Run steps pass argv directly through the hosted runner; shell steps use `sh -c`. Both tee stdout and stderr to `crates/rimz/src/disk/paths.rs::WorkflowPaths::step_log`, `work/<seq>.step.log`.

While it waits, the host re-reads the record at the bounded subprocess runner's interrupt cadence and interrupts its child when the attempt is no longer live or a bound is due. Another advance leaves a live host alone while no bound is due. A check host that is dead, or whose PID was reused, turns its attempt into an engine-origin `canceled` evaluation, which re-runs free. A command step instead journals a `canceled` attempt with a lost-host reason and follows `then`, without repeating its side effect or counting another visit.

Any advance or cancel kills the recorded group under the lock before withdrawing the attempt, including when the host is stalled or dead (`Transition::kill_child`). It signals only when the leader's start token still matches or, once the leader's token is unreadable, when a live member of that group carries this run's `RIMZ_WORKFLOW_RUN` marker. Membership is checked again after reading the marker and liveness. A missing or changed token alone never authorizes a signal. A hosted leader stays unreaped until its pipes close, so the published PID and token stay a valid kill handle. A surviving host reaps its child when it resumes, and its stale sequence cannot settle again.

A run or shell check or command step runs in the scope checkout with null stdin, the room workspace pin, `RIMZ_WORKFLOW_RUN`, `RIMZ_WORKFLOW_DIR`, and `RIMZ_WORKFLOW_DEFINITION`. `context.json` holds `run`, `prompt`, `node`, `seq`, `key`, `input`, `output_path` (`work/<seq>.check.json` for a judge, null otherwise), `retry`, `signs_path`, and `prev_attempt`. A session with a `rest-check` also publishes `live_attempt` ([rest checks](#rest-checks-judging-an-open-session)). A step's context adds `visit` (its visit count at admission, including this launch or push-back) and `visits` (its count now, since the last reset). The live attempt stamps `visit` at launch and at each admitted push-back; the context, `live_attempt.visit`, `prev_attempt.visit`, and the attempt journal row keep that latest number through resets alone. An attempt without a stamp uses the current count. `prev_attempt` exposes the step, attempt outcome, admitted outcome (`routed_by`), sequence, visit, key, start and end, claim path, handle, supervised run id, HEAD pair, stopped and surviving children, ask or limit evidence, cost, exit `code`, and `log`, with null for whatever was not observed. Signs and the run prompt compose only agent prompts and message-step messages.

### Command-step settlement

`crates/rimz/src/harness/workflow/state.rs::Transition::finish_script` is the end-recording entry for non-agent attempts across the hosting advance, bound, cancel, and dead-host reclaim. The node table decides the journal shape: a step records `Attempt` and `prev_attempt`, a check keeps the engine `Evaluation`. Agent and command steps share the attempt journal and routing tail. Exit 0 is `ended`; nonzero, an external signal, spawn failure, and log-open failure are `died`. These and a step timeout (`timeout`) follow `then` with the original input. The run deadline is `canceled` and follows `on.deadline`; cancel is `canceled` and terminal. An interrupted child whose bound was extended before settlement is `canceled` and follows `then`.

Only an interrupted child is classified by the bounds at settlement. A child that exited on its own keeps its exit outcome; the next prepare applies any still-due run deadline. Another advance meets the same rule: `Transition::bound` leaves a step whose published child has exited to its live host, and that advance stops. The hosting process samples HEAD after reaping, off-lock. Other settlers leave `head_end` null. `code` is null for a signal or an unobserved exit, and `log` is set only when the step log exists. Agent-only evidence is null, while `claim_path` still names the sequence's claim file.

Command steps bypass `AttemptHost`, prompt composition, provider windows, and occupancy completely. A message step bypasses windows, occupancy, capacity, and the throttle too, and never reaches `script::execute_step`: `prepare` composes its text before it publishes the `LiveAttempt`, so the digests are recorded, mints `LiveAttempt.message`, and returns `Decision::Message`. `engine::message_step` then calls `AttemptHost::message` off-lock, holds at `RIMZ_TEST_WORKFLOW_RESULT_GATE`, relocks, and settles through `Transition::finish_message`: `ended` with the target handle follows `then`, `died` with the reason routes `undelivered` with `ParkReason::Invalid`. The CLI host first looks the message id up in the live queue and history, and a hit returns the handle it was queued for. Otherwise it resolves the address from the scope's directory channel among living addressable agents, refuses a pinned `session` the address no longer names, queues `HarnessNotice::Wait` automated at gate `Done` with `queue_message_once` under that id, and attempts delivery at once. A compose error takes the `died` path without a host call. When the attempt is no longer current at the relock, the advance writes nothing and retires its queued message, unless the journal already holds an `ended` attempt for that sequence. A dead host's attempt with a `message` id is re-sent under the same id by the next advance's `prepare`, not canceled, and the queue keeps one copy; the attempt journal row carries the id. The common cap check still precedes visit and sequence allocation. Nothing paces a message-step cycle, so a fast one can consume its cap within one advance: route it through a waiting check.

Three windows stay open. Only the hosting process writes the step log, so when another advance enforces a bound on a stalled host, the next check can read the log before the host drains what the killed child wrote. A host killed after the spawn and before it publishes the child leaves `child` unset, so the dead-host reclaim kills nothing and the command can outlive its settled attempt. Checks share that second window. A live host that stalls (SIGSTOP, a frozen cgroup) after its command's group leader exits holds the step: `Transition::bound` leaves it to that host, so no other advance enforces the step timeout or the run deadline, and a group member still running keeps running. The host's own bound kills the group once it resumes, and the dead-host reclaim kills it once the host dies. Waiting for the group to empty would close this window only by reopening another: `kill(-pgid, 0)` succeeds while the exited leader is still unreaped, so another advance would again overwrite the exit the host is about to record.

### Check answers

Run checks save complete stderr to `work/<seq>.check.log` after the bounded runner returns, creating the file even for an empty stream. Stdout remains the answer, and invalid evaluations retain the journal's 4096-byte stderr tail. The push-back brief looks backward for the `TurnEnd {pushed}` matching `attempt.push.message`, then that check's preceding evaluation sequence. It names that check and measures `.check.log` for run/shell or `.check.json` for a judge with `FileSummary`; reason precedes the output path/label, and empty or missing files say `no output`. No file content is copied. Without a matching row it falls back to the step's first check and omits the output line. The durable push-back and journal formats do not change.

A run check or a judge answers exactly one JSON object: a required string `outcome`, an optional string `reason`, an RFC 3339 `recheck_at`, and a string or integer `key`. Other fields stay in the object as payload. The full normalized object (`crates/rimz/src/harness/workflow/state.rs::normalize_object`) becomes the next node's input, and a missing key inherits the run's current key. A sleep journals its own answers but forwards its incoming input and key on routes other than `@break`, including invalid and deadline routes; the next step's `routed_by` therefore still names the incoming outcome. A route to `@break` instead supplies the failure object plus `edge` and `from`, preserving the inherited key.

For a run check, these route `invalid` with an engine object: a nonzero exit, stdout that is not one object, a wrong field type, an unrouted or reserved outcome, a bad `recheck_at`, and a `run` file that no longer resolves. A judge's failures settle differently ([Headless judges](#headless-judges)).

`recheck_at` only delays a `@wait`. `Transition::bounded_recheck` clamps it to the earlier of the check's timeout and the run's unfired deadline, so the tick cannot sleep past either bound. A judge's provider-limit reset is clamped the same way.

### Shell checks

A shell check runs through the loop's `crates/rimz/src/harness/check_run.rs::run_command` in its hosted mode, with no SIGINT listener. A shell check or step goes through the same `rimz loop check-exec --command` trampoline as a loop check, and a run step through `rimz loop check-exec -- <argv>`, which execs the argv without a shell. The host first resolves `sh` or the run step's program on the child's `PATH`, so a missing program stays a spawn error rather than the trampoline's exit. The trampoline calls `setsid`, so the command leads a new session and process group with no controlling terminal, and a command that opens `/dev/tty` cannot stop on the caller's job control. Before polling, the spawn callback publishes the leader under the workflow lock, and a callback error kills the group and returns the error. A child killed before its trampoline reaches `setsid` leads no group yet, so `Transition::kill_child` falls back to killing the leader's PID when `killpg` finds none. The interrupt predicate runs every 20 ms, kills the group at once, and bounds pipe draining to 200 ms. Output is teed to `work/<seq>.check.log`.

The engine builds the answer from the exit: `pass` for exit 0, otherwise `fail` with a reason (the [reference](../../reference/cli/workflow.md#json-shapes) owns the shape). Digests are empty and no tail is journaled. A spawn or log-open failure routes `invalid`. The workflow's own timeout and deadline interrupt through the same predicate and settle through the engine's bound routes, never as `fail`, and no loop default timeout applies.

### Conditions and holds

A condition runs the same prepare, evaluate, and settle protocol with kind `script` and no hosted runner child (`crates/rimz/src/harness/workflow/script/condition.rs::evaluate`). Each case's truth is the shared Kleene walk `crates/rimz/src/harness/when.rs::WhenExpr::truth` over the readings: the first true case wins, an unknown case before it answers `unknown`, and all false selects `else`.

Every forge reading is cleared unless the latest probe succeeded at or after the forge floor. A held evaluation uses `held.entered_at`, the session's step entry; every other evaluation uses `record.entered_at`, the check's entry. The same floor gates the CI commit fence. The check timeout still uses `record.entered_at`, the hold time while held. Stage and projected usage-window readings have no such floor. For ordinary checks the floor has two latency costs: a check can wait about five minutes at idle probe cadence, and consecutive forge checks each wait for a new probe. A closed room leaves the last facts that pass the relevant floor in force. The answer carries the winning case index (omitted for `else` and `unknown`), the inherited key, the readings after the floor and commit fence, and, for `unknown` only, a reason naming each unread key. A held floor's reason names the session's start rather than the check's entry. Its origin is `check` and its digests are empty.

After the floor passes, bare `ci` on an Open link with a nonempty `open.head` is fenced by commit. First, a readable local HEAD differing from the PR head makes `ci` unread only when `git merge-base --is-ancestor <local> <pr_head>` exits exactly 1. Otherwise, a known, nonempty `ci_sha` differing from the PR head makes it unread. Rule 1 wins when both apply; the floor's reason precedes both. The [reference](../../reference/cli/workflow.md#json-shapes) owns the two reason forms. An unreadable local HEAD skips rule 1, not rule 2. An ancestry exit 0, 128 (including an unfetched PR head), other exit, timeout, or spawn error also leaves rule 2 to decide. An unknown `ci_sha` skips only rule 2. Without a PR head, including legacy empty heads, merged or closed links, Gitea, and GitHub facts misses, the floor alone applies. Branch selectors, `pr`, `pr.queue`, `pr.mergeable`, `pr.review`, and PR-less `branch_ci` have no commit fence and remain subject to propagation lag. Loop conditions share the floor and the fence through `crates/rimz/src/harness/when.rs::forge_unread` and `crates/rimz/src/harness/when.rs::CiSource::ci_fence` ([loops](./loops.md#condition-planning)).

The evaluator reads the cache once, then reads fresh local HEAD in the scope path, comparing the PR head with local HEAD and `ci_sha` with the PR head. Both git reads live in `crates/rimz/src/harness/when.rs::CiSource::ci_fence` and are bounded at two seconds through `crates/rimz/src/proc/mod.rs::run_bounded_git_output`; the sidebar graph reaches them through loop conditions, and they only read. Git runs only for a case naming bare `ci` after the floor passes and an open PR head is known; ancestry runs only when local HEAD differs. Settlement under the workspace lock does not re-read either input: the answer describes the cached PR head at `checked_at`. A later commit or push is a new fact for the next evaluation in this check, or on returning from a step.

No probe cadence or signal changes accompany the fence. A local HEAD change nudges one probe; if it beats the forge, the next probe uses the repository TTL (20 seconds hot, 300 seconds idle). CI signals fire only on verdict changes, so `failed` at an old commit becoming `failed` at the new one is sampled by the minute workflow tick rather than a CI signal. The wait therefore adds up to a tick after the cache catches up.

Settlement under the lock decides holds, never the off-lock evaluator. A winning case with `for` merges a wait keyed by `(outcome, case)`, with outcome `hold`, the case's outcome as detail, and the case index in `Wait.case`. A hold keeps the run's routed input and key. Once `now - first >= for`, the case routes its own outcome. An `unknown` answer routed to `@wait` keeps the hold open with its `first` when the held case itself reads true or unknown on that answer's readings (`Transition::hold_survives`), so a later true answer of the same case continues it. While it survives, `wait.unknown` keeps the unknown answer's reason, and every reader of the wait describes the node as unknown rather than holding: `workflow show` prints its `unknown: <keys>` phrase without the hold's `then <target> at <time>` forecast, the rail marks cases from that answer's readings (`crates/rimz/src/harness/workflow/script/condition.rs::case_marks`), and the sidebar strip reads `unknown`. The held case's next true answer clears it. Any other answer closes the hold: the held case reading false, another case answering, or a route that leaves the node. A later true case then starts it again. Ordinary check evaluations recompute the bounded `first + for` recheck, so a wake keeps `first`. The tick re-samples an ordinary hold before its recheck time, and a transition that falls entirely between two samples goes unseen. A held rest-check wait also rechecks on those signals and the minute tick, while its leader rests on the judged turn.

### Sleeps

A sleep evaluates in-process with no child, digest, or stderr. Its nonzero `sleep` duration runs from `record.entered_at`; entry through a route or a parked resume restarts it. Its required `then` names a node or terminal target, never `@wait`. A session's `rest-check` cannot name a sleep, because a rest check samples leader turn ends rather than running an independent timer. Sleep takes `on.invalid` as its only route; the `sleep` table has no `wake`, `timeout`, `else`, `window`, or `prompt-file`.

Expiry is checked first and answers `{outcome: then, reason: "slept <sleep>"}`. Before expiry, a plain sleep answers `{outcome: sleeping, recheck_at: <entered_at + sleep>}`. That stored edge is clamped to an earlier deadline, and the tick does not spawn before it. A plain sleep journals just its entry and expiry evaluations.

With `when`, `Check::condition_cases` compiles one derived case into the node with outcome `then` and the optional `for`; the same condition evaluator supplies freshness, unread handling, subscriptions and hold settlement, with fallback `sleeping`. `sleeping` and `unknown` store no recheck, so the minute tick keeps sampling, and matching signals wake it earlier. Expiry may be about a minute late and wins over an unfinished hold. `for` refuses when invalid, zero, without `when`, or at least `sleep`. Sleeps have real `sleeping → @wait` and, with `when`, `unknown → @wait` edges, so they bound check-only cycles without a timeout. Definition views hide those default edges and the derived case, printing `sleep`, `when`, `for`, and `then` instead. List detail and the show headline read `sleeping 12m/30m when ci=passed → fix`, omitting `when` for a plain sleep and never appending a recheck clock.

### Waits and parks

A wait keeps its node and the node's original timeout clock. Repeated identical waits merge in the record (`first`, `last`, `count`, `recheck_at`), and leaving the wait appends one summary to the journal. A check wait's span runs from the answer that opened it to the newest answer merged into it. An advance that arrives before an ordinary wait's `recheck_at` increments its count and moves `last` to that advance without evaluating. A hold is re-sampled instead.

`@done` and `@failed` end the run.

### Bounds

Every advance checks bounds before routing; an agent observation first updates its live ask hold. The engine routes a bound with an engine object that inherits the current key:

| Bound | Fires when | Input object | Route |
| --- | --- | --- | --- |
| Deadline | Once, when the unfired deadline passes. It stops gating until `--extend deadline` re-arms it. | `{outcome: deadline, deadline: T}` | `on.deadline` |
| Check timeout | The check's `timeout` after `entered_at`. It spans every evaluation and wait at the node. | `{outcome: timeout, node: C, timeout: S}` | `on.timeout` |
| Step timeout | An agent step's `timeout` after the attempt started, excluding closed hold time (`asked_ms`); never due while a hold is open (`held_since` or `asking`) (`crates/rimz/src/harness/workflow/inspect.rs::timeout_at`). | The run's routed input | Ends the attempt as `timeout`, then `on.failed` when set, else `then`. |
| Visit caps | Before launch, the step's visits since the last reset reach `max-visits + visit_grant`. Nothing launches, and no visit or sequence is consumed. | `{outcome: cap, step: S, bound: "max-visits", visits: N, max: M, routed_by: "name" or null}`. `routed_by` keeps the outcome that routed into S for re-entry at S. The grant is included in `max`. | `on.cap` |

## Agent attempts

Agent steps launch through `launcher::prepare_layout` and `launcher::execute`, with room Birth and a detached leader run (`turn` for turn steps, `session` for sessions). They open an unfocused new tab titled `run <leader kind>`, never as the advancing agent's children. The leader retains supervised preflight and defaults an unset permission mode to Auto; companions use layout preflight with loop-equivalent trust verdicts and workflow-named refusals. Every agent cell carries `WorkflowAttemptRef {run, seq, role}` and pins `RIMZ_WORKFLOW_RUN`, `RIMZ_WORKFLOW_DIR`, and `RIMZ_WORKFLOW_DEFINITION` under every isolation level. Only the leader has a run; command cells follow its durable record and close themselves after it settles. RimZ-launched children do not inherit this attempt identity, but do inherit the separate [automation stamp](../agents/model.md#the-rollup) naming the workflow and launching step. `LiveAttempt.lifecycle` is `turn` or `session`; it decodes a missing value as turn and omits turn on write.

The shared launch compiler (`crates/rimz/src/harness/launch_plan.rs::compile`) reads the pinned run's `spec_dir` for `RIMZ_WORKFLOW_DEFINITION` and the Environment `- workflow:` line, independently of `env_reminder`. A failed record read returns a launch warning and omits both. Non-workflow launches unset that variable alongside `RIMZ_WORKFLOW_RUN` and `RIMZ_WORKFLOW_DIR`.

### Admission

Admission checks, in order, bounds, the visit cap, each agent cell's provider window, checkout occupancy, workflow/step limits, the machine FIFO when machine-gated, and both machine caps, for every agent start whatever its origin. Unless `throttle = "off"`, the start also checks machine stagger, resources, and the capacity script. The caps and workflow/step limits apply even to an `off` step. One value decides whether a start waits: `prepare` reads `RunRecord.capacity` once and hands it to `prepare_capacity`, so the admission errors `prepare` keeps and the holds `prepare_capacity` waits on cannot disagree. A `skip` run launches past every hold and admission error, a start too wide for a machine cap aside, and records each hold on the attempt. Each blocked window, occupancy, or capacity check merges a wait that keeps the routed input and key and spends no visit or sequence:

| Blocker | Wait |
| --- | --- |
| The step's `window` is closed for any agent cell's provider. | `window`, with the blocking term and its reading in `Wait.detail` (`5h.left=12<42`), which the waiting line prints. |
| An occupant is mid-turn. | `takeover` |
| An idle occupant, and the step's `admission.occupancy` is `wait` (the default). | `occupied` |
| The shared start throttle or a workflow/step limit holds the step. | `capacity`, with `Wait.kinds`, `Wait.detail`, optional typed `Wait.hold`, and optional `Wait.gives_up_at`. The kind survives retries and closing the wait into history. |
| Admission times out waiting for `loops/throttle.lock` and no capacity wait is open. | `capacity`, held as `queue`, with `waiting for the start queue: <lock error>` in `Wait.detail`. A capacity wait already open is left as recorded. |

Who occupies the checkout follows the [shared takeover occupancy rule](./loops.md#condition-planning). `admission.occupancy` is one of three values (`crates/rimz/src/harness/workflow/spec.rs::OccupancyPolicy`): `wait` waits for the occupants, `takeover` stops idle ones, and `share` skips the occupancy read and eviction entirely and never records a `takeover` or `occupied` wait, while window, capacity, and visit bounds still apply; a sharing step's agent still counts as an occupant for later steps that do not share. At the project root, owned nested worktrees are excluded. A step with a `worktree` destination reads occupancy, and evicts, at that destination rather than at the run's scope (`crates/rimz/src/harness/workflow/engine.rs::prepare`), and a takeover there relaunches the destination's stopped team cohort fresh rather than resuming it. With `occupancy = "takeover"`, capacity is decided before eviction, so a capacity-held step never stops the occupant. Admission runs off-lock in its own round trip, and each return re-reads bounds, visit caps, window, and occupancy. Eviction is part of the launch (`StepLaunch.evict`): the CLI host prepares the launch first, so a launch its preparation refuses (a saved-untrusted folder, untrusted hooks) stops no one, then stops the occupants and executes the prepared launch. The host reads the checkout again there even when the first read found it free, and finds it free only by a read taken after the last stop it issued: a takeover stops the occupants a read finds, an occupant that arrived while the launch was prepared included, and reads again, up to three rounds; a read that finds any other occupancy, or occupants still there once the rounds are spent, returns that occupancy (`crates/rimz/src/cli/workflow/host.rs::Host::evict`). The engine then takes back the attempt and the visit it counted (`Transition::withdraw_attempt`) and waits `takeover` or `occupied` as the first read would, with no failure or strike. A launch whose eviction failed (`Host::evict`, reported as `NotLaunched::Unstarted`) started nothing and is retried once per step entry: the engine withdraws the attempt and its visit, sets `RunRecord::launch_retry`, and waits `retry` with the reason in `Wait.detail`, kept in the journal when it closes, and the next advance (a tick or a hook wake) launches again with no `recheck_at` floor (`crates/rimz/src/harness/workflow/engine/agent.rs::launch`). A continued restart (`StepLaunch.resume`) and a `limited` failure are not retried. A second such failure, any other host-reported failure (a refusal out of `launcher::prepare_layout`, an error out of `launcher::execute`), a launch-group resolution error, or an admission error other than a queue-lock timeout becomes a counted `died` attempt. It follows the step's `invalid` edge. The exception is that an agent group wider than a machine cap forces `@failed`, never `then` or `on.capacity`. Eviction stops occupants through `agents_cmd::stop_resolved`, which counts an occupant as stopped only when a read after its waits finds no pane hosting it and its process gone, or, for a process RimZ does not know, its end recorded, or its never-bound launch reservation cancelled ([stopping an agent tree](./fleet.md#stopping-an-agent-tree)); an occupant it cannot stop fails the eviction, and the step launches nothing.

`advance` asks `throttle::try_admit` at most once per next-sequence/node pair and carries its answer into the next locked `prepare`. A route can change the node without allocating a sequence, so either part changing discards the answer and its turn. The kind/account grouping uses the same launch-cell resolution as the window. A held answer leaves no ticket and persists `step_wait("capacity", reason)`; the minute tick retries it. A queue-lock timeout at any of admission's four queue-lock scopes (two in `throttle::try_admit_in`, two in `throttle::check_groups`), `ThrottleError::Lock(LockErr::Timeout)`, is contention, not a fault: `prepare` keeps it out of the launch error, and `prepare_capacity` records it as a capacity wait held as `queue` for a waiting run, which gives up through the same chain as any other capacity hold; a `skip` run launches past it. When a capacity wait is already open, the timeout learned nothing, so the wait keeps its hold, kinds, reason, `first`, and give-up time, and a `workflow_limit` or `step_limit` waiter keeps its FIFO standing. Lock open and acquire faults, queue and ticket I/O, reading and ticket-write failures, and a vanished ticket stay counted `died` attempts. `Wait.first` survives consecutive capacity holds, but another wait outcome restarts it. The give-up time is the node's `admission.give-up` from `Wait.first`, else the run's `give_up` instant, else none; a time already past at the first hold gives up on the same advance. At its give-up time, the engine journals a `capacity` route with input `{outcome: "capacity", step, reason, kinds, waited_ms}` plus the inherited key, then follows `on.capacity`; the run deadline remains an independent bound. Admission carries its optional turn through `StepLaunch`, `LeaderRun`, and `prepare_run_layout` to `SupervisedRunRequest.throttle_turn`, reported by `open_fresh`. Any other ending drops the turn. A `skip` run (`throttle::Run::skip`) passes every hold its start meets, the limits, the queue, the machine limits, and the capacity check, recording each as text joined by `; `, and claims an `Admitted` ticket. Command steps, checks, and existing sessions never take a turn.

The skipped pass shares the waiting pass's `launching` / `limits::evaluate` expression under the queue lock, before writing the admitted ticket and before any launch stamp moves. Workflow/step holds, the queue hold, and machine holds all become notes, and so do a census or stamp read failure and a capacity check that errors or times out. The admitted `Turn` carries the skipped hold into `prepare`; held, open, or errored answers carry none. No assist is written: the start is the user's action.

`crates/rimz/src/harness/throttle/limits.rs` owns the locked limit pass. The request carries workflow name, step, asking run id, capacity arrival (`Wait.first`, or the current request instant), and sealed limits. Whether the start waits is not part of the request: `throttle::Run::skip` decides it in the pass. Admission first refuses an automated group larger than a machine cap, naming the cap and its fix; a workflow or step limit counts the start as one whatever its width, so it refuses none. Otherwise, under `loops/throttle.lock`, an in-flight turn of the same limited workflow comes first, then FIFO, workflow count, step count, workflow stagger, step stagger, the machine queue when machine-gated, both machine caps, and finally machine stagger and resource checks when machine-gated. Every limit hold, the in-flight one included, is reported under its limit kind before any machine hold, so a waiter keeps its FIFO standing on a pass where the machine also holds it. Each machine cap requires the whole incoming agent group to fit, and other admitted-but-unlaunched starts reserve their agent counts under the same lock. A same-workflow admitted turn keeps limited starts serialized until its launch report: `engine::prepare` publishes the attempt under the workspace lock before the launch reports, so from the report the run record carries the count, and the next `sweep` drops the launched ticket's limit scope without reading any agent row. Between admission and publication the admitted ticket holds; from publication the record counts, so no instant leaves an admitted start counted by neither. No workflow or step limit bypasses a machine cap.

The census reads run records only, never an agent snapshot: `crates/rimz/src/harness/throttle.rs::SystemHost::workflows` loads every run record of every known room and keeps the non-terminal ones. Workflow scope counts one per run of that workflow name whose record holds an agent session (`RunRecord::session_attempt`: a session held at its rest check counts, a judge attempt does not); step scope also matches the session's own node (`LiveAttempt::node`), not `RunRecord::node`, which names the check while a session is held. A published attempt counts whether or not `LiveAttempt::run` is written yet, and a dead leader's attempt counts until an advance settles it: both over-count on the safe side until the next advance. Parked and waiting runs count while their record holds the session. The asking run's own record is skipped by run id, and the start it asks for adds one. Companions, RimZ-launched children and peers, and kept or `@break` agents that left their run do not count, since no record attempt names them. An unreadable required room or stagger record holds a scheduled start as `store`, never as a short count or absent stamp.

FIFO reads Active same-workflow capacity waiters ordered by `(Wait.first, run id)`: `workflow_limit` holds every step, `step_limit` only its matching step. A free slot can remain idle until the earliest waiter's next minute tick. Hold text prefixes `workflow <name>: ` or `step <name>: ` to `N of M agents open (@a, @b, +K)`, `next start in <duration>`, `N earlier start(s) waiting`, or `N start(s) launching` while a same-workflow launch is not yet counted (named for the workflow limit when one is set, else the step). Machine cap reasons name multi-agent demand separately (`this start opens 2`). Workflow and step reasons name each counted run by its recorded leader handle (`AttemptRun::handle`), at most two then `+K`; an attempt without a recorded leader yet counts only in `+K`.

`Turn::report_launch` alone stamps `loops/start-stamps.json`, resolved by `crates/rimz/src/disk/paths.rs::loop_throttle_start_stamps`, under the same queue lock as the launched ticket. The record has `machine` (an optional launch timestamp in milliseconds) and `workflows` (workflow name to `last_launch_ms` and a `steps` map of step names to timestamps). Only machine-gated launches set `machine`; limited launches set their workflow and step stamps. It uses the queue's rename-atomic cache writer, not per-launch fsync; process crashes retain completed replacements, while power loss can lose the newest queue or stagger write. Missing means no prior launch; when scheduled admission needs a configured stagger, malformed or unreadable holds as `store`. An unreported dropped turn stamps nothing. Skipped launches reserve in-flight scope and restart the stamps of every scope they are gated by without waiting; `off` launches never restart machine stagger.

Prompt composition and `git rev-parse HEAD` run under the lock after the first bound read, and they take time. So `prepare` takes a fresh clock after them and reads the bounds again, and a bound that came due meanwhile routes without publishing an attempt, spending no visit and no sequence. Only after that second read does an admitted launch count the visit, record HEAD, and publish its context and live attempt, stamped with the fresh clock. The bounds are re-read rather than the work moved off-lock, because admission and publication share the lock on purpose. After prompt composition the window reading is not re-read: it was sampled in the same pass, and provider windows move in minutes.

### Prompt composition

`crates/rimz/src/harness/workflow/engine/agent.rs::compose` joins three texts with blank lines at every launch: the prompt file, `signs/<step>.md` when present, and the run prompt. A sign's canonical path must stay inside `work/`. The digests are keyed by the spec's prompt-file spelling, `signs/<step>.md`, and `prompt`, and absent optional text has no digest. A relaunch can find a dirty checkout left by a stopped attempt, and the step's prompt must handle it.

`crates/rimz/src/harness/workflow/engine/agent.rs::break_prompt` classifies the current input edge and node, not past failures. Its trace includes the last six source entries, the latest evaluation, history/evaluation counts and the last eight journal entries. Judge evaluations name `.check.json`, run/shell evaluations `.check.log`, and conditions/sleeps no file. The serialized excerpt is capped at half the text-prompt guard, leaving room for the surrounding instructions; full journal and context paths remain outside the excerpt.

`crates/rimz/src/harness/workflow/brief.rs::step` composes a separate `### Workflow` launch-reminder body off-lock in `engine::agent::launch`, from the sealed spec and published, bumped run record. It reads the journal through the same `routing_hop` rule as `show`, and words the run's origin from what its record froze at the fire (`RunRecord::fire`: the task's name, and a scheduled fire's trigger clause), never the task catalog or `RunRecord.task`, so editing, renaming or removing the task mid-run leaves the sentence as it was, old task name included. A resume counts as the sender after a park or when returning from `@break`, even before its agent launches; an active run's `--extend` does not replace that sender. Unreadable enrichment drops only the arrival sentence. The rail follows `Definition::walk`, groups returning steps beside their check, and draws arrows only for live non-deadline routes; unreachable nodes stay out even after an explicit resume there. Visit bounds include resume grants. `StepLaunch.workflow_note` travels through the leader's supervised request as `ReminderSection::Workflow`, never as a `Loop` section; companions get no section, and a step's subscriptions are its own `subscribe` wakes. `crates/rimz/src/harness/workflow/script/judge.rs::run` sets the shorter `brief::judge` section on its headless request without changing the prompt's JSON contract. The notes point models at workflow views, not raw context files. Ordinary agent resume refuses current workflow pins, and rebirth skips them. Workflow restart, including `agents restart` of a current step, recomposes the note for its fresh or resumed leader.

The leader's check descriptions follow the step's `rest-check` order, then its `then` check, each once: conditions retain their cases, scripts and shells show command plus optional summary and their distinct execution/path rules, and judges show only a summary. A sealed judge without a summary gets a fixed agent-judge sentence, not its prompt filename. Script and shell descriptions explicitly allow the agent to run the command itself.

### How an attempt ends

`crates/rimz/src/harness/workflow/engine/agent.rs::prepare_end` observes once, stamps the clock after observation, and updates the hold before deciding an end, in this precedence order:

| Condition | Outcome / effect | Route |
| --- | --- | --- |
| Unfired run deadline at or before now | `canceled` | `on.deadline`, once |
| Agent step, no open hold, `started_at + timeout + asked_ms` at or before now | `timeout` | `on.failed` when set, else `then` |
| Supervised run `completed` | `ended` | `then` |
| `failed`, `verify_failed`, or `timed_out` | `died` | `on.failed` when set, else `then` |
| `canceled` | `canceled` | `then` |
| `budget_exceeded` | `limited`, with no known reset | `on.failed` when set, else `then` |
| Live run, observed provider limit, error, interrupt, or budget park | Keep the attempt live | None |
| Turn run `pending` or `running`, blocking ask, explicit `on.asked` | `asked` | `on.asked` |
| No supervised run and dead launch host | `canceled` | `then` |
| Session with a `rest-check`, new eligible leader turn end | Hold the session aside and evaluate its first rest check | Saved verdict decides keep or close |
| Otherwise | Keep the attempt live; persist only a changed hold | None |

The `on.failed` column is one rule, `Definition::routes_on_failed`: settlement (`Transition::settle_step`) and the routing lookup `Definition::target` that `workflow show` draws from both read it, and `inspect::attempt_superseded` folds a `died`, `timeout` or `limited` attempt into the `failed` route that follows it, so the trail prints one hop.

The terminal-status and explicit-ask mapping is one pure function, `crates/rimz/src/harness/workflow/engine/agent.rs::observed_outcome`; timeout and deadline stay outside it. Live provider limits never end an attempt. A pending ask therefore beats the step timeout even with `on.asked`, but not the deadline or cancel. A completed run still ends `ended` even if an ask remains visible.

For turn and session attempts, `LiveAttempt.asking` stores `{since, text, kind, handle}` while a blocking ask is observed. `held_since` opens one shared hold at the earliest ask, limit, error, or budget-park evidence, clamped to `[started_at, now]`; `asked_ms` stores closed held time as u64 milliseconds. Overlapping evidence keeps the hold open and is credited only once, when all pausing evidence clears. Silence and interrupts do not hold the timeout. Optional fields default when absent and are omitted when empty or zero. An ask's visibility normally begins at its open time; a Codex Auto permission is hidden during automatic review and becomes visible 60 seconds after arrival unless the rollout proves the asking Code Mode cell finished and closes the ask, so review time does not pause the attempt timeout ([waiting and asks](../agents/model.md#waiting-and-asks)). Further asks keep their interval's start and replace its text, kind, and handle. A stable hold writes nothing, and a hold-only write journals and accounts nothing. Already-ending attempts do not update the hold; staging any end clears it.

Leader lifecycle hooks wake the run; subagents have no workflow pin and are sampled by the roughly one-minute tick. Two holds without an intervening observation merge into one pause, and a subagent's answer may remain credited and displayed until the next tick. A step already overdue when the hold opened times out after it clears. An already-staged `asked` end settles and resumes. Records without pause fields start with no pause.

A route through `then` forwards the run's routed input unchanged, with the current key: the attempt's outcome and evidence go to `prev_attempt`, never into the input. A queued asynchronous question does not end an attempt. The host reads the leader's run record and the room snapshot with budget parks projected, and `harness::workflow::observe` decides from them. It scans the leader, then its live launched descendants depth first, past an ended child and everything under it. It reads each agent's first actionable ask, not one by ask id, until a blocking one is found, and never reads an agent whose permission is still under automatic review; that permission's hold starts when its review ends. Limits come from typed turn-error classes, the reset read once, from the first limited agent's account and model, never from provider text. The earliest stop wins, a tie keeps the one scanned first, and an interrupt only stands while nothing else stops the attempt. A launch refusal is `died`, or `limited` for a budget refusal, with the refusal text as the attempt's reason.

Workflow-owned supervised runs record an errored `TurnEnded` or `TurnInterrupted` as optional `stopped_turn = {at, disposition: failed | canceled}` rather than a terminal status. They remain Running and clear any inherited owed-wake `parked_at`; the next `TurnStarted`, `ToolUsed`, `AwaitingInput`, or clean end clears the evidence. Non-workflow runs keep their terminal-disposition table. Session runs record the same evidence across turns. `Observed.stopped` combines this with displayed turn-error classes and the card's budget-park timestamp, as `limit`, `error`, `interrupt`, or `budget`. Failed and interrupted turns do not enter a rest check. A turn run's provider exit still becomes Failed and follows `then` as `died`.

A session records live ask holds; it ends on a blocking ask only when the step routes `on.asked`, as a turn does (`crates/rimz/src/harness/workflow/engine/agent.rs::observed_outcome` takes no lifecycle), and never on a live provider limit. Its `timeout` ends it as `timeout` once due. Turn ends, interruptions, session-end hooks, and RimZ budget parks keep its session run open; a `rest-check` adds the check-driven close below. A park still interrupts the provider and stamps its ledger; a budget-gate refusal before launch still reads `limited`. Provider exit completes a registered session as `ended`, or an unregistered one as `died`; a crash after registration also reads `ended`. The run deadline, except at `@break`, beats a completed observation and routes `on.deadline` with outcome `canceled`. Cancel, restart, reset and rebirth also cancel sessions. Every `@break` ending detaches its agent, and its wrapper cleanup is disabled. `prev_attempt.asked` is set only for an `asked` ending, and companion trees never control an attempt's end.

### Rest checks: judging an open session

A session's `rest-check` is a nonempty list of check names (`Node::rest_check`, empty for a turn, a check, or a session without one). Entry at a rest follows the first name; membership keeps a held session open across a route. The list carries no adjacency rule: routes alone decide where the run goes next. A listed move requires the same eligible judged turn as a push or close, closes the source wait, clears the saved verdict and check retry, updates node/entry, and evaluates the destination in the same advance without changing input/key. It writes `TurnEnd {action: kept, check: source, target: destination}`; existing history, hop and assist readers project the route. Every decision names its actual check, including a discard or interruption before a verdict exists. A check reached without a held session keeps ordinary routing behavior.

An eligible leader turn end moves the agent attempt into `RunRecord.held = {attempt, entered_at, verdict?}` and enters its first rest check, with no visit or input/key change. The held attempt is a session Agent attempt with a run, a `judged` turn identity, and no ending; the slot is empty or holds that check's Script/Judge attempt. Held sessions never survive restoration, staging an ending, parking, or terminal settlement. The ordinary check engine owns windows, sequences, publication, retries, limits, timeouts, dead-host reclaim, and CAS while the session is aside. Routing saves `{node, entered_at, at, target, object, reason}` in `held.verdict` instead of applying it; `at` is the evaluation's journal instant.

The identity is `{agent_id, started_at, ended_at}` from the leader's projected turn stamps, with `ended_at >= started_at`; successful compaction at rest can supply equal stamps. An interrupted turn can have a closed identity but is not eligible while stopped. The engine requests `Observation::LeaderTurn` only when preparing an attempt whose step has a `rest-check`, without a staged ending, or observing its held session; turn attempts, sessions without a rest check, cancel and post-stop cost observations use `Observation::Attempt` without leader-turn reads. The host computes rest fresh under the workspace lock: `idle_stop::resting`, no owed wake, no queued message, and no other open supervised run, excluding exactly this session's run id. Pending ingress blocks only when its `RIMZ_WORKFLOW_RUN` names this workflow run and its `RIMZ_RUN_ID` names this leader's supervised run, except exactly the frame named by this advance's `--woken-by` ingress id. Detached former leaders and companion frames therefore do not block the current leader's rest. The waking frame's apply has committed before spawning the advance, but the drainer publishes its applied cursor only after the apply exits; the advance is the frame's wake, not a reason to wait for another one. The exception lasts for this advance's lifetime, including the fresh observation after evaluation; every other pending frame naming this leader's run still blocks. The engine also requires no blocking ask or non-clean stop, descendants included. `LiveAttempt.judged` consumes the identity before evaluation, so restoring the session cannot begin another initial check for that end; a held wait instead re-samples at the check.

Before other preparation, a held preflight observes the session and folds its hold, then checks the deadline and provider exit or budget-exceeded status before considering a verdict. A same-step verdict closes any wait, restores the session, and applies its input/key. It checks the visit cap before bumping once and stamping `LiveAttempt.visit`. A capped answer journals the ordinary cap route and closes through that route. Otherwise it publishes `LiveAttempt.push = {message, queued: false}` and `TurnEnd {action: pushed, visit, message}` under the workspace lock, then calls `AttemptHost::push` off-lock. The host composes a System/Done synthetic message and atomically enqueues only if the id is absent from both live queue and all retained history; delivery uses the ordinary message pipeline. A failed or interrupted push retries the same id without recounting. The host's enqueue acknowledgment is persisted only if sequence and message id still match. Restoration keeps the session's sequence, run and step entry time, clears check retry state and `seen`, and rewrites context to the step view. A `@wait` answer instead leaves the session held at the check, clears its saved verdict, merges an ordinary rechecking wait and writes `TurnEnd {kept}` without a visit. A new wait's `first` and every merge's `last` use the answer's `at`. Subscribed signals and the minute tick re-sample the held wait. If the leader no longer rests on its judged turn, preflight closes the wait, abandons any check in flight and restores the session with `TurnEnd {discarded, reason: "leader turn moved on"}`; the next clean rest is judged.

A closing verdict needs a fresh locked observation after evaluation. A different or missing turn tuple discards it, keeping the consumed marker; the advance may then check a newer eligible end. An identical tuple that is no longer eligible defers the saved verdict until a later advance, without paying for the check again. An identical eligible tuple restores the session and stages `Ended/Lifecycle` with `Ending.route = verdict`, then uses the ordinary off-lock stop or detach. Settlement journals the ended attempt and the closed turn end, restores the check's node and entry time, and applies its route exactly once instead of following `then`; any route other than the session itself, `@wait`, or another listed check closes it. A step destination launches normally, and another check sees the ended session in `prev_attempt`. Without a held session, the route applies at once, including after `resume --at` the check.

Provider exit and deadline abandon any live check, restore the session, record an interrupted turn end, and stage the ordinary session ending; cancellation does the same before its existing stop branch. Cancel replacing an already-staged verdict close records interruption and removes `Ending.route`, so late settlement cannot also record a close. Check timeouts still start from the hold's check entry; the deadline belongs to held preflight. Future judge backoff never suppresses paced session observations by the scheduler. A saved verdict resolves before the ordinary check timeout, even with an open wait.

Each judged end or held-wait answer has a `turn_end` decision (`kept`, `pushed`, `closed`, `discarded`, or `interrupted`), carrying the session sequence, step, turn identity, check, and optional verdict outcome/target or explanatory reason. Pushed, closed and kept moves between listed checks book one route assist at the check; a kept wait books only when the wait closes. Discards and interruptions book none. Evaluation, Route and Attempt rows alongside a decision book no additional route or retry/rerun diagnostic. Held evaluations retain ordinary retry/rerun diagnostics without route assists unless a verdict is saved: engine-origin evaluations then book nothing and raise no `WorkflowRetry` or `WorkflowRerun`. Wait, Park and Terminal rows book as [Accounting](#accounting) describes.

`context.json` has `live_attempt = {step, seq, visit, visits, key, started_at, handle, run_id, claim_path, head_start, turn_end}` while a session with a `rest-check` has no staged ending, held or in the slot. Its turn end is `judged` or null; it has no outcome, ending timestamp, or ending commit. `prev_attempt` stays the last ended attempt. Check publications retain the check's top-level sequence, output and retry fields without step visit fields; a push-back or discard restores the step view, a held wait keeps the check view, and a close leaves the next publication to replace it.

Accepted boundaries: a turn starting after the final per-run ingress read but before off-lock stop can be cut off, since stopping has no provider/input coordination; fast turns can coalesce into the latest eligible rest rather than a lossless replay; a long check window or judge-limit wait can spend a check whose later verdict is discarded. Publication still appends journal, writes record, then appends assists, so crashes can duplicate a journal row or miss an assist, as for other transitions.

A held forge reading can be one probe old, back to the session's start, rather than from the judged turn. A same-SHA CI rerun or PR reopen inside that turn can therefore read as its earlier state. CI on a new head is still fenced by the PR head. A fact changing after the leader's last turn end is sampled at the next eligible end, using the latest probe, or while held at `@wait` when a subscribed signal or the minute tick re-samples the check.

### Stopping an attempt

Every end publishes `ending` and saves the observation into `prev_attempt` under the lock before anything stops, which keeps the asks and limits the stop would retire. By default, the host stops every pinned layout agent and its tree off-lock (`harness::workflow::stop_cohort` picks them: every live pinned row, and once a pin is cleared the detached leader and its launch group; an ended child's subtree is never reached), observes cost immediately afterward, then samples HEAD. It then re-locks, checks the sequence and the stopper's identity, journals the attempt, and routes. No successor launches before the stop or detach returns.

For `keep = true`, `StepLaunch.keep` disables the leader wrapper's completion cleanup, and a Lifecycle ending whose outcome is `ended` or `asked` calls `AttemptHost::detach` instead of stop (`engine/agent.rs::detaches`). A `died`, `limited`, or `canceled` attempt stops the layout like a forced ending. A push-back cap ends as `ended` and detaches like any other natural ending. Detach cancels a nonterminal supervised run and clears each matching leader/companion pin that `harness::workflow::detach_cohort` selects through `crates/rimz/src/store/writer.rs::Store::clear_workflow_pin`, stopping nothing. Its `agent.workflow_cleared` event compares the complete expected `{run, seq, role}` again in the reducer; mismatches keep their pin. The event changes no card field, so neither the snapshot nor the rollup version moves, and older binaries decode it as `Other`. Cleared cards are ordinary recovery candidates. `agents resume` refuses a current pin with the workflow-restart fix, clears a former pin only after preflight, and keeps it with a warning when the workflow record cannot be read.

Settlement rechecks a forced ending after off-lock detach. A cancel that replaced the Lifecycle ending still stops the layout before settling. Stop can recover already-detached, unpinned cells from the leader's original launch group; a card pinned to a different attempt is never selected by that fallback.

- A later advance leaves a live stopper alone and reclaims a dead one, merging the staged child evidence with the new stop inventory.
- A cancel during launch leaves the live launch owner to publish and stop the run it gets back.
- When the launcher is dead, the stopper asks the host for the unpublished supervised run by its workflow id and attempt sequence (`AttemptHost::orphan`, which both hosts answer through `harness::workflow::orphan`) and stops it before settlement.
- Live launched descendants are stopped first; they and companion cells are recorded under `children.stopped`. Independently launched peers and team cohorts survive under `children.live`, with their board stage when available.

Stops use the shared cascade and add no workflow-specific lifecycle events. The next visit's [occupancy read](./loops.md#condition-planning) skips a stopped attempt whose owner has exited, even while its cached row remains. The host stops every unended row with the attempt pin, even if the leader row is absent or ended, plus the detached cohort described above; it falls back to the supervised stop only when neither inventory remains. Attempt cost comes from the leader run after stop or detach; companion spend stays on cards and in stats, and unstamped spend stays null.

## Headless judges

A judge (`crates/rimz/src/harness/workflow/script/judge.rs::run`) runs through the shared headless profile resolver and the judge core (`crates/rimz/src/harness/headless/judge.rs::prepare`) with automatic permission mode. The core classes a failed attempt, and `Transition::finish_judge` asks its one retry rule (`FailureKind::retry_owed`) whether the attempt is owed a second run. Its profile must resolve to exactly one agent cell, or the evaluation fails (`crates/rimz/src/harness/headless.rs::HeadlessProfile::resolve`). Its Judge section names `rimz workflow show $RIMZ_WORKFLOW_RUN --history`; the prompt names `RIMZ_WORKFLOW_DIR` and `output_path`, and demands exactly one JSON object with the check fields and no prose or Markdown fence. The schema stays open, so extra fields stay routed input. Claude receives it as its schema argument (`crates/rimz/src/agents/adapters/claude/headless.rs::ClaudeHeadless::render_argv`). Codex omits its strict structured-output switch for an open schema and reads the prompt-shaped last message from its output file. Closed schemas, loop verdicts among them, keep Codex schema enforcement. The provider's structured value is saved to `output_path`, the engine reads that file when there is none, and the value goes through the same normalizer as script stdout.

A judge is read-only on the scope checkout and its Git admin and common directories. Scoped isolation overlays them read-only after all reach rebinds, and host isolation enforces the rule only through the prompt. The root view and the required-path rebinds leave `work/` writable, a room home under host `/tmp` included. A judge evaluation never produces `asked`: nothing reads asks from a headless child, and what the provider does with a permission request in automatic mode is provider behaviour. Claude classifies provider limits in its adapter. Codex supplies no typed limit result, so a limited Codex judge fails as `died`. Before it prepares the child, `crates/rimz/src/harness/workflow/script/judge.rs::budget_refusal` reads the judge's resolved account through `harness::budget::scope_gate` (the fleet and account daily caps and the park), then `agents::provider_budget_gate` on the account binding `crates/rimz/src/harness/workflow/script/judge.rs::managed_launch` resolves for the run's checkout, then the surplus gate the record kept from its task's row when the run started (`surplus`, `surplus_after`) through `crates/rimz/src/harness/surplus.rs::surplus_refusal`, never the live row, so an edit to the row or its removal changes the next fire and not a run already started, and a record with neither field has no surplus gate; a refusal is the `budget` failure, which `Transition::finish_judge` routes to `@failed` with a `budget` route row, and `run_log::report_run` reads that row as `budget skipped`.

Folder-trust and adapter minimum-version checks run before the judge takes the workspace lock to spawn. A failed judge evaluation settles by its failure (`Transition::finish_judge`):

| Failure | Result |
| --- | --- |
| Engine-decided `canceled` (dead host) | Re-runs free. |
| Typed provider limit | Spends no retry. Waits until the known reset, clamped like `recheck_at`, or until a subscribed wake or the tick when the reset is unknown. A matching wake clears a known reset's backoff. |
| `died`: a launch refusal, a nonzero exit, no object, or an output file that is not JSON. `invalid`: an object the normalizer rejects. | One immediate retry with `context.retry = {outcome, reason}`, then `on.invalid` (explicit, on-break, or the `@failed` floor) with `outcome: "invalid"` and the original kind in `failure`. A launch refusal carries its text as `reason`. |

The record stores `check_retry` and `check_retry_context`, so retry evidence survives a dead host without reading the journal. Both reset on node entry and on a parked resume.

## Wakes

A wake only spawns an `advance`, which reads the record again. `run`, `resume`, and `restart` spawn one, and `rimz workflow advance <id>` is the manual form. There is no signal replay: a lost wake delays progress until the next tick.

### The signal helper

Every signal routed through the scheduler's shared firing entry spawns one room helper when the room has an active run (`crates/rimz/src/harness/schedule/signal.rs::wake_workflows`); a lifecycle signal spawns one only when a live session's step subscribes to its family (`engine::hears_lifecycle`, which also reads those runs' sealed specs), since no check wake hears one. That path only reads records and spawns, carrying the whole signal as JSON in the helper's argv. The helper (`engine::wake`) takes the workspace lock per run, reloads each active run and its sealed spec, and matches the current check's subscriptions and the live session's step subscriptions, through the same delivery matcher as loop triggers. A sibling skip does not wake. A run where neither matches gets no write, journal entry, or spawn.

On a match the helper clears the record's and the wait's `recheck_at`, journals the signal name, and marks a live evaluation and held session `woken`. Publishing a new held check request clears the session flag before reading its inputs. If a wake arrives during that check or before its saved `@wait` merges, the merge clears the new backoff and re-evaluates immediately, once, bypassing the hot-loop guard for that wake. Ordinary evaluation settlement does the same for a woken `@wait`. Wakes during the retry can ask for another pass, and without one the ordinary guard applies. The helper spawns one `advance` per matched run, so one slow script cannot hold back another run. A run that fails to load warns without blocking the others.

A step subscription forwards to the leader of `RunRecord::session_attempt` (`engine::subscribers`) only while that attempt is not a turn, has no staged `ending`, and has a supervised run. The held session counts, so a check and its held step can both take one signal. The helper mints the message id under the lock and records it in a `signal` journal row keyed to the session's step and seq, then queues the message off-lock through `AttemptHost::forward`. The CLI host queues it once under that id, as `Type: SIGNAL` from `@rimz` (`HarnessNotice::Signal`), automated, at the done gate, with `about_run` naming the attempt's run, then attempts delivery at once as `Host::push` does. A run that ends before delivery withdraws the message there (`crates/rimz/src/message/premise.rs::broken`), so subscriptions retire with the attempt on every path that ends its run. The text opens with `signal_subject` and the details the loop's SIGNAL delivery prints, then the workflow, step and run id. Every binding that delivers forwards its own message with its own `prompt`, and bindings with the same selector and `match` coalesce into the first. A step-only match writes only that journal row: no record write, assist, or advance. A failed queue warns and keeps the row. A check match writes the row in the same transition as its `wake` row.

### Subscriptions

A step's subscriptions come from its `subscribe` list (`Step::subscriptions`, through `Wake::step_subscription`); validation refuses `subscribe` on a turn agent step, and the `command` and `message` tables have no such field. Unlike a check's wake, a step subscription may name a team lifecycle selector, and an `agent` selector when its `match` names another agent by a non-wildcard `handle` or `session`; an `agent` selector without one refuses (`SpecErr::SelfSignal`). A predictable name can still be the leader's own (a team role's handle), so `engine::subscribers` and `engine::hears_lifecycle` also skip a lifecycle signal whose payload `handle`, compared without its channel, or `session` is the leader's (`engine::from_leader`): a leader never hears its own lifecycle. The leader's session is read only when the handle does not match and the signal names a session: through `AttemptHost::leader_session` in `subscribers`, and through a reader `schedule::signal::wake_workflows` supplies in `hears_lifecycle`, which runs where the signal fires, with no attempt host. A check's subscriptions come from its `wake` list, or, for a condition or conditional sleep, from its terms (`Check::subscriptions`). A plain sleep has none:

| Condition term | Derived selector |
| --- | --- |
| Checkout `ci` | `ci.*` |
| Checkout `pr`, `pr.queue`, `pr.mergeable`, or `pr.review` | `pr.*` |
| Stage | `team.stage` |
| Stage with a branch selector | `team.stage` with `board = "*"` |
| Forge branch-selector or `window.*` | nothing |

Negated terms derive the same selectors. At match time, never persisted, and for checks and steps alike (`engine::delivers`), `ci` and `pr` selectors add the checkout's `path` unless `path` or `branch` is explicit, and `team.stage` adds the board `crates/rimz/src/harness/scratch.rs::durable_board_path` resolves for that checkout, while another team signal, which carries no board, adds the `instance` of its team's cohort in that checkout (`<team>#<channel>`, the routing name of that checkout's own lane, or the team's own name at the project root (`crates/rimz/src/worktree/own_lane.rs::own_lane`)), unless `team`, `instance`, or `board` is explicit; the branch form's explicit `board = "*"` keeps it room-wide, since its board lives in another checkout. A check's checkout is `scope.path`; a step's is the checkout its leader launched in (`engine::destination`), so a step with its own `worktree` hears that worktree's CI and board. Other families stay room-wide. A checkout relink therefore follows its new archive, and project scope matches the project root. A check with no subscriptions runs only on its recheck time and the tick. A matched wake still clears a hold's or a judge limit's backoff.

### Supervised-run edges

An agent step's supervised run wakes its own workflow directly, through `engine::wake_run`. Every newly terminal run write through the harness wakes the run named in its `workflow` field after releasing the workspace lock: provider exits without hooks, wrapper failures, timeouts, and rebirth cancellation included ([scripting.md](./scripting.md#the-record)). Workflow budget parks never settle a run. A hook-ended run that is not a peer turn settles its session spend before the wake, so the advance reads the stamped cost. Non-terminal lifecycle and turn-error frames carrying `RIMZ_WORKFLOW_RUN` wake only that run. An advance spawned inside a frame's apply names that frame's ingress id on argv (`--woken-by`), so its own still-pending frame cannot defer rest; advances outside an apply carry no waking id.

Room teardown cancels supervised runs without waking workflows, and the next advance settles those attempts. Rebirth excludes every workflow-pinned cell from recovery and cancels nonterminal workflow runs even outside the roster, unless a live provider or wrapper still serves them, then wakes each workflow to decide again. A stop never closes a supervised run's pre-rebirth pane id in the new session. A descendant's frames carry no workflow pin, so its asks and limits are sampled at the next step edge or tick, within about a minute.

## The tick

`crates/rimz/src/harness/schedule/fire.rs::fire_due_tasks` runs every scheduler tick, from the room host or the external timer. After it fires due loop tasks, it calls `tick_workflows` for the root, then the loop backlog tick. `tick_workflows` reads the room's run records and spawns `rimz --root <root> workflow advance <id>` for each due run. An active run is due when it has no `recheck_at`, when its `recheck_at` or its unfired deadline has passed, while it holds a condition case, or while a session is held at its rest check. A terminal run is due only while it still owes its loop task a report ([Loop tasks](#loop-tasks)), and that advance's command only collects it. Its first report advance is due at once; after that it is due again once the time since the stamp reaches the time the run had been finished at the stamp, clamped to between 60 s and one hour (`fire.rs::tick_pace`), so the gap between failed collections doubles. Parked runs are never spawned. The engine decides everything else (bounds, window, occupancy, capacity, a live host). The tick reads `recheck_at` so that early advances do not inflate an ordinary wait's `×N` count, and it never clears backoff the way the signal helper does. Under the systemd timer the spawned advance leaves the oneshot service's cgroup, as a loop run does.

Spawns are paced by the runtime cache `lanes/workflow-tick.json`, a map of run id to last spawn: at most one spawn per run per 60 seconds (`WORKFLOW_TICK_SECS`), except that a `recheck_at` or deadline that passed since the last spawn fires at once. A plain sleep stores its end as `recheck_at`, so it gets no intermediate spawn; a conditional sleep stores no end backoff, so it keeps sampling each minute, including during a hold. The tick writes the cache before spawning and drops runs that are neither active nor owed a report. A read failure counts as an empty cache, and a write failure warns and skips that tick's spawns. `fire.rs` is in the sidebar import graph, so it writes only that cache and spawns, and the invariant grep keeps it off the writer and the wake socket.

For workflow authors, an ordinary check's `@wait` without `recheck_at` is re-evaluated about every minute, so a check that wants a slower pace names `recheck_at`. A session's held rest-check `@wait` follows the same cadence and subscribed signal wakes while the leader rests on its judged turn. A live step is observed every tick, so a descendant's ask or provider limit is noticed within a minute.

The external timer's roots (`crates/rimz/src/cli/loop_timer.rs::task_roots`) include every room with a nonterminal run, found through `crates/rimz/src/disk/paths.rs::workflow_runs_under`, so a manual run in a room with no loop task and no sidebar still ticks.

## Loop tasks

Every loop fire but an unguarded delivery starts a workflow run: a `workflow = "<name>"` task (`TaskAction::Workflow`) its deployed definition, and every other task the inline graph `schedule/compile.rs` builds from its row ([loops.md § The compiled graph](./loops.md#the-compiled-graph)). [loops.md § One fire](./loops.md#one-fire) owns the ladder of gates in front of the run. It ends in `engine::create` (`crates/rimz/src/harness/schedule/runner.rs::TaskFire::prepare_workflow`) with `task = Some(<name>)`, `manual` set only for `LoopRunMode::Manual`, the start arguments `StartArgs { give_up, capacity: Wait }`, where `give_up` is the fire's default for an inline definition and none for a deployed one, the row's `surplus` and `surplus-after` values for either definition, and, for an inline definition, the fire's `fire_tree`. A deployed definition's run prompt is the row's prompt with the fire's trigger evidence, or the evidence alone when the row has no prompt (`TaskFire::run_prompt`). An inline run has no run prompt: the fire rewrites its compiled `prompts/prompt.md` asset with that evidence instead, once the backlog reconcile has settled which trigger the run serves. The fire takes no start-throttle turn; the run's agent steps ask for their own turns before launching.

A task remembers its checkout when its row sets `once-per-checkout = true`, or, with the key absent, when it is a `stay` task or a `workflow` task with `when` (`crates/rimz/src/config/loop_.rs::TaskEntry::dedupes_checkout`). A scheduled fire of such a task whose checkout has a launch entry returns `AlreadyLaunched` without a history row, before the run lock and again after room birth, whether the entry's run is active, parked, or terminal. The entry outlives run-record GC. Other tasks neither read nor write these entries and admit a fresh run once the previous run finishes. A manual `loop fire` bypasses the entry check and replaces an entry only on a new run.

After `create` succeeds, the runner appends the `workflow_start` assist, writes a remembering task's launch entry, and then appends its `launched` history row with the `wf_` id. A failed entry write is logged and attached to that launched row, never reported as a failed creation. `Exists` carries the holder's task and scope kind with its unchanged display text. When that task is the firing task, a remembering fire repairs its entry. The fire then follows the task's `overlap` policy against the run (`crates/rimz/src/harness/schedule/runner.rs::TaskFire::prepare_overlap`): a strike-neutral `overlapped` row naming the run under `skip` or for a manual fire, `deferred` under a retaining policy, with `replace` also canceling the run. `NoRoom` records `start failed`. A crash after creation but before recording can start a second run if the first also ends before repair.

A task-started run reports its outcome to the task once it ends, and the scheduler, not the engine, delivers that report. `create` marks the record `loop_report = owed`. The record write that makes a run terminal also writes its typed outcome (`RunRecord.outcome`, a `store::workflow::RunOutcome`): the ending (`done`, `failed`, `canceled`, a capacity give-up with its wait and reason, or a budget end and whether an agent turn ran), the summed attempt and evaluation cost, whether the run entered an agent or message step, and a failed run's last reason, classified from the journal in that transition. A journal that cannot be read there does not hold the transition back: the outcome then carries the ending the state names, no cost and no reason, with a warning. The engine never reports and never rewrites the mark. `crates/rimz/src/harness/schedule/run_log.rs::collect_run` collects: under the workspace lock it reloads the record and, while the run is terminal and owed, appends the report row through `run_log::report_run` (run id, `completed`, `failed`, `canceled`, `throttle skipped`, or a budget result, the cost, and `acted`), notes its strike when the task's row exists, and then rewrites the mark as `sent`. It reads the record alone, never the journal or the sealed definition, so a run whose definition is no longer usable is still collected. `rimz workflow advance`, `cancel` and `restart` (which `rimz agents restart` of a current step reaches) collect the run after the engine returns, whether it returned `Ok` or an error, and `rimz loop run` collects every owed finished run of its task (`collect_task_runs`) before it reads strikes, arming and launch memory. The mark waits for both the row and the strike: a failed append returns before the strike, and a failed strike leaves the row written, each with one warning naming the run, and the run stays owed. A record without an outcome, or a crash before the mark, leaves the run owed the same way. A failed collection never fails the command's transition, which is already durable. `crates/rimz/src/harness/schedule/fire.rs::tick_workflows` treats an owed run as due, paced by its retry gap ([The tick](#the-tick)), and `advance` on a terminal run does no engine work; its command's collection is the retry. Until a collection lands, `rimz loop show` and `loop logs` list the run's launch row with no outcome row. The report can therefore land twice, and its readers fold it by run id ([strikes](./loops.md#history-strikes-and-arming)). A record without the mark reads `none`, so runs that ended before the mark existed never report. `reassign_task` clears the mark when it detaches a run from a removed task. A fresh judge decline in a task-started inline run appends a `JudgeDecline` assist (`crates/rimz/src/harness/workflow/script/judge.rs::record_decline`): a verdict whose route leads to no step or agent check while the opposite verdict's route leads to one.

`each-worktree` takes `workflow` as well as `stay`: the fire runs per owned checkout under that checkout's run lock and stamps `checkout` on its row. A project-scoped condition workflow creates its run at the root and books every checkout, including later ones; other triggers skip only while a live run holds the scope. `stay`, `takeover`, `subscribe`, `check`, `judge`, `throttle`, and `capacity-wait` are refused on a workflow task, each naming the workflow node that owns the concept (`crates/rimz/src/harness/schedule.rs::TaskActionErr::WorkflowField`). `agent` and `wait` conflict with `workflow`, and `account`, `verify`, and `max-attempts` are refused because they need an agent action (`crates/rimz/src/harness/schedule.rs::TaskAction::from_entry`). `rimz loop add --workflow` writes such a row after the same definition validation `workflow run` performs (`crates/rimz/src/cli/workflow_view.rs::deployed_definition`), and refuses at add the flags a workflow fire ignores as well as those the stored row refuses. The trust hash covers `workflow` (`crates/rimz/src/trust.rs::ExecutableTask`).

`RunRecord.task` is the provenance `rimz loop list` and `rimz loop show` select live runs by, together with the record's project root. `loop show` and `loop logs` also take finished runs by `RunRecord::ran_for` (task and project root, any state), and `loop show` joins launch memory by run id, rendering expired records as `gone`. Their RUN targets and `workflow show` commands come from one `crates/rimz/src/cli/workflow_view/resolve.rs::RunTargets` load per command, the resolver `workflow show` runs. A `rimz workflow run` run has no task, so it appears in `rimz workflow list` and the sidebar under no task. A `rimz loop fire` run retains its task and records `manual = true`. `loop list` joins every Active capacity wait of the task's runs with condition waits and waiting tickets: self-clearing starts enter HELD and count in NEXT, while needs-a-fix starts put the task in NEEDS YOU. Its JSON retains the oldest durable `capacity_wait`. `loop rename` rewrites `task` under the workspace lock (`engine::reassign_task`) on the task's nonterminal records and on finished records still owed their collection, so that collection forgets launch memory under the new name, and leaves collected terminal records unchanged; their moved launch entries still name them in `loop show`. `loop remove` first cancels the task's live runs that have not entered an agent or message step (`engine::unacted_task_runs`, each through a detached `rimz workflow cancel`, which the run reports as `canceled`), then runs the same transition with no target task, so the runs that already acted continue independently and a re-added task does not adopt them. Redefining a task cancels its unacted runs the same way and forgets the checkouts they held. Finished records keep the name they ran under, so a task re-added under that name lists them in `loop show`.

## Attention

`crates/rimz/src/sidebar/enrich.rs::project_workflow_and_throttle_state` reads workflow records once per fold, producer and passive reader alike, for group projection and `SidebarSnapshot.throttle_notices`. Active `capacity` waits contribute alongside live condition-loop records and room-scoped waiting tickets. Each needs-a-fix cause carries its oldest reason and held-start count; self-clearing holds add no notice. Workflow parks produce no attention notice. Workflow failures lead to their configured on-break agent or end the run; only an agent asks in its own pane.

The same record scan projects live runs into frame-backed worktree groups, including groups with no pane. Active and Parked runs participate; every terminal state drops out. Bounded, stat-gated caches supply the sealed main rail and the parsed journal; reached names are folded on each pass with the record's held session, sharing `inspect::hops` and `inspect::reached` with the CLI rails. Sessions held at a rest check project their held step rather than the evaluating check, and the library's `RunRecord::session_attempt` and `RunRecord::step_agent` keep CLI and sidebar agent identity aligned ([snapshot contract](../sidebar/state.md#the-fold-spine)). A parked run keeps the strip's `parked` word. This path changes neither scheduler forge demand nor workflow transitions.

## Accounting

`crates/rimz/src/harness/workflow/engine/accounting.rs::transition` runs after `persist` publishes a transition and maps the journal entries it wrote. Accounting keys on evaluation origin, not on outcome words, because a check may legally route `canceled` or `limited`. An explicit `Route` suppresses evaluation and attempt accounting. A `turn_end` row suppresses evaluation, route and attempt accounting, including retry/rerun diagnostics. A saved verdict suppresses all engine-origin evaluation accounting and diagnostics.

| Journal entry | Accounting |
| --- | --- |
| Explicit `Route` | One `workflow_route`, unless the record now waits, holds a session, or the transition carries `turn_end`. |
| Check-origin evaluation | One `workflow_route`, unless the record now waits, holds a session, an explicit route accounts for it, or the transition carries `turn_end`. |
| Engine-origin `canceled`, run active | `workflow_rerun` diagnostic, no assist. |
| Engine-origin `limited`, or run canceled | No assist. |
| Other engine-origin evaluation, active with retry context | `workflow_retry` diagnostic, no assist. |
| Other engine-origin evaluation | One `workflow_route` (including a second judge failure following `invalid`), unless the record holds a session, an explicit route accounts for it, or the transition carries `turn_end`. |
| Attempt end | One `workflow_route`, unless the run was canceled, an explicit route accounts for it, or the transition carries `turn_end`. |
| `turn_end` | One `workflow_route` at the check for a push-back, close or kept move between listed checks; none for a kept `@wait`, discard or interrupt. |
| Closed `Wait` | One `workflow_route` to `@wait` at the wait's own node and the summary's timestamp, with `count` set to the final merged count, even on cancel. |
| Park or terminal | `workflow_park` or `workflow_end`. |
| Signal `Wake` or forwarded `signal` | None. |

An open wait has no route assist yet: `list` and `show` carry its live state, while the sidebar raises notices only for holds needing a fix. Closing a window, takeover, occupied, or capacity wait follows the same summary rule. Route records outside waits omit `count`. Explicit-route suppression also keeps a bound's engine evaluation from counting twice. `crates/rimz/src/harness/workflow/engine/accounting.rs::step` appends `workflow_step` after an agent step's supervised run or a command step's child is published, and once per message attempt after the host call, with the target handle when one agent took it; a command step has null handle and supervised run id. The loop runner appends `workflow_start` on creation. All five assist kinds count under the workflow category in `rimz stats`. Diagnostics are rate-limited forensics that stats never reads.
