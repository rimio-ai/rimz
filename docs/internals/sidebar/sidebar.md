# Sidebar

This page owns the mechanics between the store and the painted sidebar: how a live pane becomes a row, how rows group and rank, which lines a card carries, how the frame composes, and how rendering launches, closes, recovers, and reloads. Four pages sit beside it. [state.md](./state.md) owns the data plane underneath: the fetch cycle, the published caches, realtime events, fusion, and cadences. [The interface reference](../../interface/sidebar.md) draws every glyph and frame. [instances.md](../agents/instances.md) owns how a session joins its pane from the session's side, and [DESIGN.md](../../../DESIGN.md) states the product commitments.

The sidebar is the narrow column pinned beside the work panes, and it answers one question: which pane needs the user now. One host paints every state of a room, from a bare shell to a fleet across worktrees, through detach and reattach. Only the snapshot changes between those states.

## The producer and the renderer

Every decision is made once, in the snapshot, and painting is a projection of it. Which agent owns a pane, which group a row belongs to, how rows rank, and what the cockpit counts are all resolved before a glyph is chosen. Painting therefore stays cheap and golden-testable (a snapshot in, a frame out), and CLI listings use the same view-model and binding rules as the pane.

That rule splits the code in two. **The host producer** folds the store over retained panes and agent projection, and alone publishes those inputs and metrics history. One-shot CLI inspection and resolution compute privately; passive CLI reads consume the host's publications. All share the fold and repair rules. **The renderer** turns the resulting `SidebarSnapshot` into lines for one terminal. A behaviour that depends on the viewer (width, color depth, selection, scroll position, the active filter) belongs to the renderer; a fact about the room belongs to the producer.

The sidebar is a client of the store and never a writer of it. Its filesystem writes are runtime display files: its heartbeat, read receipts, `lanes/unread.json`, `lanes/focus-anchor.json`, the body filter, and the producer caches. The host also keeps a best-effort status suffix on mux tab names. None of these is durable truth. `cargo xtask invariants` enforces the boundary with `ensure_sidebar_library_boundaries` for the data plane and `ensure_sidebar_renderer_boundaries` for the renderer.

## From store to screen

A shared fold feeds per-attachment frames in this order.

1. **Fold the event log** into the rollup, every durable fact the store holds about the room.
2. **Reduce lifecycle events** into one `AgentState` per agent, carrying turn, phase, subagents, and model.
3. **Bind panes.** Read the live pane frame and bind agents to panes. This is the [admission boundary](#presence-model): a pane the rules exclude folds no row, and an agent with no live pane is data, not presence.
4. **Classify the rest.** A pane no session claims becomes a [process row](#process-rows).
5. **Reap** ghosts, relaunches, and stale sessions the rollup still carries.
6. **Group and rank.** Rows fold into groups, each row and group gets a score, and the roster sorts.
7. **Enrich.** Unread state, git stats, provider panels, subagent lists, and value tallies attach to the ordered roster.
8. **Project to lines.** Each attachment resolves the visible roster, composes the zones, and paints.

Steps 1 through 7 run once per host fold. The eldest receives its worker-built `SidebarSnapshot`; other attachments receive the shared fold through memory mailboxes and project only when they consume it. Each attachment fuses the room's shared events and its own focus intent before step 8. Runtime caches feed CLI reads; the host's remembered fold seeds new attachments ([state.md](./state.md#one-fetch-cycle)).

Watched attachments paint normally; settled hidden attachments neither fold nor paint publications. A user jump pushed within the host overlays its target in `viewed_panes`, making the destination watched so it can paint on arrival before the tab switch. Otherwise, a capture of a hidden sidebar pane shows its last painted frame, including in a detached session; it is not a fresh snapshot. Hidden attachments retain the latest content under the [mailbox rules](./state.md#one-fetch-cycle), refresh heartbeats, drain wakeups, and handle self-close and reload. Arrival consumes current data, adopts the latest watched viewport and paints immediately. Resize also paints current data unless the grow-resize hold applies ([the paint clock](./state.md#the-paint-clock)).

Two commands split a bug between the halves. `rimz sidebar snapshot --json` runs steps 1 through 7 and prints the result: if the wrong answer is already in the JSON, the bug is in the producer. `rimz sidebar frame` renders that snapshot without capturing through the mux, so a correct snapshot with a wrong frame points at `sidebar_pane/`. Both take `--workspace-id`; an id with no state on this machine and no `--session-name` names no room, so both skip the producer and render the empty rollup under the machine config, creating nothing under the state or runtime roots.

## Presence model

Row presence comes from the live pane frame. The producer enumerates the session's panes, reads each pane's foreground command and cwd, resolves the cwd to a worktree, and the fold emits at most one row per admitted pane. No pane id is shared by two rows.

[`pane_admits_card`](../../../crates/rimz/src/store/snapshot/panes.rs) is the admission rule. It excludes the caller's own pane, sidebar chrome, and the remote-control and app-server hosts. In the [`rimzd` view](../rimzd.md) it admits only a pane with an agent durably stamped on it, which keeps the dashboard's infrastructure out while letting an agent started there render; every other pane is admitted. The rule is the same list the fold uses for `agent_panes`, so a pane it drops is also unreachable by message delivery.

An agent with no live pane has no row. That covers a subagent, a ghost a kill left in the rollup, and a relaunch the [reaper](../agents/instances.md#session-death) has not yet collapsed. Such an agent cannot resurrect a row or latch onto another pane, and there is no `offline` status.

Several root sessions can claim one pane: a relaunch in place, a Codex `/side` fork, or a provider that switches conversation ids. [`view/reap.rs`](../../../crates/rimz/src/store/snapshot/view/reap.rs) collapses an older root when a newer one is provably a different process, or when a rested owner gives way to a proven same-process conversation replacement. A same-process thread fork survives the reap. Among the survivors, [same-pane ownership](../agents/instances.md#same-pane-ownership) picks the one root that owns the card, and every other root's activity folds display-only onto it.

Attention lives on the agent's own row. A blocking prompt puts the session's one row in `? waiting`, so a session never stacks a second row for its ask; when the ask holds and when it releases are [model.md](../agents/model.md#waiting-and-asks). If the agent's pane closes, the row leaves with it and the durable state stays in the store.

Remote agents do not render. An agent that runs only in a daemon with no local pane (`claude remote-control --spawn`, or a Codex thread started from the web) reaches the rollup but has no pane to bind. Showing one needs a presence class that renders from the rollup alone, which does not exist; this is a known gap.

### The binding ladder

A pane binds by identity first, because its foreground command cannot name the agent on its own: Claude can run under `node`, and two same-kind agents in one worktree read identically. Every `agent.lifecycle` event carries the mux pane id its hook ran inside (`TMUX_PANE` or `ZELLIJ_PANE_ID`), and cwd and command are a guarded fallback used only when no stamp claims the pane.

[`PaneBinder::resolve`](../../../crates/rimz/src/store/snapshot/panes.rs) walks each admitted pane down this ladder and stops at the first rung that matches. [instances.md](../agents/instances.md#binding-a-session) lists the same joins from the session's side.

1. **Stamped root.** The pane binds the root agent that stamped its exact id. A `session.rebirth` boundary retires every earlier stamp, because pane ids restart on rebirth. A process-start guard refuses a stamp whose recorded pane process started after the live one. For adapters that set `registers_lazily`, a stamp also needs the live foreground or hosted process to name the same kind, and session activity no older than the pane's process start. The activity clock is waived when the agent's runtime owner is the live pane root or a process on the pane's hosted chain (`hosted_agent_lineage`, the pids the producer walked from the root down to the CLI): a launch typed into a pane's shell records its activity before the provider starts, so only process lineage proves its tenancy. Stamps come from the hook env or, for a daemon-routed session, from hook ingestion: before appending the first lifecycle event it reads the repaired pane frame, filters to same-cwd same-kind panes no live stamp owns, uses client focus to break a tie, writes one recovered stamp, and appends every attempt to `audit/binding.log.jsonl`.
2. **Stamped launched child.** A pane stamped by an agent-launched child binds as a nested agent. It stays addressable and renders inside its parent's card ([sub-agent lists](#sub-agent-lists)).
3. **Unstamped pairing.** [`compute_lazy_agent_pairings_with_index`](../../../crates/rimz/src/store/snapshot/panes/lazy.rs) pairs unstamped root sessions to same-kind, same-cwd candidate panes once per frame. A pane whose command line resumes an exact session (`codex resume <id>`, or the resume syntax the Kiro, Antigravity, and Grok adapters parse) pairs first. The remaining sessions pair newest-first by `last_activity`: each takes the free candidate whose process started latest at or before the session's first event, and otherwise the first free candidate, provided its process start does not postdate the session's `last_activity` ([`pane_start_allows_bind`](../../../crates/rimz/src/store/snapshot/panes.rs)). A session whose stamp names a dead pane enters this pairing only when its adapter sets `registers_lazily`. A choice among several viable panes appends a `audit/binding.log.jsonl` breadcrumb.
4. **Idle synthesis.** A recognized agent pane of a wired kind (installed hooks or a declared local-session observation path) renders a synthesized idle `○ <kind>` row ([`idle_agent_row`](../../../crates/rimz/src/store/snapshot/panes/lazy.rs)) until a real session binds.
5. **Process row or nothing.** Before admission, [`repair_pane_frame`](../../../crates/rimz/src/sidebar/produce/panes.rs) fills a missing command from the pane root pid's command line, falling back to its base command name, unless the read fails or the program label is `rimz`. It also backfills a missing cwd from the root pid. A pane first seen in this produce with a known command but no resolved cwd is quarantined for one frame (a `NewbornQuarantined` diagnostic) so it does not blink in as an ungrouped row. Otherwise a known command becomes a [process row](#process-rows), and a pane with no readable command folds no row.

Providers with their own session stores also bind through local session observations, applied in `view/live.rs`; the rules are [instances.md](../agents/instances.md#local-session-observations). The cases are pinned in [`view/tests/pane_binding/`](../../../crates/rimz/src/store/snapshot/view/tests/pane_binding) and [`view/tests/lazy_bind/`](../../../crates/rimz/src/store/snapshot/view/tests/lazy_bind).

A daemon-routed session arrives unstamped by construction. Codex under remote control fires its hooks from the shared per-user app-server daemon, so the hook env carries no pane id and the hook pid is the daemon's. The session id exists only in the daemon's rollout and socket traffic, never in a client's environ or open files, so no client-pid join is possible ([adapter_codex.md](../agents/adapter_codex.md#session-registration-and-launch-quirks)). Rungs 1 and 3 exist for these sessions.

### Honest reads across a mux hiccup

The mux roster can arrive incomplete: a partial pane set, or a live pane missing its command or cwd. Four guards keep a momentary glitch from reaching the screen.

| Guard | Where | What it does |
|---|---|---|
| Repaired fields | producer/private read | Joins a raced-null read to the prior process for that exact pane id (retained by the host, passively read by CLI), and backfills a missing command and cwd from the process backend (ladder rung 5), so a new shell has a row under its worktree on first appearance. |
| Carried panes | producer | A pane omitted by a cached read, or whose whole tab is omitted even by an authoritative server listing, carries forward while a matching non-zombie process proves its root alive. A pidless sibling in a tab with confirmed liveness carries through tab coherence; a proven-dead sibling does not. A server listing refutes missing siblings in tabs it lists, even while their roots live. The renderer's own pane can carry across either read by identity. Surviving carries publish `pane_carry_forward`, with `cli_confirmed` reflecting the listing's authority ([diagnostic readings](../diagnostics.md#event-taxonomy)). Sibling carries expire after `PANE_CARRY_TTL` (30 seconds); the renderer's own carry never expires. |
| Nameless and newborn panes | projection | A pane with no readable command, or a pane first seen this produce without a resolved cwd, folds no row this frame instead of an anonymous row (ladder rung 5); the next read names it. A stamped pane still binds by id and keeps rendering. |
| Last-resort hold | renderer | Absorbs a residual race that would erase or demote a stable row set. It holds an agent-to-process demotion only while the foreground command is unchanged or missing; a changed command means the agent exited and the shell returned, which commits at once. |

The producer repairs live in [`sidebar/produce/panes.rs`](../../../crates/rimz/src/sidebar/produce/panes.rs), the hold in [`app/gate.rs`](../../../crates/rimz/src/sidebar_pane/app/gate.rs), and the fusion rule that lets a real close override a carried pane in [state.md](./state.md#fusion-rules). Carried panes and gate holds show as dim bottom notices without counting as health failures. When pane discovery fails outright, the renderer keeps its last good frame and eventually raises the health alert ([degraded reads](#degraded-reads-and-give-up)).

## Ranking and grouping

### Worktree groups

Each group is one block under its header, and a group is one unit of isolated work. The header carries no status tally: the cockpit owns the fleet make-up and each row carries its own glyph. A live or process-only group's header is a jump target; a finished group with any agent makes the header an expand and collapse toggle.

Git stats live on the header and never on a row, so changes in a shared worktree never read as one agent's. The `+/-` churn is the worktree's change against its merge-base with trunk, and the `⇡`/`⇣` delta is the commit count over the same base.

The trunk glyph ranks reconciling (a local rebase or merge in flight) first, then the forge PR verdict (merged, closed, open; an open PR with a merge-queue fact swaps its glyph for the queue glyph, in the open tone while queued and the failing-CI tone once dequeued), then the local trunk relationship (merged, pristine, plain branch). A pristine fork reads `≡ <trunk>`, and a merged PR shows the merge marker alone even when squash-merge ancestry leaves the local branch diverged. The trunk checkout keeps the plain branch glyph and carries no PR verdict. Trunk resolves per repo: `[sidebar] trunk` ([configuration.md](../../guide/configuration.md#sidebar-rendering)), then `main`, `master`, and the remote's advertised default. Sourcing is [`refresh/git_stats.rs`](../../../crates/rimz/src/sidebar/refresh/git_stats.rs) and [`refresh/pr.rs`](../../../crates/rimz/src/sidebar/refresh/pr.rs), the landed verdict is [worktrees.md](../harness/worktrees.md#what-the-sidebar-asks), and the look is [the interface reference](../../interface/sidebar.md#worktree-headers).

[`GroupResolver::resolve`](../../../crates/rimz/src/store/snapshot/view/layout.rs) places a row by the first rule that matches.

| Row | Group |
|---|---|
| carries a channel | that channel's pod |
| has no worktree path | a group named by its branch if it has one, otherwise `external` |
| path inside the repo's RimZ-owned worktree home | that worktree's `#channel` pod, matching message addressing |
| path inside a group root | the deepest containing root: a checkout in a repo room, a name-only root pod for the root of a directory room |
| path outside every root, in a room with no roots at all | its own group per path |
| path outside every root that names the row's branch | a group named by the branch |
| anything else | `external` |

Group roots are the repo's checkouts from `git worktree list` in a repo room; a directory room does not scan its tree. Every row that reports both a path and a branch also adds its path as a root, and rows on several branches at one path split by branch. The `external` group (a home shell, `/tmp`, CI) renders as a dim divider, always sorts last, and keeps an attention-only tally so an out-of-project ask still surfaces. The rules are pinned in [`view/tests/grouping/`](../../../crates/rimz/src/store/snapshot/view/tests/grouping).

### Attention ranking and the cap

Within a group, agent cards lead and process rows form the tail. Rows order by three age bands, then by a fixed-point score inside each band. Read state never changes the band; unread drives the wash and blink emphasis, the jump inbox, notifications, and the cap exemption, and nothing else.

| Band | Membership | Score inside the band |
|---|---|---|
| hot | every alive `waiting`/`failed` row, plus other rows with `last_activity` inside `[agents.attention] inactive_after_secs` (default one hour) | attention rows (`waiting`, `failed`, `paused`) heat from 1.0x to 2.0x across the window; `waiting`/`failed` hold 2.0x afterward; calm rows stay flat and keep pane creation order |
| warm | calm and `paused` rows past the inactive window, inside `archive_after_secs` (default 24 hours) | decays from 1.0x to 0.0x without competing with hot work |
| archive | calm and `paused` rows past the archive window | flat status weight |

The score is status weight times that time factor, both fixed-point ([`score.rs`](../../../crates/rimz/src/store/snapshot/view/score.rs)). The weights are spaced so the lowest attention state outranks the highest calm state; why each status weighs what it does is [model.md](../agents/model.md#status-and-phase). Process rows sit outside the bands: their clock is the foreground process start, so an idle shell stays live and seats below every agent card. A `paused` row resumes on its own through [auto-continue](../agents/providers.md#auto-continue).

Co-launched agents hold one contiguous block. A named-team launch and an inline multi-agent layout render as one cohort inside their group, teams in declared role-list order and inline launches in agent-cell order. The block takes its state from its members, first match winning: any `waiting` or `failed` member makes it blocked, then any `paused` member parks it, then `running` makes it working, then `success`, else idle. Blocked and paused blocks rank by the oldest attention clock; calm blocks by the most recent member clock.

Groups rank in this order:

1. `external` groups last, whatever they hold.
2. Finished project groups after all unfinished project groups, including archived ones.
3. The band of the group's liveliest member, then that member's attention score.
4. The group's calm activity in that band: working if any member runs, else finished if any member succeeded, else idle if any agent remains, else process-only.
5. Git: dirty, clean, unknown, then done. Done needs a merged or closed PR or a `WorktreeTrunkSync::Merged` verdict, so a pristine fork whose merge-base equals `HEAD` stays clean.
6. The earliest member's pane creation order, then the label.

A done group with no attention or running member enters the finished partition, and a revived member restores its unfinished rank. The presentation sort and each live overlay refresh stamp that verdict into `SidebarWorktreeGroup::finished`, so ranking and rendering agree. The seams are `sort_rows`, `compare_groups`, and the rank key in [`layout.rs`](../../../crates/rimz/src/store/snapshot/view/layout.rs), pinned in [`view/tests/ranking/`](../../../crates/rimz/src/store/snapshot/view/tests/ranking); the user-facing account is [the sidebar guide](../../guide/sidebar.md#how-the-column-is-ordered).

A staged team's `SidebarWorktreeGroup.pipeline` adds a line below the header, projected from the producer's board-derived `lanes/pipeline.json` ([state.md](./state.md#the-fold-spine)). It carries the team badge, declared-stage dots with the board's stage name inlined, and right-pinned stage and run durations. `position()`, `span_secs(snapshot.now)`, and `total_secs(snapshot.now)` own stage and clock logic. `span_secs` sums earlier visits and the open visit; future dots consult `visited` for the `PipelineRevisited` tone; the renderer uses the owner's status style at the same animation phase for the current dot and name. `crates/rimz/src/store/snapshot/view/model.rs::SidebarWorktreeGroup::pipeline_owner` matches the group's team and card handle for the verdict, stuck projection, and renderer. The click region targets that row if visible, else the first actionable visible team row, else the first visible row, without adding a selectable row. The line itself adds no attention. Folded finished groups omit the line and append ` · <stage>` after the team name in their roster; unfolding restores it. Layout and glyph states are in the [interface reference](../../interface/sidebar.md#worktree-headers).

`crates/rimz/src/store/snapshot/view/model.rs::SidebarWorktreeGroup::unit_statuses` supplies the shared unit verdict. Every member can add attention; the resolved stage owner alone decides calm, with `Done` giving success and a successful owner before `Done` giving idle. Ownerless teams prefer running, sleeping, idle, then success. Attention suppresses calm except running. Bucket carriers are the attention rows, the stage owner for calm, every member for board `Done`, or matching rows without an owner. The cockpit alone suppresses finished-group success.

After pipelines attach, `crates/rimz/src/store/snapshot/view.rs::SidebarSnapshot::project_stuck_stages` projects a resolved owner to `Failed` when its unfinished unit has only idle or successful member attention statuses (including current-child lifts) and the latest member activity or stage start is at least `stalled_after_secs` old. The label is `stage <Stage>: nothing running <age>`. It re-stamps attention scores, counts and the finished verdict before presentation sorting, unread reconciliation and notification evaluation. The projection changes no durable state; the next fold clears it when member activity, a non-resting member or a stage flip breaks the condition.

**The cap is renderer-local and protects visible work.** The snapshot carries every row. In the resting body each renderer caps a group's idle and process tail at `WORKTREE_ROW_CAP` (6) rows with a dim `+K more`, and expanding the group shows every row plus `− less`. Active, blocked, paused, finished, unread, and focused rows are exempt.

A finished group with any agent row collapses every row, unread successes included, behind a two-line dim receipt. A process-only group stays expanded.

- The `▸` roster line leads with the shared `AgentCard::team` value when present, then each agent's final status glyph and name in source order, folds overflow and process rows into `+n`, and pins the cohort's lifetime transcript-priced cost right. Before `cohort_effort` exists, it sums the hidden agents' session costs instead; published effort wins even when its cost is unknown. Too narrow for one member, it reads `▸ +K done`.
- The totals line carries the lifetime `◇ ↘ ↗ ◌` token split and pins retained active time right, falling back to last-activity age once active-time sidecars expire.
- The producer publishes the group totals and per-seat lifetime effort, keyed by row id, through the 60-second `lanes/cohort-spend.json` lane; the renderer only formats them. The figures fold the same lifetime-admitted audit slots as [attribution](../agents/attribution.md#selecting-records), so a receipt counts only the checkout's current life.
- A revealed card from a finished population shows the seat's lifetime cost, so the cards sum to the receipt; a live card shows its session-scoped self-report.

A folded header and both receipt lines carry `HitTarget::ExpandGroup { key, row }`, naming the first hidden agent in the same `finished_members` order that draws the receipt, even when no chip fits. The click inserts the expansion key, selects and focuses that member's live pane, and sets `UiState::reveal_row` to reveal its card on the next paint. Expanded headers retain `ToggleGroup`, collapsing without focus; live more/less tails keep that target too. Both group targets have precedence 3, above the header hyperlink. A lens or query reveals matching rows uncollapsed, except the Success lens excludes finished groups. Focus or the layout freeze on any member also reveals the whole group, and the collapse lands as a unit once focus leaves and the hold expires. The reveal state is copied from the watched sidebar to unviewed sidebars.

`scroll_lines_windowed` places the centered landed chip, `[ ▸ N landed ]` / `[ ▾ N landed ]`, between dotted rules before the finished partition, with a blank group gap above it. `UiState.landed_open` defaults closed and is copied from the watched sidebar to unviewed sidebars; its whole-line `HitTarget::ToggleLanded` anchors selection, makes the offset authoritative, and cancels scroll easing like a group toggle. Opening alone arms the one-paint `UiState::landed_reveal`, consumed by `draw_into`. `scroll_lines_windowed` also reports the chip's line index and the last line of the first finished group revealed only by opening, or no span when closed, filtered, or no group was revealed. In `resolve_scroll_offset`'s authoritative branch, this span nudges the clamped offset just enough to show the first receipt and chip together; if they outgrow the viewport, the chip pins to its top. The banner recompute uses the same rule. Closing only clamps to the shorter block. Closed, composition skips only finished groups with no projected rows, preserving focus, held rows, and individual expansion without changing `VisibleRoster` or its ordinals. A lens or query suppresses the chip and bypasses this skip. `render_expanded_line_ansi` opens it along with every group without arming a reveal; fixed frames retain the closed default. The marks resolve through `WorktreeLandedClosed` / `WorktreeLandedOpen` in both glyph sets. `Component::LandedChip` resolves to the muted palette tone, used as a `picked_chip` fill with reverse video under `NO_COLOR`.

**The layout freeze keeps rows still after an interaction.** Producer rank is the truth, but after a jump or browse, arrival on the own tab, or when the focused agent's ask is answered or its turn starts, the renderer keeps the last painted row and group order and that frame's visible rows. Hidden folds never replace that painted order. `LayoutFreeze::armed_ms` starts at the interaction, tab arrival, adoption of a frozen publication, or landing paint, including a displaced landing. An unfrozen publication instead clears the adopter's hold, regardless of its origin. The hold's deadline is derived at each check: `LAYOUT_FREEZE` (5 seconds), or `LAYOUT_FREEZE_PARKED` (30 seconds) while any client focuses this sidebar pane. The latest active focus event decides, falling back to pulled `client_views`; leaving the pane restores the original five-second deadline, so an older freeze releases in that event's fold. With several clients, one client leaving currently unparks even if another stays on the sidebar; tmux departure can carry `unfocused: []`. Focusing the sidebar within an already-viewed tab alone never arms it. Each attachment owns its timer. Group order is held within the current unfinished and finished partitions, with external last, so landing or reviving work crosses the partition boundary immediately. Held frames match rows by id, then by pane id, so a launch-to-session rekey keeps its slot. A new row appends within its group, and a new group appends after live groups but before finished and external groups; expiry restores producer rank. Read state and content update immediately. Order, cap exemptions, and previous selections' expansion reach release together in the next content fold and paint.

## The cards

Each agent is a small stacked card whose anatomy is drawn in [the interface reference](../../interface/sidebar.md#the-card). A row is base identity plus one payload: [`AgentCard`](../../../crates/rimz/src/store/snapshot/row.rs) for lifecycle and context fields, or [`ProcessCard`](../../../crates/rimz/src/store/snapshot/row.rs) for command and process metrics.

### The line template

A card's slot skeleton is fixed before any content fills it; optional slots render only when their content applies. [`template`](../../../crates/rimz/src/sidebar_pane/render/sections/agent_card/template.rs) maps four inputs to an ordered list of slots:

- **Stage** (`CardStage`). A card is `Fresh` while it is `idle` with no submitted prompt, no session history, and an empty context gauge; `labeled` means it carries a RimZ-authored description instead of the compose affordance. Otherwise it is `Engaged`. The renderer marks a read card `Stale` when its child-folded `last_activity` exceeds `[theme.display] stale_after_secs` (default 86400, `0` disables), unless reach, an open delegation section, or `expanded` density keeps it open; only idle and success rows may use the stale template. `CardStage::resolve` is that one decision, and both `template` callers (`row_lines` and the frame-rate check `delegation_motion`) read it.
- **Expansion** (`CardExpansion`): `reach` (`SelectionReach`) distinguishes the live selected row (`Selected`), held source rows (`Held`), their visible named teammates (`Teammate`), and unreached rows. All three reaches open engaged cards, but only live or held source rows gain the stats line outside `expanded` density. Fresh teammates and held rows keep identity and any launch description; only the live selection gains the meter and compose dots. `delegation` (the sticky header override, else the live or held selected row itself or `expanded` density) picks whether the delegation entries show, so a teammate folds its entries behind the summary line. Expansion holds, also copied through the host's viewport publication, accumulate across clicks while `UiState::freeze` is armed and release together when it clears. Compose builds the retained opening set before measuring the scroll zone, independently of clamp geometry or authoritative scrolling. Off-screen selections reveal only after this sidebar's own input, while retaining previous selections too.
- **Density**: `[theme.display] card_density`, one of `auto`, `expanded`, `compact`.
- **Status**, read by the stale, resting compact, and delegation-summary arms.

| Card | Slots |
|---|---|
| stale idle or success, unreached, delegation closed, density not `expanded` | stale |
| compact, not expanded: `idle` | identity |
| compact, not expanded: `running`, `waiting` | identity, description, gauge |
| compact, not expanded: `paused`, `success`, `failed`, `sleeping` | identity, description |
| fresh unlabeled, not live selected | identity |
| fresh labeled, not live selected | identity, description |
| fresh unlabeled, live selected | identity, awaiting dots, gauge |
| fresh labeled, live selected | identity, description, gauge |
| engaged, unreached idle or success, delegation closed, density not `expanded` | identity, description, question, gauge |
| engaged, otherwise resting or teammate, `auto` or opened `compact` | identity, description, question, gauge, delegation |
| engaged, selected (live or held) or `expanded` density | identity, description, question, gauge, tokens, cache, delegation |
| engaged, delegation open | the applicable shape above plus delegation entries |

A unit test pins every combination. Under `auto`, selection leaves the lines above the meter in place, inserts the stats line below it, and appends delegation entries. A held selection keeps both additions until the layout freeze expires. `expanded` density keeps the stats line on every engaged card. Compact resting cards are shorter, and opening one restores its stage's shape. Selection styling stays on the focused row even when teammates expand with it.

The `Delegation` slot is one standing line with the lifetime child count and cost and the count of armed one-shot waits, background shells, and a pending idle stop; it renders empty until any exists. `DelegationEntries` lists subagents in bands, then pending waits with background shells merged in after the command and PID waits (ahead of signals), then the pending idle stop (`AgentCard.idle_stop`, attached at enrichment by `harness::idle_stop::project_requests` with its due time while the rest clock runs, so the renderer reads no record), then an optional `+K older` tail. Pending waits come from the loop catalog at enrichment; background shells come from the rollup's durable `background_shells`, folded from adapter hook reports ([model.md](../agents/model.md#turn-endings-and-parked-turns)). Two frame-rate rules follow from the slots: the serve loop holds the breath cadence while a visible selected card shows the unlabeled compose affordance, and it holds the fast grid while a visible card's open delegation entries hold motion (a running child's working or thinking head, or a running shell job's working lead; an idle or sleeping child's status head holds nothing), whatever the parent's own status. Timer and signal leads are static and hold nothing.

The template includes the `Cache` slot wherever it includes `Tokens`: live or held selected engaged cards, and every engaged card at `expanded` density, including teammates. `row_lines` adds no live-selection gate, so a held card keeps its notice as well as its stats. `CacheAge::phase` is the one expiry decision for the age pin, meter, and cache line: held, unknown, calm, closing, expired. The closing band is `min(600, ceiling_secs)`; expiry stays strict `age > ceiling`. The line reads only the producer's optional `rewarm_cost_usd`, using the shared `theme::fmt::dollars_estimate`; it performs no pricing or I/O. The [interface cache line](../../interface/sidebar.md#the-card) owns the words, widths, and tones.

Subagents and waits share [`crates/rimz/src/sidebar_pane/render/sections/agent_card/entry.rs::push_entry`](../../../crates/rimz/src/sidebar_pane/render/sections/agent_card/entry.rs): a lead, type word, optional headline separated by `GlyphRole::Seam`, pinned right spans, and an optional prebuilt detail line. [`PendingWaitTrigger`](../../../crates/rimz/src/agents/state.rs) supplies `kind_word`, `headline`, and `detail`; the renderer owns the separator and layout. Subagents supply their existing metadata grid as detail, while waits supply command or deadline text. The [interface entry table](../../interface/sidebar.md#subagents-and-waits) owns the per-kind line rules.

Delegation entries answer to two presentation states in `UiState`, shared with unviewed attachments through the host's viewport cell, never through producer folds:

- `delegation_overrides` maps a row id to open or closed. The delegation line carries `HitTarget::ToggleDelegation { row, open }` with the state its click sets, so a closed selected card and an open unselected one are both one click away. The override outranks selection and density, survives prompts and selection moves, and is pruned only when the row leaves the snapshot.
- `delegation_history` maps a row id to the parent's `user_turn_started_at` at the `+K older` click (`HitTarget::ToggleDelegationHistory`). A changed turn stamp makes it inert at once and pruning removes it, so the next user-authored prompt folds the history; automatic deliveries leave it open. Closing the section clears it too. Both clicks pin manual scroll, then select and focus the parent's own live pane, not a child's; without a parent pane they only toggle.

The entries classify `sub_agents` by status and the snapshot clock ([`bands.rs`](../../../crates/rimz/src/sidebar_pane/render/sections/agent_card/bands.rs)), never by the snapshot's `prior_turn` tag: live children (not `success`/`failed`) in the projection's spawn order, then finished children by `last_activity` descending while younger than `[theme.display] recent_subagent_secs` and up to `max_recent_subagents`, then the waits, then the older rest when history is open or when the live and recent bands are both empty (a lone tail would only cost a second click). Every band renders on one token and model column grid measured over all children, so opening history never re-pads rows already on screen. The muted `  +K older` tail shows while history is closed, at least one live or recent row is visible, and `K = sub_agent_count − rows` is positive; children the projection reaped count in `K` with no row to reveal. The shorter list is a prefix of the longer one, and a finishing child moves only from the live band to the head of the recent band.

### What fills the slots

Model and context enrichment is display-only and privacy-gated. Wait and child projections also determine displayed work status; attention follows the status ladder. Model and reasoning effort come from the session's [rich context](../agents/model.md#rich-context) or the hook and store scalars; a missing field means the agent did not report it, never zero. Account-scoped budgets stay off the card, in the [provider dashboard](#provider-dashboard).

Context severity is one four-tier ramp classified once in the domain ([`ContextSeverity::classify`](../../../crates/rimz/src/agents/state.rs)) and stamped on the row; the renderer maps the row's position between the configured stops ([configuration.md](../../guide/configuration.md#sidebar-bands)) to a continuous tone. `NO_COLOR` removes color only, and each bar's shape still carries the meter.

Three projection rules are not evident from the field catalog:

- The renderer prefers the rich `context` blob over the coarse scalars, except that `row.effort` wins over `context.effort`.
- Waiting descriptions prefer `AgentCard::open_ask`: the first sentence ending in `?`, else the whole ask, word-wrapped over at most two indented lines with `…` for overflow or hard-cut words ([the visible rule](../../interface/sidebar.md#the-card)). `description_lines` shares `layout::wrap_words` with pet captions, marks the wrapper's dropped long-word tails, and retains the usual emphasis. Other descriptions stay one line and use [`AgentCard::description`](../../../crates/rimz/src/store/snapshot/row.rs): the displayed error or pause label first, then the first Working-class wait while running with an idle or parked own turn or first Sleeping-class wait while sleeping, then activity (session name, provider thread preview, launch description, task, first prompt, latest prompt). Codex's generated title replaces its first-message preview. The stale one-liner and queued `Question` slot are unchanged.
- Display preferences travel in `SidebarSnapshot.sidebar`.

The status projection is pinned in [`view/tests/status/`](../../../crates/rimz/src/store/snapshot/view/tests/status) and [`project/tests/`](../../../crates/rimz/src/store/snapshot/project/tests).

### Unread and read receipts

Unread state is a runtime episode set (`lanes/unread.json`) plus one room read-mark record (`live/read-marks/marks.json`). The host opens an episode for a row whose displayed status is `success`, `failed`, `waiting`, or `paused` when no read mark reaches the row's `last_activity`, and every fold derives `SidebarRow::unread` from that file and the current marks. The cap keeps unread rows visible, so a row that returns to `running` or `idle` stays emphasized until read. Attaching to a busy room opens the current attention rows silently, without a burst of notifications.

| Action | Effect |
|---|---|
| focusing a row's pane | writes a receipt and clears that row |
| staying in a tab for `TAB_READ_DWELL` (2.5 seconds) | clears the unread rows in that tab; leaving earlier clears nothing |
| `m` on an unread row, or `rimz sidebar mark-read` | writes a manual receipt without focusing |
| `M` | writes manual receipts for every readable row |
| `m` on a read row, or `rimz sidebar mark-unread` | opens a fresh episode through [`sidebar::unread::mark_rows_unread`](../../../crates/rimz/src/sidebar/unread.rs), stamped at `max(last_activity, now)` so no existing receipt reaches it |

Every writer max-updates the latest clear time per row under `read-marks.lock`, and a receipt clears an episode only when its clear time is at or after the episode, so an old focus cannot erase a later turn. Marks outlive the pane that wrote them, including manual marks, until the fetch worker prunes their rows against a produced room frame. Writes use cache-class temp-and-rename without fsync. If `marks.json` is absent, readers import the maximum of legacy `manual.json` and valid `sidebar.<instance>.json` receipts with their original timestamps; the fetch worker's first prune, or an earlier changed write, materializes that import. Legacy receipts are reclaimed only by class-TTL GC, not heartbeat expiry.

### Sub-agent lists

An expanded card lists two kinds of child: provider-native subagents and pane-backed agents another agent launched ([the two meanings of subagent](../harness/subagents.md#two-things-are-called-a-subagent)). Neither renders as its own row while its parent's launch has a rendered row. The rollup carries each child's root `parent_agent_id`, and projection nests every descendant in one flat list. A launched child's link names the parent's launch and a native child's names the parent session; [`AgentState::parent_is`](../../../crates/rimz/src/agents/state.rs) resolves both, and a cross-provider launched child also carries its parent's kind, so mixed links land under one card. The list orders by `registered_at`, and Codex's root-relative task path keeps nested lineage in the label. A launched child's pane stays addressable, but its redundant process row is suppressed.

A child that no rendered parent row claims is an orphan. A pane-backed launched child is promoted to its own top-level row, because its pane is live and would otherwise render nowhere; a paneless native child does not render and is logged ([subagents.md](../harness/subagents.md#who-counts-as-a-launched-child)).

A current waiting child of either origin lifts the parent's attention to `waiting`, unless the parent already has its own actionable status. A provider-native child's failure also lifts; a launched child's failure or silence does not. `crates/rimz/src/store/snapshot/row.rs::SidebarRow::attention_status` supplies cockpit counts, filters, ranking, the inbox walk, and CLI needs-you projection without changing the parent's displayed status. The nested child has no row of its own, so without this lift its prompt would be absent from those surfaces. `crates/rimz/src/store/snapshot/row.rs::SidebarRow::attention_pane` targets the first current waiting launched child with a live pane in entry order for `n`/`N`/`Space`; own attention, native-only lifts, and pane-less children keep the row's pane. A click on the parent still targets the parent. The next walk step advances from the parent row that owns the focused child's pane. Notifications, unread episodes, tab suffixes, and lead glyphs still read the parent's own displayed status.

**A finished child stays listed until the parent's next user-authored prompt.** A running or paused child is always listed in the live band, and `--keep` keeps a launched child's pane alive. Only a displayed `running` child holds the parent as delegating, including its waiting pet and stall exemption. A live launched child's provider park instead projects the parent card as `paused`; the [status ladder's demotion](../agents/model.md#the-sidebar-ladder) turns both the entry and the parent `failed` when the park is spent. Once a child ends it holds its `✓` or `!` verdict until the parent records a new `user_turn_started_at`.

Any open native or launched child also takes the stall rung: `crates/rimz/src/agents/state.rs::AgentState::silent_child_for` checks running silence or a prompted launched child whose first turn never started (raw and effective `Idle`, no `turn_ended_at`), excluding sleep, pause, and displayed errors. Both use the configured stall window. `crates/rimz/src/store/snapshot/view/aggregate/subagents.rs::project_sub_agent` projects a match to `Failed`, phase `Idle`, label `silent Nm`, and `SidebarSubAgent.stalled = true`; its runtime freezes at the last activity. `crates/rimz/src/sidebar_pane/render/sections/agent_card/mod.rs::sub_agent_finished` excludes that marker, keeping the line in the live band rather than folding it into older verdicts. Fresh activity clears the projection. Native failures lift the parent's attention because the child has no pane; launched stalls do not. Only launched children get the parent notice, owned by [the harness backstops](../harness/subagents.md#backstops).

- A prompt RimZ delivers for an agent or the harness (`AGENT_MESSAGE`, `AGENT_REPORT`, `SUBAGENT_REPORT`, `TEAM_REPORT`, `WAIT`, `SIGNAL`) opens a provider turn (`turn_started_at`) but keeps the entries. The classifier reads the durable submitted prompt: it counts as harness-delivered only when every segment carries a non-user message header. `USER_MESSAGE`, bare leading composer text, or a missing prompt count as the user's, so headerless `--no-from` text and the budget-continue prompt reset the list. Text typed after a pasted header's body cannot be told apart from that body and stays harness-delivered.
- A fresh user prompt, `/clear`, and manual `/compact` each advance the boundary; automatic mid-turn compaction resumes the same turn and keeps the entries.
- With no known user-turn boundary (including carryover older than `user_turn_started_at`), finished entries expire after three hours of child inactivity, the ghost-session TTL. A known stamp survives log rotation.
- A launched child observed to end mid-turn (deadline, `rimz subagents stop`, or provider death) resolves to `failed` and shows `!` ([model.md](../agents/model.md#the-state-machine)). A reaper-inferred end rests it at `idle` with the calm `○` ([observed and reaped ends](../agents/model.md#observed-ends-and-reaped-ends)). Either way its elapsed time freezes at the end stamp.

Before the user-turn filter, projection de-duplicates every child the store still retains and computes `sub_agent_count` and `sub_agent_cost_usd` across both origins. It also computes the launched-only `delegated_cost_usd`, which is added to the parent's own session cost; the all-origin figure is only a breakdown, because native child spend is already in the parent's transcript.

Each origin fills its entry from a different source:

| Child | Source |
|---|---|
| Claude native | description, exact cost, start time, and the newest request's token split from the child transcript, folded on by [`with_subagent_context`](../../../crates/rimz/src/store/snapshot/view.rs) |
| Codex native | child lifecycle observations: nickname, task path, role, model and effort, current context tokens and the reported context window, with durable registration as the elapsed-time fallback |
| Copilot native | the model from the parent's start record, with the cumulative `totalTokens` reconciled from the completion record at the next parent checkpoint |
| launched | its launch profile and session-sidecar cost; window occupancy through `context_used_tokens`, else the cumulative `session_usage` total of input, cache writes, and output, excluding cache reads |

Token selection prefers `AgentState::context_used_tokens()` (`SubAgentTokens::Window`), then a positive `session_usage.displayed_total_tokens()`, then `usage.run_total_tokens` (`SubAgentTokens::Total` for either cumulative source), otherwise no token cell. Claude's statusline hybrid counter is not a source: the incremental cost cursor retains the latest request split even without pricing, and it fills only the fields lifecycle usage lacks, so the split `SubagentStop` records wins once the child stops.

Window-token entries carry `context_window` from the child's context sidecar, else its lifecycle usage. The provider's default window is never substituted. The glyph uses the worse of percent and token heat when a nonzero window is reported, and token heat alone otherwise. Total-token entries carry no window. A running Claude native child reports no window size, so it keeps token-only heat. Once `SubagentStop` names its model, the lifecycle hook resolves that model's window (the `[1m]` marker, else the price book), and the percent axis applies.

**Child activity counts as the parent's.** [`fold_child_activity_onto_parents`](../../../crates/rimz/src/store/snapshot/view/aggregate/subagents.rs) advances the parent row's displayed clock to the freshest child `last_activity`, so the stall check does not fire and the inactive sinks, ranking, and unread do not move while children work. The clock it replaces is recorded on the card as `own_last_activity`, whose one reader is the card's cache-age pin through `SidebarRow::own_last_activity`: a parent blocked on its children's reports makes no model call, so its prompt cache ages for the whole wait. A child still displayed `running` also makes a resting parent display running or delegating; a child holding a terminal verdict or projected stalled never does. A stalled launched child no longer holds the parent's turn, and its silence never lifts the parent's attention. A launched child's provider park changes the parent's displayed status as the delegated park above; its waiting prompt lifts attention only. A silent raw-running parent can then take its own root stall rung; an idle or sleeping parent shows its own rest. The fold is display-only: the rollup keeps the parent's own clock, a blocked or budget-parked parent stays put, and own or delegated pause or failure evidence beats a ticking child. Cases are pinned in [`view/tests/subagents/`](../../../crates/rimz/src/store/snapshot/view/tests/subagents).

## Process rows

A pane no agent session claims renders a one-line command row, a lead glyph and the program (`zsh`, `vim`, `cargo`), one tier below the agent cards. It carries no capability line and enters no cockpit tally, and it is still a jump target.

The label comes from the mux command through the shared parser in [`proc/command.rs`](../../../crates/rimz/src/proc/command.rs). It skips environment assignments and transparent wrappers (`sudo`, `doas`, `exec`, `command`, `nohup`, `nice`, `time`, `timeout`, `stdbuf`, `env`, and `sh`, `bash`, `zsh`, `dash`, or `fish` with `-c`), and projects a `node`, `nodejs`, `npx`, or `bun` script or a supervised `rimz agents exec` to its kind while keeping the launcher as the identity-bearing root. Shell script selection is lexical: the first simple command that is not assignment-only or `cd`, `export`, `set`, `source`, or `.` setup. The parser evaluates no expansions, redirections, or control flow, and it keeps the wrapper as the label on unsupported syntax, an incomplete wrapper, or exhausted nesting. Source spans let the details line shorten only the resolved binary's absolute path.

A shared-runtime basename such as tmux's bare `node` resolves to an agent label only when the producer proves a known CLI by walking one bounded single-child chain from the pane root over full `/proc` command lines ([instances.md](../agents/instances.md#recognizing-a-hosted-cli)). A chain that is unreadable, branches, lacks a start time, runs too deep, or matches nothing keeps the runtime label, and the proof never rewrites the mux command. On muxes that report only `comm`, even idle-looking shells are probed, and the matched `foreground_cmdline` feeds activity and details, never identity.

The lead glyph is `ProcessState`: `○` when idle, a braille spinner when busy, and an attention `!` when process metrics show a repeated zombie or uninterruptible sleep for ten seconds with no CPU or I/O progress. A foreground-command change resets the baseline, so a previous command cannot mark its replacement stuck. A working row wide enough right-pins a CPU, RSS, and I/O grid; an idle shell stays bare.

Identity and metrics key off the pane's root pid. tmux reports it as `#{pane_pid}`, and the Zellij presence plugin publishes it from `get_pane_pid` and follows `CommandChanged` and `CwdChanged`, so shell topology stays current without synchronous discovery. [`backfill_zellij_pane_pids`](../../../crates/rimz/src/sidebar/produce/metrics.rs) falls back to foreground-cmdline matching for older plugin builds and failed pid lookups, and abstains when the match is ambiguous (two idle shells in one cwd), because no stats beat another pane's stats.

A proven agent label on a process row changes its class only through wiring: once the adapter is wired, the pane becomes an idle agent card ([ladder rung 4](#the-binding-ladder)), and the first lifecycle event binds the session row. Without integration it stays a process row with the agent label.

When the foreground command runs through `sudo`, `su`, or `doas`, a bounded descendant scan can relabel the row to a known agent CLI running as another real uid, with a dim `(<user>)` marker (`claude (root)` over `sudo su`). The row stays a process row with no tally or dashboard account, and `pane.command` keeps its original value, so cwd pairing and idle synthesis still refuse a foreign-user agent.

## Composing the frame

Derived focus moving the selection arms a marker dwell at the consuming fold: `FOCUS_MARKER_TMUX_DWELL` (500 ms) or `FOCUS_MARKER_ZELLIJ_DWELL` (300 ms), selected by `ServeConfig::mux`. Each move re-arms it. After the dwell, watched paints overlay the selected card's display name at the viewport edge, after `plan_zones` and placement capture. It changes neither card rows, anchor rows, offset, nor banner choice. An up-marker yields to the unread banner; a down-marker does not. Hidden paints suppress it. A paint showing the selected card, or own input changing selection, ends it; a marker click uses the banner's minimal-reveal path without changing selection.

The host retains one in-memory viewport publication, tagged with source attachment and increasing sequence. After a watched paint changes its published fields, it replaces that cell without waking peers. The fields are target-window card rows relative to the scroll-zone top, target offset, held expansions and drawn selection, painted order, a frozen flag, expanded groups, landed visibility, delegation overrides and history, and dashboard tab. The flag records whether the publisher held a layout freeze at that paint, so freeze start and expiry each republish even when the rest of the view is unchanged. Wheel animation alone does not republish. A host restart loses the cell.

An observed tab arrival adopts the newest publication from another source before arming a fresh freeze over its order and painting immediately. Own scroll or selection input since the previous delivered fold prevents adoption. Hidden maintenance never adopts. Explicit adoption at birth, resize and own input still flushes content and rechecks eligibility; already-watched painted attachments and the source refuse that path. Both frozen and unfrozen publications apply the published order once, admitting arrivals, anchoring selection, and recapturing the order. Explicit adoption mirrors the frozen flag; arrival always arms its fresh hold afterwards. Rows rebase onto the adopter's own scroll-zone top; a newborn measures that top before its first paint. Existing anchoring uses these rows, with the copied offset as fallback. Explicit jump placement and carried order apply last and win. Selection and browse pick remain local, as does each armed hold's deadline; the local pick can open its card above the copied open set.

The sidebar is borderless, because it already sits inside a framed mux pane: a title line, hairline rules, and a one-cell left gutter (which is also the selection lane) carry the structure. The layout is drawn in [the interface reference](../../interface/sidebar.md); these are the rules behind it.

- **Three zones, two pinned.** A top-pinned cockpit, a scrolling viewport over the groups, and bottom-pinned chrome (search line, dashboard, fleet store, footer, health alert). The pinned zones reserve their rows first and the viewport takes the rest, so cards give way before either pinned zone clips. Each draw resolves `UiState::scroll_offset` around a card's own first line, clamped to the zone. `UiState::scroll_ease` supplies the visible row for the cards, scrollbar, and hit geometry; only wheel changes ease ([state.md](./state.md#the-paint-clock)).
- **Fixed height where it counts.** The repo dashboard and the cockpit make-up reserve their rows whether or not the room has agents, so the body does not shift as agents change state.
- **Measure, then paint the window.** Warm frames share one group composer across two walks: the first resolves geometry from attachment-local cached card heights, then the second paints only cards intersecting the eased viewport. Off-screen cards, headers, and pipeline lines use empty placeholders with identical row ownership; group tails still compose on both walks. Heights last for one epoch of shared groups, snapshot clock, width, theme identity, focus, and card configuration, keyed within it by row identity, resolved expansion, and selection. The cache holds its own group `Arc`, so copy-on-write unread edits invalidate it too. A new epoch paints once while filling all heights, avoiding a redundant walk when every card needs measurement. Within a warm epoch, a miss measures the card once and carries its lines into the paint walk if visible.
- **Cards anchor the viewport.** From the previous target window, choose the selected card if any of it was visible, otherwise the topmost surviving visible card. Keep its own first line at the same absolute pane row, absorbing height changes above, banner changes, and re-sorts. Retain the previous selections' whole expansion reach, unselected, while the layout freeze is armed, regardless of room to collapse. Only non-selection height changes from data or configuration accept movement when the offset clamp leaves no room. Wheel, banner jump, and group/delegation/history toggles make the offset authoritative for one paint without releasing frozen expansions, then anchoring resumes from that window. The landed toggle stays authoritative too, adding a one-paint reveal nudge only when opening. A correction translates an active wheel flight without restarting it and does not wake the auto scrollbar. The unread banner's visibility comes from the target window, so its height stays fixed during a glide. Its arrow compares the lead's first scroll-map line with the painted offset: up above the view or when the filter hides the lead, down below; clicking it minimally reveals the full-roster lead where it sits without changing selection, falling back to the top if the filter hides the lead or it has gone.
- **Only own input reveals selection.** A key or click that changes selection marks the next paint for reveal. An emitted `InputEffect::Focus` marks its target until a fold seats that pane's owning card. Any visible card line prevents a reveal. Native switches, external focus, attach seating, and row departure never reveal. A shared click placement places the card by identity instead; a rowless focus anchor leaves it anchored.
- **Counts span the cap.** The cockpit make-up derives unit buckets from the full roster, not the agent tally. A unit is a named team within one projected non-external group, or a solo row; status-less processes count nowhere. `SidebarWorktreeGroup::unit_key` is shared by the lens, banner count, and teammate reach. `BodyFilter` builds per-group facts, uses `matches` for a row's own bucket membership and `shown` for unit-wide status projection, and counts distinct matching units in `total`. The [interface rules](../../interface/sidebar.md#the-make-up-line) own active/rest precedence and the finished-group exception. Summary line 1 pairs headline facts; the `◎` sessions and token breakdown read the `[sidebar] spend_window` from the room's JSONL `workspace_value_tally`, not the live session sum. Line 2 carries the `¤` live-agent count, open-PR count when non-zero, and count-up spend. The unread banner counts units with an unread actionable member, while its visibility still follows the lead row.
- **The body holds only live rows.** History lives in the store behind `rimz transcript`, `rimz message list`, and `rimz doctor --audit`. An empty room leaves the body clear, and an active health alert takes the body alone.

**The make-up line and search share one body lens.** Each non-zero bucket is a click target that shows whole units with a matching member, a second click clears it, and a zero bucket has no hit target ([the look](../../interface/sidebar.md#the-cockpit)). The cockpit's open-PR count works the same way, painting as a chip while active; unread filtering remains on `u` and stays per row. `UiState::make_up_filter` holds a `BodyLens` with an independent pick and committed query. The renderer writes the whole lens atomically to room runtime ([`body_filter.rs`](../../../crates/rimz/src/sidebar/body_filter.rs)) and broadcasts a payload-free `BodyFilterChanged`; peers adopt it on the event or an authoritative fold, without a producer write. `reconcile_selection` clears and republishes only a pick whose full-roster unit count reaches zero, keeping the query. A query with no matches stays set.

`VisibleRoster` uses the lens only to choose membership. Every shown card renders and opens as without a filter, and selection walkers reach every shown row; worktree steps land on the neighbouring group's head. Lens changes re-anchor the selection by pane identity without starting a browse pick. Each draft search edit highlights ordinal zero of the narrowed roster.

Search editing lives in pane-local `UiState::search_draft` and overrides only the query used by `UiState::visible_roster`. The supervisor sends raw presses; `resolve_key` in [`app/input.rs`](../../../crates/rimz/src/sidebar_pane/app/input.rs) resolves help, typing, then normal bindings. The `alert_active` parameter of `handle_wakeup` in [`app/loop_state.rs`](../../../crates/rimz/src/sidebar_pane/app/loop_state.rs) blocks `Search` after help consumption. Each edit selects the first match and clears browse; a changed selection reveals only an off-screen match. Commit emits `SyncFilter` before `Focus` through `InputOutcome::effects`. While typing, a pane-focusing click uses `click_focus_pane` in `app/selection.rs`, the mouse handler's shared decision point, to resolve its target before clearing the query and emitting focus, so a row ordinal still refers to the draft-narrowed roster; other clicks commit before their ordinary action. Normal-mode `Esc` clears only the committed query, after configured bindings; help consumes it and an active alert does not block it. Own-pane focus loss or an active health alert discards only the draft. `crates/rimz/src/sidebar_pane/render/compose.rs::build_bottom_chrome` puts the query/cursor or committed chip in its first row, replacing the dashboard separator when present and reserving an extra row otherwise. It uses the same live roster as the cards for the match count, against all snapshot rows. Plain and dashboard-folded footers contain only badges and help; the search line remains visible under an active alert. While the body narrows, the cockpit counts stay full-fleet, and card clicks, `Enter`, inbox traversal, digits, arrows, pages, edges, and group motion all resolve their targets inside the lens. User-facing rules live in [Text search](../../interface/sidebar.md#text-search).

Hit-testing and keyboard motion agree with the painted frame through one mechanism. `FrameInteractions` carries bucket, count, dashboard-tab, banner, group-toggle, and row targets through the same translation and clipping as the rendered lines, and mouse targets and every keyboard walker use the same filtered `VisibleRoster` membership and ordinals as the body composer.

Pane width is a mux operation dispatched off the render thread. The room holds one shared width target; `a`, `d`, and a proven mouse drag pin it, and each renderer resolves that share against its own view and converges with one resize in flight, never adopting its own late resize as a drag. Width keys update a local target: on Zellij the first key of a burst re-reads the topology and re-resolves the room target, and later keys reuse both, while tmux, whose geometry read is a subprocess, uses its stored view; 300 ms of quiet commits one pin, broadcast, remembered tmux width, and intent diagnostic for the burst. Exact backends accumulate the pending target; relative backends lead the measured width by at most one key step. Resize wakeups defer the pixel-capability probe until 300 ms of quiet. A settled drag requires a sibling count observed before the resize and unchanged afterward; without that baseline the controller logs `rejected-unproven` and converges back to its target. Exact backends retain their native tolerance regardless of the distance a nudge travels. Zellij fullscreen parks the controller until topology reports fullscreen cleared. The share math and record are [multiplexers.md](../multiplexers.md#width), and the renderer-side controller is [`app/width_control.rs`](../../../crates/rimz/src/sidebar_pane/app/width_control.rs).

### Selection and jump

Selecting a row focuses that agent's pane through the snapshot's `pane` ref; no mux pane number is ever printed. The key table is the [interface legend](../../interface/sidebar.md#keys-and-mouse), and the handlers are [`selection.rs`](../../../crates/rimz/src/sidebar_pane/app/selection.rs).

- **Selection is derived from session focus.** The baseline is `SidebarSnapshot::focused_pane` ([multiplexers.md](../multiplexers.md#who-is-looking-at-what)), filtered to a visible non-sidebar row and moved between pulls by a fused `FocusChanged` overlay. It is keyed by pane (`UiState::selected_pane`), so a reorder keeps the highlight on the same pane. Clicks paint an immediate Browse pick; ordinary baseline updates still follow fused focus. With no visible selected pane, `UiState::selected_index` is `None`: no card or teammate opens by selection, no lane, spines, or header seal render, the dashboard holds its last provider or the first panel, the pet rests, and scroll anchors the topmost surviving card. When an own pane is configured but the frame does not list it, `session_focus_baseline` withholds focus without changing the snapshot's `focused_pane`. This covers the [startup seed](./state.md#the-room-host-and-its-attachments), whose own view comes only from the remembered fold's own frame, and the first cached fetch fold alike: a new pane's first attachment stays unseated, while a successor seats its supervisor-carried baseline and an established selection holds across a transient missing own view for as long as its row stays in the frame. Once that row leaves, the selection is dropped and the withheld focus seats nothing in its place. A frameless fold (`panes_produced_at_ms == None`) is not that row leaving: it holds the identity-keyed selection, browse pick, and baseline, withholding only the index until a frame returns. An open search draft alone may highlight a pane-less match. A correction that lists the own pane and admits the focused row seats selection without revealing it.
- **Child focus selects the parent card.** A listed child's focused pane maps through `SidebarSnapshot::row_owning_pane` to its parent's own pane for the selection baseline. The parent stays visible through idle caps and finished-group collapse. A focused child writes no focus read receipt for the parent; the delayed tab-view sweep still clears a parent whose own pane is in the viewed tab, like any other row. The focused child's entry lines carry the selection-role spine only while the parent card is selected.
- **Transient layers sit above the baseline.** Browse (`↑`/`↓`, or a card/child click) pins a pick and ends when the derived baseline changes. Clicks paint the owning card selected before dispatching focus; motion alone does not move focus. The layout freeze pins the last painted order within current group partitions and visible rows after a jump, so cap exemptions settle with the reorder.
- **Motion keys resolve in the host.** The supervisor forwards raw presses with crossterm modifiers. The host resolves them with a `NavKeymap` built from the current snapshot's `[sidebar.keys]` and rebuilt only when that table changes, so an invalid chord warns once per edit; the mode (help, typing, normal) decides before the keymap, and typing swallows every `Ctrl` or `Alt` chord other than `Ctrl+n` and `Ctrl+p`. Rebinds reach each pane with its next refreshed snapshot, using the same bindings the help overlay draws. Page and screen-edge motions read the last painted `FrameInteractions::visible_row_span`, so `Ctrl+f`/`Ctrl+b` step by the visible row count and `H`/`L` target the screen's first and last row.
- **A jump is a durable intent.** `↵`, a click, a digit, or `␣` writes and broadcasts a `Requested` focus intent before the one-way focus command; command acceptance moves it to `Applied` ([state.md](./state.md#focus-intent)). Within one host, a cross-tab jump also pushes the stored target, optional card placement with its source opening set, and frozen order to peer attachments and waits for a painted frame, all peers' release, or the common deadline before dispatch. The deadline is click + 500 ms, including request work and any stale tmux destination fit before fan-out; fitting never resets it. A fitted destination paints at its expected rows. The source arms a host-wide lease before its synchronous click paint. The lease orders clicks without suspending room work. User input stays live through a separate bounded lane: re-clicks can supersede the pending jump, and same-tab input does not wait. Pushes use a priority slot even when the ordinary inbox is full. Click-order supersession cancels older requests before store, push, and dispatch, and older parked pushes never paint. Same-tab jumps, automatic repairs, and CLI focus arm no lease and do not wait. Each renderer adopts a fresh placement once, so a cross-tab jump keeps the destination card on the same row relative to its own scroll zone. The carried opening set makes that zone-relative row the same absolute row when the two frames share geometry and data. Without placement, the viewport stays anchored unless this sidebar issued the focus request and its off-screen target lands. The jump focuses the snapshot's pane id directly, without a per-click mux roster lookup. Request and dispatch errors return on the attachment wake channel, restore pulled session focus if the failed card is still selected, and leave a recovered health notice unless an active alert already occupies it. Rollback also retires the failed local intent cut, because peer adoption can end Browse before dispatch returns.
- **The focus key reaches the sidebar from any pane.** `[sidebar] focus_key` (default `Alt+p`) runs `rimz sidebar focus`: tmux binds it at session birth, and Zellij runs it from the presence plugin ([multiplexers.md](../multiplexers.md#room-keys)).

The row takes the user to the pane; the prompt and its approve or deny stay in the agent's own UI.

A pane-backed child entry click uses the same durable focus intent, parent-card placement, and shared layout freeze as a card click. The hit region covers both entry lines; paneless entries keep the parent-card fallback and keyboard navigation stays card-level. A realtime pane close clears the entry's pane binding before the next producer pull.

### Provider dashboard

Provider budgets are account-scoped: every session of a provider shares one account's windows and paid usage, so budgets live in a pinned per-provider dashboard at the bottom instead of on rows. With several accounts the dashboard is tabbed, one account at a time. The active tab follows the selected pane's provider; `←`/`→` or a tab click pins a manual pick that ends when the selection's provider changes or the tab leaves the dashboard. Tabs are the dashboard's only hit targets. Panel sourcing and aggregation are [providers.md](../agents/providers.md), and the look is [the interface reference](../../interface/sidebar.md#the-provider-dashboard).

- **Remote-control hosts render as a flag.** The snapshot filters the Claude host pane and the Codex app-server broker out of the room and paints a health-colored `⇅ rc` flag on the provider block: green up, red down, muted `rc off` when the room started without that host. Claude health comes from its host pane in the published frame, Codex health from live daemon PIDs in the reap cache. A stopped birth records a warning and turns blocked hosts off for that run without prompting; live entry warns without changing the applied policy.
- **The fleet store seals the bottom** with trailing-week `W:` and trailing-month `M:` totals from `SidebarSnapshot::value_tally`: the exact record beside the cockpit's live read.
- **Money counts up.** The cockpit `$` headline and each card's `$cost` roll up toward the exact figure as an eased odometer, snapping on first paint and across epoch resets ([`odometer.rs`](../../../crates/rimz/src/sidebar_pane/render/odometer.rs)). The headline follows the cards through `SidebarSnapshot::today_spend_live_usd`: the walked workspace total excludes active live-card sessions, then adds their current costs back. The renderer never lets the headline decrease within a `today_spend_epoch_secs` window. The figure is presentation; `SpendTally` and per-session cost are the truth ([spending.md](../agents/spending.md#what-reads-the-totals)).

## The serve loop

`rimz sidebar serve` is the pane's command. Its supervisor owns the pane command's PID and the pane's terminal, and hands the painting to the session's room host, so a painter crash and a reload resolve in place, while a confirmed self-close ends the pane ([state.md → The room host and its attachments](./state.md#the-room-host-and-its-attachments)). The pane's loop runs on a fixed timestep, folds each wakeup through [`LoopState::step`](../../../crates/rimz/src/sidebar_pane/app/loop_state.rs) as its per-iteration body, and paints from the last committed snapshot; data flow into it is [state.md](./state.md#one-fetch-cycle). The frame-activity read that decides the paint follows wakeup dispatch, so an input that starts a glide keeps its 16 ms boundary.

A pane the host is painting reaches its supervisor over the attach stream ([`supervise.rs`](../../../crates/rimz/src/sidebar_pane/supervise.rs)):

| Round ends with | Supervisor action |
|---|---|
| `self-close` | Confirm the tab is empty with the mux, then restore the tty and end the pane, or reject and reattach ([self-close](#self-close)). |
| `reload`, or a stable attachment painting the supervisor's target build | Preflight a promotable target before supervisor exec; otherwise reattach ([build promotion](#build-promotion)). |
| Failed attach or stream ending without a control word | Show the cause and retry delay, record `sidebar_host_unavailable`, and retry. |
| Confirmed pane absence | Record `supervisor_pane_gone`, remove runtime files, and stop supervision. |
| SIGTERM | Detach, preserve tty modes for handoff, remove runtime files, and stop supervision. |

The `baseline` control updates the supervisor's remembered selection baseline without ending the round. It survives host replacement and supervisor re-exec, but no other UI state does ([attach wire](./state.md#the-attach-wire)).

The host is the only painter. All failed starts, unanswered sockets, rejected or unreadable replies, and lost attachments use the same plain-text notice and exponential retry from one second to 60 seconds, resetting after a stable minute; a workspace-record change interrupts the wait. Non-terminal stdout or unavailable runtime paths refuse before socket or terminal-mode work ([state.md → Host unavailable](./state.md#host-unavailable)).

Each attachment writes its own heartbeat in the host, naming the host's room socket in `wakeup_socket`. The heartbeat record, its protocol version, and its TTL are wire, in [`wakeup/heartbeat.rs`](../../../crates/rimz/src/wakeup/heartbeat.rs). Heartbeat write failures log as best-effort liveness failures, and the normal reattach path repairs them.

### Launch

`rimz`, `rimz start`, and cwd-based `rimz attach` ensure the workspace session exists, then launch sidebars best-effort. Both backends run the same renderer. On Zellij, the birth layout's `new_tab_template` carries a left `rimz-sidebar` pane, so every tab is born with one. On tmux, RimZ splits a left sidebar into the first window and repeats the split from an `after-new-window` hook ([multiplexers.md](../multiplexers.md#the-sidebar-and-the-after-new-window-hook)).

Launch is idempotent by heartbeat. Only readable, current-protocol, fresh heartbeats count as live, so a crashed or upgraded sidebar does not block relaunch, and `sidebar-launch.lock` serializes check-then-spawn so concurrent attaches do not each spawn one.

### Drawing

Every animation reads the wall-clock animation phase, not the age of the data, so motion stays smooth over stale data and golden tests pin each frame deterministically. A terminal resize is a wakeup too: the process holding the pane's terminal turns `SIGWINCH` into a socket nudge, the loop reads the new size from the pane's output, and the frame repaints through the synchronous input path.

Row emphasis has two depths. The read pulse is an OKLab lightness ramp on the row glyph. The unread blink hard-toggles between the resting tone and a bright crest across the lead glyph, name, description, and make-up buckets, so it reads as on and off at every color depth; under `NO_COLOR` it keeps the shape and the on-phase bold. Palette depth is resolved by the renderer, because terminal capability is local: `theme.mode = "auto"` emits RGB on truecolor terminals and quantized 256-color tones elsewhere ([theme.md](../theme.md#color-depth-and-graceful-degradation)).

### Self-close

A sidebar shares its tab with the user's panes and has no reason to outlive them. The pane's loop requests self-close, and the supervisor decides.

On tmux the supervisor pins its own pane to `remain-on-exit off` at startup so its exit also closes the pane under the user's retention settings; a failed pin only warns and serving continues.

The attachment reads the sibling count from the producer's own-view summary ([`SelfCloseState::should_close`](../../../crates/rimz/src/sidebar_pane/app/lifecycle.rs)). Once it has seen a working sibling, a zero count requests self-close immediately. When the sidebar's tab is listed, an authoritative server read that omits its sibling is final, even while that sibling's root process cleans up. A whole omitted tab keeps liveness and tab-coherence carry. A cached omission uses carry and a `PreferAuthoritative` re-pull before feeding the count; if that re-pull falls back to the cache, liveness carry still protects the sibling. A sidebar that has never seen a sibling (session birth or resurrection, before the mux materializes the tab) waits `SELF_CLOSE_EMPTY_CONFIRM` (5 seconds) of continuous emptiness first, so a tab born sidebar-only still cleans itself up. An unknown count never closes. A producer frame that omits the sidebar's own pane is also re-pulled through `PreferAuthoritative` before it feeds the count.

On `self-close` the supervisor runs one authoritative mux listing. A present own pane closes only when its view resolves and has no working sibling. An absent own pane ends supervision only when a second listing, after a short delay, reproduces the absence. Siblings, an unresolved view, a reappearing pane, or any probe error reject the request, record `self_close_rejected`, and reattach after a short retry delay, so the decision fails toward keeping the pane.

The renderer-side guards protect paint, not lifetime. A fused `PaneClosed` overlay deletes its card immediately but never changes the sibling count ([state.md](./state.md#fusion-rules)). Closing the last sibling grows the sidebar to full width, so a bounded grow-resize hold in [`lifecycle.rs`](../../../crates/rimz/src/sidebar_pane/app/lifecycle.rs) suppresses the widened repaint while the request reaches the supervisor. The hold arms only when the grow lands beyond the room width target, so attaching a detached-born session repaints at once at its legitimate width. The birth path keeps the hold through its confirm window until a non-empty fold resets it or the supervisor accepts the request.

### Degraded reads and give-up

Give-up is the counterpart of self-close: self-close asks to end the pane when the view empties, and give-up reattaches in place when the view can no longer be read.

The attachment keeps its last committed frame. When a produce fails (a vanished store, a dead mux, a transient error) the loop reuses that frame and absorbs a single failure silently. A failure that persists past the debounce raises a sticky health alert pinned to the bottom edge (`! Sidebar degraded for 8s: snapshot failed: store not found`), truncating the body so the alert cannot scroll off. On recovery the alert stays as a dim dismissable notice. An attachment recovers health only from a completed produce, so a paintable fast fold cannot hide repeated pane-read failure. [`health.rs`](../../../crates/rimz/src/sidebar_pane/app/health.rs) folds these outcomes into `Health`.

A renderer degraded past `GIVE_UP_AFTER_DEGRADED` (30 seconds) records `renderer_exit` with cause `degraded_gave_up` and closes its attachment without a control word. The supervisor observes the stream loss, shows the host-unavailable notice, and retries in the same pane; the host's other attachments stay alive.

Across attach rounds the supervisor also watches that its pane still exists. A fresh presence roster containing the pane resets the strike count without a mux command; each due probe counts on an observation newer than the supervisor's last, and supervision ends only after three distinct authoritative absences, recorded as `supervisor_pane_gone`. The evidence rules are shared with orphan reaping in [multiplexers.md](../multiplexers.md#sidebar-orphan-reaping).

## Reload and repair

Reload replaces the running binary and keeps every pane. Repair fixes the pane structure. `rimz reload --repair` completes the upgrade, then runs repair as a separate operation.

### Build promotion

Staging keys each generation by the header's linker identity (a streaming hash when absent), reuses a verified copy without reading the full source, and otherwise uses kernel-assisted copying where available and verifies the copy's identity before publishing it.

`rimz reload` is user-wide, independent of cwd, and upgrade-only. It stages the invoking executable once as an immutable user-scoped generation, records its verified path and digest as each live room's durable target, atomically refreshes the room's stable `rimz` hardlink or copy, and sends a version-stable reload word as a latency hint. The host observes the changed target and drains its attachments with `reload`; each supervisor also stats the workspace record once per second and digest-verifies a changed target, so a missed datagram costs latency, not correctness. The CLI's heartbeat wait only reports: a sidebar that has not converged keeps retrying from the durable target without a repair.

Promotion is host-first. The old supervisor attaches to the target build's host, waits for it to paint through the stable-run window, emits `supervisor_convergence` before preflighting the target's version command, and only then re-execs its own pane-command PID. A failed preflight records `supervisor_preflight_rejected` and keeps the old supervisor until the target changes. A crashing or unlaunchable host costs notice-and-retry under backoff while the old supervisor and pane stay alive, and a later record change breaks the backoff. A successful handoff keeps pane id, tab, geometry, focus, terminal raw mode, and mouse capture.

The first upgrade from per-pane datagram input to attach-stream input accepts a one-time window of about 60 seconds per pane with keyboard, mouse, and resize input ignored until supervisor promotion, while painting and room events continue.

Bare reload creates and closes no panes. It still reloads refresh dashboards, sweeps stale runtime files, and reaps sidebar processes whose pane is gone, under the double-authoritative evidence rule in [multiplexers.md](../multiplexers.md#sidebar-orphan-reaping). Since a managed room always runs a sidebar, a live session with no fresh, protocol-current heartbeat has either lost its pane or is running a renderer this build cannot signal (`fresh_sidebar_heartbeats` drops both). Reload converges neither, so `upgrade_live` counts it as `sidebar_missing` and the CLI report points at `--repair`, which mounts or replaces a pane ([the line](../../reference/cli/maintenance.md#reload-running-sidebars)). The sidebar `r` key and the stats dashboard `r` key take the same pane-preserving path. The host's coalesced decision is [`host/reload.rs`](../../../crates/rimz/src/sidebar_pane/host/reload.rs), and the Zellij mount caveat is [multiplexers.md](../multiplexers.md#zellij-backend-caveats).

A reload also restarts each live room's running hook drainer after recording the build, before sweeping runtime claims. This step is shared by both backends and leaves an absent drainer absent. The [store contract](../store.md#the-workspace-store) owns the frame-boundary stop and queued-work handover.

### Zellij plugin upgrades

A reload upgrades the Zellij presence plugin only when its identity differs. The plugin configuration names the room's build-stable `rimz` pointer and includes the embedded wasm digest (computed lazily, once) plus a hash of the loaded configuration, and the plugin echoes both in its topology writer. A fresh matching writer counts as current and skips every start, reload, and retire pipe; a stale, legacy, or mismatched writer runs the replace-and-retire path ([multiplexers.md](../multiplexers.md#retirement)) and reports the upgrade.

### Structural repair

`rimz sidebar repair` converges every view toward exactly one live sidebar: it closes duplicate and orphan sidebars, adds a missing one, and replaces an unclaimed one add-before-close, committing a replacement only after the new pane mounts in the intended view and publishes a current-build heartbeat. It owns the Zellij presence-liveness precondition, and it shares reload's orphan-reap gate. The planner, verdicts, and Zellij mount proof are [multiplexers.md](../multiplexers.md#one-sidebar-per-view) and [in-place repair](../multiplexers.md#in-place-repair).

On Zellij, repair captures one unique fresh client view before changing structure, then restores focus through the same two-phase intent a jump uses: the exact live work pane, or the viewed tab's leftmost work sibling. Unavailable or ambiguous views skip the focus change. Adds and geometry repair in a detached Zellij session wait until a client attaches; tmux mounts splits detached. Repair never closes the daemon view's managed hosts; that view counts as occupied and keeps one sidebar like any working view.

## Resume-on-rebirth

When the machine reboots or the mux server crashes, the agent processes are gone but the store remembers them, and RimZ offers to bring back the agents the sidebar producer last saw alive.

1. Every produce cycle, the host writes `records/live-roster.json`: the current pane-backed, full-session set. A publication that would drop an agent named in the roster on disk is written only while the mux still lists the host's session (`MuxBackend::session_accepts_agent_close`, probed after the snapshot was produced; a failed or timed-out listing counts as not listed). Otherwise the file is left as it was and a rate-limited `live_roster_held` diagnostic names the agents kept: a host that outlives its session can read an agent-less room from the pane cache, and its view must not replace the set the birth recovers from. A publication that removes nothing is written without a probe. Provider-native subagents ride their parent; pane-backed launched children are independent roster members.
2. A birth after a reboot or same-boot crash reads the roster and the pending-recovery record, and [`harness/rebirth.rs`](../../../crates/rimz/src/harness/rebirth.rs) intersects them with the audit rollup without writing. An interactive start prompts to recover the root agents, defaulting to yes, and asks separately, defaulting to no, before dropping the roots it cannot resume; [`room`](../../../crates/rimz/src/room/mod.rs) owns the mux birth order.
3. Before the session is created, the birth parks the roster's agents in `records/pending-recovery.json`. Once the session exists and before the new sidebar starts, settlement records `session.death{cause,lost_agents}`, archives crash caches, allocates fresh team members, settles the root candidates as the user decided, automatically ends non-live children (`rimz.child-not-resumed`), appends `session.rebirth`, and deletes `records/live-roster.json`. A resumed agent leaves the pending record only after the birth confirms its tab open. Only a user decision or a confirmed or live seat refill (`rimz.seat-refilled`) ends a root agent: the other roots stay parked, exempt from the reap, until a later rebirth asks or an explicit resume brings them back. Pending launched children are not exempt from the reap; recovery never resumes them.

Room teardown captures the roster before killing the mux session, then restores it after the scoped process sweep confirms producer exit. This preserves the pre-teardown set for a later birth even when a dying producer publishes an empty roster during shutdown. The sweep also reaps hook feeds carrying the room's workspace pin, because they can publish caches after their pane dies; reload's liveness-only sweep leaves hooks alone. The sweep checks process identity while waiting, escalates from TERM to KILL, and warns about survivors past its deadline; teardown remains best-effort and restores the roster even in that case. Normal agent exits in a living room still narrow the roster, on the producer's next cycle that finds the session listed.

The plan (which sessions resume, team layout, `resume.max`, and the replayed posture) is [fleet.md](../harness/fleet.md#resume-and-rebirth). Restored agents come back idle: the resume argv rehydrates the conversation without a prompt, so no tokens are spent until the user types. Each agent's `SessionStart` fires with `source: "resume"` and re-stamps the new pane, so the row rebinds with the same identity and team members keep their `@role` address. `--no-resume` or `resume.on_rebirth = false` gives a room with no agents, and the room `rimz reset` starts itself recovers nothing, while a later `rimz start` after `rimz reset --no-start` recovers the roster the teardown preserved; the prior root agents are ended only when such a start is attended, and are parked otherwise. Non-live children end automatically at settlement.

This continuity is RimZ-owned and transcript-based. RimZ disables Zellij session serialization in its rooms, because Zellij resurrects command panes suspended and they read as dead.

## Notifications

Notifications are best-effort over the same attention model, and the store stays authoritative. The host opens unread episodes, applies `[notifications].triggers`, debounce, and focus suppression, spawns matching handlers, and sends `SidebarEvent::Notify` directly to its subscribed panes after their snapshots. One host timer reminds on the room's unread `waiting` and `failed` rows until they clear, spawning handlers once per interval with the room count. Each renderer writes terminal-local OSC and BEL bytes outside the draw cycle. The contract is [notifications.md](./notifications.md).
