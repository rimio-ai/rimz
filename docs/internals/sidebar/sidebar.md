# Sidebar

> [DESIGN.md](../../../DESIGN.md) states the commitments this doc operationalizes, [the interface reference](../../interface/sidebar.md) draws the sidebar frame by frame, and [state.md](./state.md) owns the data plane beneath it: the node model, the producer's caches, and the timing. This doc owns the mechanics between them: how presence, ranking, layout, and recovery are computed.

The sidebar is a UI client over the workspace ledger. It reads the ledger in process, writes only runtime display files (its heartbeat, read receipts, `unread.json`, `focus-anchor.json`, and the producer caches), and imports no ledger-writer module. One renderer paints every moment of a session: a bare shell, the first agent, a waiting prompt, a fleet across worktrees, detach and reattach. What changes between those moments is the snapshot, never the renderer.

## The view-model and its renderers

The `rimz sidebar snapshot` JSON is the shared view-model, and every decision is made once, here. It carries the worktree-grouped row roster, per-agent status and capability, the ranking keys, the attention items, and timestamps. A renderer is a pure projection: it maps those semantics to glyphs and paints them. It never re-derives which worktree a row belongs to, how rows rank, or which pane runs an agent.

The snapshot command runs inside the `rimz` binary, which owns mux access, so it enumerates the session's panes and folds them into the roster before serializing. Every renderer is then a pure JSON consumer, with no mux call of its own. Pane width is likewise the launch path's concern: every sidebar pane is born at the launch's width verdict (`min(30%, max_cols)`, resolved once against the launching terminal, see [multiplexers.md](./multiplexers.md)), so the renderer never resizes its own pane and a manual resize sticks.

Two renderers project the same snapshot today: the **native pane** (`rimz sidebar serve`, the default, identical on Zellij and tmux across detach and reattach) and **CLI listings** (`rimz agents list` and friends, the same data as text). The per-renderer code is only painting, so visual parity is a maintained discipline rather than shared render code. The load-bearing rule: each glyph carries state by **shape**, so it survives `NO_COLOR`, and color only reinforces it. The full semantic-to-glyph vocabulary is drawn in [the interface legend](../../interface/sidebar.md#reading-the-glyphs), with the rationale in [DESIGN.md](../../../DESIGN.md#triage-at-a-glance). Tones are themable data over the snapshot theme path; the renderer resolves color depth itself because terminal capability is local.

## Presence model

**Row presence comes from the live pane frame, not the ledger.** The producer enumerates the session's panes, assembles them into `PaneFrame` tabs, reads each pane's foreground command and cwd, resolves the cwd to a worktree, and the fold emits **one row per admitted pane**. No pane id is ever shared by two rows. [`pane_admits_card`](../../../crates/rimz/src/ledger/snapshot/panes.rs) is the admission rule: it admits work panes and excludes the caller's own pane, sidebar chrome, and the remote-control and app-server hosts. A pane running a shell is a [process row](#process-rows); a pane an agent stamped is that agent's row.

**Binding is by identity first.** A pane's foreground command alone cannot name the agent, because Claude can run under `node` and two same-kind agents in one worktree read identically. Every `agent.lifecycle` event carries the mux pane id the hook ran inside (`TMUX_PANE` or `ZELLIJ_PANE_ID`), and the snapshot binds each live pane to the one agent that stamped that exact id. Command and cwd form only a guarded recovery path after no stamp claims a pane.

Joining a session to its pane runs a short ladder, most-certain first. The exact predicates live in [`panes.rs`](../../../crates/rimz/src/ledger/snapshot/panes.rs) and [`panes/lazy.rs`](../../../crates/rimz/src/ledger/snapshot/panes/lazy.rs); the cases are pinned in [`view/tests/pane_binding/`](../../../crates/rimz/src/ledger/snapshot/view/tests/pane_binding) and [`lazy_bind/`](../../../crates/rimz/src/ledger/snapshot/view/tests/lazy_bind).

1. **Stamped pane id.** The live pane binds the agent that stamped its exact id. A `session.rebirth` boundary clears every prior stamp at once, because pane ids restart at zero on rebirth so every old stamp names a dead pane. A per-pane process-start guard is the backstop the boundary cannot see: it refuses a stamp whose session predates the pane the id now points at.
2. **Recovered stamp.** A daemon-routed [lazy-registering agent](../agents/agent.md#the-instance-lifecycle) (one that registers on its first turn, not at launch) starts with no pane id in its hook env, so hook ingestion recovers a durable stamp before appending the first lifecycle event. It reads the same repaired pane frame the producer publishes, filters to same-cwd, same-kind panes no other live stamp owns, and writes one candidate directly. Client focus disambiguates plural candidates. Every attempt appends its probes, candidates, and outcome to `binding.log.jsonl`.
3. **Exact-cwd recovery.** An unstamped session binds the live same-kind pane whose cwd equals the session worktree *exactly*, refused when the session's last activity predates the pane's process start ([`pane_start_allows_bind`](../../../crates/rimz/src/ledger/snapshot/panes.rs)), so a stale session never latches onto a freshly-started pane. This is the normal join for a daemon-routed lazy session and the rebirth repair for a session whose stamp was cleared while its process kept running. A reborn Codex pane launched as `codex resume <id>` binds that session ahead of the heuristics.
4. **Idle synthesis or process row.** With no session bound, a wired agent pane renders a synthesized idle `○ <kind>` row until a lifecycle hook swaps in the real session ([`idle_agent_row`](../../../crates/rimz/src/ledger/snapshot/panes/lazy.rs)). An unwired pane stays a process row.

**Why a daemon-routed session is unstamped.** Codex under remote control fires its hooks from the shared per-user app-server daemon, so the hook env carries no pane id and its pid is the daemon's, shared by every client. The session id lives only inside the daemon's rollout and socket traffic, in neither the client's environ nor its open files, so a client-pid-to-session join is impossible by construction ([adapter/codex.md](../agents/adapter/codex.md#session-registration-and-launch-quirks)). Rimz therefore binds these sessions from live pane candidates, explicit `codex resume` argv, and pane process-start ordering, with cwd as the shared scope rather than the sole key.

**No live pane, no row.** An agent with no live pane, whether a subagent, a ghost a kill left in the rollup, or a relaunch the [reaper](../agents/agent.md#liveness-and-presence) has not collapsed, is data, not presence. It cannot resurrect a row or latch onto a stranger's pane, and there is no `offline` status. A relaunch in place is the one subtle case: the [reaper](../../../crates/rimz/src/ledger/snapshot/view/reap.rs) collapses an older same-pane root when the newer one is a provably different process (a genuine relaunch) or, for Codex, a same-pane `/clear` or `/new` whose fresh rollout lineage proves a new conversation. A same-process thread fork (Codex `/side` or `/btw`) carries `forked_from_id`, survives the reap, and stays pinned to the earliest-registered primary.

**Attention lives on the agent's row.** A blocking prompt is agent state: the `awaiting_input` lifecycle signal puts the session's one row in `? waiting`, so a session never stacks a second row for its ask, and the row returns to work once activity passes `waiting_since` ([agent.md → The state machine](../agents/agent.md#the-state-machine)). If the agent's pane is absent the row leaves the sidebar with it; the durable state stays in the ledger.

**Remote agents are not shown yet.** A remote agent runs only in the daemon with no local pane (`claude remote-control --spawn`, or a Codex thread started from the web). Its status can still reach this workspace's rollup, yet it renders nothing, because presence is pane-anchored and there is no pane to bind. Showing remote agents needs a presence class that renders from the rollup alone. This is a known gap, unbuilt this round.

### Honest reads across a mux hiccup

The mux roster can occasionally arrive incomplete: a partial pane set, or a live pane missing its command or cwd. Four guards keep a momentary glitch from reaching the screen as a lie. The producer-side repairs live in [`produce/panes/`](../../../crates/rimz/src/sidebar/produce/panes.rs) ([`carry.rs`](../../../crates/rimz/src/sidebar/produce/panes/carry.rs), [`validate.rs`](../../../crates/rimz/src/sidebar/produce/panes/validate.rs)); the renderer gate lives in [`gate.rs`](../../../crates/rimz/src/sidebar_pane/app/gate.rs); the fusion supersession that lets a real close still pierce a carried pane is in [state.md](./state.md#fusion-rules).

- **Repaired fields.** The producer joins a fresh raced-null read to the last published process for that *exact* pane id, and backfills a missing cwd from `/proc`, so a just-born pane groups under its worktree on first appearance rather than blinking in as an anonymous row.
- **Carried panes.** A pane a fresh read omits carries forward only while liveness proves it still exists: a matching non-zombie `/proc` process, or the renderer's own pane by identity. Carried panes are marked, publish a `pane_carry_forward` diagnostic, and expire after `PANE_CARRY_TTL`, so a real exit drops promptly once the process proof is gone.
- **Nameless panes.** A pane with no readable identity after the field repair folds no row this frame rather than an anonymous `process` row. The next read names it. An agent-stamped pane still binds by id, so it keeps rendering.
- **The renderer's last-resort hold.** Frame plausibility lives in the producer and row identity in the projection; the gate only absorbs a residual race that would erase or demote a stable row set. It holds an agent-to-process demotion only when the foreground command is unchanged or missing (the phantom-flicker signature), because a command change means the agent exited in place and the pane returned to its shell, which commits immediately.

When pane discovery itself fails, the renderer keeps the last good snapshot and, once the failure persists, raises the sticky health alert rather than inventing an empty room (see [Reload recovery](#reload-recovery)).

## Ranking and grouping

### Worktree groups

A worktree is total isolation, so each group is one bounded block under its header. Two rules the renderer enforces: the header is a **jump target** and carries **no status tally** (the cockpit owns the fleet make-up, and each row carries its own glyph), and **git stats live on the header, not a row**, so shared-worktree changes never pretend to belong to one agent. The `+/-` churn is the worktree's total change against its merge-base with trunk, and the `⇡`/`⇣` delta is the commit count over the same base, so every number measures from the fork point. The trunk-glyph ladder ranks reconciling (a local rebase or merge in flight) above local-merged, PR-merged, PR-closed, PR-open, and a plain branch; a pristine fork reads `≡ <trunk>` and landed work reads the merge glyph. The trunk resolves per repo, preference first: `[sidebar] trunk` ([configuration.md](../../reference/configuration.md#sidebar-rendering)), then `main`, `master`, and the remote's advertised default. The stat and PR sourcing lives in [`refresh/git_stats.rs`](../../../crates/rimz/src/sidebar/refresh/git_stats.rs) and [`refresh/pr.rs`](../../../crates/rimz/src/sidebar/refresh/pr.rs); the look is in [the interface reference](../../interface/sidebar.md#worktree-groups-and-the-selection-lane).

A stamped channel pane groups under its channel pod first. An unstamped pane inside the repo's Rimz-owned worktree home folds into that worktree's `#channel` pod, matching message addressing and `rimz channel list`. Other panes group by the **deepest group root that contains their cwd**. A repo room enumerates its checkouts with `git worktree list`; a directory room does not scan its tree, and the panes the root itself claims form a name-only **root pod**. A cwd outside every group root (a home shell, `/tmp`, CI) folds into a catch-all that renders as a dim `external` divider, always sorts last, and keeps an attention-only tally so an out-of-project ask still surfaces from the tail. The grouping rules are pinned in [`view/tests/grouping/`](../../../crates/rimz/src/ledger/snapshot/view/tests/grouping).

### Attention ranking and the cap

Within a worktree, agent cards lead and process rows form the command tail. Agent-card order reads in three bands plus a score inside each band; the seams are [`sort_rows`/`compare_groups` and the rank key](../../../crates/rimz/src/ledger/snapshot/view/layout.rs), with cases pinned in [`view/tests/ranking/`](../../../crates/rimz/src/ledger/snapshot/view/tests/ranking). The reader-facing reasoning behind the model lives in [guide/attention.md](../../guide/attention.md). Read and unread never change the band; unread drives the wash and blink emphasis, the jump inbox, notifications, and the cap's keep-visible rule. The order they encode:

- **Band 1 — hot work.** A row stays hot until its `last_activity` ages past the inactive window — one hour by default, set per machine with `[agents.attention] inactive_after_secs` ([configuration.md](../../reference/configuration.md#sidebar-rendering)). Attention rows (`waiting`/`failed`/`paused`) heat from 1.0× to 2.0× across that hour, so an older failure can outrank a fresh ask, while calm rows (`success`/`running`/`idle`) keep a flat score and hold pane creation order within equal states.
- **Band 2 — warm work.** Past the inactive window, an agent row is *inactive* and sinks beneath every hot agent row whatever its status; its score decays from 1.0× to 0.0× until `[agents.attention] archive_after_secs` (24 hours by default), so stale asks still lead stale calm rows without competing with current work.
- **Band 3 — archive.** Past the archive window, a row parks below hot and warm work with a flat score again; the band carries the "sleeping" verdict, and the score only orders archived asks above archived idle rows. Process rows are exempt from inactive and archive because their activity clock is foreground-process start rather than attention; an idle shell stays live presence, then seats below every agent card.
- **Co-launched agents hold one block.** A named-team launch and an inline multi-agent layout render as one contiguous block inside their worktree or channel group. Team blocks use the declared role-list order, including custom team layouts; inline blocks use agent-cell order. The block state derives from members: any `waiting`/`failed` member makes it blocked, else any `paused` member parks it, else any `running` member makes it working, else any `success` member makes it success, else it is idle. Blocked and paused blocks use the oldest attention clock, while calm blocks use the most recent member clock.
- **Groups carry the same three bands, plus git among calm git-backed groups.** A group partitions hot/warm/archive by its liveliest member, and within a partition leads with that member's attention score while calm members collapse to one constant so success/running/idle churn does not reshuffle groups. Git-backed groups then sort by git rung — dirty, clean, unknown, done — where done covers local landing and merged or closed PR verdicts, so finished clean work sinks below active dirty work when attention does not decide. Same-rank groups keep their earliest member's pane-creation order, then label; `external` groups tail unconditionally, regardless of any attention member they hold.

**The cap protects visible work.** The snapshot carries every row, and each renderer caps only a worktree's idle and process tail in the resting body, showing up to `WORKTREE_ROW_CAP` rows with a dim `+K more` for the remainder. Active, blocked, paused, finished, unread, and focused rows are exempt and always shown, so a row that may need a look or a jump never hides behind the count. Clicking `+K more` expands that group in place, and `− less` collapses it; the state is renderer-local and clears when the group no longer hides a tail.

Producer rank is truth, while the interactive renderer holds the last painted row and group order for `REORDER_HOLD` after a jump or browse, so a just-read card does not slide under your eyes. Read state clears immediately; only position holds.

**Auto-continue** is producer-owned enrichment for `paused` rows: the producer waits for the reset or backoff condition and queues a hidden `Resume` through the durable message pipeline, promoting the row to actionable `failed` when evidenced attempts exhaust rather than spinning silently.

## The cards

Each agent is a small stacked card. Its anatomy and meter grammar are drawn in [the interface reference](../../interface/sidebar.md#the-card); the mechanics here:

- **Density resolves before row lines.** `[theme.display] card_density` picks `auto` (the standard shape, subagents on the selected row), `expanded` (subagents on every card), or `compact` (resting cards trimmed by status). Auto and expanded selection only *append* the deeper lines, so the card never reflows on expand. Compact is the scoped exception: a resting compact card is shorter, and selecting it reflows up to the full shape. A selected awaiting-first-prompt idle card also opens into its compose affordance, and the serve loop holds the breath cadence while selection stays parked there.
- **Capability is preferred, never guessed.** Model and reasoning effort come from the session's rich [context](../agents/agent.md#rich-context-agentcontext) or the hook/ledger scalar, and a missing field means the agent did not report it, never a zero. Account-scoped budgets are **not** on the row; they live in the [provider dashboard](#provider-dashboard).
- **Enrichments are display-only and privacy-gated**, and none drives attention or routing. Context severity is one four-tier ramp (calm green through yellow and amber to red), classified once in the domain ([`ContextSeverity::classify`](../../../crates/rimz/src/agents/state.rs)) and stamped on each row; the renderer maps the row's position in the config stops ([configuration.md](../../reference/configuration.md#sidebar-bands)) to a continuous tone. `NO_COLOR` suppresses color only; every bar's shape still carries the meter.

A row is base identity plus one card payload: [`AgentCard`](../../../crates/rimz/src/ledger/snapshot/row.rs) for lifecycle and context fields, or [`ProcessCard`](../../../crates/rimz/src/ledger/snapshot/row.rs) for command and process metrics. Three projection rules are not evident from the field catalog: the renderer prefers the rich `context` blob over the coarse scalars but prefers `row.effort` over `context.effort`; Codex line 2 reads the app-server thread preview then name, while other agents fall through session name, task, then prompt, so a row keeps a label once the turn ends; and the display preferences ride `SidebarSnapshot.sidebar`. The status projection is pinned in [`view/tests/status/`](../../../crates/rimz/src/ledger/snapshot/view/tests/status) and [`project/tests/`](../../../crates/rimz/src/ledger/snapshot/project/tests).

The stamped verdicts are hook-ready: `ContextSeverity` rides each row, so a future flow could emit an [`AgentSignal`](../../../crates/rimz/src/agents/state.rs) (`ContextSeverity` on a tier crossing, `Attention` on entering an attention state) for a notification handler to act on (`rimz pane send /compact` at amber). The typed signal exists now; emission and handling are deliberately unbuilt.

### Unread and read receipts

Unread state is a durable runtime episode set (`unread.json`) plus runtime read receipts (`read-marks/`). The elder opens an episode for a row whose displayed status is `success`, `failed`, `waiting`, or `paused` when no read mark reaches the row's `last_activity`, and every fold derives `SidebarRow::unread` from that file plus the merged receipts. The fold stamps the unread bit before rendering, and the renderer cap keeps unread rows visible, so a row that recovers to `running` or `idle` stays visible and emphasized until read. Attaching to an already-busy room opens the current attention rows silently, without replaying a push storm.

Focusing a row's pane writes a receipt and clears that row; staying in the tab for `TAB_READ_DWELL` clears unread siblings in it, while leaving before then leaves them unread. `rimz sidebar mark-read` and the `m` key write a durable manual receipt without focusing; `M` and `rimz sidebar mark-unread` open a fresh episode through the one mark-unread write path ([`sidebar::unread::mark_rows_unread`](../../../crates/rimz/src/sidebar/unread.rs)), stamped so no read receipt can reach it. Every fold merges the maximum clear time per row, and a receipt clears an episode only when its clear time is at or after the episode, so an old focus clear cannot erase a later turn. Receipt files are disposable runtime sidecars swept once the owning heartbeat expires.

### Sub-agent lists

The expanded card lists the subagents an agent spawned this turn. A subagent has no pane of its own, so it never renders as its own row; instead the rollup carries each child's `parent_agent_id` and the snapshot nests it under its parent at projection time. The list orders by **creation time ascending** (`registered_at`), stable across refreshes.

Retention is **turn-scoped**. A live child stays listed while it belongs to the parent's current turn, and a *finished* child holds its `✓`/`!` verdict until the parent records its next prompt boundary. A fresh prompt, a `/clear`, and a manual `/compact` each advance that boundary and clear the prior turn's children; automatic mid-turn compaction resumes the same turn and keeps them. The ghost-session TTL is the backstop when the parent never records a boundary. A child whose parent row is absent is an orphan and never renders.

The child's description, token count, and start time are paneless enrichment the hook pipeline harvests from Claude's `subagentStatusLine` into a per-child sidecar; [`with_subagent_context`](../../../crates/rimz/src/ledger/snapshot/view.rs) folds them onto the child's rollup state before projection. **Child activity counts as the parent's**: at projection ([`fold_child_activity_onto_parents`](../../../crates/rimz/src/ledger/snapshot/view/aggregate/subagents.rs)) the freshest child `last_activity` advances the parent row's *displayed* clock, so the card's age stays honest and the stall check never false-fires while children work. The fold is display-only and guarded, so the rollup keeps the parent's own clock, a blocked parent stays waiting, and a turn-death marker always beats a still-ticking child. The subagent cases are pinned in [`view/tests/subagents/`](../../../crates/rimz/src/ledger/snapshot/view/tests/subagents).

## Process rows

A pane no agent has stamped renders a bare command row: a lead glyph then the program it runs (`zsh`, `vim`, `cargo`), recessed one tier below the agent cards. The program is read past a `sudo` wrapper and through a `node` or `npx` launcher to the script it runs, so `node …/codex` reads as the pre-enrichment agent host while bare `node` waits for a script path. The lead is `ProcessState`: a hollow `○` when idle, a braille spinner when busy, and an attention `!` when `/proc` reports a zombie or a repeated uninterruptible sleep. A wide enough working row right-pins a fixed CPU, RSS, and I/O grid on line 1; an idle shell stays bare.

Both reads key off the pane's root pid. tmux reports it natively (`#{pane_pid}`); Zellij reports none, so the producer derives it by matching the pane's foreground cmdline against the session's `zellij --server` process forest ([`backfill_zellij_pane_pids`](../../../crates/rimz/src/sidebar/produce/metrics.rs)). For an implicit Zellij shell pane, the presence plugin seeds the shell command and cwd once through `get_pane_running_command` and `get_pane_cwd`; pid derivation and the ambiguity rule stay the same. An ambiguous pane, such as two idle shells in one cwd, abstains and shows no stats, because no stats beats a stranger's stats. A process row carries no capability line and enters no cockpit tally, but it is still a jump target, and once an agent's hook stamps that pane it becomes the agent's row.

When a pane's foreground command runs through `sudo`, `su`, or `doas`, a bounded descendant scan can relabel the row to a known agent CLI running as another real uid, carrying a dim `(<user>)` marker (`claude (root)` above `sudo su`). The row stays a process row: it contributes no tally or dashboard account, and the elevated hint never rewrites `pane.command`, so cwd recovery and idle synthesis still refuse it as a foreign-user agent.

## Composing the frame

The sidebar is **borderless**: it already lives inside a framed mux pane, so a title line, hairline rules, and a one-cell left gutter (which doubles as the selection lane) carry the structure instead of a second border. The on-screen layout is drawn in [the interface reference](../../interface/sidebar.md); this section owns the invariants behind it.

- **Fixed height where it counts.** The repo dashboard and the cockpit make-up reserve their rows whether or not the room has agents, so the body never shifts vertically as agents change *state*. The footer and health alert are bottom-pinned chrome, reserved before the body so they can never scroll off.
- **Three zones, two pinned.** The frame composes as a top-pinned cockpit, a scroll viewport over the worktree groups, and bottom-pinned chrome (dashboard, ledger, footer, alert). The pinned zones reserve their rows first, and the viewport takes the remainder, so the cards give way before either pinned zone is clipped. `UiState::scroll_offset` is resolved on every draw: clamped to the zone, then minimally auto-scrolled so the selected card sits fully in view.
- **A fresh unread drives auto-follow.** The viewport snaps to a newly-arrived actionable unread and holds there until you engage or it stops being the lead. The `↑ N need you` banner appears while that lead card has no line inside the resolved window, and a banner click scrolls to the top.
- **Jump anchors are renderer-to-renderer scroll hints.** A sidebar-initiated jump writes `focus-anchor.json` with the focused pane and the clicked card's current viewport offset. Every renderer reads it on the fold that adopts the focus and seeds `UiState::scroll_offset` once while the anchor is fresh, so a cross-tab jump keeps the destination card on the same on-screen row instead of re-following that tab's previous selection.
- **A focus switch reveals the whole worktree.** When a fold adopts an external focus change — a tab switch, or the first focused pane the sidebar learns on attach — the renderer arms a one-shot group reveal: the next paint scrolls minimally so the focused card and its worktree header both sit in view. A sidebar-initiated jump cancels the reveal because its fresh `focus-anchor` freezes the clicked row instead, so the reveal belongs only to focus moves that originate outside the sidebar.
- **Counts span the cap, the summary spans the spend window.** The cockpit make-up buckets sum each group's `status_counts` from the full roster; every `running` agent tallies as working (the thinking head is a per-row head, not a bucket). The resting body may hide calm tail rows, while an active make-up pick shows every matching row uncapped, so bucket counts and narrowed cards agree. The summary's line 1 pairs headline facts — the `◎` sessions and the token breakdown read `[sidebar] spend_window` from the JSONL `value_tally`, not the live session sum — and line 2 carries the `¤` live-agent head-count, the steady unread count when non-zero, and the count-up spend.
- **The make-up line is the body's filter.** Each non-zero bucket is a click target that narrows the cards to its status; re-click clears, and a zero bucket emits no hit ([the look](../../interface/sidebar.md#zone-1--the-cockpit)). The cockpit unread count uses the same storage and predicate: clicking `(N)` applies the unread lens, and the picked count paints as a chip while active. The renderer emits the bucket and unread-count geometry in lockstep with the frame (`UiState::make_up_hits`, riding beside the dashboard's `tab_hits`; top-block hits are already absolute — the cockpit starts at screen row 0 — so they skip the bottom block's base translation). The pick (`UiState::make_up_filter`) is renderer-local display state over `group_visible_rows`, the shared row-visibility walk consumed by both the body composer and the selection walkers — so the hit-test `line_map`'s row ordinals and the selection's indices can never drift under capping, expansion, or filters. The cockpit counts stay full-fleet while the body narrows, and `reconcile_selection` clears the pick the moment its full-fleet count reaches zero — the body's twin of a dashboard tab pick ending when its panel leaves. A jump (`Enter`, `␣`, `1`–`9`, a card click) clears the pick as it fires: a status lens or unread lens is one tab's transient view, so it never outlives the jump that leaves the tab, and every tab's body opens at show-all when focus returns.

The body carries only live rows: the sidebar shows what needs a decision or an action, and durable history lives in the ledger behind `rimz transcript`, `rimz message list`, and `rimz doctor --audit`. An empty room keeps the body clear under the cockpit and footer, while an active health alert takes the body alone.

### Selection and jump

You do not read where to go; you go. Selecting a row focuses that agent's pane via the `pane` ref on the snapshot, and no mux pane number is ever printed. The full key table is the [interface legend](../../interface/sidebar.md#jump--the-row-is-the-link); the mechanics it leans on ([`selection.rs`](../../../crates/rimz/src/sidebar_pane/app/selection.rs)):

- **Selection is derived state, scoped to the session focus register.** The baseline is `SidebarSnapshot::focused_pane` ([multiplexers.md](./multiplexers.md#session-focus)), filtered to a visible non-sidebar row and retargeted between pulls by a fused `FocusChanged` overlay. It is keyed by pane identity, not row position (`UiState::selected_pane`), so a status-churn reorder re-anchors the highlight to the same pane. Selection cannot desynchronize, only lag a frame.
- **Transient layers ride above the baseline.** Browse (`↑`/`↓`) pins a pick without moving focus and may roam every visible row, ending when the derived baseline genuinely changes. Order hold pins the last painted order for the interaction window after a jump.
- **Motion keys resolve before the loop sees them.** The input thread builds a configurable `NavKeymap` from `[sidebar.keys]`, preserves crossterm modifiers, and sends the same wire actions as fixed keys. Page and screen-edge motions then read the last painted `UiState::line_map` window, so `Ctrl+f`/`Ctrl+b` step by visible row count and `H`/`L` target the current screen's first/last row without storing extra viewport state.
- **A jump self-corrects.** `↵`, a click, a digit, or `␣` fires the one-way focus command and records a local `FocusChanged` intent, so the highlight moves on the next fold even when a backend's raw focus marks are contested. Every jump reconciles pane id *and* `pane_process_start`, so a reused id never silently focuses a stranger.
- **The focus key reaches the sidebar from any pane.** `[sidebar] focus_key` (default `Alt+p`) toggles `rimz sidebar focus`: tmux binds it at session birth, Zellij runs it from the presence plugin ([multiplexers.md](./multiplexers.md#focus-key)).

The row routes you to the pane; the prompt and its approve/deny live in the agent's own UI, where the full context is.

### Provider dashboard

Provider budgets are **account-scoped, not session-scoped**: every session of a provider shares one account's included windows and paid-usage state. So they lift off the rows into a pinned per-provider dashboard at the bottom. With several accounts the dashboard is **tabbed**, one account deep at a time; the active tab follows the selected pane's provider, and `←`/`→` or a tab click pins a manual pick that ends when the selection-derived provider genuinely changes or its tab leaves the dashboard. How each panel's account, plan, windows, and paid row are sourced and aggregated is [provider.md](../agents/provider.md); the look is in [the interface reference](../../interface/sidebar.md#zone-3--the-provider-dashboard). This section owns the painting and the tab focus.

- **Remote-control hosts render as a flag.** They are infrastructure, so the snapshot filters the Claude host pane and the Codex app-server broker out of the room and paints a violet `⇅ rc` flag on the provider block instead. `rimz start` preflights configured hosts and refuses with the fix when one is blocked by settings, version, or auth.
- **The fleet ledger seals the bottom** with trailing-week `W:` and trailing-month `M:` totals fed by `SidebarSnapshot::value_tally`. These figures are **static**, the exact record beside the cockpit's coarse live read.
- **The money counts up.** The cockpit headline `$` and each card's `$cost` climb on an increase as an eased odometer roll toward the exact figure, snapping on the first paint and across epoch resets ([`render/odometer.rs`](../../../crates/rimz/src/sidebar_pane/render/odometer.rs)). The headline tracks cards live through `SidebarSnapshot::today_spend_live_usd`: walked workspace headline USD excludes active live-card sessions, then adds those cards' current costs back in full. The renderer ratchets the shown headline within a `today_spend_epoch_secs` window so it does not decrease until the configured spend window rolls. The figure is presentation only; the `SpendTally` and per-session cost are the truth.

The tabs are the panel's only hit targets; everything else in the dashboard stays inert in the hit-test map.

## The runtime loop

### Launch

`rimz`, `rimz start`, and cwd-based `rimz attach` ensure the workspace session exists, then launch one sidebar pane best-effort. Both backends run the same native renderer through `rimz sidebar serve`. Zellij is born from a layout whose left `rimz-sidebar` pane doubles as the default tab template, so every tab is born with a sidebar; tmux splits a left sidebar into the first window and re-runs the split from an `after-new-window` hook for every later window. Launch is **idempotent by heartbeat**: Rimz treats only readable, current-protocol, fresh heartbeats as live, so a crashed or upgraded sidebar does not suppress relaunch, and a launch lock serializes check-then-spawn so concurrent attaches do not each spawn a daemon.

### Reload

`rimz reload` is user-wide and cwd-independent, running from anywhere. It reconciles every live mux session concurrently and converges each to **one healthy sidebar per working view**: it sends the version-stable reload word to live sidebars, waits for build-stamped heartbeats to prove each pane runs the on-disk binary, and closes any pane a fresh current-build heartbeat does not claim. A sidebar already on that build refetches in place instead, so an unchanged install never churns its pane. The same pass re-adds a sidebar to any working view left without one, repairs a mis-docked sidebar toward the layout width, collapses a wedged sidebar-only orphan, and reaps orphaned sidebar processes, all in place, so the user's panes survive. Each pass is best-effort and run-once. On Zellij an add or geometry repair in a *detached* session is deferred to the next reconcile against an attached client, because the detached screen thread drops mounts; tmux mounts splits detached, so it never defers. The daemon view converges the same way but is never collapsed, since its hosts are managed, not work. The sidebar `r` key and the stats dashboard `r` key drive the same pane-stable reload from inside those surfaces. The worker reload decision lives in [`app/reload.rs`](../../../crates/rimz/src/sidebar_pane/app/reload.rs), supervisor convergence lives in [`supervise.rs`](../../../crates/rimz/src/sidebar_pane/supervise.rs), and the Zellij mount caveat is in [multiplexers.md](./multiplexers.md#zellij-backend-caveats).

`rimz sidebar serve` starts as a supervisor process that owns the mux pane command PID and spawns a worker child for the TUI. On a changed-build reload, the worker exits with `RELOAD_EXIT_CODE`; the supervisor reaps that worker, reaps any other exited children parented to it, sets `RIMZ_SIDEBAR_INSTANCE_ID` to the current instance id, and re-execs itself onto the resolved on-disk binary. The mux sees the same pane command PID, the runtime socket and heartbeat identity stay stable, and the old deleted binary inode is released. If the replacement binary is temporarily absent during an install race, the supervisor respawns the worker from the best resolved `rimz` path and tries convergence again on the next reload.

### State access

Data flow is [state.md](./state.md)'s domain: the node model, producer election, the published-file inventory, typed realtime events and push channels, fusion, render cadences, and the pull-tick table (values in [`sidebar/timing.rs`](../../../crates/rimz/src/sidebar/timing.rs)). This doc keeps the liveness contract: each renderer writes its own heartbeat in process and binds a per-instance wakeup socket, and the heartbeat carries the workspace, session, mux, instance id, protocol version, socket path, pane id, build id, and last-seen timestamp.

### Drawing

Base composition owns the row animation. The gentle read pulse is an OKLab lightness ramp on the row glyph, while the deeper unread blink hard-toggles between the resting tone and a bright crest (a square wave, not a swell) across the lead glyph, name, description, and the make-up buckets, so it reads as a clear on-off at every depth. `NO_COLOR` keeps the shape plus the on-pole bold weight. Palette depth is separate: `theme.mode = "auto"` emits RGB on truecolor terminals and quantized 256-color tones elsewhere. A terminal resize is also a wakeup (a watcher turns `SIGWINCH` into a socket nudge) and repaints through the synchronous input path.

### Self-close

A sidebar shares its tab with the user's working panes and has no reason to outlive them. Each fold counts the panes in its view from the shared pane frame. A tab that has observed a working pane exits on the first producer-verified zero-sibling fold, while `SELF_CLOSE_EMPTY_CONFIRM` settles only birth/resurrection with no sibling observed yet and any transient under-count in that path. The count reads the producer-verified frame alone: a fused `PaneClosed` overlay deletes its card on the spot but never moves the sibling count, so an exit verdict always rests on a verified frame ([state.md](./state.md#fusion-rules)). Closing the last sibling first grows the sidebar to full width, so a bounded grow-resize hold ([`lifecycle.rs`](../../../crates/rimz/src/sidebar_pane/app/lifecycle.rs)) delays the repaint until a fold carries the sibling-count verdict; a seen-sibling close exits on that fold, and the grow hold suppresses the widened repaint across the brief gap before it. The birth path, with no sibling seen yet, keeps suppressing a widened repaint across the confirm window until a non-empty fold resets it or the confirmed empty fold exits. The grow hold's lost-wakeup ceiling remains `RESIZE_PAINT_HOLD_CEILING` when no empty confirmation is active.

### Reload recovery

The sidebar keeps the last successful snapshot across iterations. When the in-process produce or the heartbeat write fails (a vanished ledger, a dead mux, a transient hiccup) the loop reuses the last good frame and absorbs a single blip silently. Once the failure persists past the debounce it raises a sticky **health alert** pinned to the bottom edge (`! Sidebar degraded for 8s: snapshot failed: ledger not found`), truncating the body before the alert so the notice can never scroll off; on recovery the alert lingers as a dim dismissable notice rather than erasing. A renderer degraded past `GIVE_UP_AFTER_DEGRADED` is non-functional and exits rather than freezing on a stale frame, and reload or attach then rebuilds a current-build sidebar against the live panes. Carried pane truth and gate holds surface as their own dim bottom notices without becoming health failures. The decision logic is the pure `app::compute_next_state` ([`health.rs`](../../../crates/rimz/src/sidebar_pane/app/health.rs)), which folds each fetch outcome into a debounced, sticky `Health`. This is the degraded twin of [self-close](#self-close): self-close fires when the view empties, give-up when the view can no longer be read at all.

## Resume-on-rebirth

When a session dies because the machine rebooted or the mux server crashed, the agent processes are gone but the ledger remembers them. Rimz offers to bring them back: a birth after a reboot or a same-boot crash with positive `agent-lost` markers prompts to recover prior agents as running panes grouped into `#channel` tabs, defaulting yes, so the room comes up where the user left off instead of empty. This is Rimz-owned, transcript-based continuity, deliberately not Zellij session serialization, which resurrects command panes `start_suspended` and so reads as unhealthy. `rimz reset` is a manual fresh start and does not recover agents.

The mechanism is a coroner then a planner, both run before a genuine birth recreates the mux session. The coroner reads the audit projection, subtracts durable ended sessions from the lost set, records `session.death{cause,lost_agents}` when a reboot or lost markers prove death, and archives the crash caches. The planner ([`harness/resume.rs`](../../../crates/rimz/src/harness/resume.rs)) is pure over the durable agent rollup: it keeps each root agent that was bound to a pane in the incarnation that died (its stamp survived the rebirth-boundary clear), collapses a relaunch that reused a pane to its newest stamp, restores named teams in their declared layout, groups other survivors by worktree or named channel as one column, and caps the flat non-team fleet after whole team layouts take priority (`resume.max`, default 128). Each resumed pane runs the supervised exec wrapper with the carried launch identity and then the adapter's resume argv (`claude --resume <id>`, `codex resume <id>`); each missing or unsupported team cell fresh-launches in the matched cwd and channel after the user confirms recovery. Planning runs first, then the confirmed birth materializes fresh team identities and appends the `session.rebirth` boundary that unstamps the prior incarnation's panes, so the plan reads the stamps it keys on and the reborn room starts stamp-free.

The restored agents come back **idle**: `--resume` rehydrates the conversation without a prompt, so no tokens are spent until the user types. Each agent's own `SessionStart` fires with `source: "resume"`, coalescing back onto the same rollup row and re-stamping its new pane, so the row rebinds with no new identity and team members keep their `@role` address. `--no-resume` (or `resume.on_rebirth = false`) opts out for a deliberately fresh start. The planner and its loop scheduling are owned by [harness.md](../agents/harness.md).

## Notifications

Notifications are best-effort polish over the same attention model this doc describes; the ledger stays authoritative. The elected producer opens durable unread episodes, applies `[notifications].triggers`, debounce, and focus suppression, then spawns matching notification handlers and broadcasts `SidebarEvent::Notify`; a renderer re-rings local unread `waiting` and `failed` rows at the configured reminder cadence until they clear. The renderer writes terminal-local OSC and BEL bytes outside the draw cycle. The full contract lives in [notifications.md](./notifications.md).
