# Supervised Runs

`rimz run` launches one interactive agent pane, waits for the agent's root turn to end, prints the final assistant message, and exits with a script-friendly status code.

Hooks supervise the run. A run record is written under `runs/<run_id>.json` before the pane opens, the launched `rimz agents exec` wrapper exports `RIMZ_RUN_ID`, and lifecycle hooks fold matching root-session observations into that record. The wrapper also records its own normalized pane id when the mux exposes one, so cleanup can close the launched pane without waiting for the sidebar snapshot to bind the agent session. The first root `TurnEnded` completes the run as `completed` or `failed`; a session `Ended` before a turn result marks it failed; subagent events and same-kind descendant processes with a different session id are ignored for the run so child completions never finish the parent command. If the wrapper observes the agent process exit and no terminal lifecycle hook lands after a short grace, it writes `failed` and wakes the waiter, making process death a liveness backstop without treating pane exit as success.

The blocking CLI binds `sock/run.<short_id>.sock` before opening the pane. When a hook writes the first terminal run record it sends a `run_completed` wakeup frame to that socket; the record on disk remains truth, and the datagram only cuts latency. If the wait cap expires, the CLI reloads the record once to catch a just-written terminal result, otherwise writes `timed_out` and exits `124`.

Permission posture is adapter-owned. The run command chooses `auto`, `ask`, or `yolo`; adapters translate that into provider CLI arguments. Claude maps `auto` to accepted edits and `yolo` to its dangerous bypass flag. Codex maps `auto` to `--ask-for-approval never --sandbox workspace-write`, leaves `ask` at the provider default, and maps `yolo` to its dangerous approvals-and-sandbox bypass.

Run records are cold-path durable state and use temp-file-plus-rename with fsync through the ledger atomic helpers. `rimz run status <run-id>` and `rimz run list` read the current workspace's retained run records; they report the durable run status and do not fold in the live agent phase from the sidebar snapshot. Records are retained until an operator removes state, so `list` scans the retained JSON files in that workspace.

After a blocking run finishes, pane cleanup is best-effort: Rimz closes the recorded launch pane when available, then falls back to finding the agent row by `(kind, agent_id)` in the snapshot. Detached runs pass cleanup ownership to the in-pane wrapper: unless `--keep` was set, the wrapper watches the run record, terminates the agent process once the run is terminal, performs marked-worktree cleanup, and closes its own pane.
