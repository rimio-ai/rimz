# Codex adapter

> The agent-agnostic boundary, state machine, and context read-path are in [model.md](./model.md); the account, balance, spend, and pricing model is in [providers.md](./providers.md). The raw upstream protocol — the hooks, the `notify` channel, the app-server JSON-RPC API, the rollout JSONL, and the auth file — is in [codex-reference.md](../../externals/agent-adapter/codex-reference.md).

This doc is the single home for everything Codex-specific: the native-event mapping, the daemon-routed launch quirks, the rollout and app-server context read-path, and the account, balance, and spend surfaces.

## Hooks and lifecycle

Native event or derived surface → internal mapping; the upstream events, payloads, and decision schema are in [codex-reference.md](../../externals/agent-adapter/codex-reference.md).

| Native event / surface               | Channel       | `observe_lifecycle` → [`LifecycleSignal`](../../../crates/rimz/src/agents/lifecycle.rs) | Normalized fields                                |
| ------------------------------------ | ------------- | ----------------------------------- | ------------------------------------------------ |
| `SessionStart`                       | lifecycle     | `Registered`; `source = "compact"` maps to `CompactionEnded { auto: None }` | model, effort, root lineage    |
| `UserPromptSubmit`                   | lifecycle     | `TurnStarted`                       | root prompt, or child progress when `agent_id` is distinct |
| `SubagentStart`                      | lifecycle     | `SubagentStarted`                   | child id plus rollout nickname/path/role/model/context |
| `SubagentStop`                       | lifecycle     | `SubagentStopped { errored }`       | child rollout error marker decides the verdict |
| `Stop`                               | lifecycle / awaiting-user | `AwaitingInput { PlanApproval }` when the resting rollout carries a same-turn `Plan` item; otherwise `TurnEnded { errored, parked_on_background: false }` | plan detail or clear task; refresh context/tokens; merge rollout markers |
| `PermissionRequest`                  | awaiting-user | `AwaitingInput { Permission }` → `waiting` | —                                          |
| `PreToolUse: request_user_input`     | awaiting-user | `AwaitingInput { Question }` → `waiting`   | user question                              |
| `PostToolUse`                        | lifecycle     | `ToolUsed { mutates, edits }` for every observed tool completion | `edits` for `apply_patch`; non-mutating completions use proof-of-work persistence, including answered asks |
| `PreToolUse` (other observed tools)  | lifecycle     | `ToolUsed { mutates: false, edits: false }` as proof-of-work only | persisted when it reconciles a resting row, clears waiting, or closes a compaction bracket |
| `PreCompact`                         | lifecycle     | `Compacting`                        | stamps the head                                  |
| `PostCompact`                        | lifecycle     | `CompactionEnded` with known trigger | safely redundant as a close; carries the auto/manual trigger bit |
| pane liveness + rollup reaper        | derived       | durable end stamp and runtime hiding for the hooks matrix `ended` row | gap: no `SessionEnd` hook; hidden after liveness convergence, not at session exit |

`request_user_input` self-classifies from `tool_name` on the broad `PreToolUse` hook. RimZ parses its question ids, headings, labels, and descriptions into structured ask options; its own non-mutating `PostToolUse` records the id-keyed native answers and clears waiting. `update_plan` remains a non-blocking todo tracker. Plan mode has a separate client-side approval gate: a `Stop` resting on a rollout `Plan` item records `AwaitingInput { PlanApproval }`, while every other non-question `PreToolUse` remains lifecycle proof-of-work only.

Codex provider-error evidence comes from the rollout tail. RimZ checks explicit error records on `Stop`; the stat-gated local refresh also checks the resting tail, so a provider-killed turn that writes no `Stop` still publishes `AgentContext.turn_error`. Timestamped rollout error records and the resting message-less `task_complete` shape write the marker, while newer live rollout records clear it. Explicit error evidence marks the `TurnEnded` lifecycle signal errored so a provider-killed `Stop` never reduces as success. The row then pauses or fails through the shared display projection ([Turn-death marker](#turn-death-marker)). Token and cost enrichment still refreshes on `SessionStart`, `UserPromptSubmit`, `PostToolUse`, and `Stop` through the stat-gated local context path. Codex's hook coverage is a progress signal rather than an enforcement boundary: upstream currently intercepts simple shell calls, `apply_patch`, and MCP calls, while unified-exec, web search, and other tool paths can bypass `PreToolUse`/`PostToolUse`.

Codex shares the same keyed subagent identity as Claude (`resolve_subagent_identity`): a child hook needs a non-empty `agent_id` distinct from the root `session_id`, and a malformed `SubagentStart`/`SubagentStop` is quarantined rather than folded onto the parent. Codex 0.144.4 supplies that optional identity on `UserPromptSubmit`, `PreToolUse`, `PermissionRequest`, `PostToolUse`, `PreCompact`, and `PostCompact`, so each updates the durable child row and its heartbeat. The hook-reported root remains `parent_agent_id` for every descendant; rollout `parent_thread_id` is immediate-lineage metadata only. Codex child hooks bypass root `AgentContext` merging and detached app-server refresh, preventing the root session id and parent rollout from contaminating the child. Codex has no `SessionEnd` or `Notification` hook, so `ends_session` is never true and liveness drives the reaper's durable end stamp while runtime views hide the row (see [model.md](./model.md#liveness-and-presence)). It has no background-task parking, so `parked_on_background` is always `false`.

**Neutral output.** Codex's neutral path is empty stdout. Permission and user-input prompts remain in Codex's own UI, and the sidebar's `?` row routes you there.

**Structured answers.** `rimz answer` drives the verified Codex 0.144.3 subset: `implement` presses Enter on the plan selector's default “Yes, implement this plan” row, and one option per `request_user_input` question moves down from the default first row before Enter commits and advances; the last question submits. Multi-select, custom free-text options, refinement text, alternate plan actions, and permission decisions stay in the Codex pane. A native `PostToolUse` answers-map closes a question ask with the selected labels, and the next `UserPromptSubmit` closes a plan ask with the submitted prompt.

**Timeout & install.** Installed ask hooks use the short lifecycle timeout because they record the waiting observation and return neutral. Install writes inline `[[hooks.Event]]` tables in `~/.codex/config.toml` with the same `--event`-free command and substring reclaim as Claude; the legacy `[hooks.rimz]` table is ignored by Codex and removed on uninstall. Codex gates installed hooks behind its own per-hash trust state and **silently skips** an untrusted hook ([codex-reference.md → Trust state](../../externals/agent-adapter/codex-reference.md#trust-state)) — only the user can open the channel (`/hooks` inside Codex), so the adapter reports installed-but-untrusted events (`untrusted_installed_hooks`) and `rimz start`/`rimz doctor` surface the fix.

**Subagents.** Hooks remain lifecycle authority. The child rollout header is best-effort keyed enrichment: `agent_nickname` supplies the display name, `/root/` is removed from the canonical `agent_path` while deeper hierarchy remains, and `agent_role` falls back to hook `agent_type`. Without a readable matching header, V1 `agent_type` remains the display/task fallback. Descendants stay flat under the root card in creation order, with the relative path carrying nesting context. Any live descendant projects an otherwise clean idle, successful, or running root back to running/delegating; native asks, budget parks, pauses, and failures remain higher precedence, and the durable resting status returns after the final child stops.

**Compaction.** Claude and Codex both use `PreCompact` as the bracket opener. `PostCompact` closes the bracket when it arrives and carries the auto/manual trigger split described in [model.md](./model.md#the-compaction-bracket). `SessionStart` with `source = "compact"` is triggerless close evidence, so a missed `PostCompact` still closes and counts the bracket, while a duplicate `PostCompact`/`SessionStart(compact)` pair counts once.

### Session registration and launch quirks

Codex registers its session lazily. A plain CLI launch fires no `SessionStart`; the first prompt fires `SessionStart` and `UserPromptSubmit` together, both carrying the session id. So a freshly launched Codex is an agent instance with no session id until its first turn, which is why the sidebar synthesizes an idle row for it ([agent.md → The instance lifecycle](./model.md#the-instance-lifecycle)). Codex 0.144.5 also fires `SessionStart` on `/clear` / `/new`, creating a pane-less registered record before the new conversation's first prompt.

RimZ reads each root's rollout `session_meta` on identity events and carries its lineage durably on the rollup: `forked_from_id = null` is a fresh `/clear` / `/new` conversation, a populated `forked_from_id` is a fork, and an unreadable head stays unknown. On the first post-clear prompt, daemon-routed recovery stamps the new fresh root onto the focused occupied Codex pane or, without focus evidence, the sole occupied pane whose fresh owner is at rest. The incoming id may be unknown or known only through a pane-less registration record that has never opened a turn; both remain eligible at the first turn start. That durable dual stamp lets `cleared_conversation_supersedes` reap the older same-pane fresh root, so every consumer — sidebar, message delivery, and CLI — sees only the fresh conversation. A same-pane newer root with `forked_from_id` is a fork and stays subordinate to the primary. When `/clear` interrupts a running turn before the fresh root registers, the interrupted-turn marker below settles the old root to idle so queued messages do not wait forever on a missing `Stop`.

A `/side` / `/btw` thread fork registers a **fresh** session id in the same pane and `codex` process while the main session stays live. The pane's card stays pinned to the primary (earliest-`registered_at`) session, so the fork's newer activity never repaints it; the fork is not rendered ([sidebar.md → Presence model](../sidebar/sidebar.md#presence-model)) and is not nested as a child row.

Codex hooks are **daemon-routed** (since 0.137 for a plain TUI launch, not just under `codex remote-control start`): they fire from the shared per-user app-server daemon with the session cwd as working directory, `RIMZ_AGENT_PID` as the daemon pid, and the **daemon's environment**. Any ambient workspace or pane pin therefore names the daemon's launch room or pane rather than the session's; `rimz hooks feed` classifies that owner as a daemon, drops both ambient pins, recovers the workspace from the in-pane `codex` process at the same cwd, and keeps the session pane unstamped until focused-pane recovery binds it ([agent.md → Hooks resolve the room they live in](./model.md#hooks-resolve-the-room-they-live-in)). A same-kind provisional launch stamp leaves that pane eligible for recovery: the recovered pane id lets the reducer adopt the launch placeholder on first registration, or release a leftover placeholder when a pre-fix split session reports a later stamped turn. Binding an unstamped in-pane session stamps the full `PaneRef` and re-owns runtime liveness to the in-pane CLI process; an unbound daemon-owned session falls to the ghost TTL, with `thread/loaded/list` as a faster keep/drop signal. A relaunched `codex` in a reused cwd starts fresh because both the CLI owner and the pane-start guard point at the new in-pane CLI. A session with no local pane is a *remote* agent, not rendered yet (same section).

### Local session discovery

Codex local-session discovery reads the first `session_meta` line from recent rollout files under `CODEX_HOME` or `~/.codex`. The elected room producer makes one discovery call for the exact admitted Codex workspaces and distributes the normalized observations through `local-sessions.json`; consumer folds never enumerate the rollout store. One discovery call enumerates the shared active and archived rollout trees once for every requested absolute workspace, then admits a parsed session only when its payload `cwd` exactly matches that workspace set. Active rollouts come from `sessions/YYYY/MM/DD/` newest date first; archived rollouts are flat files under `archived_sessions/` ordered by the timestamp in `rollout-<timestamp>-<uuid>.jsonl`. The payload `id` supplies session identity with the filename UUID as fallback, the header timestamp supplies creation time, and file mtime supplies last activity. A header with `thread_source = "subagent"` or structured `source.subagent.thread_spawn` is excluded before it can bind to a pane; `forked_from_id` alone does not exclude user-created forks.

One scan examines at most 512 rollout files and stops before active date directories or archived filename dates older than 14 days. Active storage wins when the same session also has an archived twin. These bounds keep provider fallback and lazy pane binding independent of a user's full Codex history. Discovery observations are identity-only: rollout creation and mtime bound resume clustering and safe pane binding, while hooks remain authoritative for lifecycle state, prompts, waits, routable asks, compaction, context, and clocks on an exact durable session.

## Context and transcript

Codex writes one rollout file per session at `~/.codex/sessions/YYYY/MM/DD/rollout-*-<session_id>.jsonl` and moves archived rollouts into the flat sibling `~/.codex/archived_sessions/` directory. A root hook accepts its `transcript_path` or searches by root `session_id`. A child accepts native `agent_transcript_path`; a common `transcript_path` is accepted only when the header id matches the child, then lookup falls back by child `agent_id` without ever searching through the root id. Header enrichment is applied only when its id matches the child. The rollout head feeds root lineage and child display metadata; the bounded tail feeds usage, model, effort, and stop-error enrichment:

| Rollout event   | Field                                          | Internal                                  |
| --------------- | ---------------------------------------------- | ----------------------------------------- |
| `token_count`   | `payload.info.last_token_usage.input_tokens` / `payload.info.model_context_window` | `context_pct` (input × 100 ÷ window, clamped) |
| `token_count`   | `payload.info.last_token_usage.total_tokens`   | `total_tokens`                            |
| `token_count`   | `payload.info.last_token_usage.cached_input_tokens` | `cache_read_input_tokens` (the card's `◌`) |
| `token_count`   | `payload.info.last_token_usage.input_tokens − cached_input_tokens` | `fresh_input_tokens` (the card's `↘`; `input_tokens` includes the cached slice) |
| `token_count`   | `payload.info.last_token_usage.output_tokens`  | `output_tokens` (the card's `↗`)          |
| `token_count`   | consecutive `payload.info.total_token_usage` deltas across the rollout | `cost` (per-request price fold, resumed from the context sidecar cursor) |
| `turn_context`  | `payload.model`                                | `model` (display name)                    |
| `turn_context`  | `payload.effort`                               | `effort` (live reasoning effort)          |
| `item_completed` + clean `task_complete` | same-turn `item.type = "Plan"`, non-empty `item.text` | plan approval ask / `plan_proposed` backstop |

Unlike Claude — which stores raw tokens and derives the window from the payload model — Codex carries `model_context_window` directly and the projection derives occupancy from the current call/context reading. For a child, `last_token_usage.total_tokens` is displayed as current context usage; `total_token_usage` includes copied parent history and therefore never becomes child lifetime usage or cumulative child spend.

The adapter's `parse_transcript_messages` function is the single conversation parser for Codex rollouts. It reads `event_msg` / `user_message` prompts and `event_msg` / `agent_message` assistant text with their top-level timestamps; `stream_assistant_messages` filters that normalized parse and continues to ignore duplicate `response_item` rows.

**Rich context.** Codex has no statusline, so its `AgentContext` is split. The rollout local read owns the live per-session usage fields (`tokens`, context percentage/window, cumulative `cost`, and the observed reasoning effort from the latest `turn_context`; a tail that misses `turn_context` carries effort forward from the sidecar). Cost uses the same per-request delta parser as the history walk: the first refresh folds the whole rollout, then a byte cursor and opaque parser state ride the context sidecar so later refreshes price only appended requests. An unknown model contributes zero until the history walk's price-resolution cold reparse heals the durable tally. `rimz hooks feed` attempts a local refresh inline on `SessionStart`, `UserPromptSubmit`, `PostToolUse`, and `Stop`, but only after the hook's decision channel is irrelevant and only when the stat gate says the rollout changed. The hidden `rimz codex refresh-context` helper performs the same local merge before any app-server work, the elder renderer's transcript watcher fires the refresh on the rollout write itself so mid-turn growth lands without waiting for a hook ([state.md → Push Channels](../sidebar/state.md#push-channels)), and the elected snapshot producer runs an in-process stat-gated backstop for visible root Codex rows. All four write the same runtime sidecar and wake the sidebar; none touches the durable store.

The official `codex app-server` (JSON-RPC 2.0 over stdio) owns the fields the rollout does not: rate-limit windows, account plan, model display name, thread preview/name, and agent version. The client speaks only **read-only, non-interfering** methods — the handshake, the rate-limit read, the model list, and stored-thread summary reads (`thread/read`, with `thread/list` as the preview/name fallback; the methods and their response schemas are in [codex-reference.md → App-server API](../../externals/agent-adapter/codex-reference.md#app-server-api)). It never calls `thread/resume`, `turn/start`, or any write, which would rejoin and own the user's live thread. `model/list.defaultReasoningEffort` is deliberately ignored for the row because it is a catalog recommendation/default, not the current session's configured effort.

The app-server trigger is never inline: a turn-boundary hook spawns `rimz codex refresh-context` detached with null stdio, so the hook returns before the round-trip and adds no latency. The helper throttles app-server-owned fields by their own `rate_limits_observed_at` stamp, so a fresh transcript/cost merge never suppresses a due account refresh and an app-server retry never suppresses local usage. The producer also keeps the account-scoped balance windows fresh between turns on a bounded cadence — the rate-limit refresh logic and OAuth usage cadence live in [Account and balance](#account-and-balance) below. `RIMZ_CODEX_BIN` overrides the binary for tests. Connection preference is warmest-first, all best-effort with a cold-spawn floor so enrichment never depends on any one of them:

1. **The per-session broker** ([`broker.rs`](../../../crates/rimz/src/agents/codex/broker.rs), run as `rimz codex app-server serve` in the `rimzd` daemon tab) holds one warm, already-handshaked `codex app-server` and serves it over a unix socket, so each datapoint skips the cold handshake.
2. **The per-user remote-control daemon**, re-used by opening its WebSocket control socket directly (overridable by `RIMZ_CODEX_APP_SERVER_SOCK`).
3. **A fresh cold-spawned `codex app-server`** — the always-present fallback, so headless / no-mux still enriches.

[`codex/app_server/daemon.rs`](../../../crates/rimz/src/agents/codex/app_server/daemon.rs) owns the managed remote-control daemon protocol: standalone-install readiness and guidance, start/stop commands, liveness, and tightly verified stale-updater recovery. It also detects updater version skew for `rimz doctor` as an advisory only when the control socket exists, the updater PID still matches its recorded process identity, and its executable differs from the managed standalone target. `reconcile` retries one failed start after a settle delay to absorb the upstream stop→start teardown race. Room birth and runtime toggles call that provider module directly; the root remote-control module coordinates its result with room and sidebar effects.

The one datapoint the app-server does **not** expose read-only is token / context-window usage: it rides only the live `thread/tokenUsage/updated` notification behind a subscribing `thread/resume`. RimZ therefore treats the rollout as authoritative for live Codex usage, including the `AgentContext.tokens` value the card reads; app-server unavailability can stale rate limits, display-name metadata, or the thread preview/name, but it cannot stall the context meter, token composition, or per-session cost.

### Plan-approval marker

Codex plan mode ends a planning turn with an `item_completed` record whose item is a non-empty `Plan`, followed by a clean same-turn `task_complete`; the plan body is absent from `last_agent_message`. [`detect_plan_proposed`](../../../crates/rimz/src/agents/codex/transcript.rs) matches those turn ids in the bounded tail. On `Stop`, that evidence replaces the normal `TurnEnded` signal with `AwaitingInput { PlanApproval }`, so the existing ask feed persists the plan and a supervised `-p` run waits rather than completing with an empty final message. `UserPromptSubmit` starts the selected implementation or continued-planning turn and clears the ask.

The stat-gated local refresh stamps `AgentContext.plan_proposed` with the completing record's timestamp and suppresses `turn_complete` for the same tail. This is the missed-`Stop` backstop: while the marker postdates `last_activity`, a falsely-`running` row projects to `waiting`, which keeps message delivery out of the selector. Enrichment does not invent a durable ask when the hook was missed. A newer live record clears the marker. Leaving Plan mode with Shift+Tab without submitting a prompt can leave the durable ask open until the next hook, matching the native-prompt dismissal gap on other adapters.

### Turn-death marker

Codex writes most provider-error evidence to the rollout tail, which is the local death certificate for RimZ's non-interfering read path. On `Stop`, [`detect_turn_error`](../../../crates/rimz/src/agents/codex/transcript.rs) scans the bounded tail newest-first. A newer live record (`agent_message`, `task_started`, `user_message`, or `turn_context`) clears the check; `token_count` is usage evidence, not recovery evidence. A timestamped `event_msg` error record (`turn_error`, `stream_error`, `error`, or `task_complete` carrying `error`) or schema-shaped `ErrorNotification` error object emits `AgentContext.turn_error` with `at`, a capped label, and a `class`. The detector maps Codex's app-server `codexErrorInfo` vocabulary first (`usageLimitExceeded` → `PausedRateLimit`, `serverOverloaded` and `internalServerError` → `PausedOverloaded`, other known variants → `Failed`), then falls back to label keywords: "spend limit" pauses for `PausedSpendLimit`; "usage limit", "session limit", "rate limit", "quota", or "too many requests" pause for rate limit; "overloaded", "at capacity", "server is busy", "server error", "internal server error", "service unavailable", "bad gateway", "gateway timeout", "stalled", "timed out", "timeout", "connection error", or "network error" pauses for the backoff class; everything else fails. On `Stop`, the same marker also makes the lifecycle turn end as errored, preventing a native clean Stop from painting a provider-killed turn as success. The projection in [agent.md → Displayed status](./model.md#displayed-status) uses the marker to choose paused or failed for the row.

Codex 0.142.x can end a turn on provider capacity or usage limits with no rollout error record, no `Stop` hook, and no app-server error field: the rollout rests on a clean-looking `task_complete` whose `last_agent_message` is null or empty, while the warning is rendered only in the TUI. The local refresh path treats that resting shape as `Unknown` with the generic label `turn ended with no final message`; a later `task_started` from compaction or a new prompt clears it before it can stamp. When the marker is generic, the producer backstop and hidden `rimz codex refresh-context` helper run a two-rung confirmation ladder. First, a bound live pane gets one bounded capture, and RimZ scans the frame above the input prompt bottom-up: keyword-proven pause classes win, while the nearest unrecognized `⚠` banner is adopted as a conservative `Failed` label so the upstream reason remains visible. Continuation text is copied only from the selected block. Second, if pane proof is absent or inconclusive, the helper reads the fused account budget and infers `PausedRateLimit` only when a subscription window is spent and has a future reset. The producer re-runs this ladder on each tick while the marker remains generic and is younger than ten minutes; the first successful refinement stops the retries. Explicit rollout errors never use pane confirmation because the upstream text already names the failure. `rimz agents refresh @codex` remains the manual re-run for markers older than the retry window.

### Turn-completion marker

A turn that finished without a `Stop` hook resolves from the rollout tail too — the success twin of the death certificate. Codex's `/review` runs in review mode (`entered_review_mode`/`exited_review_mode`) and closes on a clean `task_complete` while firing no `Stop`, so the lifecycle state machine never leaves `running`. [`detect_turn_complete`](../../../crates/rimz/src/agents/codex/transcript.rs) scans the bounded tail newest-first through the stat-gated local refresh ([`refresh_transcript_context`](../../../crates/rimz/src/agents/codex/transcript.rs)): when the session is at rest on a clean `task_complete` — no later `user_message`/`task_started`, no `error` field at all, and a non-empty `last_agent_message` string — it stamps `AgentContext.turn_complete` with that record's timestamp, and the projection settles the falsely-`running` row to `success`. The clean shape is strict: an errored `task_complete` stays the turn-death marker's, an ambiguous empty `error` (`null`/`false`/`""`/`{}`) settles nothing, and a clean-looking task complete with no final assistant message is the capacity-kill death shape above. The marker postdates `last_activity` and self-clears the same way as the death marker — a newer prompt advances `last_activity` past it and the row drops back to its lifecycle status.

A turn that completed before this detector shipped does not re-settle on its own: the stat gate skips the tail read while the rollout is unchanged, so an already-stuck `/review` row recovers only on its next rollout write (a new turn) or a one-off nudge (clearing its context sidecar). New review turns settle automatically — their `task_complete` write advances the stat and triggers the scan.

### Turn-interruption marker

A turn that was interrupted without a `Stop` hook resolves from the rollout tail as the idle sibling of completion. Codex writes `event_msg` / `turn_aborted` when Esc aborts a turn and when `/clear` interrupts a running turn; the payload may carry `reason: "interrupted"`, but RimZ accepts any reason because the operative condition is that the abort rests at the tail. [`detect_turn_interrupted`](../../../crates/rimz/src/agents/codex/transcript.rs) stamps `AgentContext.turn_interrupted` with the abort record's timestamp, and the projection settles the falsely-`running` row to `idle` while the marker postdates `last_activity`. A later `user_message`, `task_started`, `agent_message`, or `turn_context` means the session is live again and clears the marker the same way as turn completion and turn death. A steer-replaced abort is followed by new live rollout records, so it does not stay settled.

A turn that was interrupted before this detector shipped does not re-settle on its own: the stat gate skips the unchanged rollout, so an already-stuck row recovers only on its next rollout write or a one-off context-sidecar nudge. New interruptions settle automatically — their `turn_aborted` write advances the stat and triggers the scan.

## Account and balance

Live account identity comes from [`account/rateLimits/read`](../../externals/agent-adapter/codex-reference.md#app-server-api) `planType` → `plan`, riding `AgentContext.account`. Idle: a file-backed [`~/.codex/auth.json`](../../externals/agent-adapter/codex-reference.md#auth-file) maps API key → unmetered by subscription windows and `tokens` → metered ChatGPT, while the explicit trimmed `tokens.account_id` fills `AgentAccount.account_id` and cache ownership; when Codex stores credentials in the OS keyring, `codex login status` supplies the same metered/unmetered distinction. The OAuth usage response's `plan_type` and the app-server's `planType` persist in `credits.json` when no live session reports a plan; a present realtime plan wins, while an absent one preserves the OAuth label for idle and keyring-backed display.

Balance comes primarily from [`account/rateLimits/read`](../../externals/agent-adapter/codex-reference.md#app-server-api) `primary`/`secondary` windows, each with `windowDurationMins` ([`app_server.rs`](../../../crates/rimz/src/agents/codex/app_server.rs)). App-server and OAuth transports parse their wire fields into [`codex/account.rs`](../../../crates/rimz/src/agents/codex/account.rs), which owns plan trimming, percentage clamping, short-to-long ordering, dynamic durations, numeric/string credit balance cleanup, and the authoritative lifted 5h row when a nonempty temporal Codex/OpenAI reading omits a real 5h row. Optional `credits` fields map `overageLimitReached` to exhausted, `unlimited` to usable unknown balance, numeric/string `balance` to `ExtraCredits::Known { remaining_usd }`, and `hasCredits: false` to `ExtraCredits::Disabled`, then cache with `planType` in `credits.json`. Reset-credit wire parsing stays transport-local; available count and earliest available expiry feed the dashboard's `↻ N` marker. The direct probe reads file-backed `~/.codex/auth.json`, returns the exact `tokens.account_id` used for the request with the normalized snapshot, and best-effort reads the sibling reset-credit endpoint with the same token. Codex uses the app-server as the low-latency realtime account surface and the direct OAuth endpoint as a second authoritative cadence when a file token is available. The account/balance model these fields fold into is [providers.md](./providers.md).

**Refresh cadence.** Codex keeps its included balance current without a live turn through the read-only app-server path: active root session sidecars refresh at most once per 60 s, so a long turn's windows stay fresh. Active-session retries are throttled by per-session stamps in runtime `shared/`; stale stamps self-reap after the short Codex TTL so ended sessions do not accumulate files. The per-session broker compares `~/.codex/auth.json`'s modification stamp before each child round-trip and respawns its held `codex app-server` child when the auth file changes. The producer's uniform `rimz agents refresh-usage --kind codex` helper also runs for metered Codex accounts on `OAUTH_USAGE_TTL` regardless of a live root session, claims the read in `credits.json`, reads the app-server/realtime account surface first, then runs the direct OAuth usage endpoint when `RIMZ_OAUTH_USAGE_OFFLINE` is unset. Realtime writes preserve the direct attempt and claim, an account-id change drops cached windows and refetches immediately, and a detected budget-reset epoch invalidates the attempt and claim for an immediate re-probe.

The account probe reads `~/.codex/auth.json` first. A missing file falls back to `codex login status` for keyring storage; an unreadable file or unrecognized command response is retry-worthy `Unavailable`, while a readable file with no credential and the command's `Not logged in` response are authoritative `LoggedOut`. The arms and TTLs are [provider.md → The out-of-band probe](./providers.md#the-out-of-band-probe).

## Cost

Codex's full-history spend is parsed by [`codex/spend.rs`](../../../crates/rimz/src/agents/codex/spend.rs), read-only and sidebar-safe, aggregated by the [`SpendingWalker`](../../../crates/rimz/src/agents/spending/mod.rs) into the configured headline window plus trailing 7d / 30d / 365d windows ([provider.md → Cost history](./providers.md#cost-history)). Discovery walks both `~/.codex/sessions/` and `~/.codex/archived_sessions/`; an active rollout wins when both trees retain the same relative file, so archiving preserves history without double-counting the move. Forked and subagent rollouts begin with a timestamp-collapsed replay of their parent's cumulative history, so the parser suppresses that prefix while retaining its last cumulative total as the baseline for the first new delta. A provider-namespaced fingerprint over the native timestamp, model, and token split also collapses copied events across distinct files while preserving events that differ at subsecond precision. Because Codex logs token counts, the spending walk multiplies each [`CodexTokenEvent`](../../../crates/rimz/src/agents/codex/spend.rs) through the per-model [pricing table](./providers.md#token-pricing): uncached input at the input rate, the cached slice at the model's cache-read rate when that rate is explicit and at the input rate otherwise (a Codex model without a discounted cache-read rate does not discount cached tokens), and output (which already includes reasoning tokens) at the output rate. `gpt-5` is the parser's fallback model, so a Codex event with no resolvable model still prices — and `gpt-5` is mandatory in the pricing builtins for exactly that reason. A turn whose model has no known price keeps its tokens and session with zero dollars while the pricing chase looks for a price.
