# Antigravity adapter

This page maps the Antigravity CLI (`agy`) onto RimZ's types: launch and resume, the hooks RimZ installs, session discovery from the provider's local store, the transcript, subagents, statusline context, the account, and cost. The provider-neutral agent model is in [model.md](./model.md), the integration layer in [adapter.md](./adapter.md), and pane binding and supersession in [instances.md](./instances.md). Accounts and balances are in [providers.md](./providers.md), spend and pricing in [spending.md](./spending.md). The upstream protocol, pinned at `agy` 1.5.14 with transcript and subagent captures from 1.1.2, plugin and `/usage` captures from 1.5.12, custom-agent and `/compact` captures from 1.5.13, permission, sandbox, and MCP captures from 1.5.14, workspace-trust, outside-workspace `write_file`, and routine `command(<prefix>)` captures from 1.5.16, and terminal-sandbox Git-directory `read_file` captures from 1.5.17, is in [antigravity-reference.md](../../externals/agent-adapter/antigravity-reference.md).

Antigravity reaches RimZ through four sources, and each owns different facts. Command hooks carry turn boundaries and tool progress. The custom statusline carries the live model, account, and context gauge. The provider's local `brain/` store carries conversation identity, history, priced spend, and native questions between hooks. The statusline and a print-mode `agy -p /usage` run both carry the quota. RimZ installs no `PreToolUse` hook. On agy 1.5.14 an `allow` answer left the native permission prompt in place, but an empty or failed reply denies the tool, so every tool call would wait on RimZ's hook for a start signal the transcript and `PostToolUse` already give; file-edit prompts and auto mode are uncaptured ([reference](../../externals/agent-adapter/antigravity-reference.md#decisions)).

## Launch and resume

The launch spec maps RimZ's launch inputs onto `agy` flags:

| Input | Argv |
| --- | --- |
| fresh launch | `agy` |
| startup prompt | `agy --prompt-interactive <prompt>` |
| profile `model` | `--model <model>`, a catalog short name as its `gemini-` ID |
| profile `effort` | `--effort <effort>`, from `low`, `medium`, `high`, and `xhigh` |
| permission `ask` | `--settings {"agentMode":""}`, merged into the launch's one `--settings` |
| permission `auto` | `--mode auto` |
| permission `plan` | `--mode plan` |
| permission `yolo` | `--dangerously-skip-permissions` |
| exact resume | `agy --conversation <id>` |
| definition `allowed-tools` | one `--settings` whose `permissions.allow` holds the [translated rules](#permission-rules-sandbox-and-added-dirs) |
| routine RimZ commands and served MCP (`allow-routine-rimz` on) | `command(<prefix>)` for every entry of `ROUTINE_RIMZ_PREFIXES`, and `mcp(rimz_tools/*)` when RimZ's MCP server is served, in the same `--settings` `permissions.allow` |
| `sandbox` isolation | `--sandbox` |
| added directory | `--add-dir <dir>`, once per directory |
| profile system prompt, fresh launch | `--agent rimz-<label>-<hash>` after the rest of the argv, selecting [the agent file](#the-agent-file) |

The 1.3.3 CLI accepts `low`, `medium`, `high`, `xhigh`, and `max` for `--effort` ([reference](../../externals/agent-adapter/antigravity-reference.md#flags)), but agy 1.5.13 refuses `max` on every model and takes a per-model subset of the rest: hydrogen and neon take `low` to `xhigh`, carbon, argon, flash, and `claude-` IDs `low` to `high`. The adapter declares no version floor, so an older `agy` that lacks the flag rejects a profile that sets effort at its own startup.

`crates/rimz/src/agents/adapters/antigravity/mod.rs::MODELS` is the one table of Gemini model facts: each short name, its base ID, its default effort (`high`), and the level `max` launches at. The three Orchestrator IDs (`gemini-pro-orchestrator-neon`, `gemini-pro-orchestrator`, `gemini-pro-orchestrator-argon`) are rows with no short name, no default effort, and `takes_effort: false`: agy 1.5.14 refuses `--effort` with them in print mode and runs Gemini 4 Neon (High) instead in the TUI ([reference](../../externals/agent-adapter/antigravity-reference.md#models)), so `LaunchSpec::drop_refused_effort` skips any effort for them, `max` included, with a `SkippedField` warning, and the launch record carries none. It runs only where the final model is known (`crates/rimz/src/harness/plan.rs::normalize_cell_preset` and `crates/rimz/src/harness/plan.rs::apply_preset_args`): a profile renders its effort beside an Orchestrator ID and validates it against the level list, so a `--model`, `--tier`, or `--agent` override to a model that takes effort keeps it, and `crates/rimz/src/harness/plan.rs::settle_effort_arg` removes the rendered arg when the ID stays. agy knows no short name, so `AntigravityAdapter::resolve_model_alias` rewrites one to its ID at fresh launch, below a machine pin. RimZ sends a base ID plus `--effort`, and sets no kind-wide default effort, because agy exits on an effort-suffixed ID (`gemini-4-hydrogen-high`) beside a differing `--effort`: an uncataloged or suffixed ID launches as written. The effort matcher refuses a level outside `low` to `xhigh` at launch, naming the levels. `crates/rimz/src/agents/definition.rs::LaunchSpec::lower_max_effort` launches `max` at the entry's level, `high` for a `claude-` ID (the ceiling beside that prefix in `foreign_prefixes`), or `xhigh` for another ID outside the catalog, with a `SkippedField` warning. `crates/rimz/src/harness/plan.rs::finalize_agent_cell` settles `max` and the built-in default for the launch's final model, a `--model` override or a machine pin included, and re-renders the one `--effort` arg to match. A level the model lacks within that list is left to agy's own refusal. The `gemini-` prefix routes a definition to Antigravity; a `claude-` ID runs here only under `agent: antigravity` or `agent: agy` (`DefinitionSpec::foreign_prefixes`). Under `yolo`, implementation-plan approval still follows the user's `artifactReviewPolicy`, which RimZ leaves untouched ([reference](../../externals/agent-adapter/antigravity-reference.md#execution-modes)).

Resume takes a conversation id only when `session.rs::valid_conversation_id` accepts it: nonblank after trimming, at most 256 bytes, not `.` or `..`, no leading `-`, and no control character, `/`, or `\`. The same rule gates every path built from an id. On a live pane, `session.rs::resumed_session_id` reads the first `--conversation <id>` or `--conversation=<id>` after a program whose basename is `agy`. `-c` and `--continue` resume the workspace's latest conversation, so they prove no exact identity and bind nothing. The process matcher (`process_names`, `bin_names`) recognizes only `agy`, so the desktop app's `antigravity` processes stay outside this adapter.

Some launch inputs have no Antigravity channel:

| Input | Behaviour |
| --- | --- |
| `rimz agents fork` | unsupported: native `/fork` switches identity inside the TUI and has no source-id launch flag ([reference](../../externals/agent-adapter/antigravity-reference.md#fork-rewind-and-clear)) |

### Permission rules, sandbox, and added dirs

`permissions.rs::translate` maps each `allowed-tools` rule into agy's grammar by the table in [definitions.md](../../reference/definitions.md#tools-to-provider-arguments), and `permissions.rs::render` unions the results into `permissions.allow` through `crates/rimz/src/agents/launch_settings.rs::merge_settings`, the merge Claude uses. agy keeps only the last `--settings` ([reference](../../externals/agent-adapter/antigravity-reference.md#permission-resources)), so a profile's own `--settings`, inline or a file, merges into the one RimZ emits; a file source becomes a private `settings.<digest>.json` artifact, and a malformed or non-object source fails the launch. A source led by one UTF-8 byte order mark reads as the JSON behind it, and an inline value with the mark before its brace is still inline. A `--settings` `permissions.allow` replaces the account's saved global allow list for the session, while saved global and project deny rules stay in force, so `folder_trust.rs::bridge` (`LaunchCapability::bridge_saved_settings_args`) unconditionally unions the login's saved `permissions.allow` rules into the launch's one `--settings` document from the same read as workspace trust. `permissions.rs::render` emits nothing for a list with no translatable rule, while every launch with room roots or saved allow rules still carries its `permissions.allow` in that one document. A rule with no translation never reaches agy, which accepts any rule string and matches nothing; `rimz agents validate` and the launch both name it, because both ask `ToolRules::untranslated` the same `translate`. The argv is recompiled on every launch, so a resume carries the rules again, which agy needs.

The modes rest on a capture of agy 1.5.14 ([reference](../../externals/agent-adapter/antigravity-reference.md#execution-modes)). With no mode argument agy starts in Auto, so `ask` pins Default, which asks before a write or a command, with an empty `agentMode`. `crates/rimz/src/agents/adapters/antigravity/permissions.rs::pin_modes`, through `LaunchCapability::fold_permission_settings`, takes the pin's own `--settings` out of argv and merges `"agentMode": ""` into the last remaining `--settings` (a profile's own, or an empty object) before any other settings contribution, so the ask launch carries one document and the pin wins over a profile's `agentMode`. Every launch, whatever its mode, merges `"queuedMessages": "queue"` into that same document, over a profile's own value, since message delivery queues with Enter and sends now with Alt+M, two keys a `send-immediately` setting swaps. The pin wins over `--mode` too, and a resume recompiles it, which agy needs since a resumed conversation takes its mode from the new argv. `auto`, `plan`, and `yolo` write no `agentMode`. `yolo` passes the skip flag alone: beside it a `--mode` changed nothing observed. Under `auto`, agy's reviewer model can clear a command to run outside agy's terminal sandbox without asking, also under `--sandbox`. Sandbox isolation adds no RimZ mount view, so there nothing bounds a command the reviewer cleared; under scoped isolation RimZ's view still confines it. Where agy offers no Auto, `--mode auto` falls back to Default. A saved `toolPermission: strict` outranks Auto and still asks before edits, and RimZ reads no saved agy setting to say so.

`allow_routine_rimz_args` calls `crates/rimz/src/agents/adapters/antigravity/permissions.rs::allow_routine_rimz`, which unions `command(<prefix>)` for every entry of `crates/rimz/src/agents/mod.rs::ROUTINE_RIMZ_PREFIXES` into `permissions.allow` of the launch's one `--settings` document on every real launch (every action, child, permission mode, and isolation level, with or without `allowed-tools`; preflight compiles skip it) when `allow-routine-rimz` is on, ignoring skill roots and scratch/shared directories. A malformed passthrough `permissions` value fails the launch with an error naming the settings source and the key, and names no switch: `allow_write_dirs` merges into the same `permissions.allow` with `allow-routine-rimz` off. On agy 1.5.16 under `--mode auto` with the terminal sandbox on, a matching `command(<prefix>)` rule silences the reviewer prompt and lets a sandbox-bypassing call run outside the sandbox without asking, without excluding default calls from the sandbox ([reference](../../externals/agent-adapter/antigravity-reference.md#permission-resources)). `configure_room_permissions` appends `--sandbox` at sandbox isolation unless the argv already has it. Yolo keeps `--dangerously-skip-permissions`, which agy lets override its sandbox, so `native_sandbox_overridden` reports that flag in the compiled argv and the launch and `rimz agents validate` warn that sandbox isolation is not in effect. `configure_sandbox_settings` and `allow_team_notes_args` both call `permissions.rs::allow_write_dirs`, which unions one `write_file(<resolved path>)` rule into `permissions.allow` for each of the three room roots (`StatePaths.root`, `RuntimePaths.root`, `RuntimePaths.shared_root`), each active notes run, and the home-wide note store once it exists, at every mode and isolation level (yolo included). `configure_sandbox_settings` also resolves the launch working directory's own `.git` entry via `crates/rimz/src/worktree.rs::common_git_dir` (without spawning Git; covering a launch at a checkout's root for linked worktrees, submodules with relative `..` `gitdir:` entries, separate Git directories, and primary checkouts), and calls `permissions.rs::allow_read_dirs` to union one `read_file(<canonical common Git dir>)` rule into `permissions.allow` at every mode and isolation level, never a `write_file` rule. That read rule exposes the common directory's `config` (remote URLs and any credentials stored in it), refs, objects, and other worktrees' admin directories read-only to sandboxed commands while keeping Git writes refused inside the sandbox (observed on agy 1.5.17). When the launch working directory is not a checkout root, or when its `.git` or `commondir` fails to resolve to an admin directory holding a `HEAD` file and a common directory holding `objects` and `refs` directories, no Git read rule is added and the launch compiles cleanly. agy matches file permission targets on the resolved path only ([reference](../../externals/agent-adapter/antigravity-reference.md#permission-resources)), so each path is canonicalized (falling back to the path as written for `write_file` when canonicalization fails), and no rule is emitted for a `.rimz/team` link spelling. Both `write_file` and `read_file` rules also open their paths to agy's terminal sandbox. Preflight compiles carry no room roots or notes paths, and so emit none of these `write_file` or Git `read_file` rules. RimZ never writes `toolPermission` or `allowNonWorkspaceAccess`, and never writes these rules into the account's saved `settings.json`.

`allow_added_dirs_args` adds one `--add-dir` per directory the argv lacks. agy opens each as a workspace and loads its instructions, rules, and skills and runs its hooks, so `added_dirs` answers `AddedDirs::Workspace`: the launch warns, the supervised undecided-cwd fallback never chooses Antigravity, and the empty-directory reminder says the target was loaded.

### Folder trust

agy skips its trust prompt only for a launch directory `trustedWorkspaces` names exactly ([reference](../../externals/agent-adapter/antigravity-reference.md#workspace-trust)), so a grant on the repository would still prompt in every subdirectory and linked worktree. `crates/rimz/src/agents/adapters/antigravity/folder_trust.rs::folder_trust` reads `settings.json` from the login env (`crates/rimz/src/agents/adapters/antigravity/install.rs::settings_path`, the file install writes), tolerating a byte order mark and comments. A missing file holds no entry. A file that does not parse, a non-object top level, a non-array `trustedWorkspaces`, a non-object `permissions`, or a non-array `permissions.allow` is a gap whose fix names the file to repair; non-string entries inside either array are dropped.

The cwd is decided in three cases, each entry compared as written and canonicalized: an entry names the cwd; an entry is an ancestor of the cwd; or the cwd is in a linked worktree (`crates/rimz/src/worktree.rs::linked_worktree`, read from git metadata without spawning git) whose primary checkout is at or below an entry. A pull-request worktree, one whose RimZ marker records `from_pr` or cannot be read, is decided only by an entry naming the cwd, so in one of its subdirectories an entry for the worktree root does not decide. A fresh `--from-pr` launch preflights before that worktree exists, so the launcher checks again there once it does ([fleet.md](../harness/fleet.md#every-path-that-builds-a-launch-layout)). The grant key is the canonical primary checkout in a linked worktree, the cwd in a pull-request worktree, and otherwise the repository root the caller passes, else the cwd. The preview appends the key to `trustedWorkspaces` and renders the file through `settings_json::render_json`, keys sorted, as install's rewrites do; the neutral `grant_folder_trust` writer publishes it. A grant on the empty root covers each per-agent directory below it.

agy would still prompt in a directory decided by an ancestor or a primary checkout, and any session `permissions.allow` replaces the account's saved allow list, so `crates/rimz/src/agents/adapters/antigravity/folder_trust.rs::bridge`, through `LaunchCapability::bridge_saved_settings_args` in `crates/rimz/src/harness/launch.rs::compile_agent_process_with_extra_env`, unions the saved `trustedWorkspaces` entries and the cwd (as written and canonicalized) when `cwd` is trusted only by inheritance, and unions the saved `permissions.allow` rules unconditionally, into the launch's one `--settings` document after a profile's own entries, any translated `allowed-tools` rules, and the routine `command(<prefix>)` rules (when `allow-routine-rimz` is on), and before the notes and room-root `write_file` rules, the checkout common-Git-directory `read_file` rule, and the served `mcp(rimz_tools/*)` rule. Every launch, resume, restart, molt, and supervised run compiles there, so each carries them. The saved file never gains the worktree, per-agent, or room-root paths. Which spelling agy compares for trust was not captured, so only a directory whose written and canonical spellings are both saved goes without a trust bridge; one saved in a single spelling is bridged in both. An undecided directory gets no trust bridge, and when `settings.json` cannot be read or has the wrong shape for `trustedWorkspaces` or `permissions`, the bridge skips silently without failing compile (while folder-trust preflight surfaces the `repair <path>` gap) and the launch still emits its room and notes write rules, its checkout Git read rule, and the routine command rules and served `mcp(rimz_tools/*)` rule while `allow-routine-rimz` is on.

### The agent file

agy publishes no system-prompt flag, so a fresh launch whose definition carries prompt sources (a kind base, a craft body, or a team layer) writes its composed system prompt into an agy custom agent and selects it with `--agent <name>`. `compile` plans the file through `agent_file.rs::plan`, and `apply` writes it through `crates/rimz/src/agents/agent_file.rs::publish_agent_file`. The file is `agents/<name>.md` in RimZ's plugin directory, resolved by the installer's rule from the launch env's `HOME` or `RIMZ_ANTIGRAVITY_HOOKS`. Its frontmatter holds `name`, a quoted `description`, `mainAgent: true`, `tools`, and the [MCP keys](#mcp-servers) when a launch has any; its body is the composed prompt, a blank line, and the launch reminder, so the file is also the reminder channel. The name is `rimz-<label>-<hash>`: the label is the profile name with every character outside `[A-Za-z0-9._-]` replaced by `-`, or `antigravity` without a profile, and the hash is 12 hex characters of SHA-256 over the rest of the file, so equal content shares one file and any change gets its own. Publishing gives the file a fresh mtime and removes `rimz-*.md` regular files beside it older than seven days.

Whenever a prompt is composed, a profile's own `--agent` is removed, on every action. A resume selects no file and passes no `--agent`: the conversation keeps the prompt, tools, and MCP servers it started with. A launch with no prompt sources keeps its argv and writes no file; its launch reminder is not delivered, and a subagent's no-delegation body arrives through the user-prompt fallback ([fleet.md](../harness/fleet.md#launch-reminders)). Such a fresh launch that carries `tools`, or an `mcps` list that limits servers (one without `*`), has no file to write the list into, so it is refused before any pane opens (`crates/rimz/src/harness/plan.rs::validate_fresh_agent_file_lists`): at layout, and before a molt or a restart whose conversation cannot resume reserves its swap, through `crates/rimz/src/harness/plan.rs::ResumeLaunchPosture::validate_fresh_agent_file_lists` on the posture the replacement launches with. The refusal names the field and the fix: add the kind base `agents/antigravity.md` or another prompt source, or remove the field. A cell carrying both lists is refused for `tools`. `compile` refuses the launch when the plugin directory does not hold RimZ's manifest, with the fix `rimz hooks install antigravity`, or when agy has the plugin disabled, with the fix `agy plugin enable rimz`.

agy needs a `tools` list on every definition. `agent_file.rs::map_tools` maps RimZ's names once, for the file and for the launch notices:

| RimZ name | agy names |
| --- | --- |
| `Read`, `Grep`, `Glob`, `LS` | `read_file` |
| `Edit`, `MultiEdit` | `edit_file` |
| `Write` | `write_file` |
| `Bash` | `run_command` |
| `WebSearch`, `WebFetch` | `search_web` |
| `AskUserQuestion` | `ask_question` |
| `Agent` | `invoke_subagent`, `define_subagent`, `manage_subagents`, `run_workflow` |
| `Skill` | none |

An agy name passes as written: the 13 defaults (`agent_file.rs::DEFAULT_TOOLS`) and `generate_image`. Any other name is dropped with the dropped-tools notice and never reaches the file, and a restriction suffix (`Bash(git *)`) is reported with the restrictions notice while its base name is mapped. A launch with no list writes the 13 defaults. The four subagent names, `run_workflow` among them since it fans work out to subagents, are written only when the launch keeps native subagents on (`crates/rimz/src/harness/launch_reminders.rs::LaunchReminders::disable_native_subagents`). On agy 1.5.13 `read_file` refuses a directory under a custom agent (`path is a directory, not a file`) and agy registers no other listing tool, so `LS` maps to `read_file` and grants no directory listing: a definition that needs one lists `Bash`.

#### MCP servers

`takes_mcp_servers` is on; no `--mcp-config` argument reaches argv, and `mcp_server_args` merges `mcp(rimz_tools/*)` into `permissions.allow` of the launch's one `--settings` document through `crates/rimz/src/agents/adapters/antigravity/permissions.rs::allow_mcp_server` whenever `launch.server` carries `grant: true` (the launch serves RimZ's MCP server and `allow-routine-rimz` is on). RimZ's server is the rimz plugin's own `mcp_config.json` entry (`rimz mcp serve --launch-env`, written by [install](#install)), which agy starts for every session of the account and names `rimz_tools` (`<plugin>_<server>`, the adapter's `mcp_server_name`). `serves_mcp_from_launch_env` is on, so `compile` hands the server over on every launch that serves a capability (fresh with or without a prompt, and resume) and records the launch directory as the agent sees it (`LaunchReminders::mcp_cwd`); `crates/rimz/src/harness/launch.rs::compile_agent_process_with_extra_env` then sets `RIMZ_MCP_SERVE` (the served capabilities and their marks, `crates/rimz/src/mcp/launch_env.rs::render`) and `RIMZ_MCP_CWD`, and removes and unsets both on every launch that serves nothing, of every kind. A mark on `rimz` marks every served capability that has no mark of its own (`crates/rimz/src/config/mcps.rs::served_marks`). The server reads the two variables when agy starts it, so a resumed conversation serves what its launch names, and a session RimZ did not launch gets a server that writes one stderr line and exits, which `/mcp` shows as that server's error ([mcp.md](../../reference/cli/mcp.md#launch-registration)). The quota read's `agy -p /usage` child removes both variables (`crates/rimz/src/agents/adapters/antigravity/usage.rs::command`).

A profile's `mcps` list rides the agent file, after `tools` and inside the hashed part. `crates/rimz/src/agents/adapters/antigravity/agent_file.rs::mcp_lines` writes nothing without a limit; with one, `inheritMcp: false`, then `mcpServers: [<name>...]` when the list names a user server. `<name>` is `{"name": "<server>"}` for each `crates/rimz/src/config/mcps.rs::McpName::user_server` in list order, with no check that the server exists; agy ignores an unknown one. `inheritMcp: false` does not withhold the plugin's own server: on agy 1.5.14, `rimz_tools` stayed listed and answered a first-turn call beside `inheritMcp: false` and a name-only user item, whether or not the list also named `rimz_tools` ([antigravity-reference.md](../../externals/agent-adapter/antigravity-reference.md)). agy keeps the user servers a conversation started with across a resume, even after the file changes or is pruned. A mark on one of the user's servers, or any mark while the server is not handed over, is returned in `AgentFile::warnings`, and `compile` adds each to the launch warnings and `mcp_warnings`; the name-only item is still written.

agy binds a plugin server's tools from the first turn, so a scoped Antigravity launch hides the `rimz-*` skill of each capability it serves, as Claude and Codex launches do (`crates/rimz/src/harness/launch_reminders.rs::LaunchReminders::hidden_skills`); a host launch hides none, since agy's `HostSkills::Unsupported` has no per-launch switch, and the reminder's `lsp` bullet names `mcp(lsp)`. Because `mcp_server_args` runs after `bridge_saved_settings_args` and `union_settings_array` keeps first occurrences, a launch with an unreadable saved file still receives `mcp(rimz_tools/*)` whenever RimZ serves the server and `allow-routine-rimz` is on, and a saved file or an `allowed-tools` `mcp__rimz` entry produces no duplicate. A hand-run nested `agy` inside an agent's shell inherits `RIMZ_MCP_SERVE` with no launch `--settings` document, so it prompts for MCP tools once any leftover saved rule is stripped.

### Skills

`skills_home` is `$HOME/.gemini/config/skills`, the global root agy's built-in skills name, and `manual_skill` is `Frontmatter`: on 1.5.13 `disable-model-invocation: true` hides a skill from the model and keeps it in the `/` menu, and symlinked skill directories and a read-only root are discovered ([reference](../../externals/agent-adapter/antigravity-reference.md#remote-control-mcp-plugins-and-custom-agents)). Host launches link RimZ skills there, creating the root, and a scoped profile `skills` list overlays it ([sandbox.md](../sandbox.md#skill-roots-and-user-only-markers)). agy also reads `~/.gemini/antigravity-cli/skills`, `~/.gemini/skills`, a plugin's `skills/`, and the workspace `.agents/skills`, which RimZ leaves native, so a list does not restrict a skill kept there. On a duplicate name the `~/.gemini/antigravity-cli/skills` copy wins over `~/.gemini/config/skills`, which wins over `~/.gemini/skills` (1.5.14, print mode). agy never reads `~/.agents/skills`, so a skill kept only there does not reach it. Nothing about skills goes in the agent file. `host_skills` stays `Unsupported`: a host launch with a list warns and runs unrestricted.

### Install

`rimz hooks install antigravity` writes an agy plugin and edits one settings file, and the preview shows each diff:

| File | Override | Change |
| --- | --- | --- |
| `~/.gemini/config/plugins/rimz/hooks.json` | beside `RIMZ_ANTIGRAVITY_HOOKS` | one top-level hook named `rimz` holding the six handlers below |
| `~/.gemini/config/plugins/rimz/mcp_config.json` | beside `RIMZ_ANTIGRAVITY_HOOKS` | RimZ's MCP server: `{"mcpServers": {"tools": {"command": "rimz", "args": ["mcp", "serve", "--launch-env"]}}}`, which agy names `rimz_tools` |
| `~/.gemini/config/plugins/rimz/plugin.json` | beside `RIMZ_ANTIGRAVITY_HOOKS` | the manifest: name `rimz`, author `RimZ`, version, description |
| `~/.gemini/antigravity-cli/settings.json` | `RIMZ_ANTIGRAVITY_SETTINGS` | `statusLine` set to `rimz statusline feed --source antigravity`; strips any leftover `mcp(rimz_tools/*)` rule from `permissions.allow` regardless of [`allow-routine-rimz`](../../guide/configuration.md#routine-rimz-commands) (dropping an emptied `allow` or `permissions` container while leaving other rules and a wrong-shaped `permissions` container untouched), and adds nothing to `permissions` on a fresh login |
| `~/.gemini/config/plugins/rimz/agents/rimz-*.md` | beside `RIMZ_ANTIGRAVITY_HOOKS` | not written by install: launches write [agent files](#the-agent-file) there, install keeps them, and uninstall removes them with the directory |
| `<rimz home>/antigravity-statusline.json` | the RimZ home | the displaced `statusLine`, written when install displaced one and removed when `statusLine` is absent |

Every path resolves from the process `HOME` (and the RimZ home) through `crates/rimz/src/agents/locate.rs::agent_config_path`, except that a login env carrying `RIMZ_ANTIGRAVITY_HOME` (a standalone account) keeps `settings.json` and its displaced statusline (`rimz-statusline.json`) in that account directory (`install.rs::AntigravityManagedIntegration::paths`). A shared account carries `RIMZ_ANTIGRAVITY_LOGIN_HOME` and no `RIMZ_ANTIGRAVITY_HOME`, so its `settings.json`, displaced statusline, and folder-trust grants resolve to the default directory and install writes nothing in the account directory. The plugin and `config.json` stay one copy per `HOME`, so a standalone account's uninstall leaves them. A launch resolves the same rule from its launch env instead (`install.rs::launch_plugin_dir`). The plugin directory is `plugins/rimz` beside the global `hooks.json` that `RIMZ_ANTIGRAVITY_HOOKS` names, and agy's enablement file is `config.json` there (`install.rs::Paths`). agy 1.5.12 loads a plugin's `hooks.json` with no install step and enables it by default ([reference](../../externals/agent-adapter/antigravity-reference.md#files-and-format)).

Ownership of the directory is the manifest, as for MiniMax: `crates/rimz/src/agents/adapters/antigravity/install.rs::check_plugin` accepts an absent or empty path, or a real directory whose `plugin.json` names `rimz` and author `RimZ`, or one holding only files install writes before the manifest (`hooks.json` and `mcp_config.json`), its `hooks.json` holding RimZ's handlers (an install the manifest has not yet followed). A file, a symlink, a plugin file that is not a regular file, a foreign manifest, a manifest-less `hooks.json` without RimZ's handlers, or any other content refuses install with a move-aside fix naming the path, and uninstall leaves that path in place while it still cleans the rest. Such a path is not a RimZ artifact either, so a home holding only it reads as untouched. Install writes the plugin last, after the settings pair below, so a failed settings, global-hooks, or record write leaves the legacy global handlers as the one hook set. It writes `hooks.json` and `mcp_config.json` before `plugin.json`, so agy never sees a manifest whose hooks or server are missing, and writes only files whose bytes differ. `installed` is every plugin file byte-equal, no owned handler left in the global file, and the statusline command equal to RimZ's; a leftover saved `mcp(rimz_tools/*)` rule leaves `installed` true so launches are not blocked as missing hooks, while `crates/rimz/src/agents/adapters/antigravity/install.rs::outdated_files` reports `settings.json` so `rimz start`, `rimz setup`, and `rimz doctor` offer the refresh that removes it (`crates/rimz/src/agents/adapters/antigravity/install.rs::holds_saved_mcp_rule`). `managed_artifacts_present` does not inspect `permissions.allow`, so a no-arg uninstall skips a login whose only leftover is that rule; named uninstall and any install strip it (`crates/rimz/src/agents/adapters/antigravity/install.rs::strip_allow_rule`). A rule the user saved under the same `mcp(rimz_tools/*)` spelling cannot be told apart from RimZ's and is stripped too. A plugin an older release installed lacks `mcp_config.json` or holds a `hooks.json` with older matchers (before the 1.5.14 tool names), so it reads not installed and `ProviderLogin::health` answers `HooksMissing`: each launch is refused with the hooks-missing text ("RimZ hooks are missing for antigravity account `default` at `<home>`; run `rimz hooks install antigravity`", `rimz accounts add antigravity <name>` for a named account, and "`rimz agents -p` requires antigravity hooks ..." for a supervised run) until `rimz hooks install antigravity` runs. `rimz doctor` shows the plugin's server in its hooks section, read from `mcp_config.json` and agy's enablement file (`ManagedIntegration::shipped_mcp_server`).

An older RimZ wrote its handlers into the global `~/.gemini/config/hooks.json`. agy runs a hook name defined there and in a plugin twice, so a surviving owned handler makes the global file outdated, and install removes it. `install.rs::strip_owned_hooks` removes every handler whose command contains `rimz hooks feed --source antigravity`, under any hook name, and drops a hook name, event, or entry only when that strip emptied it; containers the user left empty stay. A `rimz` hook of the user's own in the global file stays untouched. Install commits settings and the stripped global file as one pair (`crates/rimz/src/agents/settings_json.rs::commit_pair`): a failed second write restores both files to their original bytes. Every handler is `{"type":"command","command":...,"timeout":5}` and starts with `RIMZ_AGENT_PID=$PPID exec`, so the hook carries its owner pid ([instances.md](./instances.md#session-death)). agy runs plugin hooks with the plugin directory as cwd, so no handler reads its cwd. Uninstall removes the plugin directory, strips owned global handlers, restores the statusline, and deletes the record. Its report names only what it changed: the removed events only when the plugin's `hooks.json` held RimZ's handlers, and `settings.json` only when it was written.

A plugin the user disabled (`plugins.rimz.enabled == false` in `config.json`, read through `crates/rimz/src/agents/jsonc.rs`) is reported by `hooks_disabled` with the fix `agy plugin enable rimz`; an absent, `true`, unreadable, or malformed value reads as enabled. RimZ never writes `config.json`, and `installed` stays a statement about files.

The statusline follows the marker-free ownership Cursor uses (`crates/rimz/src/agents/adapters/owned_statusline.rs::OwnedStatusLine`), because agy 1.5.12 rewrites `settings.json` keeping only `type`, `command`, and `stack_with_default` under `statusLine`, so no marker key survives a start. Installed means the command equals RimZ's; owned means it contains RimZ's statusline marker. A `statusLine` that exists and is not a JSON object refuses install. The displaced object goes whole to `antigravity-statusline.json` and is restored on uninstall. After each install the record describes what that install displaced: another statusline (an empty-command object included) overwrites it, a RimZ-owned one keeps it, and an absent `statusLine` removes it, which the dry run shows as `removes file`. When install would not write `settings.json`, the preview shows it unchanged. A legacy inline `_rimz_wrapped` value migrates there on reinstall. While RimZ is installed, the active entry keeps only one of the user's rendering options, `stack_with_default`. When `statusLine` was absent, install sets `stack_with_default: true` so Antigravity keeps its built-in line. A statusline the user replaced after install is left by uninstall and wrapped again by the next install. RimZ reads `settings.json` and agy's `config.json` past one leading UTF-8 byte order mark, which agy accepts too in `settings.json` and `--settings` files, so a file an editor saved with one reads as installed; malformed JSON behind the mark still fails, and an install that rewrites `settings.json` writes no mark.

### Events

The catalog holds four native events, with `PostToolUse` split by three disjoint matchers. The matchers name the documented tools and the names agy 1.5.14 was captured sending, and keep the legacy step names because the adapter declares no version floor ([reference](../../externals/agent-adapter/antigravity-reference.md#tool-vocabulary)). A tool outside all three sends no `PostToolUse` at all: there is no catch-all, so an unknown tool is never read as an edit or a mutation by guess. `run_workflow` and `call_mcp_tool` count as mutating because either can change anything, as `run_command` can.

| RimZ event | Native event and matcher | Signal | Reply |
| --- | --- | --- | --- |
| `PreInvocation` | `PreInvocation` | when `invocationNum` is `0`, `Compacting` when the row at `initialNumSteps - 1` is a bare `/compact` (or, with `initialNumSteps` absent or the transcript unreadable, when `lastUserInput` is a bare `/compact`), routing only when the transcript shows no prompt opened the invocation ([Steering](#steering)), and `TurnStarted` otherwise; routing only for a later invocation | `{}` |
| `PostToolUse:edit` | `PostToolUse`, `write_file`, `edit_file`, and the legacy `write_to_file`, `replace_file_content`, `multi_replace_file_content` | `ToolUsed`, mutating and editing | `{}` |
| `PostToolUse:mutating` | `PostToolUse`, `run_command`, `run_workflow`, `call_mcp_tool` | `ToolUsed`, mutating; `run_command` with `stepIdx` reports `BackgroundShellReport::Finished` for `<conversationId>/task-<stepIdx>` | `{}` |
| `PostToolUse:observed` | `PostToolUse`, the remaining known tools (`view_file`, `read_file` through `browser_.*`) | `ToolUsed`; `manage_task` with `Action: "kill"`, a nonblank `TaskId`, and no error reports `BackgroundShellReport::Finished` for that `TaskId` | `{}` |
| `PostInvocation` | `PostInvocation` | a `TurnStarted` state snapshot with the prompt when the transcript holds a user turn at or past the payload's `initialNumSteps` and before the next `PLANNER_RESPONSE` or `CHECKPOINT` row ([Steering](#steering)); routing only otherwise or when the transcript cannot be read | `{}` |
| `Stop` | `Stop` | `CompactionEnded` when `lastUserInput` is a bare `/compact` and `terminationReason` is `TERMINAL_CUSTOM_HOOK`, `TurnEnded` otherwise; every `Stop` that decodes to `TurnEnded` (including a post-compaction continuation while `lastUserInput` stays `/compact`) attaches a `BackgroundShellReport::Snapshot` (empty when `fullyIdle: true`, or read from the validated transcript when `fullyIdle: false`) | `{"decision":""}` |

Hook stdout is Antigravity's decision channel, and every wired event must answer with JSON. `{}` is the documented no-op, and `{"decision":""}` is a `Stop` decision other than `continue`, so the stop proceeds ([reference](../../externals/agent-adapter/antigravity-reference.md#events)). Any other event name, such as a hand-fed `PreToolUse` or `SessionStart`, gets no output and records nothing. For every Antigravity event the feed waits up to 1.2 s for the drainer to apply the frame and prints the drainer's reply ([adapter.md](./adapter.md#the-feed)). That early return also skips the deadline rung a `PostToolUse` could otherwise carry.

Every payload carries the conversation id (`conversationId`, or `conversation_id`), `workspacePaths`, `transcriptPath`, and `modelName`. A payload without a nonblank id records nothing. The first nonblank workspace path becomes the worktree path, and `modelName` becomes the launch model hint: a trailing `-low`, `-medium`, `-high`, `-xhigh`, or `-max` is split off into the launch effort (`mod.rs::split_model_effort`), so `gemini-4-hydrogen-xhigh` records model `gemini-4-hydrogen` and effort `xhigh`. Five decoding rules in `mod.rs::decode_lifecycle_fields` are easy to break:

- Only `invocationNum: 0` opens a turn. Later invocations of the same execution follow tool calls and must not reopen it, and a payload without `invocationNum` opens nothing.
- An `invocationNum: 0` opener whose transcript shows no prompt opened it (a background command's or a native subagent's result continuing the turn) decodes to routing only, so it neither records nor confirms a prompt ([Steering](#steering)). The row keeps the state it had: after a `fullyIdle: false` stop it stays `Parked` until a `PostToolUse` moves it to acting or the `Stop` ends the turn (`crates/rimz/src/agents/lifecycle.rs::map_phase`). After a background command, that command's own `PostToolUse` arrives just before the opener.
- A failed tool (a nonempty `error`) keeps its `ToolUsed` progress and tool name but clears the mutating and editing flags. The tool name is the trimmed `toolCall.name`. A release that omits `toolCall` sends unnamed progress.
- A bare `/compact` compaction is classified from the opener's transcript row below `initialNumSteps`, and closed only by a `Stop` whose `lastUserInput` is a bare `/compact` and whose `terminationReason` is `TERMINAL_CUSTOM_HOOK`, compared without case ([Compaction](#compaction)). Any other `Stop`, even while `lastUserInput` still holds `/compact` on a post-compaction continuation, decodes by the ordinary turn rule, and `/compact <message>` and payloads without `lastUserInput` decode as turns.
- A turn's `Stop` needs `fullyIdle`, which upstream marks required. A turn's `Stop` without it records no lifecycle event and no final message. `terminationReason` `ERROR`, `MAX_INVOCATIONS`, `MAX_FORCED_INVOCATIONS`, `MAX_TOKEN_BUDGET_EXCEEDED`, or the 1.3.3 `max_steps_exceeded`, compared without case, or a nonempty `error`, ends the turn errored (`payloads.rs::FAILED_REASONS`). Every other reason is a clean end: `NO_TOOL_CALL`, `TERMINAL_CUSTOM_HOOK`, and `USER_CANCELED`, which agy 1.5.14 and 1.5.15 were not seen to send, since Escape fires no hook ([Interrupt](#interrupt)). A clean `Stop` with `fullyIdle: false` parks the turn on background work, and a failed one never parks ([model.md](./model.md#turn-endings-and-parked-turns)). Any `Stop` that decodes to `TurnEnded` with `fullyIdle: true` attaches an empty `BackgroundShellReport::Snapshot` from the payload alone, which repairs any missed finish; any `Stop` that decodes to `TurnEnded` with `fullyIdle: false` (failed or clean) snapshots the running background tasks from the validated transcript (`session.rs::running_background_shells_under`) and reports nothing when the transcript is missing, unreadable, or outside the path guard. Because agy fires no installed hook naming a task when it backgrounds one, a command enters `background_shells` at the first `Stop` after backgrounding rather than at the backgrounding call itself.

A supervised run (`rimz agents antigravity -p`) completes from the `Stop` hook. Its final message is the newest completed assistant text in the hook's transcript ([Transcript](#transcript)).

### Compaction

The compact command is a bare `/compact`, and Antigravity takes no compaction instruction: `/compact <message>` compacts and then answers the message as an ordinary turn, so RimZ refuses an instruction. agy brackets a bare `/compact` (at rest, on a parked turn, or queued mid-turn with Enter) with a `PreInvocation` (`invocationNum: 0`) and a `Stop` (`terminationReason: "TERMINAL_CUSTOM_HOOK"`), both carrying `lastUserInput: "/compact"`. On the opener, `session.rs::prompt_opened_under` inspects the rows below `initialNumSteps`: when step `initialNumSteps - 1` is a bare `/compact` user row, the opener decodes to `Compacting`, which acknowledges a sent compact command, with no prompt. When a continuation opens after the compaction (for example on a background command's result), step `initialNumSteps - 1` is the `SYSTEM` / `CHECKPOINT` row, so the opener decodes to routing only even though `lastUserInput` stays `/compact`. When `initialNumSteps` is absent or the transcript read is `Unread`, `lastUserInput` decides the opener. The closer decodes to `CompactionEnded` with `auto: Some(false)` only when `lastUserInput` is a bare `/compact` and `terminationReason` is `TERMINAL_CUSTOM_HOOK` (compared without case), failed when the `Stop` carries a non-empty `error`, whether or not it carries `fullyIdle`. It sets no final message, since the newest assistant row predates the compaction. Every other `Stop`, including a continuation's `NO_TOOL_CALL` or an error stop while `lastUserInput` stays `/compact`, follows the ordinary turn rule. A user's own hook that ends a post-compaction continuation with `TERMINAL_CUSTOM_HOOK` carries the same `lastUserInput` and reason and reads as the compaction's close, since no payload field tells the two apart. Because that closer reads no `fullyIdle`, a parked row that enters a bare `/compact` before a complete rest report finishes it stays parked across the compaction until a complete rest report arrives or a later turn ends cleanly.

Two cases leave the bracket without a closer. An Escape during the compaction fires only the opener and writes no `CHECKPOINT` row, leaving the `/compact` user row orphaned, so the compacting head stays until the next lifecycle signal and a continuation opened directly above that row reads as `Compacting` (its `Stop` still settles the run). Because Antigravity declares `compaction_ended` `Native`, that next non-end signal only lowers the compacting head: it leaves `compaction_count`, `compacted_at`, and the sidecar's reading untouched ([the compaction bracket](./model.md#the-compaction-bracket)). A `/compact` in a conversation with nothing to compact fires no hook, so a sent command times out unconfirmed. A user's own `/compact <message>` stays a turn, though agy compacts before it answers.

The transcript is append-only across a compaction: a `USER_INPUT` row for `/compact`, then a `SYSTEM` / `CHECKPOINT` row with the summarizing call's tokens. History drops a user row whose request is exactly `/compact`, so a sent command never shows as the user's words. The statusline keeps its pre-compaction context reading until the next turn's first model call returns, so Antigravity declares `Capabilities::context_lags_compaction`: the store stamps the sidecar's current occupancy onto each usage-retiring close event as `retired_context_tokens`, and the fold retires it so the gauge and smart-compaction reminder withhold the stale reading across the first prompt until a different figure arrives ([the compaction bracket](./model.md#the-compaction-bracket)). RimZ's compacted-at guards (the command's recorded token count and the compacted-awaiting-prompt mark) also keep idle compaction and compact-first from firing again before the next prompt. agy compacts on its own near the context limit by its docs, but no hook for that was observed, so `auto-compact` stays unsupported.

### Steering

agy queues a message submitted with Enter during a running turn until the turn ends, and Alt+M sends one message into the running turn instead ([reference](../../externals/agent-adapter/antigravity-reference.md#interrupt-and-queued-messages)). The descriptor declares Enter then Alt+M as its send-now keys and Enter as its queue keys, so a steer presses Enter then Alt+M (a forced steer onto an open prompt presses Alt+M alone) and a boundary send presses Enter ([the message keys](../harness/messaging.md#the-message-keys)). The Enter submits the steer before Alt+M, so an Alt+M that does nothing leaves it queued rather than unsent. Which message Alt+M sends when several are queued, and what it does on a resting agent, is not recorded. The two hold under `queuedMessages: "queue"`, which every launch pins ([Permission rules](#permission-rules-sandbox-and-added-dirs)).

The model invocation that takes the message in writes its user row at the `step_index` equal to its `initialNumSteps`; the row is absent at that invocation's `PreInvocation` and present at its `PostInvocation`, and every later invocation begins past it (1.5.14 capture, [antigravity-reference.md](../../externals/agent-adapter/antigravity-reference.md#interrupt-and-queued-messages)). So `PostInvocation` reports every non-`/compact` user turn at or past `initialNumSteps` and before the first `PLANNER_RESPONSE` or `CHECKPOINT` row from there, in step order and joined by a blank line, as one `TurnStarted` state snapshot, once per message, including steers into a post-compaction continuation whose `lastUserInput` stays `/compact`. That row is the invocation's own answer or checkpoint boundary, and the bound holds when the frame is applied late, against a transcript that already carries rows a later invocation wrote. The snapshot confirms the `Sent` record of each message it carries and records each prompt without opening a turn or moving `turn_started_at` ([Confirmation and retry](../harness/messaging.md#confirmation-and-retry)). A `PostToolUse` can show the row half a second earlier, but carries no step bound. Two steers taken in by one invocation (one row each in live run 1) arrive in one report, and each confirms its own record.

The `invocationNum: 0` opener classifies what opened its invocation from the rows below its own `initialNumSteps` (`session.rs::prompt_opened_under`). A turn's first prompt, a message agy drains at the turn's end, and a bare `/compact` write their user row just below that bound before the opener fires, while a continuation (a background command's result, a post-compaction continuation, or a native subagent's result waking the parent) has the `PLANNER_RESPONSE` or `CHECKPOINT` row that ended the previous execution there and no user row after it (1.5.15 and 1.5.16 captures, [antigravity-reference.md](../../externals/agent-adapter/antigravity-reference.md#interrupt-and-queued-messages)). `lastUserInput` carries the older prompt or `/compact` on a continuation, so it cannot tell them apart. When step `initialNumSteps - 1` is a bare `/compact` user row, the opener decodes to `Compacting` with no prompt. Otherwise it reports, on a `TurnStarted`, the newest completed user row after the newest `PLANNER_RESPONSE`, `CHECKPOINT`, or `/compact` row below the bound, so an execution that ended with no answer row never hands its prompt to the next opener, and an earlier `/compact` is never read as one. When the rows read reach the row just below the bound and no user row follows that boundary, no prompt opened the invocation, and the opener decodes to routing only, so a steer taken in earlier is never recorded again and a post-compaction continuation never reads as `Compacting`. The read takes the 64 KiB tail, and the whole file when the tail misses the row just below the bound or starts inside the interval with no boundary row in it. A payload without `initialNumSteps` falls back to `lastUserInput` for `/compact` and otherwise reads the latest completed user prompt; a bound of 0, an unreadable transcript, or a file that stops short of the row just below the bound falls back to `lastUserInput` (`Compacting` for a bare `/compact`, else `TurnStarted` with no prompt); a native child's first opener (bound 0, before agy creates its transcript) is that case. Every row read sits below the bound, and the whole-file read covers rows a later invocation pushed out of the tail, so the read holds when the frame is applied late.

### Interrupt

The interrupt key is Escape. agy fires no hook for it, so only the statusline's rest report below shows the stop to the interrupt's wait ([the interrupt key](../harness/messaging.md#the-interrupt-key)). Escape also moves a message queued behind the running turn back into the composer, where the interrupt's own text joins it before the send-now keys. With no hook context, a supervised child's deadline stop goes out from the host at the deadline as that interrupt.

The statusline reports an Escaped turn and a parked turn whose last background work ended without opening a new turn: agy 1.5.15 reads `agent_state` `idle` 70 to 263 ms after Escape ([reference](../../externals/agent-adapter/antigravity-reference.md#agent-state-in-1515)), and agy 1.5.16 and 1.5.17 emit `idle` without `task_count` after a `/tasks` kill of the last background task or after a native child ends with no follow-up parent turn. A payload reading `idle`, compared without case, with `task_count` absent or 0 and no `tool_confirmation_pending: true` reports the agent at rest (`ContextObservation::provider_at_rest`, set in `crates/rimz/src/agents/adapters/antigravity/statusline.rs::StatuslinePayload::at_rest`). On that payload `crates/rimz/src/cli/statusline.rs::persist_observation` writes the context with no settle, then appends a rest report to hook ingress (`crates/rimz/src/cli/statusline.rs::append_rest_report`): a `RimzProviderRest` frame carrying the payload and stamped with the observation's instant, followed by a drainer nudge. It never waits on a drainer, drains inline, or takes the workspace lock; inside a scoped sandbox view it reaches the host drainer before it appends, as a hook does, and drops the report with a warning when there is none. `crates/rimz/src/agents/adapters/antigravity/mod.rs::AntigravityAdapter::decode_hook_in` decodes the frame through `crates/rimz/src/agents/adapters/antigravity/statusline.rs::StatuslinePayload::provider_rest` into a rest report for its conversation without reading any transcript: `Complete` when `subagents` is absent, `null`, empty, or lists only `completed` entries (compared without case), and `Foreground` when any entry carries another status, lacks a string status, or `subagents` is not an array. The hook transaction decides the report in log order on one audit read (`crates/rimz/src/cli/hooks/lifecycle/observe.rs::record_provider_rest`), without the transcript overlay, which can open a turn before its hook: on a hook-folded row that is `running` and not parked on background work, or `waiting`, whose `last_activity` is older than the report's instant (`crates/rimz/src/agents/state.rs::AgentState::rest_interrupts_turn`), it records `TurnInterrupted` regardless of `subagents[]`, which rests the row `idle`, closes its ask, clears an owed compaction continue, and opens a supervised child's interrupt hold with no stored reply, attaching an empty `BackgroundShellReport::Snapshot` when `crates/rimz/src/agents/state.rs::AgentState::rest_clears_background_shells` also holds. On a parked row whose `last_activity` is older than the report's instant (`crates/rimz/src/agents/state.rs::AgentState::rest_ends_parked_turn`, with no delay margin because agy sends no later payload on its own and every captured spawn-lag payload read `working`, never `idle`) and whose report is `Complete` (`HookOutput::provider_rest_ends_parked_turn`), it records a clean unparked `TurnEnded` (attaching the empty `BackgroundShellReport::Snapshot` when `rest_clears_background_shells` holds): the row settles to `success` at `idle`, an owed compaction continue stays owed (parking a supervised run on `SoftCompact`), turn-end reactors run, and only on that recorded `TurnEnded` does `crates/rimz/src/cli/hooks/lifecycle/mod.rs::handle_lifecycle_frame` resolve the agy transcript by conversation id through `session_transcript` (ignoring the statusline's `transcript_path`, which points under `.gemini/antigravity/brain/`) and harvest the parked turn's last assistant message through `read_transcript_messages` (leaving the run with no answer when the transcript cannot be read), skipping `record_conversation` so RimZ's own transcript keeps the assistant entry recorded at the parked `Stop` without a duplicate. On any other row whose `last_activity` is older than the report's instant and whose `background_shells` is non-empty (`rest_clears_background_shells`), including a parked row with a live native subagent, it records a keyless `AskResolved` carrying an empty `BackgroundShellReport::Snapshot`: `crates/rimz/src/agents/lifecycle.rs::step` ignores `AskResolved` outside `waiting`, so status, phase, an owed compaction continue, and any open supervised run stay untouched while `crates/rimz/src/store/snapshot/project.rs::assemble_agent_state` empties `background_shells`. Any other row records nothing, and the frame then refreshes no context, runs no reactor, and wakes no workflow. A rest report that records something also counts as a workflow edge, waking a workflow session leader's run as a `Stop` does. agy reads `idle` about 200 ms after every `Stop`, and its hook path appends the `Stop` and waits for the drain before it replies (`crates/rimz/src/cli/hooks.rs::run_feed_inner`), so a normal turn end precedes its `idle` in the log and the report records nothing: an owed compaction continue stays owed. A report observed before a new turn's first hook (or before a shell-listing `Stop`) but appended after it compares older and records nothing, and a report names one conversation id so a newer conversation's payload leaves an older parked row alone. agy sends a payload only when a field changes ([reference](../../externals/agent-adapter/antigravity-reference.md#agent-state-in-1515)), so a report that records nothing is not followed by another: a parked turn's end is decided on the report as it arrives, never deferred to a later one. A binary that does not know the frame reads an unknown event and leaves the row `running`. An Escape while a background command from an earlier turn still runs reads `task_count: 1`, so that row stays `running` until the next turn or a manual compaction.

A row still Running at rest (that background case, or a rest report dropped in a sandbox view with no host drainer) gets the interrupt's Escape on a resting agy, which stops nothing, so the stop wait reads no change and the text goes out after the bound, reported not confirmed ([the interrupt key](../harness/messaging.md#the-interrupt-key)).

## Sessions

Antigravity registers lazily (`registers_lazily`). A live `agy` pane renders as the idle row of [instances.md](./instances.md#before-a-session-binds) until a hook or local discovery binds a conversation. Upstream documents `SessionStart`, but RimZ leaves it unwired: on 1.5.14 it carries no `source`, fires on no `--conversation` resume, and fires for a child before anything ties the child to its parent ([reference](../../externals/agent-adapter/antigravity-reference.md#events)). The first `PreInvocation` of an unseen conversation creates it.

One live `agy` follows its latest conversation, so the spec declares `SamePaneSessionPolicy::FollowLatest`. Pane adoption, ownership, and the in-place-switch supersession follow from that policy ([instances.md](./instances.md#binding-a-session), [same-pane ownership](./instances.md#same-pane-ownership), [supersession](./instances.md#supersession)). RimZ records no `Fresh` origin for a switch, because the hook wire does not say whether `/clear` or `/fork` created the new conversation.

### Local discovery

Antigravity declares `local_session_discovery = FullScan`. `session.rs::discover` reads the provider home from the login env map: `RIMZ_ANTIGRAVITY_HOME` when set (a standalone account), else `$HOME/.gemini/antigravity-cli` (both `default` and a shared account, which carries `RIMZ_ANTIGRAVITY_LOGIN_HOME` alone). A standalone account's agy reports paths under the mount target, so `session.rs::payload_on_host` rewrites a hook's `transcriptPath` to the account directory at decode, and the subagent join maps child log paths the same way; for a shared account `session.rs::mounted_view` is `None` and paths stay under `$HOME/.gemini/antigravity-cli`. One pass serves every admitted workspace:

1. Catalog. `enumerate_conversations` lists every directory under `brain/` whose name passes `valid_conversation_id`. The shared `IncrementalCatalog` rescans when the stamped topology changes or after the 30-second backstop (`crates/rimz/src/agents/local_session_cache.rs::LOCAL_SESSION_DISCOVERY_BACKSTOP`).
2. Selection. A conversation counts when `.system_generated/logs/transcript_full.jsonl`, or else `transcript.jsonl`, is a regular file. The 512 newest by that file's mtime are kept (`MAX_DISCOVERED_SESSIONS`).
3. Fold. Each selected conversation is validated and folded from the shared 64 KiB record-aligned tail. The fold is cached against five stamped paths: the conversation, `.system_generated`, and `logs` directories and both transcript files. A transcript change or a fallback promotion refolds that conversation alone. A tail with no visible record yields no observation, and the first visible record in the tail stands in for the creation time.
4. Index. `cache/last_conversations.json` maps a workspace path to its current conversation id. It is parsed once per pass and cached on its own stamp, so an index-only change rematerializes without a rescan or a refold.
5. Materialize. Every folded conversation becomes one `Lifecycle` observation for each admitted workspace. Only the conversation the index names for that exact workspace path gets `fresh_binding_at`.

The store is provider-global, so an observation's workspace proves nothing about where the conversation ran. A conversation without `fresh_binding_at` binds only through an exact durable row or a `--conversation` command line. The fresh fallback is reserved for the index's pairing ([instances.md](./instances.md#local-session-observations) owns the binding order). Because hooks bind first, a lagging index cannot pull a native question away from a conversation the hooks already identified.

A transcript path is accepted only through `session.rs::valid_transcript_under`. `brain/` and `brain/<id>` must be real directories, not symlinks, and `brain/<id>` must canonicalize directly under `brain/`. The path itself must be a regular, non-symlink file that canonicalizes to `brain/<id>/.system_generated/logs/` plus one of the two basenames. Discovery, `session_transcript`, the first-prompt read, the background-shells read, and the subagent join all check this. The `Stop` final-message read does not ([Known gaps](#known-gaps)).

## Transcript

The 1.1.2 fixtures define the record shape: JSONL with `step_index`, `source`, `type`, `status`, `created_at`, and optional `content` and `tool_calls` ([reference](../../externals/agent-adapter/antigravity-reference.md#transcripts)). A line missing a required field is skipped. `session.rs::fold` reads records in physical order, and only these records move the projection:

| Record | Fold effect |
| --- | --- |
| `USER_EXPLICIT` / `USER_INPUT`, `DONE`, except a bare `/compact` | `running`, phase `reasoning`, prompt set, native question cleared. This is the turn start; a bare `/compact` row is skipped without moving status, prompt, or timestamps |
| `MODEL` / `PLANNER_RESPONSE`, `DONE`, with an `ask_question` call holding a nonblank question | `waiting`, phase idle, the first nonblank question as the native prompt detail, `waiting_since` from `created_at` |
| `MODEL` / `PLANNER_RESPONSE`, `DONE`, with any other tool call (a blank `ask_question`, `invoke_subagent`, and `run_workflow` included) | `running`, phase `reasoning`, native question cleared. The requested tool has no later planner row yet, so the turn is open |
| `MODEL` / `GENERIC`, `RUNNING`, whose content names `running as a background task with task id: <id>` | that task stays running across later user turns until a finish row or the server-restart notice clears it. The row stays `RUNNING` after the task ends; `Task Description:` supplies its command text and `created_at` supplies `started_at` (falling back to hook time when unparseable) |
| `SYSTEM` / `SYSTEM_MESSAGE` whose `[Message]` `content=` begins with `Task id "<id>"`, whatever word follows | that task has ended |
| `SYSTEM` / `SYSTEM_MESSAGE` whose `[Message]` `content=` begins with `[Notice] All your subagents and background tasks have been stopped due to server restart` | clears every running background task |
| `MODEL` / `PLANNER_RESPONSE`, `DONE`, with no tool call, while any background task runs | `running`, phase `parked`, native question cleared, as the hook's `Stop` with `fullyIdle: false` leaves it |
| `MODEL` / `PLANNER_RESPONSE`, `DONE`, with no tool call, and no background task running | `success`, phase idle, native question cleared |
| `MODEL` / `PLANNER_RESPONSE`, `ERROR` | `failed`, phase idle, native question cleared. The content is never shown |
| anything else (other `SYSTEM` history and checkpoints, bare `/compact` user rows, other statuses, unknown sources or types, unparseable `created_at`) | ignored |

While a tool waits at agy's native permission prompt or runs, the transcript already ends in its planner row, so the fold reads `running` and a newer statusline `NativeWait` raises the card to `waiting` ([Statusline context](#statusline-context)). A turn stopped with Escape during a tool call fires no hook and writes no later row, so the fold reads `running` until the rest report of the statusline's `idle` rests it ([Interrupt](#interrupt)). When a background task ends, agy 1.5.14 appends its completion message and a planner row with no `USER_INPUT`, and fires `PostToolUse` and a fresh `PreInvocation` ([reference](../../externals/agent-adapter/antigravity-reference.md#subagents-and-background-tasks)); that woken planner row folds as the turn's result. `session.rs::fold` and `session.rs::running_background_shells_under` share one running-task tracker (`session.rs::RunningTasks`), which carries running tasks across later user prompts because agy keeps background commands alive across follow-up turns, and clears all tasks on agy's server-restart `SYSTEM_MESSAGE` notice. The `ERROR` row is an assumption: no failure capture has shown which source and type carry a terminal model error. A later turn start or completed planner response supersedes it. User content wrapped in `<USER_REQUEST>` contributes only the text up to the matching `</USER_REQUEST>`, so the trailing metadata and settings blocks stay private. An unclosed or empty wrapper yields no prompt. Unwrapped text passes through as it is. Both forms then pass through `sanitize_user_prompt`.

`ask_question.args.questions` is an array in `transcript_full.jsonl`, and `transcript.jsonl` may carry it as a JSON-encoded string. The parser accepts either form in either file. The native question stays pane-only: it creates no durable RimZ ask, and an accepted fold clears any older routable ask ([model.md](./model.md#waiting-and-asks)). A fold overlays a durable row only when its activity is at least as recent, compared in whole seconds (`crates/rimz/src/store/snapshot/view/live.rs::local_observation_is_current`). A fold written in the same second as a newer hook can therefore replace that hook's state until the next hook ([instances.md](./instances.md#local-session-observations)).

Five readers use the transcript:

| Reader | Path source | Read | Rule |
| --- | --- | --- | --- |
| history (`session.rs::messages`) | `session_transcript`, validated | the lines the shared transcript reader supplies | `DONE` visible records with content, user text normalized as above, less a user request that is exactly `/compact` |
| first prompt (`session.rs::read_prompt_under`) | hook `transcriptPath`, validated | 64 KiB tail; on the opener, the whole file when the tail does not reach back over its interval | on an `invocationNum: 0` opener (`PreInvocation`), classifies step `initialNumSteps - 1` as a bare `/compact` (`Compacting`), else the newest completed user row after the newest `PLANNER_RESPONSE`, `CHECKPOINT`, or `/compact` row below `initialNumSteps` (`TurnStarted`), or routing only when none follows; with no `initialNumSteps`, falls back to `lastUserInput` for `/compact` and otherwise reads the latest completed visible user prompt ([Steering](#steering)). On `PostInvocation`, every non-`/compact` user row at or past `initialNumSteps` and before the next `PLANNER_RESPONSE` or `CHECKPOINT` row, joined by a blank line (`session.rs::prompt_taken_in_under`). Other hooks read no prompt |
| final message (`crates/rimz/src/agents/adapters/antigravity/session.rs::last_assistant_message`, and `crates/rimz/src/agents/adapters/antigravity/session.rs::messages` for rest ends) | hook `transcriptPath`, not validated, on `Stop`; `session_transcript` by conversation id, validated, on a rest-ended parked turn | 64 KiB tail, then whole file (`Stop`); whole file via `read_transcript_messages` (rest end) | on every `Stop` that decodes to `TurnEnded`, the newest `DONE` planner text after the last turn start (a bare `/compact` user row starts no turn, while `/compact <message>` does; when the tail holds neither a turn start nor an answer, it reads the whole file without a bound, and a file without a turn start counts as one turn). On a parked turn ended by a rest report, read only when `crates/rimz/src/cli/hooks/lifecycle/mod.rs::handle_lifecycle_frame` records that `TurnEnded`, taking the newest assistant message after the last user message (`crates/rimz/src/agents/adapters/antigravity/session.rs::messages` drops bare `/compact`), never on a rest `TurnInterrupted` or `AskResolved` |
| background shells (`session.rs::running_background_shells_under`) | hook `transcriptPath`, validated | whole file, lossily | on every `Stop` that decodes to `TurnEnded` with `fullyIdle: false`. Every running `MODEL` / `GENERIC` background-task start row not followed by a `SYSTEM_MESSAGE` finish row or server-restart notice becomes a `BackgroundShell` |
| subagent join | parent row's path, or rebuilt from the parent id | 64 KiB tail | [Subagents](#subagents) |

A turn with no answer returns no final text, never the previous turn's reply. A torn final record stays out of every tail until it completes. Once a hook records the prompt, a later discovery tail with no visible user record supplies no newer prompt, so the card keeps its launch description or hook prompt through a long turn.

## Subagents

Antigravity fires the ordinary hook set for each asynchronous or nested child, with the child's own `conversationId` and transcript and no parent id: the 1.5.14 binary defines `parentConversationId` and `rootConversationId`, but a capture found neither on any hook of a child or a nested child ([reference](../../externals/agent-adapter/antigravity-reference.md#subagents-and-background-tasks)). RimZ recovers the parent from the parent's transcript, where a completed `MODEL` / `PLANNER_RESPONSE` record holds an `invoke_subagent` call with ordered `Subagents` specs, and a later completed `MODEL` / `INVOKE_SUBAGENT` record's `content` returns one `{conversationId, logAbsoluteUri, workspaceUris?}` object per spec in the same order. This shape is live-verified, not documented upstream.

### The forward join

`crates/rimz/src/cli/hooks/lifecycle/observe.rs::correlate_subagent_observation` runs on a root `TurnStarted`, `TurnEnded`, or `ToolUsed`:

1. Known child. A prior row of this id with a parent supplies the relation, with no transcript read.
2. Trigger. Otherwise only a `TurnStarted` or an unparked `TurnEnded` tries a join, and the hook needs a pane and a worktree path.
3. Candidates. The candidates are the other Antigravity rows stamped on the same pane, newest first. Above 64 (`MAX_SUBAGENT_PARENT_CANDIDATES`) the join is skipped.
4. Match. `AntigravityAdapter::correlate_subagent` tests each candidate against its validated transcript. Exactly one candidate must match, and a match that resolves to the child itself is discarded.
5. Flatten. A candidate that is itself a child stands in for its root parent, so nested children attach to the root card.

A match sets the child's name from `TypeName`, its role from `Role`, its task from `Role` or else `Prompt`, and its prompt from `Prompt`. It also clears the hook's model hint, because the correlation carries no model. Later child hooks reuse the stored relation and keep their `modelName`. Child observations take no root launch environment or configured identity.

| Child signal | Becomes |
| --- | --- |
| `TurnStarted` | `SubagentStarted` |
| `TurnEnded`, unparked | `SubagentStopped { errored }` |
| `TurnEnded`, parked on background | unchanged, until the terminal `Stop` |
| `ToolUsed` | unchanged, keyed to the child |

### Parent validation

`session.rs::validated_subagents_under` reads the parent's 64 KiB tail. A request whose result falls inside the tail but whose `invoke_subagent` record lies before it leaves a result with no request, which voids the record. Some failures void every child of the parent transcript, and others drop one child:

| Scope | Failure |
| --- | --- |
| whole record | the parent path fails [path validation](#local-discovery), the parent workspace does not canonicalize, or the tail ends in a torn record |
| whole record | any line fails to parse as a transcript record |
| whole record | an `invoke_subagent` call does not parse, has no specs, or has a spec with both `Prompt` and `Role` blank or a blank `Workspace` |
| whole record | an `INVOKE_SUBAGENT` record is not `DONE`, has no pending request, or holds fewer objects than specs or a further object after them |
| whole record | a valid child id repeats, even when either copy would be dropped later |
| whole record | a request is still unmatched at the end of the tail |
| one child | the returned id fails `valid_conversation_id` |
| one child | `logAbsoluteUri` is not a `file:` URI, or not a valid transcript of that child id |
| one child | the spec's `Workspace` is relative (such as `branch` or `share`) or does not canonicalize. An absent `Workspace` or the literal `inherit` means the parent's workspace |
| one child | `workspaceUris` is present but empty, holds a URI that does not canonicalize, or does not contain the expected workspace |

A child then joins only when its id equals the result's id and its canonical hook workspace equals the expected workspace. A worktree child whose hook workspace differs stays a root.

### The reverse pass

1.1.2 buffers the parent transcript. In a two-child capture, both children's `PreInvocation` and `Stop` hooks ran before the parent's request and result records reached disk, and the file flushed before the parent's own `Stop`. The forward join therefore often fails, and a reverse pass catches up.

On every root `ToolUsed` or `TurnEnded`, `crates/rimz/src/cli/hooks/lifecycle/observe.rs::record_mapped_lifecycle_observation` calls `AntigravityAdapter::spawned_subagents`. It returns every validated child in the parent's tail. The store writer (`crates/rimz/src/store/writer/lifecycle.rs`) then emits a `SubagentStopped` for each child, errored when the child row is `failed`:

- A child with no parent is adopted (`SubagentAdopted`), unless its row is stamped on another pane. Adoption also restores a child that a supersession reap already hid ([instances.md](./instances.md#supersession)).
- A child already under this parent is reconciled (`SubagentReconciled`) while its row is still `running`, or when its model or tokens changed. A settled child with no change is skipped.

The pass treats a returned result as proof that the child finished, and no capture confirms that for an asynchronous child. A child still `running` is closed by its parent's next tool hook. Until the reverse pass runs, the supersession open-turn guard keeps the active parent from being reaped by a provisional child root ([instances.md](./instances.md#supersession)).

## Statusline context

The wrapper runs `RIMZ_AGENT_PID=$PPID exec rimz statusline feed --source antigravity`, which forwards the user's prior command and prints nothing when there is none. `statusline.rs::StatuslinePayload` needs `conversation_id` (or `conversationId`) and maps the rest into `AgentContext`:

| Payload field | `AgentContext` |
| --- | --- |
| `model.id` | `model_id`, with a recognized trailing qualifier removed |
| `model.display_name` | `model_display_name`, with a recognized trailing qualifier removed |
| `model.effort`, else the display-name qualifier, else the `model.id` qualifier when the display name carries none | `effort`, trimmed and lowercased |
| `(Thinking)` qualifier, from the display name, else from `model.id` when the display name carries no qualifier | `thinking_enabled` |
| `version` | `agent_version` |
| `plan_tier`, `email` | `account` plan and id, `metered: true` |
| `context_window` size, percentages, `current_usage` (`null` before the first model turn) | `tokens`. `current_context_tokens` stays empty, so the gauge comes from the percentages and window size alone |
| `quota`, its `gemini-` buckets only | `rate_limits`: `BestEffort` 5h and weekly windows stamped at `observed_at` ([Quota windows](#quota-windows)) |
| `tool_confirmation_pending: true` | a `NativeWait` settle stamped at observation time |
| `agent_state` `idle` with `task_count` absent or 0 and no pending confirmation, plus `subagents` entry statuses | no field: the feed appends a rest report that the hook drainer decides in log order, interrupting an open turn, finishing a parked turn when no live native subagent remains, and emptying `background_shells` ([Interrupt](#interrupt)) |

Antigravity puts the selector label, such as `Gemini 3.5 Flash (Medium)`, in both `model.id` and `model.display_name` ([reference](../../externals/agent-adapter/antigravity-reference.md#payload)). The recognized qualifiers are `(Low)`, `(Medium)`, `(High)`, `(XHigh)`, `(Extra High)`, `(Max)`, and `(Thinking)`, matched without case. `Extra High` maps to `xhigh`. An unknown parenthetical stays in the label. The `(Extra High)` and `(Max)` spellings come from the 1.3.3 effort list and have no label capture yet.

The `NativeWait` settle projects a `running` card to `waiting` while it is newer than the row's activity ([model.md](./model.md#waiting-and-asks)). It creates no ask and sends nothing to Antigravity. Any later hook advances the row's activity past the marker, so a missed `false` refresh clears itself.

RimZ reads no other statusline field. `cost` reached no 1.5.14 payload on an OAuth sign-in and RimZ prices the transcript instead ([Cost](#cost)), `subagents` carries no stable ids so RimZ reads only its entry statuses to gate a parked turn end, and `conversation_title` would replace RimZ's launch description on the card.

The plan, the account id, and `metered` reach the login's account record through the producer's live merge, and the windows reach the rate-limit cache, so every surface shows them from there ([the account record](./providers.md#the-account-record)). One session's payloads fill in stages: the first carry neither `quota` nor `plan_tier`. A payload without them is no reading, and what the record and the cache already hold stays.

## Account and balance

One print-mode run, `agy -p /usage --output-format json`, answers both account probes. It spends no model turn, fires no hook, and leaves no conversation ([reference](../../externals/agent-adapter/antigravity-reference.md#exit-timeout-and-read-only-commands)). RimZ reads no OAuth token and sends no pane input. The version probe returns `None` instead of running `agy --version` ([providers.md](./providers.md#the-out-of-band-probe)).

`crates/rimz/src/agents/adapters/antigravity/usage.rs::run` starts the `agy` that `locate_binary` finds, with the inherited environment plus:

- `SSH_CONNECTION`, and one newline on stdin. A logged-out `agy -p` otherwise waits 60 s for a sign-in and opens a browser. The SSH variable selects agy's URL-and-code flow, and the newline answers its code prompt, so the run exits within a second.
- the login env's `HOME`, when it carries one.
- a session of its own, so the child has no controlling terminal. Run from a terminal in the caller's session, a logged-out agy reads its code prompt from that terminal, not from stdin, and waits out the deadline. The default login's child calls `setsid` before it execs (`usage.rs::command`), and a named account's bubblewrap runs with `--new-session`.
- for a named account, a bubblewrap mount over agy's directory (`crates/rimz/src/agents/adapters/antigravity/usage.rs::mounted_command` binds the whole directory for a standalone account, and `crates/rimz/src/agents/adapters/antigravity/usage.rs::prepare_login_probe_command` prepares the shared-account probe). `crates/rimz/src/agents/adapters/antigravity/usage.rs::holds_credential` requires `antigravity-oauth-token` in the account directory to be a non-empty regular file (an empty placeholder or missing file never counts as a credential). For a shared account, an absent or non-directory account home refuses with `AccountProbeError::SourceUnavailable` without creating the directory or either placeholder, preserving `home missing`; when the account directory exists, the default token is absent, and the account holds no non-empty token, the probe runs agy directly without bubblewrap (writing nothing and leaving the default directory untouched); otherwise each missing token endpoint (and a missing default directory when the account holds a token) is created as an empty `0600` regular file through `crates/rimz/src/agents/provider_file.rs::create_empty_if_absent` (matching reconcile's placeholder for the account and preventing bubblewrap from leaving a read-only `0444` mountpoint at the default token) before bubblewrap binds the login files over the default directory. A symlink or directory at either token path refuses with `AccountProbeError::SourceUnavailable`; a symlinked optional `installation_id` is omitted. A login found while the account directory holds no non-empty credential file is another account's (`Read::ForeignLogin`): it reads as unavailable, and a launch refuses it (`AccountCapability::foreign_login`). With no credential file, a launch proceeds only on a definite `Read::LoggedOut`: a read that failed refuses too, since it cannot rule out the keyring login.
- a 10 s deadline (`DEADLINE`), after which the process group is killed and reaped. An offline run took 7.3 s on 1.5.12, a logged-in one at most 2.8 s.

`usage::classify` reads stdout as one JSON envelope, and `Read::account` and `Read::usage` map the one reading onto both probes:

| Outcome of the run | `probe_account` | `probe_account_usage` |
| --- | --- | --- |
| exit 0, `status: "SUCCESS"`, `command.name: "usage"`, windows fold | `Found`, `metered: true`, and the credential file's account id | `Found`, default identity, the windows, no plan |
| the same envelope with no bucket | `Found` | `NoCredentials` |
| the same envelope whose buckets fail the fold, a type mismatch included | `Found` | `Failed` |
| `status: "ERROR"` whose `error` contains `not available with a Gemini API key`, at any exit (1.5.14 under `GEMINI_API_KEY` with `modelProvider: "gemini"`, exit 2) | `Found`, plan `API key`, `metered: false`, no account id | `NoCredentials` |
| any other `status: "ERROR"` whose `error` contains `authentication` in any case, at any exit | `LoggedOut` | `NoCredentials` |
| any other `ERROR` envelope, at any exit | `Unavailable(SourceUnavailable)` | `Failed` |
| a non-zero exit without an `ERROR` envelope | `Unavailable(ExitNonZero)` | `Failed` |
| the deadline | `Unavailable(TimedOut)` | `Failed` |
| no binary, or a failed spawn | `Unavailable(SpawnFailed)` | `Failed` |
| exit 0 without that envelope | `Unavailable(UnparseableOutput)` | `Failed` |
| `RIMZ_OAUTH_USAGE_OFFLINE` set, `agy` never started | `Unavailable(SourceUnavailable)` | `Failed` |

The `/usage` reading names no email, so the usage identity carries no owner key and its default `KindWide` scope ([providers.md](./providers.md#the-credits-cache-and-usage-identity)). Where the CLI stores tokens in files rather than the keyring, `Read::account` adds the account id from the `id_token_email` field of `<credential home>/antigravity-oauth-token` (`crates/rimz/src/agents/adapters/antigravity/session.rs::credential_home`: the account's own directory for both shared and standalone logins, else `$HOME/.gemini/antigravity-cli`), stamped at the file's mtime; it reads no other field and never logs the value. `rimz accounts show` and `rimz accounts list --json` print it as the account id, as they do Cursor's email. On a keyring install only the statusline names the account. The plan comes only from the statusline, through the account record, so `rimz accounts list` and the sidebar show it once a session has reported it, with no expiry. An API-key reading is the exception: it states plan `API key` and `metered: false`, which differs from an OAuth login's metering, so the account merge starts the record again and drops the login's account id and plan; under the key the statusline carries no plan or email, so it never sets the record back to metered ([reference](../../externals/agent-adapter/antigravity-reference.md#exit-timeout-and-read-only-commands)).

`usage::read` keeps each reading for 60 s (`REUSE`) per credential home (`crates/rimz/src/agents/adapters/antigravity/session.rs::credential_home`, so shared logins sharing one history directory keep distinct quota and launch-refusal entries) within one process, whichever probe asks and whatever the reading was, so one `rimz accounts list` starts `agy` once. The reuse is per process, and the sidebar's two lanes run in different ones: the account lane probes in the sidebar host (`crates/rimz/src/sidebar/refresh/accounts.rs`), while the usage read runs in a detached `rimz agents refresh-usage` helper (`crates/rimz/src/sidebar/refresh/usage.rs`). A cold pass therefore starts `agy` twice, and the steady state is the usage claim cadence (every 5 min while an agent is in use, 60 min once a read settles on a login failure, 3 h idle) plus one account start per `ACCOUNTS_TTL` (10 min), where a failed account probe retries after `ACCOUNTS_RETRY_TTL` (10 s), doubling up to that window. The reuse stamp is taken before the run, and the windows carry the run's start as `observed_at`.

### Shared-history login mounts

Shared Antigravity accounts run agy on `~/.gemini/antigravity-cli` with bubblewrap file binds for `antigravity-oauth-token` (always, backed by an empty `0600` placeholder until signed in) and `installation_id` (only when both the account directory and `~/.gemini/antigravity-cli` hold one). Live checks on agy 1.5.16 and bubblewrap 0.11.1 (scratch copy of the default directory) established:

- Print-mode `agy -p /usage` and interactive TUI turns run under the two file binds on the account's login without sign-in or terms prompts, and `agy --conversation <id>` without binds resumes that conversation on the default login from the same transcript file.
- An expired bound `antigravity-oauth-token` is refreshed in place (same inode, updated token and expiry), leaving the covered default token untouched and creating no stray temp file.
- An empty bound `antigravity-oauth-token` reads as signed out (`agy -p /usage` exits 1 with an authentication error and writes nothing to either file).
- Before a bubblewrap file bind runs on a missing default `antigravity-oauth-token`, RimZ creates the missing `~/.gemini/antigravity-cli` directory (on launches and on probes of a signed-in shared account) and creates the missing default token file at mode `0600` through `crates/rimz/src/agents/provider_file.rs::create_empty_if_absent` (bubblewrap itself would create a read-only `0444` mountpoint that refuses later in-place writes), and refuses a symlink or directory at the target token path. Probes where the account directory is absent return `SourceUnavailable` without creating anything, and probes where the account directory exists, the default token is absent, and the account holds no non-empty token run without bubblewrap and write nothing.
- Observed on agy 1.5.16 (scratch `HOME`, fake token, `strace`, no model turn): `/logout` on a normal token unlinks `antigravity-oauth-token` (`openat` `O_RDONLY`, then `unlinkat = 0`), while on a token carrying `wif_provider` it truncates and rewrites in place (same inode). Static disassembly of agy 1.5.16 shows token writes use `os.WriteFile(path, data, 0600)` (`O_WRONLY|O_CREAT|O_TRUNC` in place, never a temp-file rename).
- Single-file bind detach hazard: if the host unlinks or renames over `~/.gemini/antigravity-cli/antigravity-oauth-token` while shared-account panes are running (which `/logout` on `default` with a normal token does), the kernel detaches the single-file bind in those running panes. Those panes then see `default`'s token file (reading `default`'s login once recreated, and writing any later token refresh into `default`'s file). The live bind guard repairs only protected identity entries, not mounted login files ([sandbox.md](../sandbox.md#mounted-account-homes)). An in-place sign-in or refresh write on `default` keeps the same inode and does not detach an existing bind.

Not live-tested on agy 1.5.16: a live trace of interactive sign-in or refresh write (including sign-in inside a shared-account pane starting from the empty placeholder), `/logout` inside a shared-account pane, a keyring-backed machine, and two distinct logins writing `~/.gemini/antigravity-cli` concurrently.

### Quota windows

`usage.rs::rate_limits` folds quota buckets into at most two windows, for both sources: the buckets of every `/usage` group, and the statusline's `quota` map. Only a bucket whose id starts with `gemini-` counts, and the id's suffix gives its period: `5h` means five hours and `weekly` a week. Every other bucket, the `3p-` buckets of Claude and GPT models included, is never parsed, so its content cannot change or fail a reading.

- Each enabled Gemini bucket with a remaining fraction joins its period. A disabled bucket, or one without a fraction, marks the period present and contributes nothing.
- The period's window is the bucket with the smallest remaining fraction. A tie takes the later reset.
- A present period with no usable bucket publishes a window with unknown fill and reset. An absent period publishes no window, so a weekly-only response yields one window.
- Used percentage is `100` only at a remaining fraction of exactly `0`. Otherwise it is rounded and capped at `99`.
- A Gemini bucket of the wrong shape, a usable bucket's fraction outside `0..=1`, or a reset that is missing, unparseable, or not in the future, rejects the whole reading. So does a `/usage` response whose buckets hold no Gemini one. A `/usage` response with no bucket, and a statusline payload whose map holds no valid Gemini window, are no reading.

The `/usage` windows are `Authoritative` and the statusline's are `BestEffort`, as Claude's are ([providers.md](./providers.md#window-fusion)), and RimZ invents no credits or dollars from them. They never arm auto-continue, because no Antigravity stop class is certified recoverable ([providers.md](./providers.md#auto-continue)).

## Cost

`spend.rs` reads `brain/<conversation>/.system_generated/logs/transcript_full.jsonl` under the login's provider home (`config_home`). `transcript.jsonl` repeats the same rows and is never a source. Each row carrying `input_tokens` (a completed `MODEL` / `PLANNER_RESPONSE`, or a compaction's `SYSTEM` / `CHECKPOINT`) becomes one entry: message id `<conversation>:<step_index>`, thread id the conversation, time from `created_at`. `input_tokens` excludes cache reads and `output_tokens` already counts thinking, so `input_tokens`, `cache_read_tokens`, and `output_tokens` are disjoint inputs to `Pricing::cost_of`. The model is the row's slug with its effort suffix (`-low`, `-medium`, `-high`, `-xhigh`, `-max`) removed by the same `mod.rs::split_model_effort` the hook decoder uses. Pricing tries the raw slug, then that base name, with `PriceBook::exact_price` only, so a related model never lends its rates ([spending.md](./spending.md#resolving-a-model)). A model neither prices keeps its tokens without dollars and is recorded unknown under its base name. A `CHECKPOINT` row names no model, so its tokens count at $0 and record no unknown model. Rows name no working directory, so Antigravity spend carries no workspace attribution.

The dollars are a list-price estimate: Antigravity quota is measured by work, and a plan bills no tokens. That is why `account_spend` is partial, which keeps Antigravity out of account-day caps.

Response timing for `MODEL` / `PLANNER_RESPONSE` rows lives in [spending.md](./spending.md#response-timing).

The statusline carries no dollars into RimZ: upstream documents a `cost` object, but no 1.5.14 payload on an OAuth sign-in carried one, so whether it is cumulative or survives a resume is unknown ([reference](../../externals/agent-adapter/antigravity-reference.md#cost)). The card's cost is the conversation's transcript total instead. Every hook, producer tick, and transcript-watch write runs the adapter's context refresh (`crates/rimz/src/agents/adapters/antigravity/spend.rs::refresh`): it stats `transcript_full.jsonl`, even when the hook names `transcript.jsonl`, and, when the file has new bytes, prices only the rows written since the last refresh, resuming a stored fold. A file with no new bytes costs one stat, loads no price book, and writes nothing. The refresh patches cost alone, since the statusline owns the model, tokens, and wait. A turn end whose refresh set no cost falls back to the whole-file total (`supplement_realtime_cost` through `session_cost_usd`), and later statusline payloads keep the figure ([spending.md](./spending.md#live-cost-coverage)). So the price appears with the first priced row and moves as the file grows, mid-turn included. A transcript that comes back shorter folds again from its start, and when that total is below the stored one, the fresh fold, its cursor at the new end of the file, carries the stored total as its floor: the figure never drops, and each row written after the cut adds to it once. A rewrite in place at the same or greater length goes unseen, since the fold resumes at its byte offset: the 1.5.12 and 1.5.13 captures saw agy only append, `/compact` included, but the 1.1.13 changelog names a rewrite during compaction, and `/rewind` is uncaptured. It counts toward room spend and per-agent and room budget caps.

`ContextCapability::prompt_cache_ttl` declares one hour for every sign-in, the upper end of the 45 to 60 minute bracket the 1.5.15 probe measured ([reference](../../externals/agent-adapter/antigravity-reference.md#prompt-cache)). Antigravity reports no cache write retention, so no observation overrides it, and only `harness.prompt_cache_ttl.antigravity` changes it: `fallback` does not reach the kind. With the default one-minute margin, idle compaction and cache pings fire at 59 minutes, which only one sample shows still warm.

## Known gaps

`rimz coverage --wiring` prints the declared concern and lifecycle verdicts. These gaps have a reason worth recording:

- No recoverable failure. No 1.3.3 error class carries a provider-owned typed discriminator captured twice, so every errored `Stop` is terminal. Message text, error-shaped objects, quota exhaustion, and a stalled pane never arm auto-continue, and a supervised run or loop attempt does not survive an Antigravity limit.
- Subagents are partial. Child hooks are documented, but the parent's request and result records are live-verified only. An errored invocation may write an `INVOKE_SUBAGENT` record with status `ERROR` ([reference](../../externals/agent-adapter/antigravity-reference.md#transcripts)). Its shape is uncaptured, and the non-`DONE` status voids every sibling in that record.
- The reverse pass closes children on a returned result, which may arrive before an asynchronous child finishes ([The reverse pass](#the-reverse-pass)).
- The `Stop` final-message read takes the hook's `transcriptPath` without path validation, and its fallback reads the whole file.
- No billed ledger. Machine-readable credits, API keys or BYOK, and account-day dollar caps are unsupported. Spend is a list-price estimate from the transcripts, and carries no workspace.
- Permission wait detail, durable asks, artifact-review waits, and structured answers are unsupported. The user answers native prompts in the Antigravity pane.
- Remote control is unsupported. Upstream offers a daemon (`agy remote-control`) and session-scoped connections (`--remote-control`, `/remote-control`), and RimZ wires neither ([reference](../../externals/agent-adapter/antigravity-reference.md#remote-control-mcp-plugins-and-custom-agents)).
- Tool statistics are partial. Names come only from live `PostToolUse.toolCall`, on releases that send it and for tools the three matchers cover. A lazily loaded MCP tool counts only as `call_mcp_tool`, without its server or tool name, an eager one (`mcp_<server>_<tool>`) not at all, and transcript history is not counted.
- Background shells appear from the first `Stop` after agy backgrounds a task, not from the backgrounding tool call itself, because agy fires no installed hook naming the task when it transitions to the background. Every background-task start row in the transcript is listed (native subagents write no such row). A cancel done interactively in the `/tasks` panel fires no hook and writes no transcript row until the next prompt; when it cancels the last running task, the rest-report path empties `background_shells` and finishes the parked turn when no live native subagent remains ([Interrupt](#interrupt)), while cancelling one of several running tasks clears on the next `Stop`, and an Escape mid-turn while an earlier command still runs keeps `task_count: 1` so that turn stays `running` until the next turn or a manual compaction.
- Registration is derived. `SessionStart` stays unwired, since on 1.5.14 it fires on no resume and carries no `source`.
