# Claude Code adapter

> Read [model.md](./model.md) for the provider-neutral agent model and [adapter.md](./adapter.md) for the integration layer every adapter implements. Accounts, balances, and spend are in [providers.md](./providers.md); the raw upstream protocol is in [claude-reference.md](../../externals/agent-adapter/claude-reference.md).

This doc is the single home for everything Claude-specific: how each native event maps to a lifecycle signal, how the decision shapes render, and how Claude's transcript, statusline, account, and spend surfaces fold onto RimZ's internal types.

## Hooks and lifecycle

Native event → internal mapping. The table says *which native events are wired* and *how each maps*; the behaviour they drive is the state machine in [model.md](./model.md), and the upstream events, payloads, and decision schema are in [claude-reference.md](../../externals/agent-adapter/claude-reference.md).

| Native event                  | Channel       | `decode_hook` → [`LifecycleSignal`](../../../crates/rimz/src/agents/lifecycle.rs)                                          |
| ----------------------------- | ------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `SessionStart`                | lifecycle     | `Registered`; `startup`/`clear` stamp fresh lineage; `compact` maps to `CompactionEnded { auto: None }` - model, context window/tokens (transcript) |
| `UserPromptSubmit`            | lifecycle     | `TurnStarted` - sanitized `task`/`prompt`; refresh context/tokens                                                            |
| `SubagentStart`               | lifecycle     | `SubagentStarted` - keyed by child `agent_id`; `parent_agent_id` = `session_id`; `task` = `subagent_type`/`description`      |
| `SubagentStop`                | lifecycle     | `SubagentStopped { errored: false }` - child row; upstream supplies no outcome field, so the adapter closes the bracket without inventing failure; keeps the type label and parent link |
| `Stop`                        | lifecycle     | `TurnEnded { errored, parked_on_background }` - refresh context/tokens; pending `background_tasks` or `session_crons` paint a `⋯ bg` marker |
| `StopFailure`                 | lifecycle     | no lifecycle envelope - writes `AgentContext.turn_error`; rollup stays `running`                                             |
| `SessionEnd`                  | lifecycle     | `Ended` → stamps `ended_at`; runtime hides the retained resumable row (`ends_session`)                                      |
| `Notification`                | lifecycle     | none (silent)                                                                                                                |
| `PreToolUse` (broad)          | lifecycle     | `ToolUsed { mutates: false, edits: false }` as proof-of-work only; persisted when it reconciles a resting row, clears waiting, or closes a compaction bracket |
| `PostToolUse`                 | lifecycle     | `ToolUsed { mutates, edits }` for every tool; non-mutating tools use proof-of-work persistence, including answered asks; `edits` for a file-writing tool; context/tokens |
| `PreCompact`                  | lifecycle     | `Compacting` - stamps the head, keeps the prior status (see [model.md](./model.md#the-compaction-bracket))                   |
| `PostCompact`                 | lifecycle     | `CompactionEnded` with known trigger - safely redundant as a close; carries the auto/manual trigger bit                       |
| `PermissionRequest`           | awaiting-user | `AwaitingInput { Permission }` → `waiting` - sync                                                                            |
| `PreToolUse: ExitPlanMode`    | awaiting-user | `AwaitingInput { PlanApproval }` → `waiting`                                                                                 |
| `PreToolUse: AskUserQuestion` | awaiting-user | `AwaitingInput { Question }` → `waiting`                                                                                     |

**Ask tools self-classify.** `ExitPlanMode` and `AskUserQuestion` ride the broad `PreToolUse` hook and self-classify from `tool_name`, so they need no dedicated matcher (Claude runs every matching matcher group, and the broad entry already covers them). Under manual mode Claude 2.1.205 also emits `PermissionRequest` for those native ask tools; the adapter recognizes their tool names and ignores that duplicate lifecycle callback so it cannot replace the structured ask id.

**Tool events split by mutation.** A non-blocking `PreToolUse` is proof-of-work only: it does not join `activity_events`, and hook ingestion persists it when `step` reconciles a resting row back to `running`, clears waiting, or closes an open compaction bracket. Every `PostToolUse` records a signal; read-only and answered-ask completions use the same non-mutating proof-of-work shape, so they stay out of the durable lifecycle log unless they clear waiting, reconcile a resting row, or close a compaction bracket. The `mutates` bit marks durable tool work, and the `edits` bit marks the file-writing subset (`tool_edits_files`), which moves the turn's phase from reasoning to acting ([model.md → Turn phase](./model.md#turn-phase)).

**Turn endings.** A `Stop` carries the raw `errored` bit (`stop_payload_errored`) and whether in-flight `background_tasks` or scheduled `session_crons` (Claude Code v2.1.145+) remain; the [`step`](./model.md#the-state-machine) table turns those into the final status (a clean parked stop stays `running`, an error always wins). `StopFailure` is Claude's provider-error certificate: `rate_limit` writes a rate-limit paused marker, `overloaded` writes the backoff paused marker, unknown errors classify their capped assistant label the same way as the transcript tail, and no `agent.lifecycle` envelope is appended so the rollup stays `running`. The transcript death certificate is the backstop for old Claude builds or sessions whose hooks were installed late ([Turn-death marker](#turn-death-marker), [claude-reference.md](../../externals/agent-adapter/claude-reference.md#transcript-death-certificate)).

**Conversation replacement.** A root `SessionStart` from `startup` or `clear` stamps [`SessionOrigin::Fresh`](../../../crates/rimz/src/agents/observation.rs); `resume`, `compact`, and unknown sources leave lineage unset. When `/clear` creates a new fresh session id in the same pane, the shared supersession rule reaps the older fresh row even though Claude keeps the same process.

**Answer delivery.** `AskUserQuestion` supports structured single picks, multi-select, and free text through the native TUI. Permission asks expose only `allow`, which sends digit 1 for the stable first menu action. Plan approvals expose only caution-marked `approve`, which sends Shift-Tab and engages accept-edits mode. Each kind's Escape rejection path emits neither `PostToolUse` nor `Stop` in Claude Code 2.1.205, so deny, keep-planning, refinement text, persistent grants, and manual-review approval stay in the pane.

**Neutral output.** Claude's neutral path is empty stdout. Permission, plan, and question prompts remain in Claude's own UI, and the sidebar's `?` row routes you there.

**System-prompt replacement.** Claude's typed launch matcher is `--system-prompt-file`. With only `system-prompt-file`, RimZ preserves the declared path; with ordered `append-system-prompt-files`, the shared exec wrapper writes the composition to a content-addressed runtime artifact and passes that path through the same replacement flag. Claude's native append flag is intentionally outside the typed preset surface so every adapter keeps identical replacement semantics.

**Remote-control sessions.** Hooks inherited by a `claude remote-control` SDK child are infrastructure events, so hook ingestion returns the empty neutral output before workspace resolution or store access. A non-empty `CLAUDE_CODE_SESSION_ACCESS_TOKEN` or `CLAUDE_CODE_ENVIRONMENT_KIND=bridge` identifies the session directly; a 32-level process-ancestry walk back to `claude remote-control` covers SDK children that omit those environment markers. The remote session remains owned by Claude's web UI and does not create a RimZ agent card.

**Remote-control host readiness.** [`claude/remote_control.rs`](../../../crates/rimz/src/agents/adapters/claude/remote_control.rs) owns the full Claude host protocol: executable and version probing, settings and authentication conflicts, setup guidance, and the exact `claude remote-control --spawn worktree` argv. Room start, doctor, daemon-view reconciliation, and runtime toggles consume that provider-native readiness through the root coordinator rather than rebuilding Claude rules. Passing `--spawn` explicitly also settles Claude's second interactive question, the spawn-mode chooser, which only appears when the flag is absent.

**Remote-control consent.** [`claude/remote_consent.rs`](../../../crates/rimz/src/agents/adapters/claude/remote_consent.rs) records the one-time `Enable Remote Control? (y/n)` answer as `remoteDialogSeen` in `${CLAUDE_CONFIG_DIR:-$HOME}/.claude.json`, which is the gate Claude itself reads before serving. The key is inserted textually as the root object's first member so Claude keeps its own key order and formatting across a config RimZ does not own, and the result is re-parsed before it replaces the file. Seeding fills an unset value only: an explicit non-`true` value stays as the operator left it and readiness refuses with the fix. Claude records the flag whether the answer was `y` or `n` and exits `0` on refusal, so the flag alone never proves consent — the RimZ toggle is what carries the operator's intent.

**Remote-control host liveness.** [`claude/remote_liveness.rs`](../../../crates/rimz/src/agents/adapters/claude/remote_liveness.rs) reads `<config>/projects/<project>/bridge-pointer.json` and confirms the recorded pid and kernel start token still name a live process, the same evidence Claude uses to decide whether to reuse a pointer. A managed pane keeps the joined argv as its title for its whole life, so pane presence alone reads healthy long after the child stops serving; the pointer is what the `⇅ rc` flag and doctor's serving line resolve. No pointer reads as no evidence rather than as failure.

**Install.** Installed ask hooks use the short lifecycle timeout because they record the waiting observation and return neutral. Install merges non-destructively into `~/.claude/settings.json` under per-matcher `_rimz_managed` markers; only `PermissionRequest` carries `_rimz_sync = true`, and an existing async marker on it is a hard install error.

**Subagents.** Claude routes Task-tool children through `SubagentStart`/`SubagentStop`, keyed by the child `agent_id` with the payload `session_id` captured as `parent_agent_id`, so the child gets its own row nested under its parent (see [model.md](./model.md#instance-identity-and-age) and [sidebar.md](../sidebar/sidebar.md)). Identity is keyed, never guessed: the shared [`resolve_subagent_identity`](../../../crates/rimz/src/agents/mod.rs) requires a child id distinct from the parent. A subagent event missing one is **quarantined** — it yields no observation (logged at `error!` under `rimz::agent::lifecycle`) rather than folding onto, and renaming, the parent's row. The child's type label is identity, not activity: the reducer carries it forward, so a `SubagentStop` that omits or blanks `agent_type` leaves an already-started child labeled rather than degrading it to a `subagent <id>` placeholder. A stop-only child with no type is ignored at reduction time; it lacks enough identity to create a sidebar child row. The published stop payload exposes the final message and child transcript path but no outcome or exit code, so the lifecycle close stays non-errored.

Claude runs `/btw` as a sidechain that emits only `SubagentStop`, with a short child `agent_id` and the main session as `parent_agent_id`; it emits no start or prompt hook and writes no main-session transcript entry. The stop-only observation stays out of the child rollup, touches the parent's activity heartbeat, and pulses an already-open parent active-time span without opening one.

Esc can end a child without emitting `SubagentStop`. On the parent's next `PostToolUse` or `Stop`, the adapter enumerates the provider-owned `subagents/agent-*.jsonl` files and returns only children whose own newest conversation record is the `[Request interrupted by user` marker. The record's `agentId` must match the child filename, so nested-child replay cannot settle its parent. The store derives a non-errored close: when it adopts a missing child, `.meta.json` supplies identity and the child transcript supplies usage; when it reconciles an existing child, the hook-established identity carries forward while transcript model and tokens may update. If Esc interrupts the whole parent turn, no parent hook remains to trigger that repair; the next prompt's supersession reap heals the display, and that turn's first parent tool use or turn end closes the durable child bracket.

### In-subagent attribution

Claude stamps `agent_id` on *every* payload fired inside a subagent ([claude-reference.md](../../externals/agent-adapter/claude-reference.md)), so attribution is total: only the `Subagent*` brackets fold to the child's rollup, and any other event carrying a distinct `agent_id` — a backgrounded child's `PreToolUse`/`PostToolUse`, an in-subagent `PreCompact`/`PostCompact` — is dropped at the adapter ([`resolve_root_identity`](../../../crates/rimz/src/agents/mod.rs), logged at `debug!`). The lifecycle channel is bracket-grained for children; per-tool child activity rides the child-keyed activity heartbeat ([model.md → Liveness](./model.md#liveness-and-presence)). The drop is load-bearing for attention: folded onto the parent, a backgrounded child's tool events would advance the parent's `last_activity` past `waiting_since` and release its `waiting` row while the parent is still blocked.

## Context and transcript

Claude names the active session log in every hook payload's `transcript_path`. Each assistant line carries a `message.usage` block; the newest one wins:

| Transcript field                                                          | Internal                                  |
| ------------------------------------------------------------------------- | ----------------------------------------- |
| `usage.input_tokens` + `usage.cache_read_input_tokens` + `usage.cache_creation_input_tokens` | context tokens (the gauge numerator) |
| context tokens + `usage.output_tokens`                                    | `total_tokens`                            |
| `usage.input_tokens`                                                      | `fresh_input_tokens`                      |
| `usage.cache_read_input_tokens`                                           | `cache_read_input_tokens`                 |
| `usage.cache_creation_input_tokens`                                       | `cache_write_input_tokens`                |
| `usage.output_tokens`                                                     | `output_tokens`                           |
| `message.model`                                                           | `model` (bare id — no capability marker)  |

The four components ride alongside the total they sum to, so the card reports where the window went rather than one opaque figure — a warm session is mostly cache reads, and a 250k-token gauge backed by cache reuse reads very differently from 250k of fresh input. A transcript that opens with no assistant usage yet reports `total_tokens = 0` (the gauge baseline) and leaves the split `None`: unknown, never four asserted zeroes.

The local context refresh also folds every assistant usage entry into session-cumulative input, output, cache-write, and cache-read counters. The transcript byte cursor and sums ride in `LocalSpendFold`, so steady refreshes parse only appended lines; truncation restarts the fold. A hook-provided transcript path wins, the stored path is the steady-state fallback, and `<config>/projects/*/<session_id>.jsonl` discovery selects the newest readable match. The projection updates `AgentTokenUsage.session_usage` while keeping the statusline's current-window fields and cost authoritative; whole-context statusline writes retain the folded session projection.

A subagent payload carries two transcripts — `transcript_path` is the parent's and `agent_transcript_path` is the child's. Child usage and model resolve from `agent_transcript_path` alone; without it they stay unknown rather than inheriting the parent's figures onto the child's row.

The adapter's `parse_transcript_messages` function is the single conversation parser for Claude transcripts. It reads main-thread `user` and `assistant` entries with timestamps, filters sidechain replay, and excludes API-error assistant entries from conversation output; `stream_assistant_messages` filters that normalized parse for supervised streaming.

### Local session discovery

Claude local-session discovery reads each configured project store from a valid `CLAUDE_CONFIG_DIR` override, otherwise from the XDG Claude directory and `~/.claude`. The elected room producer batches the exact admitted Claude workspaces and distributes normalized observations with adapter wiring through one `agent-projection.json`; consumer folds parse that publication once and never read project stores. The absolute workspace path maps to `projects/<bucket>` by replacing every non-alphanumeric path byte with `-`; the first record carrying both `cwd` and `timestamp` within the first 32 lines and 64 KiB must still name the exact workspace, which makes that lossy bucket name an index rather than an authority.

The producer snapshot keys the ordered config roots and exact normalized workspace batch. It retains every recursively visited project directory and known JSONL candidate: a directory topology change rebuilds the catalog, while a changed selected file alone re-runs its bounded head and tail validation. Restatting the whole known catalog before newest-512 selection lets an older transcript whose mtime advances re-enter without a recursive walk; unchanged accepted and rejected heads remain cached until their stamps or the 30-second backstop change.

Only `*.jsonl` files whose stem is a UUID become root-session observations. Metadata rows such as `mode`, `permission-mode`, `bridge-session`, and `file-history-snapshot` may precede the first session record; that record must not set `isSidechain`. The newest tail-record timestamp supplies the activity bound, with file mtime as the fallback. Discovery returns at most the 512 newest candidates for each admitted workspace, so one workspace cannot evict another from a batched call; each accepted transcript keeps its filename UUID as the exact `claude --resume` identity. These observations are identity-only: hooks remain authoritative for lifecycle state, prompts, waits, asks, compaction, context, and clocks on an exact durable session.

Claude writes only the bare model id, so the **window divisor is resolved by the caller, not the transcript**: [`context_window_for`](../../../crates/rimz/src/agents/adapters/claude/mod.rs) reads the `[1m]` marker off the *hook payload's* `model` (1,000,000 tokens) and otherwise assumes the 200,000 standard window, then scales the context tokens to `context_pct`. The marker rides only the payload, never the transcript, so resolving the payload model first is what keeps the 1M gauge correct.

**Rich context.** Claude `exec`s its configured `statusLine` command on every render and pipes a JSON blob to stdin (the full schema is in [claude-reference.md → Statusline JSON](../../externals/agent-adapter/claude-reference.md#statusline-json)). Install points `statusLine` at `rimz statusline feed --source claude`; [`observe_context`](../../../crates/rimz/src/agents/adapters/claude/statusline.rs) parses that blob into `AgentContext`. When the user already has a `statusLine`, install **wraps** it rather than replacing it: it captures the JSON, passes it unchanged to the original command, and forwards that command's stdout and exit code, so rendering is visually identical. The original is stored verbatim under `_rimz_wrapped` and restored on uninstall. The wrap is a visible security surface — the consent gate summarizes it and the install diff shows it in full — and its child's stdio is fully piped, never inherited. Field-exact shapes are the inline goldens in [`statusline.rs`](../../../crates/rimz/src/agents/adapters/claude/statusline.rs). Claude's statusline `cost.total_cost_usd` is live-session-only and reads `0` on resume, so turn-end card cost reconciles upward to the transcript-priced session total through `supplement_realtime_cost`.

Install wraps Claude's per-child `subagentStatusLine` the same way (at `rimz statusline feed --source claude --subagent`). That feed harvests each task's `description`, `tokenCount`, and `startTime` — parsed by [`subagent_statusline.rs`](../../../crates/rimz/src/agents/adapters/claude/subagent_statusline.rs) — into a per-child sidecar the sidebar folds onto the subagent row (see [sidebar.md](../sidebar/sidebar.md)). It also derives `subagents/agent-<id>.jsonl` from the payload's parent `transcript_path` and advances a byte cursor through that child's usage-bearing assistant records. Each request is priced under its own model and cache tier; the cursor retains cumulative cost, the newest child `message.model`, and the last request key so a contiguous richer duplicate replaces rather than doubles its earlier record. The retained model paints the running child until `SubagentStop` supplies lifecycle-authoritative transcript metadata. A request with a plausible model absent from the price table poisons display of the cumulative figure instead of publishing a partial sum. The cursor records that price book's file fingerprint, stays on incremental suffix reads while it is unchanged, and replays the child transcript once after a pricing refresh so the figure can heal. The figure remains display-only because the parent session already includes subagent spend. It is enrichment for RimZ's own expanded card, not a row override, so Claude's panel renders unchanged. The consent gate summarizes both wraps and the install diff shows them in full.

### Turn-death marker

Claude's `StopFailure` hook is the precise provider-error certificate, and the transcript tail is the backstop when that hook did not fire or was installed late. On each statusline push, [`detect_turn_error`](../../../crates/rimz/src/agents/adapters/claude/statusline.rs) scans the bounded tail newest-first and lets the **first conversation-bearing entry decide**: an `assistant`/`user` entry with a parseable `timestamp`, skipping sidechain replay and non-conversation records (`system`, `file-history-snapshot`, `summary`). A flagged `assistant` entry (`isApiErrorMessage: true`) emits `AgentContext.turn_error` with `at`, a capped label, and a `class`: labels containing "spend limit" become `PausedSpendLimit`; labels containing "usage limit", "session limit", "rate limit", "quota", or "too many requests" become `PausedRateLimit`; labels containing "overloaded", "server is busy", "server error", "internal server error", "service unavailable", "bad gateway", "gateway timeout", "stalled", "timed out", "timeout", "connection error", "connection closed", "connection reset", "connection lost", "socket hang up", "broken pipe", "econnreset", "mid-response", "mid-stream", or "network error" become `PausedOverloaded`; other API errors become `Failed`. Anything else means alive or recovered. The marker is display-only enrichment — the projection in [model.md → Displayed status](./model.md#displayed-status) pauses or fails the row, and the rollup never changes.

### Turn-interruption marker

Esc emits no root lifecycle hook. Claude instead appends a timestamped `user` record whose text begins `[Request interrupted by user` (including the `for tool use` variant). The same newest-first statusline scan emits `AgentContext.turn_interrupted` when that record is the latest conversation-bearing entry. A marker newer than `last_activity` settles a falsely `running` row or an Esc-cancelled `waiting` ask to `idle`; any newer hook activity self-clears it. The root marker refines display and delivery gates while the durable rollup keeps the provider-reported status; child markers drive the durable subagent repair described above.

## Account and balance

[`claude auth status`](../../externals/agent-adapter/claude-reference.md#auth-surface) maps `subscriptionType` to `plan` and derives `metered` from the normalized `authMethod`: `apiKey` is unmetered, another non-empty method is metered, and an absent method leaves metering unknown. [`claude/account.rs`](../../../crates/rimz/src/agents/adapters/claude/account.rs) owns the shared 5h/7d duration and utilization normalization. The statusline parses epoch reset seconds and marks its windows `BestEffort`; [`oauth_usage.rs`](../../../crates/rimz/src/agents/adapters/claude/oauth_usage.rs) reads `~/.claude/.credentials.json`, parses RFC 3339 resets, calls Claude's usage endpoint, and marks the same normalized windows `Authoritative`. `extra_usage` maps cents to `ExtraCredits::Known { used_usd, limit_usd }` or `Disabled`. The account/balance model these fields fold into is [providers.md](./providers.md).

**Refresh cadence.** Claude keeps OAuth windows and extra usage current through the producer's uniform `rimz agents refresh-usage --kind claude` helper, claimed durably in `credits.json` on `OAUTH_USAGE_TTL`. A recent Claude statusline rate-limit reading remains the freshest window source; the helper merges windows only when no root Claude session has fresh statusline windows, and always may refresh the account-scoped credits entry. The credentials-file mtime rides the display account as the cheap scheduling stamp; macOS Keychain-only credentials use the narrow identity fallback.

The usage observation owns a domain-separated SHA-256 account key derived from `refreshToken`, or from `accessToken` when no refresh token exists. Only that digest enters the shared cache; token rotation stays on one owner when the refresh token is stable. The probe remains read-only and performs no token refresh or credential write. When the file is absent on macOS, the compatible Keychain fallback runs `/usr/bin/security` with null stdin and a 1.5-second subprocess deadline; a timeout or denied/nonzero result is quiet `NoCredentials`, though macOS can still briefly present Keychain UI.

The account probe forks `claude auth status`, capturing stdout with stdin and stderr nulled (never inherited, so it stays quiet in a TUI); the display-only `claude --version` probe feeds the same account cache and repairs entries whose login facts are fresh but whose version field is absent. The arms and TTLs are [providers.md → The out-of-band probe](./providers.md#the-out-of-band-probe).

## Cost

Claude's full-history spend is parsed by [`claude/spend.rs`](../../../crates/rimz/src/agents/adapters/claude/spend.rs), read-only and sidebar-safe, aggregated by the [`SpendingWalker`](../../../crates/rimz/src/agents/spending/mod.rs) into the configured headline window plus trailing 7d / 30d / 365d windows ([providers.md → Cost history](./providers.md#cost-history)). Two Claude-specific concerns:

Named `PostToolUse` completion events feed the live session tool map; broad `PreToolUse` proof remains unnamed so one call counts once. Historical tool statistics count `tool_use` blocks on the same usage-bearing assistant message parsed for spend, so the existing message/request dedup also counts retry and sidechain copies once.

The durable seat fold resolves the main transcript together with every `subagents/*.jsonl` companion in both Claude layouts: `<session_id>.jsonl` with `<session_id>/subagents/`, and `<session_id>/chat.jsonl` with `<session_id>/subagents/`. This is the same file population the fleet-wide spend walk discovers through its recursive JSONL source.

- **Dedup.** Claude replays a parent message into each subagent file with an inflated cost; the spending walk dedups by `(message.id, requestId)` across files, preferring a main-thread record, then the largest token total, then speed metadata when totals tie. Sidechain replay suppression counts the selected turn once. A Claude session's subagent files fold under its `session_id` directory, so one thread counts once.
- **Cost source.** Current Claude transcripts carry no `costUSD`, so the spending walk prices each `message.usage` through the per-model [pricing table](./providers.md#token-pricing) — input, output, 5-minute cache creation, 1-hour cache creation, and cache-read each at their own rate, with the 1-hour cache-creation slice billed at 2x input. Each `advisor_message` under `message.usage.iterations` is a separately billed nested request with its own model and token buckets, so it becomes a stable child entry under the parent response rather than disappearing into the main model's usage. An older Claude turn that still logs a positive `costUSD` uses that authoritative figure verbatim for the top-level request while any advisor requests remain independently priced. A turn whose model has no known price keeps its tokens and session with zero dollars while the pricing chase looks for a price; the sentinel `<synthetic>` model is filtered out because it is not an API model id.
