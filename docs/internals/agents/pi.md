# Pi adapter

> The agent-agnostic boundary, state machine, and context read-path are in [model.md](./model.md); the account, balance, spend, and pricing model is in [providers.md](./providers.md). The raw upstream protocol — the in-process extension API, the session JSONL, the headless RPC/JSON modes, and the auth file — is in [pi-reference.md](../../externals/agent-adapter/pi-reference.md).

This doc is the single home for everything Pi-specific. Pi's integration surface is in-process TypeScript extensions, so the adapter ships one — [`extension.ts`](../../../crates/rimz/src/agents/pi/extension.ts), embedded at compile time — that forwards each event below to `rimz hooks feed --source pi` as a fire-and-forget child. The child direction inverts: Claude and Codex run RimZ as a hook child and read its stdout; pi's extension runs RimZ as *its* child. One event blocks: `tool_call`, pi's pre-tool gate, whose handler pi awaits — there the extension reads the child's stdout as the decision and applies it through the handler's return value. Every envelope also stamps the model, the thinking level as `effort`, the context gauge (`context_pct` / `context_window` / `total_tokens`, rounded) from the in-process `ctx.getContextUsage()`, the latest per-call token split, cumulative `total_cost_usd`, and the latest captured rate-limit windows, so a pi row's live context is payload-first with no transcript tail read. Pi 0.80.4's `agent_settled` is the final turn boundary; the extension carries the preceding `agent_end` verdict into it so retries and queued continuations do not flash idle.

## Hooks and lifecycle

Native event → internal mapping; the upstream extension API, payloads, and session JSONL are in [pi-reference.md](../../externals/agent-adapter/pi-reference.md).

| Native event             | Channel   | `observe_lifecycle` → [`LifecycleSignal`](../../../crates/rimz/src/agents/lifecycle.rs) | Normalized fields                          |
| ------------------------ | --------- | ------------------------------------------------ | ------------------------------------------ |
| `session_start`          | lifecycle | `Registered`                                     | worktree from `cwd`                        |
| `before_agent_start`     | lifecycle | `TurnStarted`                                    | sanitized `prompt` (labels the row)        |
| `agent_end`              | lifecycle | — (low-level run ended; automatic work may remain) | captures `stopReason`, `errorMessage`, `model`, and tokens for `agent_settled` |
| `agent_settled`          | lifecycle | `TurnEnded { errored, parked_on_background: false }` | replays the final `agent_end` verdict after retries, compaction, and queued continuation settle |
| `tool_execution_end` (mutating) | lifecycle | `ToolUsed { mutates: true, edits }`       | `edits` for `edit`/`write`; `bash` mutates only; read-only tools stay silent |
| `model_select`           | lifecycle | —                                                | `model` enrichment-only marker          |
| `thinking_level_select`  | lifecycle | —                                                | `effort` enrichment-only marker         |
| `tool_call`              | **awaiting-user** (`Permission`) | —                         | `tool_name` (lowercase), `tool_input`; pi awaits the handler |
| `session_before_compact` | lifecycle | `Compacting`                                     | a leading signal, like Claude's `PreCompact` |
| `session_compact`        | lifecycle | `CompactionEnded { auto }`                         | `manual` → false; `threshold` / `overflow` → true; unknown/older Pi → unknown |
| `session_shutdown`       | lifecycle | `Ended` → removed (`ends_session`)               | fires on quit incl. Ctrl+C/SIGHUP/SIGTERM and on `/new`/`/resume` replacement |

Pi's vocabulary distinguishes a *turn* (one LLM call) from a low-level `agent_start`/`agent_end` run. That run may still lead to an automatic retry, overflow compaction-and-retry, or queued follow-up; `agent_settled` fires only after none remains, so RimZ maps `before_agent_start` → `agent_settled` as its user-visible turn. The `agent_end` error bit is in band: a failed or aborted LLM call ends with an assistant message carrying `stopReason: "error" | "aborted"` plus `errorMessage`; the extension retains the latest verdict and visible assistant text and stamps both onto `agent_settled`, giving RimZ an explicit death certificate, durable assistant log entry, and supervised-run result without transcript forensics. Pi's compaction lifecycle is a true bracket (`session_before_compact`/`session_compact`), and releases from 0.79.10 carry `reason: "manual" | "threshold" | "overflow"` plus `willRetry`; older or future unknown reasons degrade to trigger-unknown. Identity is direct: the extension runs in-process in the pane, the session id exists from launch (no lazy-registration window), and there is no daemon or remote mode, so every pi session is standalone and stamped.

**The blocking gate, without a native prompt.** Pi intentionally ships no permission prompts, plan approvals, or questions of its own — tools run unasked. What it exposes is `tool_call`, and RimZ returns neutral with **no waiting observation** because `native_ask_ui` is declared off and a `waiting` row would strand on a prompt pi never draws. Pi now supplies the final-idle `agent_settled` event; the descriptor keeps `idle` `Partial` only because the shared concern also covers an idle-timeout Notification nudge, which Pi does not expose. Rich context is also `Partial`: pi refreshes it through extension envelopes on pi's own events rather than through a dedicated out-of-band transport like Claude's statusline or Codex's app-server, and each envelope feeds `observe_context` a full live context — model, effort, cost, and account/rate-limit windows. Subagents, background tasks, plan approval, questions, and remote control carry no native signal and no derivation, so they stay `Unsupported` and the absences render deliberately. A single pi session can also switch provider accounts mid-session, so the provider dashboard keys the panel by the agent kind — *pi* — and aggregates whatever accounts pi used.

**Neutral output.** `render_neutral` prints nothing — empty stdout is the allow, the only safe default for an agent with no prompt to fall back to.

**Install.** Install is whole-file ownership keyed on the first-line `_rimz_managed` marker: a marked file (RimZ wrote it, however edited since) is reclaimed verbatim on re-install; an unmarked file at the path is the user's own extension and install, preview, and uninstall all refuse to touch it. The managed file is removed whole on uninstall and hot-reloads via `/reload`; the spawned child needs `rimz` on `PATH` (or `RIMZ_BIN`), and the extension skips the `reason: "reload"` shutdown so a `/reload` never tombstones the session it is about to re-register. The extension reads Pi's exported `VERSION`: 0.80.4+ waits for native `agent_settled`, while older releases normalize their historical `agent_end` boundary to the same RimZ event so they continue to finish turns.

**Resume.** `pi --session <session_id>` restores a rollup-recorded session (a partial UUID suffices); the extension re-fires `session_start` with `reason: "resume"`.

**Integration-blind modes.** `--no-extensions` disables discovered extensions (an explicit `-e` still loads), and `-p` / `--mode json` run extensions without a UI — same posture as an agent run before `rimz hooks install`: invisible, never silently broken.

## Context and transcript

Pi needs no transcript tail for live token context: RimZ authors pi's hook wire ([pi-reference.md](../../externals/agent-adapter/pi-reference.md)), so the extension stamps the gauge onto every hook envelope — `context_pct` / `context_window` / `total_tokens` from the in-process `ctx.getContextUsage()` (rounded on the wire), plus `model`, the thinking level (`off` through opt-in `max`) as `effort`, the latest per-call usage split (`◌` cache-read, `◍` cache-write, `↘` fresh input, `↗` output), and cumulative `total_cost_usd`. Optional upstream `usage.reasoning` is already a subset of `output`, so the normalized output total needs no adjustment. `observe_lifecycle` reads the row fields straight off the payload, and `observe_context` publishes the same envelope as `AgentContext.tokens`, `AgentContext.cost`, `model_id`, `effort`, and rate-limit windows. The extension also pushes an immediate envelope on `model_select` and `thinking_level_select`, so a mid-session model or thinking-level switch stamps the row at once rather than riding the next event's carry-forward. The sidebar reads the rich path for decimal context percentages while the lifecycle row still carries the fallback split. The extension accrues dollars only on `turn_end`, then rides the sum on the next forwarded envelope; `agent_end` reuses the final turn's message and does not add cost. The settled-boundary spend walk remains authoritative: when `agent_settled` lands, RimZ resolves the current session file by the UUID in `<ISO-timestamp>_<uuid>.jsonl`, runs the same `parse_spend` path as history, and reconciles `AgentContext.cost` to the session sum. The descriptor declares `live$` as `Partial` because the in-process accumulator resets on `/resume`; the reconciling walk corrects that best-effort live value.

## Account and balance

[`pi/account.rs`](../../../crates/rimz/src/agents/pi/account.rs) reads [`auth.json`](../../externals/agent-adapter/pi-reference.md#auth-file): oauth → metered subscription, api_key → unmetered. The plan names the sub the fleet uses (`Anthropic OAuth`, `OpenAI API Key`) — the freshest session's `message.provider` picks among several credentials, else the first OAuth entry — and the raw credential key rides `sub_provider`; the shared display-only `pi --version` probe is the panel header's fallback for a provider whose sessions report none. The account probe reads `~/.pi/agent/auth.json` (absent file → `LoggedOut`, unparseable → `Unavailable`); the arms and TTLs are [provider.md → The out-of-band probe](./providers.md#the-out-of-band-probe).

Balance is self-reported under the `pi` kind. The extension captures `after_provider_response` headers and publishes best-effort windows on the next hook envelope: Codex-style `x-codex-primary-*` / `x-codex-secondary-*` headers map to 5h and 7d windows, and Anthropic `anthropic-ratelimit-unified-*` variants are parsed tolerantly when present. The producer also spawns the uniform `rimz agents refresh-usage --kind pi --workspace-id <id>` helper unless `RIMZ_OAUTH_USAGE_OFFLINE=1` disables account-usage fetches; it reads Pi's selected OAuth credential from `auth.json` ([`oauth_usage.rs`](../../../crates/rimz/src/agents/pi/oauth_usage.rs)), reuses the Claude or Codex OAuth usage fetcher, and writes authoritative windows plus extra credits into the shared `rate_limits.json["pi"]` / `credits.json["pi"]` caches on `OAUTH_USAGE_TTL`. API-key credentials remain unmetered and get the API paid-usage row.

## Cost

Pi's provider-native transcript is JSONL, so the adapter normalizes visible `user` text and assistant `content[type = "text"]` blocks for `agents history`, reply streaming, and transcript-backed consumers; thinking, tool calls, tool results, summaries, and extension records stay out of that conversation stream. Full-history spend rides the shared spend pass ([provider.md → Cost history](./providers.md#cost-history)): one `<ISO-timestamp>_<uuid>.jsonl` per session under `~/.pi/agent/sessions/--<cwd-with-dashes>--/`, parsed by [`pi/spend.rs`](../../../crates/rimz/src/agents/pi/spend.rs). A present non-negative `usage.cost.total` is authoritative, including zero under a subscription login; a token-bearing record where the direct cost is absent falls back to model pricing, and an unpriced model still contributes tokens while scheduling a price-table chase. `totalTokens` fills a missing output component so sparse records retain their known total. Token and cost fields accept JSON numbers or numeric strings, and malformed nested usage values become absent fields instead of dropping an otherwise usable record. Pi sessions are single-file and need no cross-file dedup. The extension pushes a live cumulative sum between turns, and the live-card dollar supplement uses the same parser for the current session on turn end, so history and row-level `$` converge on one cost interpretation.
