# Pi adapter

> Read [model.md](./model.md) for the provider-neutral agent model and [adapter.md](./adapter.md) for the integration layer every adapter implements. Accounts, balances, and spend are in [providers.md](./providers.md); the raw upstream protocol is in [pi-reference.md](../../externals/agent-adapter/pi-reference.md).

This doc is the single home for everything Pi-specific. Pi's integration surface is in-process TypeScript extensions, so the adapter ships one — [`extension.ts`](../../../crates/rimz/src/agents/adapters/pi/extension.ts), embedded at compile time — that forwards each event below to `rimz hooks feed --source pi` as a fire-and-forget child. The child direction inverts: Claude and Codex run RimZ as a hook child and read its stdout; pi's extension runs RimZ as *its* child. One event blocks: `tool_call`, pi's pre-tool gate, whose handler pi awaits — there the extension reads the child's stdout as the decision and applies it through the handler's return value. Every envelope also stamps the session name, model, thinking level as `effort`, context gauge (`context_pct` / `context_window` / `total_tokens`, rounded) from the in-process `ctx.getContextUsage()`, latest per-call token split, cumulative `total_cost_usd`, and latest captured rate-limit windows, so a pi row's live context is payload-first with no transcript tail read. Pi 0.80.4's `agent_settled` is the final turn boundary; the extension carries the preceding `agent_end` verdict into it so retries and queued continuations do not flash idle.

## Hooks and lifecycle

Native event → internal mapping; the upstream extension API, payloads, and session JSONL are in [pi-reference.md](../../externals/agent-adapter/pi-reference.md).

| Native event             | Channel   | `decode_hook` → [`LifecycleSignal`](../../../crates/rimz/src/agents/lifecycle.rs) | Normalized fields                          |
| ------------------------ | --------- | ------------------------------------------------ | ------------------------------------------ |
| `session_start`          | lifecycle | `Registered`                                     | worktree from `cwd`                        |
| `before_agent_start`     | lifecycle | `TurnStarted`                                    | sanitized `prompt` (labels the row)        |
| `agent_end`              | lifecycle | — (low-level run ended; automatic work may remain) | captures `stopReason`, `errorMessage`, `model`, and tokens for `agent_settled` |
| `agent_settled`          | lifecycle | `TurnEnded { errored, parked_on_background: false }` or `TurnInterrupted` | clean/error/aborted after retries, compaction, and queued continuation settle |
| `turn_end`               | lifecycle | —                                                | publishes assistant and tool-result usage/cost immediately |
| `after_provider_response` | lifecycle | —                                               | publishes newly captured provider rate-limit windows immediately |
| `message_update`         | lifecycle | —                                                | enrichment-only streaming activity; context/cost changes push at most once per second |
| `session_info_changed`   | lifecycle | —                                                | publishes the `/name` session title immediately |
| `tool_execution_end` | lifecycle | `ToolUsed { mutates, edits, native_key }` | mutating `edit`/`write`/`bash`/`powershell` calls prove work; only `edit`/`write` count as editing; `ask_user_question` is the read-only resolution boundary that clears waiting; `tool_call_id` carries Pi's `toolCallId`; other read-only tools stay silent |
| `model_select`           | lifecycle | —                                                | `model` enrichment-only marker          |
| `thinking_level_select`  | lifecycle | —                                                | `effort` enrichment-only marker         |
| `tool_call`              | **awaiting-user** (`Question`) for `ask_user_question`; every other tool stays neutral | `AwaitingInput { native_key }` for the questionnaire | `tool_name`, `tool_input`, `has_ui`, and `tool_call_id` from Pi's `toolCallId`; absent `has_ui` assumes an interactive older RimZ extension |
| `subagent_started`       | lifecycle | `SubagentStarted`                                | normalized child `subagent_id`, parent `session_id`, `subagent_label`, source, and `cwd` |
| `subagent_stopped`       | lifecycle | `SubagentStopped { errored }`                    | the same child identity plus outcome and optional `total_tokens` |
| `session_before_compact` | lifecycle | `Compacting`                                     | a leading signal, like Claude's `PreCompact` |
| `session_compact`        | lifecycle | `CompactionEnded { auto, failed: false }`          | adds compaction usage; `manual` → false; `threshold` / `overflow` → true; unknown/older Pi → unknown |
| `session_compact_failed` | lifecycle | `CompactionEnded { auto, failed: true }`           | closes the bracket without a context reset; preserves status and stops active time |
| `session_shutdown`       | lifecycle | `Ended` → stamps `ended_at`; runtime hides the retained row (`ends_session`) | fires on quit incl. Ctrl+C/SIGHUP/SIGTERM and on `/new`/`/resume` replacement |

Pi's vocabulary distinguishes a *turn* (one LLM call) from a low-level `agent_start`/`agent_end` run. That run may still lead to an automatic retry, overflow compaction-and-retry, or queued follow-up; `agent_settled` fires only after none remains, so RimZ maps `before_agent_start` → `agent_settled` as its user-visible turn. The final assistant message carries `stopReason: "error" | "aborted"` plus optional `errorMessage`; the extension retains that verdict and visible text for `agent_settled`, mapping errors to failed completion and aborts to `TurnInterrupted`/idle while preserving supervised-run output without transcript forensics. An interrupted signal alone creates no success-shaped durable assistant entry. Pi's compaction lifecycle is a true bracket: `session_before_compact` opens it, and either `session_compact` or `session_compact_failed` closes it. A failed close never records a successful context reset or opens a resumed turn. Events carry `reason: "manual" | "threshold" | "overflow"` plus `willRetry`; older or future unknown reasons degrade to trigger-unknown. Root identity is direct: the extension runs in-process in the pane and the session id exists from launch (no lazy-registration window). RimZ does not use Pi's experimental remote-session mode, so every managed root session is pane-backed and stamped.

**The extension-provided questionnaire.** Pi itself intentionally ships no permission prompts, plan approvals, or questions — ordinary tools run unasked and their `tool_call` gate stays neutral. When the user installs [`@juicesharp/rpiv-ask-user-question`](https://github.com/juicesharp/rpiv-mono/tree/v2.7.1/packages/rpiv-ask-user-question), that extension registers `ask_user_question` and draws its structured questionnaire in pi's pane. RimZ's own extension sees the awaited `tool_call`, forwards its Claude-compatible `questions` / `options` / `multiSelect` input plus `has_ui` and Pi's `toolCallId`, and records a `Question` ask only when UI exists. The matching `tool_execution_end` carries the same key, so parallel sibling completions leave the questionnaire open. A completed questionnaire also forwards `result.details`: native `option`, `custom`, and `multi` answers create the structured Answer transcript entry, while Esc cancellation or validation failure only clears waiting. `rimz answer` drives zero-based option focus with Down and Enter, toggles multi-select rows with Space, crosses the always-present Type something. row to commit Next, and confirms the final Submit tab for multi-question asks. Free text is supported on every question shape. The questionnaire-wide `globalNote` stays out of per-question `AskAnswer` records because it already reaches the model in the result envelope.

### Subagents

Pi supplies no built-in subagent lifecycle, so each managed RimZ extension instance identifies its own place in the Pi process lineage. The first instance in a process claims `globalThis[Symbol.for("rimz.pi.primary-session")]` and writes its session id to `RIMZ_PI_PARENT_SESSION`; in-process children see the shared global marker, while child Pi subprocesses inherit the environment marker and then claim their own process for any descendants. A child feeds `subagent_started` with the marker's parent id and its own Pi session id as `subagent_id`, so its normal session, model, effort, context, usage, and cost envelopes enrich that same nested row. Hook ingestion handles either ordering between the child's registration and lifecycle feed with a guarded `SubagentAdopted` record, and root-parent resolution flattens nested descendants to the root row.

This self-identification covers tintinweb's in-process children and nicobailon's foreground and async subprocess children without depending on either plugin's event bus or registry. The child label uses its Pi session name, then nicobailon's inherited `PI_SUBAGENT_CHILD_AGENT`, and remains absent when neither exists. A child configured without the RimZ extension remains invisible, matching the root contract for `pi --no-extensions`; tintinweb's `extensions: false` and a nicobailon `extensions:` allowlist that omits RimZ are the deliberate opt-outs.

The child feeds `subagent_stopped` at its own final-idle `agent_settled` boundary, deriving failure from the retained stop reason or error message; the pre-0.80.4 `agent_end` compatibility path does the same, and non-reload `session_shutdown` is the subprocess-exit backstop. A later `before_agent_start` re-feeds the start after a stop so a reused child row returns to running. The stop stays lean because the child's own envelopes carry the full usage split. A hard-killed subprocess can leave a running row through the current parent turn; the parent's next prompt retires it through the shared keep-through-parent-turn reap.

A single pi session can switch provider accounts mid-session, so the provider dashboard keys the panel by the agent kind — *pi* — and aggregates whatever accounts pi used.

**Neutral output.** `decode_hook` returns no neutral JSON value — empty stdout lets ordinary tools run and lets `ask_user_question` proceed into the rpiv extension's native questionnaire.

**Install.** Install is whole-file ownership keyed on the first-line `_rimz_managed` marker: a marked file (RimZ wrote it, however edited since) is reclaimed verbatim on re-install; an unmarked file at the path is the user's own extension and install, preview, and uninstall all refuse to touch it. Interactive setup compares a marked file byte-for-byte with the source embedded in the running RimZ build and offers a consented refresh when they differ; the older file remains installed until accepted. The managed file is removed whole on uninstall and hot-reloads via `/reload`; the spawned child needs `rimz` on `PATH` (or `RIMZ_BIN`), and the extension skips the `reason: "reload"` shutdown so a `/reload` never stamps the session ended immediately before re-registration. The extension reads Pi's exported `VERSION`: 0.80.4+ waits for native `agent_settled`, while older releases normalize their historical `agent_end` boundary to the same RimZ event so they continue to finish turns.

## Launch and resume

`pi --session <session_id>` restores a rollup-recorded session (a partial UUID suffices); before re-firing `session_start` with `reason: "resume"`, the extension walks `sessionManager.getBranch()` to hydrate cumulative assistant, tool-result, compaction, and branch-summary cost, the latest assistant usage split, and the session name. Older Pi releases without that read surface degrade to sparse enrichment and reconcile at the settled spend pass.

RimZ renders typed prompt replacement through `pi --system-prompt <text>`. The full text is visible in the process argv, so RimZ rejects values over 120 KiB before exec. Pi's replacement is not hermetic: Pi still appends its native `APPEND_SYSTEM.md`, context files, skills, and cwd material after the replacement text.

**Integration-blind modes.** `--no-extensions` disables discovered extensions (an explicit `-e` still loads). `-p` / `--mode json` run extensions without a UI; the RimZ extension stamps `has_ui: false`, so the 2.x `ask_user_question` extension errors with `no_custom_ui` without creating a stranded ask row.

## Context and transcript

Pi needs no transcript tail for live token context: RimZ authors pi's hook wire ([pi-reference.md](../../externals/agent-adapter/pi-reference.md)), so the extension stamps the gauge onto every hook envelope — `context_pct` / `context_window` / `total_tokens` from the in-process `ctx.getContextUsage()` (rounded on the wire), plus `session_name`, `model`, the thinking level (`off` through opt-in `max`) as `effort`, the latest assistant-call usage split (`◌` cache-read, `◍` cache-write, `↘` fresh input, `↗` output), and cumulative `total_cost_usd`. Optional upstream `usage.reasoning` is already a subset of `output`, so the normalized output total needs no adjustment. `decode_hook` reads the row fields straight off the payload, and `observe_context` publishes the same envelope as `AgentContext.session_name`, `AgentContext.tokens`, `AgentContext.cost`, `model_id`, `effort`, and rate-limit windows. The extension pushes immediately on model, thinking-level, session-name, completed-call usage/cost, and provider-window changes; streaming context changes push at most once per second and only when the gauge or cost differs. The sidebar reads the rich path for decimal context percentages while the lifecycle row still carries the fallback split. The extension accrues assistant and tool-result dollars on `turn_end`, compaction dollars on `session_compact`, and branch-summary dollars on the accumulation-only `session_tree` subscription; `agent_end` adds nothing. The settled-boundary spend walk remains authoritative: when `agent_settled` lands, RimZ resolves the current session file by the UUID in `<ISO-timestamp>_<uuid>.jsonl`, runs the same `parse_spend` path as history, and reconciles `AgentContext.cost` to the session sum. The descriptor declares `live$` as `Wired`: resume hydration preserves the active branch's complete running sum, and every turn reconciles the dollar to the authoritative session-spend sum.

## Account and balance

[`pi/account.rs`](../../../crates/rimz/src/agents/adapters/pi/account.rs) reads [`auth.json`](../../externals/agent-adapter/pi-reference.md#auth-file): oauth → metered subscription, api_key → unmetered. The plan names the sub the fleet uses (`Anthropic OAuth`, `OpenAI API Key`) — the freshest session's `message.provider` picks among several credentials, else the first OAuth entry — and the raw credential key rides `sub_provider`; supported OAuth credentials also carry a normalized `openai` or `anthropic` quota scope, while API-key and unsupported providers carry no quota scope. The shared display-only `pi --version` probe is the panel header's fallback for a provider whose sessions report none. The account probe reads `~/.pi/agent/auth.json` (absent file → `LoggedOut`, unparseable → `Unavailable`); the arms and TTLs are [providers.md → The out-of-band probe](./providers.md#the-out-of-band-probe).

Balance is self-reported under the `pi` kind and keyed by the selected backing credential's normalized scope plus non-secret owner identity. [`delegated_account.rs`](../../../crates/rimz/src/agents/delegated_account.rs) selects the credential once for each usage result, preferring an OpenAI `accountId` and otherwise hashing the refresh token or access-token fallback under Pi's domain. The extension captures `after_provider_response` headers and publishes best-effort windows immediately on that event: Codex-style `x-codex-primary-*` / `x-codex-secondary-*` headers map to 5h and 7d windows, and Anthropic `anthropic-ratelimit-unified-*` variants are parsed tolerantly when present. Missing best-effort headers do not claim a lifted duration. The claimed uniform helper delegates Anthropic tokens to Claude normalization and OpenAI tokens to Codex normalization, writing authoritative windows plus extra credits under `pi`; OpenAI therefore receives Codex's lifted 5h completion while Anthropic does not. API-key credentials remain unmetered and get the API paid-usage row.

## Cost

Pi's provider-native transcript is JSONL, so the adapter normalizes visible `user` text and assistant `content[type = "text"]` blocks for `agents history`, reply streaming, and transcript-backed consumers; thinking, tool calls, tool results, summaries, and extension records stay out of that conversation stream. Full-history spend rides the shared spend pass ([providers.md → Cost history](./providers.md#cost-history)): one `<ISO-timestamp>_<uuid>.jsonl` per session under `~/.pi/agent/sessions/--<cwd-with-dashes>--/`, parsed by [`pi/spend.rs`](../../../crates/rimz/src/agents/adapters/pi/spend.rs). It counts Pi's four total-bearing shapes: assistant message usage (attributed to `responseModel ?? model`), optional tool-result `message.usage`, and top-level `usage` on compaction and branch-summary entries. A present non-negative `usage.cost.total` is authoritative, including zero under a subscription login; a token-bearing assistant record where the direct cost is absent falls back to model pricing, and an unpriced model still contributes tokens while scheduling a price-table chase. `totalTokens` fills a missing output component so sparse records retain their known total. Token and cost fields accept JSON numbers or numeric strings, and malformed nested usage values become absent fields instead of dropping an otherwise usable record. Pi sessions are single-file and need no cross-file dedup. Nicobailon child processes write standard Pi session JSONL below the same sessions root, so the recursive `pi_session_files` walk already ingests them for spend and stats; tintinweb children persist only when their agent config sets `persist_session: true`, then land in Pi's normal session location and follow the same path. The extension pushes the same cumulative sum between turns, so history and row-level `$` converge on one cost interpretation.

Every named `tool_execution_end` event feeds the live session tool map. Historical tool statistics count `toolCall` blocks inside the durable assistant message that also owns usage; extension `tool_call` traffic is not a second durable call record and is excluded to prevent double-counting.

## Known gaps

Run `rimz coverage` for the current wired/partial/unsupported matrix. The gaps below are the ones with a reason worth recording.

- **Permission prompts and plan approval have no native signal.** Pi intentionally ships neither, so ordinary tools run unasked. The only structured prompt is the community `ask_user_question` extension covered above.
- **Idle stays partial** because the shared concern also covers an idle-timeout notification nudge, which Pi does not expose. Pi's own final-idle `agent_settled` boundary is wired.
- **Background tasks and remote control** remain unsupported. Pi has no native background-task signal, and RimZ deliberately does not adopt the experimental remote-session protocol.
- **Older Pi releases degrade rather than fail.** Releases without `sessionManager.getBranch()` lose resume hydration and reconcile at the settled spend pass; releases before 0.80.4 normalize their historical `agent_end` boundary to the same RimZ event.
