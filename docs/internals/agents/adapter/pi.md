# Pi adapter

> The agent-agnostic boundary, state machine, and context read-path are in [agent.md](../agent.md); the account, balance, spend, and pricing model is in [provider.md](../provider.md). The raw upstream protocol — the in-process extension API, the session JSONL, the headless RPC/JSON modes, and the auth file — is in [pi-reference.md](../../../externals/agent-adapter/pi-reference.md).

This doc is the single home for everything Pi-specific. Pi's integration surface is in-process TypeScript extensions, so the adapter ships one — [`extension.ts`](../../../../crates/rimz/src/agents/pi/extension.ts), embedded at compile time — that forwards each event below to `rimz hooks feed --source pi` as a fire-and-forget child. The child direction inverts: Claude and Codex run Rimz as a hook child and read its stdout; pi's extension runs Rimz as *its* child. One event blocks: `tool_call`, pi's pre-tool gate, whose handler pi awaits — there the extension reads the child's stdout as the decision and applies it through the handler's return value. Every envelope also stamps the model, the thinking level as `effort`, the context gauge (`context_pct` / `context_window` / `total_tokens`, rounded) from the in-process `ctx.getContextUsage()`, the latest per-call token split, cumulative `total_cost_usd`, and the latest captured rate-limit windows, so a pi row's live context is payload-first with no transcript tail read.

## Hooks and lifecycle

Native event → internal mapping; the upstream extension API, payloads, and session JSONL are in [pi-reference.md](../../../externals/agent-adapter/pi-reference.md).

| Native event             | Channel   | `observe_lifecycle` → [`LifecycleSignal`](../../../../crates/rimz/src/agents/lifecycle.rs) | Normalized fields                          |
| ------------------------ | --------- | ------------------------------------------------ | ------------------------------------------ |
| `session_start`          | lifecycle | `Registered`                                     | worktree from `cwd`                        |
| `before_agent_start`     | lifecycle | `TurnStarted`                                    | sanitized `prompt` (labels the row)        |
| `agent_end`              | lifecycle | `TurnEnded { errored, parked_on_background: false }` | `model`, `total_tokens`                |
| `tool_execution_end` (mutating) | lifecycle | `ToolUsed { mutates: true, edits }`       | `edits` for `edit`/`write`; `bash` mutates only; read-only tools stay silent |
| `model_select`           | lifecycle | —                                                | `model` enrichment-only marker          |
| `thinking_level_select`  | lifecycle | —                                                | `effort` enrichment-only marker         |
| `tool_call`              | **blocking-feed** (`Permission`) | —                         | `tool_name` (lowercase), `tool_input`; pi awaits the handler |
| `session_before_compact` | lifecycle | `Compacting`                                     | a leading signal, like Claude's `PreCompact` |
| `session_compact`        | lifecycle | `CompactionEnded` with unknown trigger            | clears the head and preserves the prior status/phase |
| `session_shutdown`       | lifecycle | `Ended` → removed (`ends_session`)               | fires on quit incl. Ctrl+C/SIGHUP/SIGTERM and on `/new`/`/resume` replacement |

Pi's vocabulary maps onto Rimz's turn cleanly: a pi *turn* is one LLM call, and its `agent_*` pair brackets one user prompt — pi's `agent_*` is what Rimz calls a turn. The `agent_end` error bit is in band: a failed or aborted LLM call still ends with an assistant message carrying `stopReason: "error" | "aborted"` plus `errorMessage` — an explicit death certificate at the turn boundary, with no transcript forensics needed (unlike Claude's recovered `StopFailure` gap). Pi's compaction lifecycle is a true bracket (`session_before_compact`/`session_compact`), but the extension event omits the manual/auto reason that headless JSON mode carries, so Rimz clears the head without changing the underlying lifecycle status. Identity is direct: the extension runs in-process in the pane, the session id exists from launch (no lazy-registration window), and there is no daemon or remote mode, so every pi session is standalone and stamped.

**The blocking gate, without a native prompt.** Pi intentionally ships no permission prompts, plan approvals, or questions of its own — tools run unasked. What it exposes is `tool_call`, and Rimz returns neutral with **no feed item** because `native_ask_ui` is declared off and a `native_ui` row would strand waiting on a prompt pi never draws. Pi's `idle` slice is reconstructed rather than native — `agent_end` settles a finished turn to a calm state and the stall window escalates a silent `running` row, so the descriptor declares `idle` `Partial` (gap: no idle Notification hook, no idle-timeout nudge). Rich context is also `Partial`: pi refreshes it through extension envelopes on pi's own events rather than through a dedicated out-of-band transport like Claude's statusline or Codex's app-server, and each envelope feeds `observe_context` a full live context — model, effort, cost, and account/rate-limit windows. Subagents, background tasks, plan approval, questions, and remote control carry no native signal and no derivation, so they stay `Unsupported` and the absences render deliberately. A single pi session can also switch provider accounts mid-session, so the provider dashboard keys the panel by the agent kind — *pi* — and aggregates whatever accounts pi used.

**Neutral output.** `render_neutral` prints nothing — empty stdout is the allow, the only safe default for an agent with no prompt to fall back to.

**Install.** Install is whole-file ownership keyed on the first-line `_rimz_managed` marker: a marked file (Rimz wrote it, however edited since) is reclaimed verbatim on re-install; an unmarked file at the path is the user's own extension and install, preview, and uninstall all refuse to touch it. The managed file is removed whole on uninstall and hot-reloads via `/reload`; the spawned child needs `rimz` on `PATH` (or `RIMZ_BIN`), and the extension skips the `reason: "reload"` shutdown so a `/reload` never tombstones the session it is about to re-register.

**Resume.** `pi --session <session_id>` restores a rollup-recorded session (a partial UUID suffices); the extension re-fires `session_start` with `reason: "resume"`.

**Integration-blind modes.** `--no-extensions` runs with no events at all, and `-p` / `--mode json` run extensions without a UI — same posture as an agent run before `rimz hooks install`: invisible, never silently broken.

## Context and transcript

Pi needs no transcript tail for live token context: Rimz authors pi's hook wire ([pi-reference.md](../../../externals/agent-adapter/pi-reference.md)), so the extension stamps the gauge onto every hook envelope — `context_pct` / `context_window` / `total_tokens` from the in-process `ctx.getContextUsage()` (rounded on the wire), plus `model`, the thinking level as `effort`, the latest per-call usage split (`◌` cache-read, `◍` cache-write, `↘` fresh input, `↗` output), and cumulative `total_cost_usd`. `observe_lifecycle` reads the row fields straight off the payload, and `observe_context` publishes the same envelope as `AgentContext.tokens`, `AgentContext.cost`, `model_id`, `effort`, and rate-limit windows. The extension also pushes an immediate envelope on `model_select` and `thinking_level_select`, so a mid-session model or thinking-level switch stamps the row at once rather than riding the next event's carry-forward. The sidebar reads the rich path for decimal context percentages while the lifecycle row still carries the fallback split. The extension accrues dollars only on `turn_end`, then rides the sum on the next forwarded envelope; `agent_end` reuses the final turn's message and does not add cost. The turn-end spend walk remains authoritative: when `agent_end` lands, Rimz resolves the current session file by the UUID in `<ISO-timestamp>_<uuid>.jsonl`, runs the same `parse_spend` path as history, and reconciles `AgentContext.cost` to the session sum. The descriptor declares `live$` as `Partial` because the in-process accumulator resets on `/resume`; the reconciling walk corrects that best-effort live value.

## Account and balance

[`pi/account.rs`](../../../../crates/rimz/src/agents/pi/account.rs) reads [`auth.json`](../../../externals/agent-adapter/pi-reference.md#auth-file): oauth → metered subscription, api_key → unmetered. The plan names the sub the fleet uses (`Anthropic OAuth`, `OpenAI API Key`) — the freshest session's `message.provider` picks among several credentials, else the first OAuth entry — and the raw credential key rides `sub_provider`; the shared display-only `pi --version` probe is the panel header's fallback for a provider whose sessions report none. The account probe reads `~/.pi/agent/auth.json` (absent file → `LoggedOut`, unparseable → `Unavailable`); the arms and TTLs are [provider.md → The out-of-band probe](../provider.md#the-out-of-band-probe).

Balance is self-reported under the `pi` kind. The extension captures `after_provider_response` headers and publishes best-effort windows on the next hook envelope: Codex-style `x-codex-primary-*` / `x-codex-secondary-*` headers map to 5h and 7d windows, and Anthropic `anthropic-ratelimit-unified-*` variants are parsed tolerantly when present. The producer also spawns the uniform `rimz agents refresh-usage --kind pi --workspace-id <id>` helper unless `RIMZ_OAUTH_USAGE_OFFLINE=1` disables account-usage fetches; it reads Pi's selected OAuth credential from `auth.json` ([`oauth_usage.rs`](../../../../crates/rimz/src/agents/pi/oauth_usage.rs)), reuses the Claude or Codex OAuth usage fetcher, and writes authoritative windows plus extra credits into the shared `rate_limits.json["pi"]` / `credits.json["pi"]` caches on `OAUTH_USAGE_TTL`. API-key credentials remain unmetered and get the API paid-usage row.

## Cost

Pi's full-history spend rides the shared spend pass ([provider.md → Cost history](../provider.md#cost-history)): one `<ISO-timestamp>_<uuid>.jsonl` per session under `~/.pi/agent/sessions/--<cwd-with-dashes>--/`, parsed by [`pi/spend.rs`](../../../../crates/rimz/src/agents/pi/spend.rs). Pi logs dollars directly (`usage.cost.total` — [pi-reference.md → Session JSONL](../../../externals/agent-adapter/pi-reference.md#session-jsonl)), used verbatim with no pricing-table multiplication. Pi sessions are single-file and need no cross-file dedup. The extension pushes a live cumulative sum between turns, and the live-card dollar supplement uses the same parser for the current session on turn end, so history and row-level `$` converge on one cost interpretation.
