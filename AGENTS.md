# AGENTS.md

> **Invariant.** RimZ routes attention: it surfaces which agent needs you and takes you straight to its pane, where you answer in the agent's own UI.

## How to read this contract

This file carries two kinds of statement, and they earn different deference.

**Invariants** are load-bearing: a product promise, an architectural boundary that a `cargo xtask invariants` grep enforces, or a durability rule. Breaking one breaks the build or the product. Each section below says which of its statements are invariants. Change one deliberately, in its own commit, with the doc and the gate moving together.

**Everything else is a default**: the choice that has been right most of the time here. Follow it absent better information. Depart from it when the work in front of you argues otherwise, and say why in the PR or hand-off. A default that keeps losing is a bug in this file, so fix the file.

Match the size of the change to the size of the ask. A refactor you noticed on the way becomes a note unless it blocks you. When this map and the territory disagree, the code is what ships: follow the code, then fix the map in the same change.

## Engineering principles

The house style is explicit Rust, and [rust-conventions.md](./docs/contributing/rust-conventions.md) is its authority: typed IDs across module boundaries, structured parsers over ad-hoc string work, state machines where a bool would drift, typed `Result` errors at library boundaries. `unwrap`, `expect`, and panics belong in tests, build scripts, and provably impossible states; leave a comment naming why the state is impossible.

Unsafe code is denied; two sites are admitted, each annotated with `#[expect(unsafe_code, reason = "...")]`: the glibc arena cap in `crates/rimz/src/main.rs`, and the bench-only counting allocator in `crates/rimz/benches/fleet.rs`, which the shipped binary never links. A third site is a design decision.

An event or timing fix is proven at the consumer's decision point. That the producer emitted, or that a timestamp is fresh, is not evidence that the consumer saw it in time. Work placed between a decision and the action it gates (a helper process, a lock, a network call) makes the decision stale by that work's duration: read the decision again after the work, or say why it cannot have changed. A stamp another rule compares with is taken at the instant that rule means. A floor that must expire with an existing cadence takes that cadence's own stamp, passed in, not a fresh `now()` after the pass's work, or it outlasts the cadence and skips the next due pass. A freshness stamp checked against later triggers is taken before the request it covers, or a trigger that lands during the request is absorbed. A refresh an event triggers reads its inputs at the instant the trigger fires, so a limit stated for it says what that read finds then and what next moves the trigger: an answer read too early sticks until that next move. A fix that changes which clock stamps a value audits every comparison against that value for its behaviour at ties, since a stamp that used to trail another may now equal it. A refactor that moves time reads onto an injected clock keeps every read that followed a lock, I/O, or spawn after that work, and converts between clocks at the present, never at construction.

Three invariants sit underneath that style:

- **Store durability.** Every durable write follows the [store durability contract](./docs/internals/store.md).
- **Classed room paths.** Room state and runtime paths are constructed only by the disk path module; the classed-path invariant rejects callers assembling paths from room roots outside tests.
- **Fail-fast at the point of use.** The room always opens. A configuration problem (an unreadable file, an invalid value, a broken account, a plugin manifest, a remote-control blocker) warns at entry, the room runs as if that setting were absent, and the room's record keeps the warning for the sidebar and `rimz doctor`. A configured capability that cannot work fails with the fix at the command that uses it: an agent launch, a team, a subagent, a loop fire. Such a command never reads a broken setting as absent where that would change the account it runs on. The room still refuses for what is not configuration: a missing, old, or unresponsive multiplexer, socket budgets, the project claim, store or runtime state, a birth inside a scoped pane, remote version skew, and a malformed or unusable `--account`. Best-effort is for latency and enrichment (sidebar wakeups, app-server context), never for a precondition the user switched on. An optional language server is enrichment, so its configuration errors warn with the fix; `policy = "required"` makes it a precondition. A profile's `empty-dir` is enrichment too: an account without folder trust on the empty root starts in the caller's directory with a stderr notice and a `rimz doctor` row, while a dirty empty root refuses the launch. Profile `skills` lists apply at every isolation level: via the scoped view or the provider's host-mode switch; host providers without a switch warn and run unrestricted. The `sandbox` isolation level is flag mapping: RimZ adds each provider's own sandbox flags and owns nothing past them, so what the provider does with them, including when its sandbox cannot start, is the provider's behaviour, and a provider without a sandbox switch warns and launches without one. Two named exceptions: off Linux, where no scoped view exists, a configured `scoped` isolation falls back to host with a warning, while an explicit `--isolation scoped` still refuses; hibernation is enrichment on every platform, on by default and skipped where Linux, swap, a cgroup freezer, or a systemd user manager is unavailable. `rimz doctor` says why hibernation is skipped, and an explicit `[agents.hibernate] enabled = true` warns once at `rimz start`.

## Product invariants

These are the promises the product is built on. A change to one is a product decision, not an implementation detail.

- **Durability first.** Correctness lives in durable records, CAS rules, nonces, and per-request sockets. Wakeups and pane reads are latency, never truth.
- **Automation is accountable.** User-benefiting automation appends durable assist records and surfaces in `rimz stats`; internal repairs keep durable diagnostic records ([loops.md](./docs/internals/harness/loops.md#the-assist-log), [diagnostics.md](./docs/internals/diagnostics.md)).
- **One interface language.** Every human-facing surface resolves color through the [shared theme core](./docs/internals/theme.md): provider identity for names and emblems, typed state roles, hierarchy tones, and quantity tones. Invariants enforce the renderer boundaries.
- **Hook stdout is the decision channel.** Logs go to stderr or RimZ state logs; hook helper children get fresh stdio.
- **Cross-backend parity.** Zellij and tmux are first-class; core behaviour never depends on a backend-only feature.
- **Pane I/O is explicit.** `pane capture` and `pane send` are public primitives, and `message` routes human text through the same send path. Pane reads stay in five places: rendering, explicit `pane capture` calls, explicit `rimz agents show --capture` calls, a failed supervised run's tail capture before cleanup, and Codex turn-death confirmation. `cargo xtask invariants` admits each of the last three only behind its `rimz-invariant` marker comment.
- **Transcript origin is explicit.** RimZ-introduced text never renders as the user merely because it lacks a header: one write-side classifier and one read-side projection preserve its recorded author ([contract and remaining launch gap](./docs/internals/harness/transcript.md#writing-entries)). `rimz pane send` is the boundary: it is the raw keystroke primitive, carries no record by design, and its caller is the author.
- **Sidebar is read-only on the store.** Store-write modules stay out of the sidebar's import graph.
- **Trust is product behaviour.** Every command-executing config field is in the trust hash, with a test that proves it.
- **Security surfaces stay visible.** Project trust, notification handlers, hook install diffs, provider folder-trust grants, and privacy settings are product behaviour.

## Room quick reference

Addresses are `@handle[#channel]`; the full grammar lives in [agents.md](./docs/reference/cli/agents.md).

```sh
rimz agents list                     # agent cards, current channel
rimz agents profiles                 # configured profiles, commands, and descriptions
rimz agents validate                 # check Markdown definitions and the skill library
rimz agents list '#auth'             # one lane's cards
rimz agents show @coder              # card: activity, context, messages, transcript
rimz agents logs @coder -n 20        # transcript tail (-f follows)
rimz agents history @coder -n 10     # per-turn tokens, cost, and outcome
rimz agents attribution --md         # credit the lane's agents in a PR footnote
rimz agents restart @coder           # bounce in place and resume the session
rimz agents resume '#docs'           # restore every closed place in one lane
rimz teams list                      # configured teams and their live cohorts
rimz teams show forge#feat-x         # resolved roles, status, and one live cohort
rimz teams forge -w feat-x           # launch one configured cohort in a worktree
rimz teams resume forge              # reopen a configured team cohort
rimz teams focus|restart|stop forge  # drive one live team cohort
rimz teams wait forge#feat-x         # block until the board reaches Done
rimz subagents claude "review this"  # from an agent: launch a supervised child
rimz subagents profiles              # configured child profiles, commands, and descriptions
rimz subagents wait @otter @fox      # collect named children's results
rimz subagents list                  # inspect own children, or the user shell's channel
rimz subagents stop --all            # from an agent: stop all its live children
rimz message @coder "rebase first"   # park for the next turn boundary
rimz message @coder --wait "did the migration land? one line" # ask and print the reply
rimz message --steer @coder "stop"   # type into the live turn now; it does not interrupt
rimz message show msg_<id>           # why a message hasn't landed
rimz asks --json                     # structured prompts that currently block agents
rimz answer @coder 2                 # answer the current supported prompt in its native UI
rimz pane list                       # every pane, labelled with @handles
rimz pane capture @coder             # what the agent's pane shows right now
rimz loop show <task>                # schedule, next fire, run forensics
rimz loop logs <task>                # full forensics for recent runs
rimz wait --in 30m                   # wake me once, 30 minutes from now
rimz wait --run 'cargo test'         # wake me when the command exits
rimz loop add merged --signal pr.merged --wait --once # deliver the next merge signal to me
rimz events emit deploy.done         # fire a signal for whoever is listening
```

## Implementation rules

- `AGENTS.md` and `CLAUDE.md` are one file per directory, joined by symlink; an edit to either lands in both. Edit `AGENTS.md`: tools refuse to write through the `CLAUDE.md` link.
- Write Rust unless the task targets docs, tests, scripts, examples, or build glue. Use `uv` for Python helpers.
- A Rust comment or doc comment that an edit writes or lengthens, or a macro call rustfmt cannot parse (tracing's `%field`/`?field` sigils, an `if` inside `json!`), is wrapped by hand to the width of the code around it, at most the 100-column `max_width`: rustfmt leaves both as written and no gate catches an overlong one. A harness rule against hard-wrapping prose covers messages and Markdown, not source comments.
- rustfmt gives up on a whole expression, often a closure passed as an argument, when it cannot fit some part of it within `max_width`, and leaves the whole expression as written; `cargo fmt --check` and `cargo xtask lint` still pass. When new code's layout looks hand-made, indent one statement in a scratch copy and run rustfmt: if the indent stays, split the body into named functions until rustfmt restores it.
- Root docs stay short and authoritative; detail lives in `docs/` and is linked. Update the [code map](#code-map) when modules move, [ARCHITECTURE.md](./ARCHITECTURE.md) when the runtime shape changes, and [DESIGN.md](./DESIGN.md) only when a product or runtime invariant changes. A new `disk/` module also gets a row in the Disk module table of `docs/internals/store.md`.
- Leave [CHANGELOG.md](./CHANGELOG.md) untouched in a pull request. It is written as a standalone change once the work merges and before the version release, so concurrent branches never contend over the same lines.
- `examples/` is sample configuration for users to copy: not source code, not documentation. Do not read it while working unless the user asks, and do not treat it as authority on behaviour.
- Contributor automation lives in `xtask/`. Each repository loop task owns a directory under [loops/](./loops/README.md), whose coordinator runs read-only at the project root and gives each editing attempt a fresh RimZ worktree. The command surface and gate stack live in [rust-conventions.md](./docs/contributing/rust-conventions.md).
- Bulk command output (`--json` snapshots, transcript tails, gate logs) reaches an agent truncated, so printing it to stdout burns a turn and still loses the part that mattered. Redirect it to a file under `/tmp` in the same command, then narrow it with `jq` or a targeted read. Name that file under `$TMPDIR` or the session scratch directory, never a bare `/tmp/<short>.log`: agents share `/tmp`, and another agent's run can overwrite it.
- Never gate a command on a piped check (`cargo xtask check | tail && git commit`): the pipe exits with `tail`'s status, so a failed check still commits. Redirect the output to a file under `$TMPDIR` and chain on the check itself.
- A scan command never passes `-r` to `rg`: it is `--replace`, so `rg -rn PATTERN` parses as `-r n` and rewrites every match to `n`. Single-quote any argument that starts with `=` or carries a glob character (`echo '==='`, `rg -g '*.rs'`), since the shell otherwise aborts the whole command before it runs. Both failures return plausible-looking output, so they cost a call each time.
- A scan command never passes `-h` to `rg` to hide file names: it is `--help`. Use `--no-filename`.
- Name only files you have listed; a glob that matches nothing aborts the command before it runs.
- Search a snake_case field or function name with `rg -w`; a bare substring also matches every longer identifier that starts with it.
- rustfmt splits long method chains one segment per line, so a grep for a field access through a path (`self.ui.freeze`) uses `rg -U 'self\s*\.ui\s*\.freeze'`; a single-line pattern misses the split form.
- A scan command always names its path (`rg PATTERN .`): in an agent shell stdin is not a terminal, so a pathless `rg` searches stdin and hangs until the tool timeout.
- A tree-wide `rg` skips dot-directories: name `.github` as a path (or pass `--hidden`) when the question includes workflows.
- A tree-wide `rg` also skips the paths the root `.ignore` lists (`docs/externals/`, `examples/`, `CHANGELOG.md`, `Cargo.lock`, `supply-chain/`) without saying so: a removal or rewording grep passes `--no-ignore-dot` or names `docs/externals` as a path.
- Stop a process you started by its PID (`$!`, `pgrep -x`), never with `pkill -f PATTERN`: the pattern matches the shell running `pkill` and kills it.
- Brace a shell variable that a colon follows (`git show "${rev}:path"`): zsh reads `$rev:c` as a modifier on the variable and passes git a mangled revision.
- zsh reserves `status` as a read-only alias of `$?`: name an exit-code variable `rc`.
- A scope check against trunk diffs from the merge base, `git diff --stat origin/main...HEAD -- <path>` (three dots). Once trunk moves, a two-dot diff against `origin/main` lists trunk's own changes as the branch's.

## Testing

- While iterating, the per-commit signal is `cargo xtask check` (singular; `checks` is the non-test gate composite) followed by `cargo xtask lint` (which checks whole-tree formatting first; the pre-commit hook checks staged Rust index copies with `cargo xtask fmt --staged`), plus `cargo xtask docs-links` for a change that touches Markdown, which `lint` does not cover, and `cargo xtask doc` for a change that adds or edits rustdoc, since only that step denies rustdoc warnings such as a public item linking to a private one. Run `cargo fmt --all` first; `lint` only checks formatting and fails on an unformatted edit. The pre-commit hook (`cargo xtask hooks` activates it) adds the surface-budget and dependency check, `cargo xtask atlas conform --ratchet`, which `check` and `lint` do not see; a new `pub` or `pub(crate)` item, module, or cross-module import fails it until `refactor-target.toml` admits it: a `[[verdict]]` for the item (a `pub` method on an existing type needs none but still counts toward its module's surface) and, when its module's surface is at the cap, a raised `surface-budget` with a `#` line above it naming the item and the raise (`(+1)`), every earlier line kept. A plan that routes a call into another module first reads the calling module's `allowed-dependencies` (or `upward-dependencies`) entry there: a module missing from the list reshapes the design or needs an admission the plan names. The file runs to about 8,000 lines: find your module's entries with `rg -n '<module path>' refactor-target.toml` and read around each hit, never the whole file. `[[verdict]]` keys are Rust paths (`agents::spending::publish::ProviderSpendingCache`) and `[[module]]` budgets are keyed by file or directory path (`crates/rimz/src/agents/spending`), so search both forms. A rebase runs no hook, so run `cargo xtask atlas conform --ratchet` and `cargo xtask invariants` yourself after one, and `cargo fmt --all --check` at every commit whose conflict you resolved (`git rebase --exec 'cargo fmt --all --check' origin/main`): a resolution left unformatted passes `check`, and the next commit that formats the file carries the churn in its diff. Run `cargo xtask gate` before a PR or hand-off: `--keep-going` runs every step and reports all failures in one pass, and `--check` verifies formatting instead of applying it. On a cold or loaded tree the gate's 15-minute budget trips inside the test step, so run it there as `RIMZ_XTASK_TIMEOUT=90m cargo xtask gate`, and when the test step still times out, rerun it alone with `cargo xtask test --profile gate --no-fail-fast`.
- A change that alters a documented rule greps the old wording across `docs/`, `crates/**/AGENTS.md`, module `//!` headers, and item rustdoc and comments in `crates/**/*.rs` before hand-off, not only the lines the plan names. When the change deletes a mechanism, the grep also covers the verbs that describe it (what it publishes, pairs, or reads), not just the names of its items. When a path stops travelling through a module (a wire, a queue, a socket), the grep also covers the doc links to that module (`rg -n 'wakeup/mod.rs' docs crates --glob '*.md'`), and each hit is read for what it says travels through it. Grep by word stem (`memoiz`, not `memoized PNG`), since a doc may name the same mechanism in another word order. When the stem is also part of code identifiers (`peek` in `peekable`), limit the grep to `docs/`, `AGENTS.md` files and comment lines, or search with `rg -w`, so that a hit means a stale sentence. A change that adds or changes a value a CLI column, detail row, or sidebar row prints greps that column's or row's name (`rg -n 'EXTRA LEFT' docs`) across `docs/reference/` and `docs/guide/`, since a page that lists the possible values does not contain the new one. A change that adds a new way to reach a value a command already prints (a new cause of the `canceled` status) also greps the sentences that define that value (``rg -n -i '`canceled` means' docs/guide docs/reference``) and reads each against the new cause, since a one-sentence summary of a status names neither the change's words nor the path that produces it. A change that adds a member to an enumerated set (a stop reason, a state, a provider) also greps two existing members together across `docs/` and `crates/**/AGENTS.md`, joined by `.*` rather than as a literal pair since other members may sit between them (`rg -n -i 'idle timeout.*memory pressure' docs crates --glob '*.md'`): a sentence that lists the set names neither the type nor the new member. Such a change also reads the paragraph that introduces the set or table for a spelled-out count of its members and updates it, grepping the old count beside the set's noun (`rg -n -i 'nine classes' docs crates --glob '*.md'`): a sentence that counts the members names none of them. A public item added to or removed from a module counts as a member of the set its docs list: grep two of the module's existing items together (`rg -n 'ServeConfig.*SidebarAppErr' docs crates --glob '*.md'`). A change that adds an element to a rendered line (a sidebar row, a CLI column) also greps the names of two elements already on that line, joined by `.*`, across `docs/guide/` and `docs/interface/` (`rg -n -i 'tokens.*model' docs/guide docs/interface`): a sentence that lists the line's contents names neither the new element nor any word the change introduces. A change to what a command prints, writes, or leaves behind (what survives `teams stop`) also greps the command's name (`rg -n 'loop show' docs/guide docs/reference docs/internals`) and reads each hit against the new behaviour, since a guide or internals page describes output and effects in its own words rather than the deleted ones. A renamed or removed identifier (field, type, variant) is grepped across the whole tree with `rg -w <old-name> . --no-ignore-dot`, not only over the paths a plan names. Its stem is also grepped without `-w` over test function names (`rg -n 'fn <stem>_' <test paths>`), and each test whose body now calls the new item is renamed: `-w` cannot match `fn agent_breakdown_folds_tail` once `agent_breakdown` is renamed. A change to a subprocess argv greps its tokens with any separator between them (`rg -n 'attach.{1,4}--create' . --no-ignore-dot`): a test may join them with a tab, or list them as separate array elements, and a search for the space-joined words misses both. A change that makes a command refuse or ask where it used to proceed also greps the repository's own scripted callers of that command, its tokens joined by any separator (`rg -n 'teams.{1,6}launch' loops xtask/src scripts .github crates/rimz/tests`), and reads each call for its stdin and flags: a coordinator runs without a terminal and so takes the refusal path, and its tests that pin only the argv still pass. Read each test hit for the environment it runs under: the integration builders scrub the `RIMZ_*` identity pin and the `TMUX*`/`ZELLIJ*` detection variables (`common::ScrubSessionEnvExt`), so a refusal keyed on ambient state fires there even when every production spawn passes. Before adding a sentence to a doc paragraph, read the whole paragraph against the code it describes, and fix any statement there that the change makes wrong or that is wrong already. A sentence that describes a path through several functions (a walk, a chain, a pipeline) must hold for each of them: list them with `rimz lsp callees` on the path's entry and check the sentence against every one, not only the one the change touched.
- Compile tests with `cargo xtask check`. A bare `cargo check --tests` compiles the same shape: the crate's self dev-dependency turns `testkit` on for every build that carries dev-dependencies, so editors and agent harnesses report the gate's diagnostics rather than phantom `testkit` errors.
- A remove-and-compile census (delete an item, count the compile errors) measures the library alone: the unit-test target is the library built under `cfg(test)`, and the crate's self dev-dependency links the library into it, so neither `--tests` nor `--keep-going` type-checks `#[cfg(test)]` code while the library fails. Count test-side reach after the production errors are fixed, or report it as unmeasured.
- This worktree's built binary is `$(cargo metadata --format-version 1 --no-deps | jq -r .target_directory)/debug/rimz`. The target directory may be shared with other worktrees, each under its own hash directory, so resolve it this way rather than picking the newest.
- Batch focused tests with `cargo xtask test --name <test> [--name <test>...]`, exact names only. `--name` takes the nextest test name without the binary: an integration test is `lsp::some_test`, not `integration::lsp::some_test`; `cargo xtask test --list <fragment>` prints each binary's id (`rimz::integration`) followed by its exact names, not the binary's path; the path comes from `cargo xtask test --list <fragment> --message-format json` or the `binary:` line of a `cargo xtask stress` `summary.txt`. A file mounted with `#[path = "..."] mod name;` runs under the mounting module's path plus `::name`, never under its file name: a sibling `#[path = "foo_tests.rs"] mod tests;` runs as `loop_cmd::list::tests`, and the integration file `loop_list.rs` runs as `loop_schedule::list_tests`, so `test(loop_list::)` matches nothing. `--list` builds the test binaries first, so run a cold one under `rimz wait --run` (a cold build on a loaded host outlasts the 10-minute tool cap), never as a foreground call. During a read-only sweep, run `rimz lsp hover` on the test function instead: the module path it prints, minus the crate name (`rimz::` or `integration::`), plus `::<fn>`, is the exact name, `#[path]` mounts included. Run a whole module through a bare nextest filter: `cargo xtask test 'sidebar_pane::app::width_control'`. A filter and `--name` intersect rather than union, so the two run as separate calls; passing both is what "0 tests run" means. Integration tests live in their own binary, so a module filter has to name it: `cargo xtask test -E 'binary(integration) & test(message::)'`, where a bare `'integration::message'` matches nothing. xtask's own unit tests run in binary `xtask::bin/xtask`, and the `rimz` library has modules of the same names (`sandbox::`), so a filter for them also names the package: `cargo xtask test -E 'package(xtask) & test(/^sandbox::/)'`. `-P` and `-E` combine, so one live module runs as `cargo xtask test -P live -E 'binary(integration) & test(/^backend::tmux::team_stage::/)'`.
- A change to how `harness/schedule/runner.rs` reads a watch result also runs `cargo xtask test -E 'binary(integration) & test(/^wait::/)'`; the `loop_schedule::` filter does not reach the subscriber path.
- A change to what a command prints, text or `--json`, also runs every integration module that invokes it, not only the one named after it: list the files with `rg -l -U '"<cmd>",\s*"<verb>"' crates/rimz/tests/integration`, map a `#[path]`-mounted file to its mounting module, and run each as `cargo xtask test -E 'binary(integration) & test(/^<module>::/)'`. A smoke test in another command's module can assert a line of the output (`loop_schedule.rs` asserts `loop list --all` lines), and several tests compare whole JSON rows. Update each whole-row golden in place so its only diff is the new key, and never drop a key from a comparison to make it pass. Anchor the module name: `test()` matches a substring, so an unanchored `test(stats::)` also runs `performance::sidebar_diff_stats::` tests and `test(wait::)` runs `teams_wait::`.
- A change to code the parked exec wrapper runs (`store::follow::LaunchTail`, `harness::parent_watch`, `cli/agents_cmd/exec`) also runs `cargo xtask test -P live --name backend::tmux::agent_lifecycle::parked_wrapper_holds_under_8_mib`: the parked image's 8 MiB private-memory budget is guarded only there, and `gate` runs no live test.
- Run live Zellij tests through `cargo xtask test`. A bare `cargo nextest run` from a shell that exports `ZELLIJ_SOCKET_DIR` can fail them with `There is no active session!`; prefix it with `env -u ZELLIJ_SOCKET_DIR`.
- A hand-built Zellij probe runs under `env -u ZELLIJ_SOCKET_DIR -u ZELLIJ -u ZELLIJ_SESSION_NAME` with its own `XDG_RUNTIME_DIR`; the inherited socket dir otherwise addresses the user's live sessions. Zellij tries `$HOME/.config/zellij` before `$XDG_CONFIG_HOME/zellij`, so a probe that seeds a user config writes it under the isolated `HOME` or points `ZELLIJ_CONFIG_FILE` at it.
- A hand-built tmux probe runs as a bash script under `tmux -L <name> -f /dev/null` with `TMUX_TMPDIR=/tmp/<8 chars>`: the session `TMPDIR` makes the socket path exceed the 108-byte limit, and zsh does not word-split an unquoted variable holding several arguments.
- A hand-built `rimz remote connect` probe against real OpenSSH runs its own sshd. Generate a host key and a client key under `$TMPDIR` with `ssh-keygen`, and give the server an `sshd_config` with a free high `Port`, `ListenAddress 127.0.0.1`, that `HostKey`, a `PidFile` and `AuthorizedKeysFile` under `$TMPDIR`, `StrictModes no`, `UsePAM no`, and a `ForceCommand` script that runs the session under `env -i` with the isolated remote home. Start it as `bwrap --dev-bind / / --ro-bind "$TMPDIR/group" /etc/group -- /usr/sbin/sshd -D -e -f "$TMPDIR/sshd_config"`, where `group` is a copy of `/etc/group` without its `tty` line: the agent sandbox leaves gid 5 unmapped, so a plain sshd aborts every PTY session with `chown(/dev/pts/N, <uid>, 5) failed: Invalid argument`. Point `RIMZ_SSH_BIN` at a wrapper script running `exec ssh -F "$TMPDIR/ssh_config" "$@"`, whose `Host` entry sets the port, `IdentityFile`, `IdentitiesOnly yes` and a scratch `UserKnownHostsFile`. The `-F` selects that scratch configuration. Stop the sshd by the PID in its `PidFile`.
- `cargo xtask sandbox -- <command>` drives a real multiplexer from disposable roots. To run a command as a room agent, hold a room with `sandbox room` and use `sandbox in <root> --as @handle` ([recipe](./docs/contributing/sidebar-live-check.md#run-a-command-as-an-agent)). From an agent pane, run a live room check through `cargo xtask sandbox room`; a bare `rimz start` refuses inside the agent sandbox.
- A live check of a branch binary runs under an isolated `RIMZ_HOME` seeded from a copy of the state it reads (`cp -r ~/.rimz/cache/providers "$RIMZ_HOME/cache/"`), never the real home: `~/.rimz/cache/` is shared by every running RimZ, and a branch that bumps a publication version rewrites it for all of them. A documented read-only command (`rimz doctor` without `--clear` or `--output`) may be timed against the real home when the branch changes no published cache format.
- An isolated `rimz accounts` check first runs `rimz accounts add <provider> <name>` (or `rimz hooks install <provider>` for `default`) inside the isolated home: a missing-hooks problem takes the `PLAN` column and hides a lapse or the normal plan label.
- A live check whose command rereads transcripts (`rimz stats --refresh`) finds none under an isolated home: the transcripts live in the real account and provider homes. Run each binary inside `bwrap --dev-bind / / --ro-bind ~/.rimz ~/.rimz --bind "$TMPDIR/cache-copy" ~/.rimz/cache --ro-bind ~/.claude ~/.claude --ro-bind ~/.codex ~/.codex --ro-bind ~/.config ~/.config -- <binary> ...`, where `cache-copy` is a copy of `~/.rimz/cache`: it reads the real transcripts and writes only the copy.
- A live check of a branch binary whose command writes the room's own records (a `rimz lsp` query appends to the room's query usage log) runs under `bwrap --dev-bind / / --bind "$TMPDIR/records" <room>/records --bind "$TMPDIR/locks" <room>/locks -- <binary> ...`, where `<room>` is the room's state directory under `~/.rimz/ws/` and each bound directory is a copy of the room's, so the real room is read but never written.
- A live check of a user-shell view (`rimz wait list`, `rimz loop list --all`) from an agent pane runs the binary from a script started with `setsid -f` that writes its output to files under `$TMPDIR` and touches a marker file last. Caller resolution falls back to process ancestry (`CallerIdentity::from_process_ancestry`), so unsetting `RIMZ_AGENT_*` and `TMUX_PANE` still finds the calling agent, and bwrap `--unshare-pid --proc /proc` cannot mount proc under scoped isolation; the orphaned script has no agent among its ancestors.
- A hand-built isolated home keeps `XDG_RUNTIME_DIR` short (`/tmp/<8 chars>`): RimZ refuses a runtime root whose socket paths exceed 108 bytes. It sets `RIMZ_HOME` too: an agent shell exports the real one, which wins over `HOME`, so a probe that isolates only `HOME` or a provider home such as `CODEX_HOME` still resolves the real account homes, and a `rimz trust grant` writes the user's real provider config. It also unsets `CLAUDE_CONFIG_DIR` and `CODEX_HOME`, or points them inside the isolated home: an agent shell exports its own account's directory there, the `default` login reads it, and a probe that isolates only `HOME` and `RIMZ_HOME` still writes that account's `.claude.json`. It also unsets `XDG_CONFIG_HOME`, or points it inside the isolated home: Cursor and Muse hooks resolve their config there, not under `HOME`. It also unsets `XDG_DATA_HOME`, or points it inside the isolated home: OpenCode's database and OMP resolve their data there, so a spend probe otherwise reads the real account's history. A probe that runs a Rust toolchain or rust-analyzer passes `RUSTUP_HOME` and `CARGO_HOME` through, pointing at the real toolchain: an isolated `HOME` has no rustup default, so the server crashes with `rustup could not choose a version`.
- Run one Cargo-family command at a time in a worktree; concurrent builds only queue on the same target-directory lock, and a Cargo process from another worktree on the shared target directory queues yours the same way, so start your command rather than waiting for it.
- The gate stack, the nextest-only runner, the sandbox roots, the test tiers and what each owns, and the one-home rule for a module's unit tests all live in [rust-conventions.md](./docs/contributing/rust-conventions.md). An inline `mod tests` over 500 lines fails the pre-commit invariant; move the whole module to a sibling `tests.rs`.
- Judge the reach of your own change. Escalate past `gate` to the journey (`cargo xtask test -P journey`), live-backend and `journey::deep` (`cargo xtask test -P live`), performance (`cargo xtask perf`), or dependency (`cargo xtask externals`) gates, or to full CI (`cargo xtask ci`), when the change touches those surfaces, their fixtures, or shared infrastructure. A test's profile is set by the filters in `.config/nextest.toml`, not by its directory: get the exact name from `cargo xtask test --list <fragment>` and match it against those filters. CI's `tests` job is the branch-protection floor, not the ceiling.
- A change to any `Cargo.toml` dependency, including an optional or feature-gated one, runs `cargo xtask externals`: cargo vet audits every non-dev dependency at safe-to-deploy, and a dependency that only the `testkit` feature enables passes every per-crate check and fails only there.
- A change that bounds a reader by a window relative to now greps the tests that write its records for fixed timestamps (`rg -n '"20[0-9]{2}-[0-9]{2}-[0-9]{2}T' <test paths>`) and makes each now-relative or gives it an explicit floor, since a fixture inside the window today falls out of it later.
- A change that adds or extends a probe or poll path (a forge lookup, a provider refresh, a status read) tests each failure path before hand-off, not only the success path: the first attempt failing with no prior state falls under the lane's backoff rather than re-running every pass; one target's error does not fail or silence its group; a lookup that matches by a loose key (a branch name, a title) also asserts the owner it must match. A test over a stubbed command asserts the per-endpoint call count, since a duplicate or missing read passes a results-only assertion.
- A change to how a shared probe spawns (a memo, a cache, a dedupe) finds the tests that count its spawns before hand-off, by the counting stub's log (`rg -n -i 'probes' crates/rimz/src crates/rimz/tests`), and runs them: a test that counts spawns inside one process (`harness::launch_plan::tests::configured_prompt_changes_control_snapshot_reuse`) breaks under a per-process memo, and only the full gate otherwise catches it.
- A change that points an existing read at rooms or targets beyond the caller's (a per-room snapshot in a machine-wide list) traces every diagnostic record that read can emit to `classify_diagnostic` in `crates/rimz/src/cli/doctor/runtime.rs` before hand-off. A record it classes `Investigate` files a `warn` or `alarm` incident against that other room's `rimz doctor` health tally, so a read-only command run elsewhere becomes a false health warning there, written again on every run.
- `gate` compiles the host target only. A change that touches `nix`, `libc`, or platform-gated code also runs CI's macOS type-check, `cargo-zigbuild check -p rimz --target aarch64-apple-darwin --locked`: an item that exists only on Linux passes the gate and breaks that step.
- Capture planned behaviour in the owning doc and add the executable test when the implementation can make it pass. An ignored test standing in for a future product target does not land.
- A shell snippet that another host runs through its login shell (`remote setup`, `remote connect`) is tested by executing the generated text under `sh` and, when present, `zsh`, with the network commands stubbed; a substring test cannot see a zsh-only reserved word such as `status`.
- **Invariant.** `cargo xtask invariants` greps tracked text, Rust and Markdown alike, to guard the architectural boundaries. Because it matches text rather than parsed code, an `AGENTS.md` inside a guarded subtree is scanned with it: describe a boundary in prose and leave the banned path unwritten. Because it reads only tracked text, a new untracked file escapes both `invariants` and `gate` until the pre-commit hook rejects it, so stage new files with `git add -N` before running either.

## Code map

This indexes what lives where. Runtime shape and the single-binary rationale live in [ARCHITECTURE.md](./ARCHITECTURE.md), and each module's `//!` header is the per-file authority.

**Repository** — `crates/rimz/` (the binary plus the runtime/domain library; `benches/`, contributor sidebar stories in `scenarios/`, and the `presence/`, `pricing/`, and `themes/` data that `build.rs` embeds), `crates/rimz-presence-zellij/` (headless Zellij presence plugin, wasm32-wasip1, no rimz-crate deps), `docs/` (product and engineering docs; `docs/externals/` mirrors upstream), `xtask/` (task runner and every gate), `loops/` (one directory per isolated automation task), `examples/` (user-facing sample configuration, read only on request), `ci/`, `docker/`, `scripts/`, `supply-chain/`.

**Subsystems** in `crates/rimz/src/`, each carrying its own `AGENTS.md` contract:

- `cli/` — command parsing, one `run(...)` per subcommand, shared `cli/render/` output, and the subagent fleet digest. `cli/` is declared in `main.rs` and calls the library as `rimz::`, so it reaches only `pub` items.
- `agents/` — the provider-neutral `AgentDefinition` catalog, caller-aligned capability contracts and services, `state.rs` rollup, agent handle minting and validation (`petname`), private `adapters/` implementations for every built-in and process plugin, host-mode skill links, shared spend/pricing/account machinery including upstream pricing projection, and provider login resolution (`login`: named account homes, a room's login set, resume account checks).
- `room/` — private managed-room context, birth/reset/teardown lifecycle, sidebar/presence options, and health gating.
- `sandbox/` — Linux bubblewrap agent mount views, live protected-bind repair, provider-home binds, per-agent temp units, rewritten skill copies, profile skill views, and capability preflight.
- `harness/` — layout IR, teams, team prompt layer and built-in consensus, locked board entries and stage flips, launch plan compile/apply and argv, shared headless check launches (`headless.rs`), supervised run transitions and their wake socket, workflow definitions, the agent-attempt host seam and condition/script/shell/judge transitions (`workflow/`), the elected hook drainer and socket leases (`hook_drain.rs`), loop scheduling over clock/signal/watch/condition triggers and the home-wide start throttle (`schedule/fire.rs` and the read-only `schedule/when.rs` evaluator are in the sidebar graph), signal selectors and in-process firing, resume planning, and rebirth recovery inspection/materialization.
- `message/` — message delivery: park-vs-live dispatch, live-pane send, reply waits, scheduled wakeups, synthetic text for a card (composition, boundary attempt, recorded miss).
- `store/` — durable state engine: `Store` handle, canonical snapshot schema, writer mutation vocabulary/choreography, framed event log, raw hook ingress and drain cursor (`ingress.rs`), message record and queue codec, lifecycle follower, the supervised-run record with its codec and terminal wake sender, workflow records and journals (`workflow.rs`), GC.
- `mux/` — Zellij/tmux seam: `MuxBackend`, cross-backend live-session snapshot, subprocess engine, reconcile planner, recovery, focus-intent anchor, room width target, Zellij pane-topology and presence-desired caches, per-pane write lock, pane winsize repair.
- `sidebar/` — data plane: Zellij presence ingestion, shared host production, pulled-truth/event fusion, realtime overlay store, projection fold, heavy-lane refresh.
- `sidebar_pane/` — native renderer: the per-pane supervisor, the per-session host that paints every pane, the attach wire between them, pets, and the ratatui theme/component edge.
- `remote/` — SSH grammar, reconnect policy, link health, `remote.toml`.
- `diag/` — diagnostic-only JSONL append surfaces.

**Top-level modules** in `crates/rimz/src/`, by purpose:
